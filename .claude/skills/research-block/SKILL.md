# 調査ブロックへの着手

**この手順を飛ばして原文を読み始めた結果、誤った巻・誤った日付を採用して手戻りした事故が複数回あります。**
1〜2 は合わせて数分です。

## 0. 着手の3点は1メッセージで同時に出す

着手時に要るものは互いに依存しません。**1つのメッセージにまとめて呼びます**
（全34セッションの実測で、依存の無いツール呼び出しの並列化率は **0.2%** でした）。

- `python3 scripts/brief_block.py <書名> [--id <皇帝id>]` — 罠
- `jq '...' data/emperors.json` — 対象レコードの現状（**全体を Read しない**）
- `ls _corpus_cache/<id>.txt` — 原文キャッシュの有無
- `python3 scripts/check_regime_conventions.py --scope` — 政権単位で確定済みの範囲（0.5 節）
- `python3 scripts/check_screenings.py --scope` — 母集団 N → 要読解 M（0.6 節）

**worktree にはコーパスが無い**（`.gitignore` 対象なので primary にしか実体がない）。
無ければ `ln -s /home/sakis/emperor-stats/{_corpus_cache,china-history,daizhigev20} .` で通す。

**advisor を呼ぶならここ**（方針が固まる前）と**完了直前**の2点だけです。advisor は
会話全文を非キャッシュで再送するので、同じ助言でも会話が長いほど高くつきます。

## 0.5. 政権単位で決まることを、人物単位で365回やらない

「この政権は廟号を立てるか」「第N代をどう数えるか」は人物の属性ではなく**政権の慣行**です。
先に政権単位で確定すると、人物単位の問いが「この人に廟号はあるか（判定）」から
**「冒頭1行を書き写す（転記）」**に変わり、しかも複数項目が1回の読みで同時に取れます。

```bash
python3 scripts/check_regime_conventions.py --scope        # 母集団 N → 要調査 M
python3 scripts/check_regime_conventions.py --for <皇帝id>  # その人物に効く慣行（未確定なら 1 で終了）
```

記録するのは**書式と所在だけ**です。`data/regime-conventions.json` に

> 舊唐書は本紀冒頭に「〈廟号〉〈諡号〉皇帝，讳〈諱〉」を並べる（書名・巻・行・引用）

とは書けますが、**「唐は全員に廟号がある」とは書けません**（人物単位の主張で、24人読まないと
言えない）。書こうとしている記述が**特定の人物の値を1つでも含意していないか**確かめてください。

**絞り込みの誤りは非対称です。**「書式がある」を誤ってもトークンを損するだけですが、
「無い」を誤るとその政権の空欄を全件まとめて「正しい」と結論します。打ち切り側
（`absent-by-institution`・`biography-only`）の根拠だけは厚く取ってください（ゲートが要求します）。

**機械の書式当たりは絞り込みであって判定ではありません** — 前漢14人は冒頭3行に「讳」が0件ですが、
これは廟号が無いのではなく漢書が冒頭に並べないだけです。

## 0.6. 原典を読む前に、機械で母集団を絞る

**原典読解のトークンは母集団に比例します。**先に機械で前提を検査すると読む量が桁で変わります
（#34 は note の干支が旧暦年月に実在するかを sxtwl で検査して293件中282件を裏付け、
残り20件だけを本紀で読みました。#38 は `quote_diff.py` で234件を仕分けました）。

絞り込みは**その場の一発コマンドにせず** `scripts/screens/<名前>.py` にコミットし、
結果を `data/screenings.json` に残します。

```bash
python3 scripts/check_screenings.py --scope        # 母集団 N → 要読解 M
python3 scripts/check_screenings.py --for <皇帝id>  # その人物がどのバケットか
python3 scripts/check_screenings.py --update       # 調査が進んで母集団が減ったとき（件数だけ）
```

バケットは3種です。

| kind | 意味 | 要るもの |
|---|---|---|
| `read` | 要読解。原典に当たる | — |
| `corroborated` | 独立した計算か原典の明文が前提を**積極的に裏付けた** | `establishes`（何を裏付けたか） |
| `absent` | 機械が**何も見つけなかっただけ** | **種つき無作為標本の監査**（`audit`） |

**`absent` を「値が無い」と読まないでください。**Issue #37 の名前データで実際に測ったところ、
諡号の absent 側は標本6件中3件が取りこぼしでした（廟号で呼ばれる皇帝は commonName が
「神宗」になるので、諡号が本紀冒頭に並んでいても検査に当たらない）。

標本は**スクリプトが種から引き**、ゲートが同じ種で引き直して突き合わせます。
自分で選んだ標本では取りこぼし率の区間は言えません（ゲートが落とします）。

**絞り込みは読む順序と量を変えるだけです。**判定を機械にさせるわけではありません（`R-NO-AUTOGEN`）。

## 1. 罠を出す（読むのは全文ではなくこの出力）

```bash
python3 scripts/brief_block.py <書名や時代区分> [--id <皇帝id>]
```

必ず出るもの（全書共通）と、その書に固有の罠・行範囲だけが出ます。
**該当なしと出たら、その書は罠が未調査**です。1〜2件を原文の「卷○○」見出しと照合し、
巻数が絶対か相対か・「原文」ラベルの中身が本当に文言文か・人物記事が巻をまたいでいないかを
確かめ、結果を `docs/process/CORPUS_NOTES.md` と `SOURCE_MAPPING.md` に**足してから**配ります。

## 2. 曖昧点をユーザーに詰める

判定基準を新設・変更するときは、**答えによって判定が変わる点から**一問一答で確認し、
基準を文書化して承認を得てから着手します（着手後に基準を変えると、調査済みブロックの
遡及監査が必要になる）。適用範囲が書かれていない規則に出くわしたら、自分で決めずに聞く。

## 3. エージェントを立てる

- **素の Agent を立てない。** `.claude/agents/corpus-researcher.md` を使う
  （引用規約・出力契約・grep 制約が system prompt 側に入っているので、写し漏れが起きない）
- **調査単位は人物**（皇帝個人の行為）。王朝単位の離散イベントだけ王朝単位で年表を作って逆引きする
- **同じ原文を読む複数項目は1エージェントに合算する**
- **id はプロンプトに直接埋め、「一字一句そのまま返す」と書く**
- 段構成が2段以上になるなら `.claude/workflows/` に名前つきで置く（毎回書き直さない。
  既存: `name-block.js`）。**検証段を省かない** — 自分の出力を自分で検証させると通ってしまう
- **検証段の体数はブロックごとに決めない**（規則 `R-VERIFY-TIER`）。政権の史料形態から引く:

  ```bash
  python3 scripts/check_verification.py --for <皇帝id>   # tier・体数・観点
  python3 scripts/check_verification.py --scope          # ブロック全体の内訳
  ```

  本紀・帝紀が独立して立つ王朝は1体（`facts`）、載記・類書・別史・地方志に依存する政権は
  **3体**（`facts`・`kinship`・`dates`）。欠陥密度が実測で 0件/人 と 1.56件/人 の段になっていて、
  どのブロックも同じ厚みで回すと薄い側に無駄が出て厚い側で漏れます。
  **記録に無い政権は厚い側（3体）**で、政権が薄い側でも**所在が違う人物は例外**として厚い側に
  残る（舊唐書の殤帝ら4人）。だから**政権ではなく人物 id で `--for` を引く**。
  3体の指摘は `(field, problem)` で畳んでから数える

## 4. 受け取る

出力は `docs/process/CLAIMS_CONTRACT.md` の形（claims-first）。まとめて掛ける:

```bash
python3 scripts/check_claims.py <断片ディレクトリ>
```

**エラー0でも REPORT 行を読む**（字体で当たった＝打ち直しの印・行ズレ・合成疑い）。
本体（`data/emperors.json`）への投入は**親セッションだけ**が行います（並行編集を避ける）。
投入したら該当ゲート（`validate_emperors.py` ほか）と
`docs/process/COUPLINGS.md` の結合を確認してからコミット。

## 4.5. 完了は宣言せず、実測する

```bash
python3 scripts/coverage.py                 # 項目別・政権別の実測（0.1秒）
python3 scripts/coverage.py --write         # PROJECT_STATUS.md の進捗表記を引き直す
```

**「ブロックを回したから完了」と書かない**（規則 `R-COVERAGE-MEASURED`）。グループ2の
「364人完了」はチェックリスト上の申告で、実測は355人でした。数えるのは**確定したか**で、
`判別不能` の欄は「誤り」ではなく「**完了の主張が機械では確かめられない**」という意味です。

`--write` を忘れたコミットは CI と turn 終了時のゲートが落とします。**残ったセルは
`--field <項目>` で id が出る**ので、そのまま次のブロックの母集団になります
（0.6 節の絞り込みへ戻る）。

## 4.6. 検証段の指摘率を記録する

ブロックを終えたら `data/verification.json` の `blocks` に1行足します（規則 `R-VERIFY-TIER` の完了条件）:

```bash
python3 scripts/check_verification.py          # ゲート
python3 scripts/check_verification.py --rate   # ブロック別の指摘率
```

- `raised` = 検証段の指摘を `(field, problem)` で畳んだ一意件数（**体ごとに数えると3体で水増し**）
- `confirmed` = そのうち**親セッションが原文で確かめて実欠陥だった**件数。検証段に自己採点させない
- `escapes` = 後日、別作業の途中で見つかった実欠陥（あとから足す）

**体数を動かした効果は同じ tier の中でしか読めません**（tier をまたぐと政権の密度と交絡する）。
また **`confirmed/raised` は検証段の精度**であって再配分の成否ではありません（観点を足せば下がりうる）。
効いたかを示すのは **`dependent` ブロックの `escapes`** が 1.56件/人 から下がるかどうかです。

## 5. 手順の改善を提案する

調査中に「この手順のここが効かない／こうすれば減る」と気づいたら、**その場でユーザーへ提案**します。
後からは思い出せません。採否が決まったら `docs/process/PROCESS_IMPROVEMENTS.md` に記録します
（規則 `R-PROCESS-FEEDBACK`）。
