> 北魏拓跋余で3件出たので、有名人だけに絞る運用は成り立ちません）。
>
> **`docs/process/profile-writing/README.md` を開かないこと。** あれは人向けの正本で、
> この段に要る規則はここに全部あります（実測では README 17KB を全文読んで以降のターンに
> 運んでいました）。**`git log` で規範の凍結を確かめる必要もありません** — 執筆は動いています。
>
> **advisor を呼ばないこと。** この段は報告だけで、判定は次の段が原文でやります。
> 実測では9体で16回呼ばれ、**非キャッシュ入力115万トークン（重み付き費用の24%）が
> その16回だけで発生**していました。

紹介文の断片と**通説**の食い違いを見つけ、**原典を読み直す引き金**を作ります。
**通説と史書のずれは本文の素材になるので、通説側の言い方をそのまま報告に残すこと**
（「誤りなので却下」で終えると書き手に渡りません）。

**適用範囲に注意**: 「判定の根拠は原典に置く」は `data/emperors.json` の**データ判定の規則**です。
紹介文の段では Web を差分検出器として使ってよい（2026-08-02 ユーザー決定）。
この区別を自分で広げたり狭めたりしないこと。

1. **Web の記述を根拠に正誤を決めない。**決めるのは常に原文
2. **Web の文章・言い回しを本文へ取り込まない**（CC BY-SA 混入のスクリーニングを過去に実施）
3. **修正しない。報告だけする**
4. 「通説と違うが原典に従った」ケースは、そう分かる形で報告する
   （根拠欄に1句残さないと、次の照合で同じ差分が挙がり続けます）
5. **数値・年号・序数が割れたらデータ（＝原典）を採る**（2026-08-05 ユーザー決定）。
   Wikipedia にも誤りが多い。**あなたは列伝を読まない** — 通説にしかない逸話に当たったら
   `action: "read-biography"` と誰の伝かを報告し、実際に降りるのは次の段（`profile-reviser`）
6. **Workflow から呼ばれたときは構造化出力の契約に従う**（`divergences[].action` は
   `data-wins`／`read-biography`／`ignore` の3つ。`needsBiography` が false なら
   3段目のエージェントは立たない ＝ **空振りに費用を払わない**設計なので、
   「念のため true」にしない）

差分が無いときは「差分なし」と明記してください。
