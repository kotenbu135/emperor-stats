皇帝1人の紹介文を書きます。emperorstats.com に公開され検索結果にも出るので、
**誤りを出さないことが分量より優先**です。

> **`docs/process/profile-writing/README.md` を開かないこと。** あれは人向けの正本で、
> 執筆に要る規範は**この文書が持っています**（下に全部あります）。実測では9体すべてが
> README 17KB と SKILL.md 6.5KB を全文 Read して以降20ターンぶん運んでおり、
> キャッシュ読みの17%がこれでした。判断に迷ったらここを読み直す。
>
> **advisor を呼ばないこと。** この作業の判定者は
> `check_profile_fragment.py --strict` で、助言が判定を変える余地がありません。
> 実測では9体で16回呼ばれ、**非キャッシュ入力115万トークン（重み付き費用の24%）が
> その16回だけで発生**していました。

親から渡された `{{ID}}`・出力先（`workDir`）を当てて従ってください。

## 走らせる順

```bash
python3 scripts/extract_profile_material.py <id>          # --notes on を付けない
python3 scripts/new_profile_fragment.py <id> --out <workDir>
#   … 読んで書く …
python3 scripts/check_profile_fragment.py <workDir>/<id>.json --strict
python3 scripts/check_profile_ngram.py    <workDir>/<id>.json
```

素材の末尾に **読み地図**（本紀のどの区間が詔・冊文でどこが叙事か）・**列伝の在り処**・
**見本1本の全文**・**ゲートの走らせ方**が出ます。**見本や構造をこれ以上引き直さない**
（`emperor-profiles.json` のキーを探る・`name-readings.json` を grep する必要はありません）。

**本紀の原文キャッシュ `_corpus_cache/<id>.txt` を1巡だけ読んで書きます。** 読み直さない。
簡体字なので検索も簡体字で（`scripts/hanzi_norm.py`）。詔・冊文の区間は**速度を上げる**
（飛ばさない — 大赦・改元・遷都は詔の中にあります）。読み地図の割合は下限なので、
迷ったら読む側へ倒す。**列伝を最初から読みに行かない**（2段目の Web差分が当たった箇所だけ、
あとで本紀の外を1箇所だけ降ります）。

## 書き方をこう決めてある

**`build.py` の類を書かないこと。** `Write` は骨格を埋める1回だけで、以降の直しは `Edit`。
実測では9体すべてが 6.7KB の builder を書いてゲートで落ちるたびに丸ごと書き直しており、
本文2,000字の成果物に対して1体3〜6万トークンの出力になっていました。

**引用台帳は `<workDir>/<id>.claims.jsonl` に1行1件**（`{"text": 本文で書く事実,
"quote": 根拠の原文句, "src": "ファイル:行"}`）。読みながら足します。断片の中に持つと、
本文を1文直すたびに台帳40〜50件ごと再送されます。

### 全員に同じ5つの問いを立てる。字数は揃えない

1. **誰の何にあたる人か**（どの政権の、前任者とどういう関係か）
2. **どうやって位に就いたか**
3. **在位のあいだ何が起きたか**（確かめられる場面を最低1つ）
4. **どう終わったか**
5. **記録が伝えないことは何か** — 薄い人物ではこれが本文の主題になる。逃げ口上ではなく、
   「『遼史』がこの皇帝について伝えるのは数行しかない」は**その人物にしか書けない事実**

### 長さ

`lead` 70〜260字・`body` 100〜2400字・`description` 100〜140字（ルビを剥がして数える）。

**`body` の目安は800〜1,500字。上限に合わせて書かない。** 先行の Workflow 3本が原文の量と
無関係に2,000字級へ揃いました（原文が22倍違う清の咸豊帝と南漢の劉鋹が3%差）。
超えてよいのは**材料が本当に多いと言えるときだけ**で、**書くことが尽きたら止める**。
手抜きに見えるのは短さではなく水増しです。

### 文体

- だ・である調。**現代の日本語**で書く。原文を訓読しただけの語は使わない:

  | 使わない | 書く |
  |---|---|
  | 崩じた・薨じた | 死んだ |
  | 母を皇太后に尊んだ | 母を皇太后の位に就けた |
  | 六国を併せた | 六国を併合した |
  | 蒙恬を監させた | 蒙恬の軍を監督させた |
  | 誅した／徙した／賜った | 処刑した／移した／与えた |
  | 請う／奉じた／可とした | 願い出た／差し出した／認めた |

  **「没した」は禁じていません**（現代の日本語でも広く通用する）。判定は「原文の語を
  訓読でそのまま持ってきたか」で、見慣れない語かどうかではありません。
  ゲートが落とします（語の一覧は `scripts/profile_prose.py`）。**カギ括弧の中は対象外**で、
  『漢書』が「薨」とだけ書く、のように史書の語そのものを話題にする箇所は落ちません。
  「即位」「封じる」「詔」は歴史用語なので禁じていません。
- 原文の言い回しを写さず、内容を理解して自分の言葉で書く。漢文をそのまま持ち込まない
- **敬称・賛辞・主観的評価を書かない**（「名君」「暗愚」）。史書の評を引くときは
  「『漢書』は〜と評する」と主語を立てる
- **集計値を書かない**（「改元4回」「大赦10回」— 同じページのすぐ下に回数の表があります）。
  **個々の事件は集計値ではないので書く**
- `lead` の第1文は定義文（「〜の皇帝」）。そこから即位・事績・最期までを1段落で見通す。
  **年譜形式にしない**
- **節見出し（`## `）を立てない**（立てると本紀の通読要約に引きずられ、読む量が青天井になります）。
  段落は空行で分ける

### 人物名は素材の「本文で使う名前」をそのまま使う

素材の冒頭に **`本文で使う名前: ｜慕容垂《ぼようすい》`** が1行出ます。本文で
その人物を指すときは**必ずこの形**で、ルビも振ります（2回目以降も）。

**原文は諱1字で人物を指しますが、そのまま持ってこないこと。**「垂は兵を返し」
「勒が部下を監督した」は日本語として通用しません。既存148本のうち91本・延べ922箇所が
そうなっていて、2026-08-07 にまとめて直しました。ゲートが落とします。

**姓を繋げれば済む話でもない**ので、自分で組み立てず素材の1行から採ってください
（遼の太祖は諱が「億」ですが通用名は**耶律阿保機**、元の世祖は**クビライ**）。
判断が要るのは1箇所だけ — **諱そのものを話題にしている文**（「諱は禅、字は公嗣」
「石を姓とし勒を名として与えた」）はそのままでよく、ゲートも数えません。

### ルビ

**総ルビはやめました。** 振るのは固有名詞と中国史の語（人名・**帝号・廟号**・元号・地名・
官職・制度・器物・故事・干支）で、一般語には振らない（「皇太子」「儒学」「政治」）。
記法は `｜親文字《ルビ》` で **`｜` を省略しない**。`description` には振らない。親文字が2字以上で `data/name-readings.json` に
載っているものはテーブルと同じ切り方・同じ読みにそろえます（**先に grep しなくてよい** —
違えばゲートが落として正解を出します）。

**2回目以降の出現にも振ります**（2026-08-05 ユーザー決定）。初出だけに振って以降を
素通りさせない。`lead` と `body` はつないで1本として見ます。**書き終えたら1回流せば
機械が全出現へ写す**ので、手で数えなくてよい:

```bash
python3 scripts/reapply_profile_ruby.py <workDir>/<id>.json --write
```

`data/profile-ruby-lexicon.json` に載る語（干支・官職・制度・地名・故事）は**必ず**
振ります。ルビ無しで残っていればゲートが落とし、正しい記法を出します。
新しい難読語に振ったときは、**2冊以上に出そうな語だけ**辞書へ足してください
（1つ足すごとに残り318人へその読みが固定されるので、その本にしか出ない語は
本文のルビだけで済ませる。同じ本の中の揃いはゲートが本文から引きます）。

**読みはユーザーに確認しません**（2026-08-06 ユーザー決定）。振る語も読みも書き手が
決めます。ただし**中国史の語に日本の元号の読みを当てない** — 「元和」は日本だけが
げんな で、中国の元号は**げんわ**（同じ本に出る「章和」しょうわ・「永和」えいわ と
そろう）。同じ理由で音を落とさない（「鈕祜禄」は じゅうころ ではなく **じゅうころく**）。
本をまたいで読みが割れると `validate_readings.py` の検査7・8 が落とします。

**ルビは読みの手当てでしかない。** 読めても意味が分からない語（「奇貨居くべし」「仲父」）は、
ルビに加えて**地の文でその場で意味が通るように書く**。史書の語をそのまま置いて読者に
辞書を引かせない。ここは機械では見られないので、書き手が見ます。

### `basis` はポインタであって覚え書きではない

ファイル名＋行番号＋そこに何があるか。**散文で書かない。**

```
_corpus_cache/han-yuandi.txt（漢書 巻九 元帝紀）L1 宣帝との問答・立太子／L16-17 蕭望之と弘恭・石顕
```

前の手順では `basis` の総量（49,984字）が `body` の総量（46,754字）を上回っていました。
**成果物より覚え書きが多い状態を作らない。**

## 破ってはいけない規則

1. **原文 → 引用台帳 → 本文。台帳に無い事実は書かない**（`R-CLAIMS-FIRST`）。
   **既存 note はあなたに渡りません**（素材コマンドが既定で伏せます）。note を読むと
   note の筋書きに合う原文句を探すことになり、note の誤りが本文へ流れます。
   **`--notes on` を自分で付けないこと** — 突き合わせは検証段の仕事です
2. **原文引用は手打ちしない**（ツール出力からコピー・字体を変えない）。
   **コーパスに `.{0,N}` 型の抽出 grep を掛けない**（`R-CORPUS-GREP`・WSL ごと落ちます）
3. **原文が続柄を直接述べていない関係は書かない**（推論で世代を埋めない）
4. **素材の値（在位年・年齢・回数・events の日付）が原文と食い違ったら原文を採り、必ず報告する。**
   食い違いが無いときも「食い違い: なし」と書く。**数値の理由を推測で埋めない**
5. 他サイトからの文章の取り込み禁止（Web は差分検出器としてのみ）
6. **人物の内心を断定しない**（「〜と考えた」を書かず、史料の発言・詔・行動に置き換える）
7. **1つの文が2つの条をまたぐときは、条ごとに主語を分けて書く。** 唐の敬宗で、本紀の
   「賊が御座に登った」（主語は無名の賊）と五行志の「二人対食于清思殿」を1文へ融合させかけた
   ことがあります。その像は資治通鑑のもので、**引用が実在していてもゲートは通ってしまう**

## 返す前に

`check_profile_fragment.py --strict` を**通るまで直してから**返します。
落ちたらエラー行の**「直し方」**を読む（ゲートのソースを読みに行かない）。
エラーだけでなく報告欄も読むこと。
