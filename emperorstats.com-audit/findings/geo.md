## 1. AIクローラのアクセス可否

robots.txt（本番、`curl` で取得。2026-07-27時点）:

```
User-Agent: *
Allow: /
Disallow: /kinship-source

Sitemap: https://emperorstats.com/sitemap.xml
```

`User-Agent: *` に `Allow: /` のみで、クローラ名を個別指定した行は無い。実際にUAを偽装して疎通確認した結果:

| クローラ | UA文字列 | 応答 |
|---|---|---|
| GPTBot | `GPTBot` | HTTP 200 |
| OAI-SearchBot | `OAI-SearchBot` | HTTP 200 |
| ClaudeBot | `ClaudeBot` | HTTP 200 |
| PerplexityBot | `PerplexityBot` | HTTP 200 |
| Google-Extended | `Google-Extended` | HTTP 200 |
| CCBot | `CCBot` | HTTP 200 |
| Bingbot | `Bingbot` | HTTP 200 |

**重大度: Low（現状維持で問題なし。明示宣言は「保険」程度の価値）**

- 証拠: 上表（`curl -A "<UA>" -o /dev/null -w "%{http_code}" https://emperorstats.com/`、2026-07-27実行）。robots.txtは `User-Agent: *` の1ブロックのみで個別クローラ行は存在しない（`curl https://emperorstats.com/robots.txt` で確認）。
- 評価: **現状「ブロックされていない」は事実として正しいが、それは「デフォルトで許可されている」だけであり、能動的にAI検索エンジンへの露出を歓迎する意思表示にはなっていない**。CCBot（Common Crawl。学習用途）を個別にDisallowしていない点も、方針として「学習データ提供は拒否、検索での引用は歓迎」のような区別ができていない状態。
- 修正案: `User-Agent: *` ブロックに加えて、GPTBot・OAI-SearchBot・ClaudeBot・PerplexityBot・Google-Extended・Bingbotを個別に明示`Allow: /`する行を追加すると、（1）サイト運営者がAI検索での引用を意図的に歓迎している意思表示になる、（2）将来どれか1クローラだけを制限したくなった時に個別行が既にあるため差分変更で済む。CCBot・anthropic-ai・cohere-aiは学習専用bot（検索連携なし）のため、方針次第でDisallowも選択肢（現状Allowのままでも実害は小さい）。
- 失敗判定: robots.txtの個別クローラ行追加後もAI引用率（後述の先行指標）が変化しない、またはOpenAI/Anthropic/Perplexityが「robots.txtの個別Allow行の有無はクロール判断に影響しない」と明言した場合、この指摘は「効果なし」と判定できる。
- 先行指標: 変更前後でサーバーログの`User-Agent`別アクセス数（GPTBot/ClaudeBot/PerplexityBot/Bingbot）を比較する。本監査ではアクセスログ取得手段がないため「取得不可」（Cloudflareのログ機能や別途Bot Analyticsの導入が必要）。

## 2. llms.txt

`https://emperorstats.com/llms.txt` は **HTTP 404**（`curl -o /dev/null -w "%{http_code}" https://emperorstats.com/llms.txt` で確認）。

**重大度: Medium**

- 前提の明記: **Google検索・Google AI OverviewsはllmsTxtを参照しない**（llms.txtはOpenAI/Anthropic系のエージェント的な取り込みを想定した非公式の民間規格であり、いずれの主要検索エンジンも公式にサポートしていない）。したがって「llms.txtを置けばAI検索順位が上がる」という主張は過大評価であり、本サイトの主戦場である一般的なAI検索（ChatGPT検索・Perplexity・Bing Copilot・Google AIO）への直接効果は保証されない。
- それでもこのサイトには**固有の実利がある**: 本サイトは「データセット配布サイト」（`/about`にCC BY 4.0・JSON/CSVダウンロードURL・スキーマ定義を明示済み）であり、llms.txtは「このサイトはデータセットであり、機械可読な本体はここ、ライセンスはこれ」という要約をLLMエージェント（ChatGPTのプラグイン的なブラウジングツール、Claude・Perplexityのようにファイル取得を試みるエージェント型利用）に即座に伝えられる。現状この要約は`/about`ページの散文の中に埋もれており、専用の機械可読エントリーポイントが無い。
- RSL 1.0（Really Simple Licensing）: `curl -o /dev/null -w "%{http_code}" https://emperorstats.com/rsl.xml` → **404**。`grep -c 'rel="license"' site/out/about.html` → **0**（`<link rel="license">`等のRSL関連マークアップは無し）。RSLはまだ普及初期の規格であり、CC BY 4.0の明示（既に実装済み・後述）で実質的なライセンス表明はできているため、RSL単体の追加優先度は低い。
- 修正案: `/llms.txt` に以下を含める最小構成を提案（本文はCC BY 4.0のためAI側の判断材料として引用可）:
  - サイトの1行要約（`/about`のDataset descriptionと同一文言でよい）
  - データセット本体へのリンク: `https://emperorstats.com/data/emperors.json`（完全版）・`https://emperorstats.com/data/emperors.csv`（平坦化版）・`https://emperorstats.com/data/emperors.schema.json`（スキーマ）
  - ライセンス: `CC BY 4.0`、帰属表示例（`/about`に既にある文言 “出典: 中国皇帝統計 (emperorstats.com), CC BY 4.0” を転記）
  - 統計ページ6件・皇帝一覧・年表への主要リンク
- 失敗判定: 導入後もChatGPT検索・Perplexityでの本サイトへの言及率・参照率に変化がなければ、「llms.txtの実利はデータダウンロード発見性の向上に留まり、引用率には寄与しない」と判定できる。
- 先行指標: 監査を再実行せず観測する方法として、（a）`emperors.json`/`emperors.csv`への`Referer`なしダウンロード数の増減（サーバーログ、現状取得不可）、（b）ChatGPTやPerplexityに「中国皇帝 在位年数 データセット ダウンロード」等で問い合わせ、本サイトのデータURLが直接提示されるかを定期的に手動確認する。

## 3. 引用適性（Citability）— パッセージ単位評価【最重要】

### 3.1 手法

`site/out/` の統計6ページ（`reign.html` `death-accession.html` `court-events.html` `military.html` `ages.html` `dynasties.html`）から `<script>`・`<style>`を除去し、タグを除去した素の可視テキストを抽出して評価した（Nivo/rechartsのチャート内SVGテキストがどう扱われるかは §4 で別途評価）。

### 3.2 本文の文字数（ナビ・フッター約200字を含む、script/style/タグ除去後）

| ページ | 文字数 | 静的な数値リスト（上位10名等） | 「読み取れること」断定文 |
|---|---|---|---|
| `/death-accession` | 314字 | **ゼロ**（円グラフSVGのみ） | 死因・即位経路それぞれ1文のみ（8分類の内訳数値は本文になし） |
| `/dynasties` | 483字 | **ゼロ** | 平均在位年数のみ1文（死因内訳セクションには断定文なし） |
| `/ages` | 914字 | あり（即位時年齢・没年齢 各10名） | 2セクション中1セクションのみ（即位時年齢のみ。没年齢ランキングに無し） |
| `/military` | 1093字 | あり（親征・反乱鎮圧・被反乱 各10名） | 3セクション中1セクションのみ（反乱鎮圧・被反乱に無し） |
| `/reign` | 1144字 | あり（在位年数10名のみ。復位者一覧は全8名の実データ表） | 2セクション中1セクション（復位者一覧に無し） |
| `/court-events` | 1540字 | あり（改元・大赦・立后・皇太子廃立・遷都 各10名＝5セクション全て） | 5セクション中1セクションのみ（改元のみ。大赦・立后・皇太子廃立・遷都に無し） |

（`/timeline` 2372字、トップ`/` 1277字。参考値）

### 3.3 「主語＋数値＋出典」断定文の実例（存在する箇所）

素のHTMLに以下のような、AIがそのまま抜き出せる断定文が確認できた（`grep`／タグ除去後テキストで実在確認済み）:

- `/reign`: 「収録した365名の在位期間は、最長が聖祖・康熙帝（清）の61年332日、最短が末帝（金）の1日未満です。1人あたりの平均は約9.9年です。」（70字）
- `/court-events`: 「改元回数が最も多いのは高宗と則天大聖皇帝・武則天の2名で、14回です。即位時の建元を含め在位中に一度でも改元した皇帝は332名です。」（67字）
- `/military`: 「親征（皇帝自身が軍を率いた出征）の回数が最も多いのは太武帝（北魏）で、15回です。親征の記録がある皇帝は112名です。」（60字）
- `/ages`: 「即位時の年齢（数え年）が判明する172名のうち、最も年長で即位したのは則天大聖皇帝・武則天（周）で、68歳です。」（98字）
- `/dynasties`: 「皇帝が5名以上いる王朝では、1人あたりの平均在位年数が最も長いのは清で、約26.1年（11名）です。」（96字）
- `/death-accession`: 「365名の死因で最も多いのは「病死」で、161名（44%）です。」（32字）／「即位経路で最も多いのは「世襲」で、120名（33%）です。」（29字）

これらはいずれも「読み取れること」という共通ラベルの直下に置かれた1〜2文であり、**グラフ内の数値としてではなく素のHTMLテキストとして存在する**（Nivo/rechartsのチャート本体とは独立した静的な文）。この点は明確にプラスの評価。

**ただし英語圏の「134〜167語が最適」というAI引用パッセージ長の目安は英語の語数基準であり、日本語の文字数にそのまま当てはめられない**（本監査では日本語文字数として実測するに留め、日本語向けの最適語数の確証あるデータは持ち合わせていないため、断定的な「最適文字数」は示さない）。実測した29〜98字という長さは、単発の事実（ファクトイド）としては十分だが、「文脈込みで自己完結した回答ブロック」としてはかなり短く、集計方法・母数の注記（例:「172名分のみ、生年不明者を除く」）が同じ文に含まれている場合とそうでない場合が混在する。

### 3.4 最大の指摘: セクション単位での「読み取れること」実装漏れ

全6統計ページを合算すると、ランキング／内訳の「セクション」は16個（reign:2, death-accession:2, court-events:5, military:3, ages:2, dynasties:2）存在するが、そのうち「読み取れること」の直接回答文があるのは7個のみ（44%）。内訳: reign 1/2（在位年数ランキングのみ、復位者一覧に無し）・death-accession 2/2（死因別・即位経路別とも有り）・court-events 1/5（改元回数ランキングのみ）・military 1/3（親征回数ランキングのみ）・ages 1/2（即位時年齢ランキングのみ、没年齢ランキングに無し）・dynasties 1/2（平均在位年数のみ）。

**重大度: High**

- 証拠: `<script>`・`<style>`除去後の可視テキストで「読み取れること」という文字列の出現回数を数えた（Next.js静的書き出しHTMLはほぼ1行に圧縮されているため、行単位の`grep -c`は使わずPythonで`text.count("読み取れること")`を実行）。結果: `court-events.html`=1（改元・大赦・立后・皇太子廃立・遷都の5ランキング中、改元のみ）／`military.html`=1（親征・反乱鎮圧・被反乱の3ランキング中、親征のみ）／`reign.html`=1（在位年数ランキングのみ、復位者一覧には無し）／`ages.html`=1（即位時年齢ランキングのみ、没年齢ランキングに無し）／`death-accession.html`=2（死因別・即位経路別の両方）／`dynasties.html`=1（平均在位年数のみ）。
- 影響: 大赦回数最多は誰か・反乱鎮圧回数最多は誰か・被反乱回数最多は誰か、といった「上位10名リストの中身から人間なら読み取れるが、AIが抜き出しやすい形の断定文としては明文化されていない」問いが多数存在する。上位10名のリスト自体は存在するため完全に引用不能ではないが、AIが「大赦回数が最も多いのは梁の武帝で37回」という文を得るには、リストの1位行（ランク・名前・王朝・回数がそれぞれ別の`<span>`）から自力で合成する必要があり、直接引用できる完成文より抽出コストが高い。
- 修正案: 既に4ページに実装済みの「読み取れること」パターン（`〜が最も多いのは◯◯で、△件です。`）を、court-eventsの残り4セクション・militaryの残り2セクション・reignの復位者一覧に横展開する。既存パターンの流用のため実装コストは低い（1セクションあたり1文の追加）。
- 失敗判定: 追加後もAI（ChatGPT/Perplexity/Copilot）に「中国皇帝 大赦回数 最多」等で問い合わせた際に本サイトの数値が引用されない場合、「文の有無より他の要因（被リンク・認知度）が支配的」と判定できる。
- 先行指標: 追加前後でChatGPT検索・Perplexityに個別に同じ質問（改元・大赦・立后・皇太子廃立・遷都・反乱鎮圧・被反乱の「最多」を問う7問）を投げ、emperorstats.comが情報源として提示される回数を手動比較する（再監査不要、都度数分で実施可能）。

### 3.5 死因・王朝ページの内訳数値が本文にゼロ（`death-accession` `dynasties`）

**重大度: High**

- 証拠: `death-accession.html`から`<script>`・`<style>`を除去した可視テキストで死因8分類（病死・暗殺・不詳・処刑・自尽・諸説あり・戦死・事故死）の出現回数を数えたところ、「病死」=1（「読み取れること」文の中の1件のみ）に対し、残り7分類（暗殺・不詳・処刑・自尽・諸説あり・戦死・事故死）はいずれも**0件**だった。円グラフSVGにも`<text>`要素は無い（=§4）。なお同じラベルをHTMLファイル全体（`<script>`除去前）に対して素朴に`grep`すると「暗殺106件・病死173件」等、大量にヒットする——これは`<script>`内のチャート用JSONデータペイロードに埋め込まれた値であり、AIクローラが実際に読める可視テキストではない（この差分自体が「グラフのデータはJSに埋まっているだけで本文化されていない」ことの直接的な証拠）。同じ8分類の内訳は、実は**トップページ`/`の本文（可視テキスト）には全カテゴリが存在する**（`index.html`の可視テキストから「病死161名44%」「暗殺96名26%」「不詳35名10%」「処刑35名10%」「自尽15名4%」「諸説あり15名4%」「戦死7名2%」「事故死1名0.3%」を確認）。`dynasties.html`も同様に、王朝別平均在位年数の一覧が可視テキストとして存在しない（棒グラフのみ）。
- 影響: 検索意図として最も自然な着地点である統計トピックページ（`/death-accession` `/dynasties`）自体が、そのトピックの核心データを非JSクローラに渡せていない。トップページには同じデータがテキストとして存在するため完全な欠落ではないが、`/death-accession`のtitle・meta description・canonical・構造化データ（WebPage、`isPartOf: Dataset`）が指し示す「このURLが死因分布の正式な参照先」という主張と、実際の本文情報量が一致していない。
- 修正案: `reign.html`等で既に実装されている「上位10名の静的リスト」と同じ設計思想で、`death-accession`に死因8分類・即位経路8分類の内訳を`<ol>`または`<table>`で列挙し、`dynasties`に王朝別平均在位年数の一覧（王朝名・人数・平均年数）を追加する。データは`data/emperors.json`から機械集計可能なため、原典再調査は不要（統計値の再掲であり個別調査済みデータの表示形式変更のみ）。
- 失敗判定: 追加後も`/death-accession`・`/dynasties`のAI引用率が変化しない場合、「本文情報量よりページの被リンク・ドメイン権威が支配的」と判定できる。
- 先行指標: ChatGPT/Perplexity/Copilotに「中国皇帝 死因 内訳」「中国 王朝 平均在位年数」等で問い合わせ、本サイトの具体的な数値（44%・161名など）が引用されるかを追加前後で比較する。

### 3.6 皇帝個別365ページは極めて高品質（ポジティブな指摘）

**重大度: Info（維持・横展開を推奨）**

- 証拠: `site/out/emperors/qing-shengzu.html`を実測。「365名中1位」「172名中・年長順152位タイ」のような相対順位を明記した断定文、即位経路の判定根拠（「順治18年正月、世祖崩御に伴い遺詔により8歳で即位」＋出典「清史稿 巻六（聖祖本紀一）」）、死因の経緯（毒殺説の否定を含む学術的な判定）、在位日付の典拠として正史原文の引用（「顺治十八年正月丙辰，世祖崩，帝即位，年八岁，改元康熙。」）と暦換算の調査記録まで、すべて素のHTMLテキストとして存在する。
- 評価: これはAI Overviews・ChatGPT・Perplexityが好む「一次情報源＋直接の答え＋文脈」の教科書的な形。`grep -L '出典' site/out/emperors/*.html | wc -l` を実行したところ**0**（＝365ページ全件に「出典」という文字列が存在する）ことを確認しており、少なくとも出典表記そのものの欠落は無い。ただし「出典」という語の有無は書名・巻まで特定した引用の深さそのものを保証するものではなく、記述の詳しさ（引用文の長さ・調査メモの厚み）に個体差がある可能性は残る（本監査では抜き取りでの精査はしていない）。

## 4. 図表（チャート）のAIクローラ可視性 — 技術的到達性・マルチモーダル

**重大度: High**

- 証拠: `reign.html`・`death-accession.html`の素のHTML内`<svg>`タグは19件・15件検出したが、すべて`class="lucide lucide-menu"`等のUIアイコン（ハンバーガーメニュー・アコーディオンのシェブロン）であり、円グラフ・棒グラフを構成する`<text>`要素は**両ページとも0件**（`grep -o "<text" site/out/reign.html site/out/death-accession.html` → いずれも0）。Nivo/rechartsによるチャート本体はNext.jsの静的書き出し後もSSRされておらず、クライアント側JS実行後に初めてDOMへ挿入される構成になっている。
- 影響: GPTBot・ClaudeBot・PerplexityBot・CCBotは公開されている挙動としてJavaScriptを実行せず生HTMLのみを取得する（本監査ではこれらのボットの実行時のJS実行有無を直接観測する手段が無いため、この記述は一般に文書化されている挙動に基づく推定であることを明記する）。この前提が正しい場合、これらのクローラにはグラフの数値が一切見えず、§3で確認した静的テキスト（見出し・「読み取れること」文・上位10名リスト）だけが取得可能な全情報になる。GoogleおよびBingは検索インデックス用に長年JSレンダリングを行っていることが知られているため、Google-Extended・Bingbotの実態的な到達データはGPTBot等より多い可能性があるが、これも本監査では直接検証できていない（推定）。
- 修正案: 少なくとも各チャートの脇に、チャートが表現する数値を要約したテキスト（`<caption>`や`<figcaption>`、または視覚的に隠す`sr-only`ではなくクローラにも見える通常のテキスト）を追加する。すでに`/`のトップページの死因ドーナツには全カテゴリのテキスト併記があるため（§3.5参照）、同じ実装パターンを`death-accession`・`dynasties`にも適用すれば、チャート自体をSSR化せずとも実質的な情報欠落は解消できる。
- 失敗判定: GPTBot/ClaudeBot/PerplexityBot/CCBotが実際にはJavaScriptを実行してSVGを取得できることが判明した場合（各社の技術文書更新等で反証された場合）、この指摘の前提は成立しなくなる。
- 先行指標: サーバーログでAIクローラのUAが取得したレスポンスサイズ・後続のJSファイル（`/_next/static/chunks/*.js`）への同一UAからのリクエストの有無を確認する（現状ログ取得手段なし、Cloudflare Logpushやアクセス解析の導入が前提）。

## 最重要指摘3件（要約）

1. **統計ページのセクション単位で「読み取れること」直接回答文が16セクション中7つ（44%）しか実装されておらず、特に`death-accession`と`dynasties`は内訳数値が本文の可視テキストとして皆無**（トップページには同じ数値が可視テキストとして存在するのに、専用ページには無いという矛盾）。既存パターンを横展開するだけで解消できる、費用対効果の高い改善。
