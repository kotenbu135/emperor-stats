# 視覚・モバイル監査（emperorstats.com）

## 対象・手法

- 実サイト（本番 `https://emperorstats.com/`）を Playwright (Chromium, headless) で撮影。
- ビューポート: デスクトップ 1440×900 / モバイル 390×844（device_scale_factor=2, is_mobile=true, has_touch=true）。
- 撮影ツール: `claude-seo` の隔離 venv (`/home/sakis/.local/share/claude-seo/.venv`) に導入済みの Playwright を、監査要件どおりの寸法（1440×900 / 390×844）で呼び出すカスタムキャプチャスクリプトを使用（同梱の `capture_screenshot.py` はプリセット寸法（1920×1080 / 375×812 等）のみで、指定寸法に対応していないため）。
- 保存先: `/home/sakis/emperor-stats/emperorstats.com-audit/screenshots/`（全ファイル本文中に相対パスで記載）。
- 全スクリーンショットは目視で確認済み。加えて、モバイル横スクロールの有無は `document.documentElement.scrollWidth` と `window.innerWidth` を実ページ上で比較する簡易 JS 計測で裏付けた。

### 個別ページのURLについて（注記・サイト不具合ではない）

指示された `https://emperorstats.com/emperors/qin-shihuang` は本番・ローカル静的書き出し（`site/out/emperors/`）のいずれでも該当ファイルが存在せず、実機で **404**（`ページが見つかりません`）を返すことを確認した。`site/out/emperors/` 配下の実ファイル名は `qin-shi-huang.html` であり、正しい URL は `https://emperorstats.com/emperors/qin-shi-huang` である（ハイフンの位置違い）。これは監査タスクの指示側のタイポであり、サイトの不具合ではない。参考までに正しい URL で撮影は完了しており（`screenshots/qin-shi-huang-desktop.png` / `screenshots/qin-shi-huang-mobile.png`）、目視評価は下記「5. 皇帝個別ページ」に記載した。

## 1. トップページ `/`

**デスクトップ（`home-desktop.png`）**: H1「中国皇帝統計」とリード文、「収録の概況」の統計カード（365名・87王朝・前221〜1945年・平均9.9年）までがスクロールなしで視認できる。左サイドバーのナビゲーションも常時表示。「在位が長かった皇帝」セクションの上部（カード1〜3）もファーストビュー内に収まっている。明確な「CTA ボタン」は無いが、これは学術系データセット公開サイト（EC・SaaS ではない）としては妥当な構成であり、指摘ではなく確認事項として記録する。

**モバイル（`home-mobile.png`）**: H1・リード文・区切り線までがファーストビューに収まり、「収録の概況」見出しも視認できる（統計カードの中身は数行スクロールが必要）。ヘッダーは右上のハンバーガーボタン（≡）に折りたたまれている。レイアウト崩れ・要素の重なりは確認されなかった。

## 2. `/reign`（在位年数ランキング）

**デスクトップ（`reign-desktop.png`）**: 見出し・説明文・「読み取れることボックス」・王朝／区分／並び順のフィルタまでがファーストビューに収まり、水平バーチャート（1〜20位程度）が同一ビューポート内で見え始める。バーの色分け（王朝別）・数値ラベルとも明瞭。

**モバイル（`reign-mobile.png`）**: フィルタ（王朝・王朝の区分・並び順）は縦積みのセレクトボックスに変わり、タップ領域は十分に広い（各セレクト行の高さが指1本分以上）。バーチャートはビューポート幅（390px）に収まっており、はみ出し・横スクロールは発生していない（前述の `scrollWidth`/`innerWidth` 実測でも `390 === 390` を確認）。

## 3. `/emperors`（皇帝一覧・365件）

**デスクトップ（`emperors-desktop.png`）**: 検索ボックス・王朝セレクト・王朝区分セレクトが横並びで配置され、時代ジャンプのチップ（「秦・前漢 16」など）がタブ状に並ぶ。カードは6列グリッドで肖像画（またはイニシャル文字のプレースホルダー）・氏名・在位年が読み取れる。

**モバイル（`emperors-mobile.png`）**: 検索ボックスは全幅、王朝・王朝区分セレクトは2カラム、時代ジャンプのチップは横スクロール可能な1行に収まっている（右端が見切れており、他ページ同様「続きがある」ことを示唆する視覚処理と考えられる）。カードは2列グリッドに変わり、365件という件数に対しても1画面あたりの情報密度は破綻していない。ページ全体としての横スクロールは発生していない（実測済み）。

## 4. `/timeline`（通史年表・大河ビュー）

**デスクトップ（`timeline-desktop.png`）**: 表示範囲切り替え（全体／拡大／詳細）・時代へ移動のショートカット・凡例まで含めてファーストビューに収まり、「秦・漢」〜「南北朝」あたりまでのリバー・チャートが横並びで視認できる。右上に「横スクロールで続き→」という明示的なアフォーダンス表示があり、チャートが意図的に横スクロールを前提とした設計であることが分かる。

**モバイル（`timeline-mobile.png`）**: 表示範囲ボタン・時代へ移動チップは2行に折り返され、タップ領域は確保されている。チャート本体はファーストビュー下端からわずかに見え始める程度で、実際のリバー・チャート全体を見るには縦スクロールが必要。ページ全体の横スクロールは発生していない（`scrollWidth`実測で確認）ため、チャート内部の横スクロールは意図どおりコンテナ内に閉じている。なお、モバイルでのチャート内の文字サイズ・可読性（王朝名・年号ラベルの視認性）は今回のファーストビュー範囲のキャプチャのみでは十分に検証できておらず、追加確認の余地がある。

## 5. 皇帝個別ページ `/emperors/qin-shi-huang`（始皇帝）

正しい URL（`qin-shi-huang`）で撮影・目視確認済み。

**デスクトップ（`qin-shi-huang-desktop.png`）**: 肖像画・基本情報（諱・在位・在位期間・即位経路・死因・即位時年齢・没年齢）が2カラムのカードで整理され、右カードに改元・大赦・親征等のカウント一覧が並ぶ。前後ナビゲーション（‹ ›）・「王朝の皇帝一覧へ戻る」導線も視認できる。下部に「即位の経緯」「死因の経緯」の説明文が2カラムで続く。レイアウト崩れ・テキスト溢れは見られない。

**モバイル（`qin-shi-huang-mobile.png`）**: 同じ情報が1カラムに再配置され、肖像画→各データ行→前後ナビの順に縦積み。ラベルと値の対応も崩れておらず、文字の折り返しも自然。

## 横断的な確認事項

- **タップターゲット**: モバイル版ハンバーガーメニューのボタンは、スクリーンショットのピクセル計測（device_scale_factor=2 の物理ピクセルをCSSpxに換算）でおよそ48×48CSSpx相当と推定され、48px基準を満たしていると考えられる（DOMの`getBoundingClientRect`による厳密測定ではなく画像計測による近似値）。
- **横スクロール**: 5ページ（`/` `/reign` `/emperors` `/timeline` `/emperors/qin-shi-huang`）すべてで、モバイル幅（390px）における `document.documentElement.scrollWidth` と `window.innerWidth` が一致（390===390）し、ページ全体としての意図しない横スクロールは検出されなかった。
- **フォントサイズ**: `analyze_visual.py` による自動解析（`/` `/reign` で実行）は base font size 16px・readable: true を報告しており、日本語本文の可読性は基準を満たす。
- **コントラスト**: トップページの補足キャプション文字（例:「実際に『皇帝』を名乗った人物のみ」）についてスクリーンショットの画素値を実測したところ、文字色はおおむね RGB(108,98,93)、背景色はおおむね RGB(250,247,240) であり、WCAG の相対輝度式で計算したコントラスト比は約 5.5:1 となる。通常テキストの WCAG AA 基準（4.5:1）を満たしている。
- **レイアウト崩れ・要素重なり**: 撮影した10種のスクリーンショット（+ 個別ページ2種）のいずれにおいても、重なり・テキストの切れ・画像の非スケーリングは確認されなかった。

## 総評

撮影した範囲では、デスクトップ・モバイルとも致命的なレイアウト崩れやモバイル未対応の兆候は見られなかった。ページ全体の意図しない横スクロールは発生しておらず、`/timeline` の横スクロールはチャート内に限定された意図的な設計（「横スクロールで続き→」の明示的アフォーダンス）として機能している。フォントサイズ・コントラスト・タップターゲットも基準を満たしていると考えられる。優先して確認すべき残課題は、`/timeline` モバイル版のチャート内ラベルの可読性（表中#3）の追加検証のみである。
