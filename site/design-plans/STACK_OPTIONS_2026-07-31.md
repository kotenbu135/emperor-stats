**目的**: 自前でデザイン言語を書き起こす方式を捨て、**外部が作り込んだ完成度の高い UI 一式**に乗り換えて、
「中国皇帝統計」を表示する公開サイトをプロ水準に引き上げる。このファイルは着手前の候補調査と推奨。

前提の背景: 2026-07-30 の視覚品質工程が、設定したゲートを全部緑にしたまま目的（見た目を上げる）を
達成できずに終わった。その申し送り（`docs/site-design/VISUAL_QUALITY_HANDOFF.md`）と反省会は
ブランチ `site-craft-2026-07-30` にあり、**このブランチには存在しない**。要点だけ引くと、
**未検証の仮説をゲートに固定すると反証できなくなる**（特に上限値）、
**ゲートの通過数を品質の根拠にしない**、**見た目が目的の工程は着手前に外部の目を入れる**の3つ。

## 1. 候補の評価

### Tier A — Next.js + Tailwind を残し、デザイン層だけ外部由来に差し替える

移植コストが小さく（制約3を払わなくてよい）、**今回の失敗の原因（自前規範）だけを外せる**。

#### A-1. shadcn/ui を正式採用（+ 公式 Charts）★推奨の土台

- 無料・MIT。Radix / Base UI ベース。**コードを自分のリポジトリに持つ方式**なので、テンプレートに縛られない
- 公式 Charts は **Recharts** ベース（`ChartTooltip` などの薄い層のみ提供・抽象に閉じ込められない設計）
- 既に `shadcn` CLI と `radix-ui` が入っており、追加の技術リスクがほぼ無い
- 弱点: shadcn 単体は「部品」であって「完成した画面」ではない。**見た目の正解は供給されない**（＝今回失敗した部分がそのまま残る）

#### A-2. Tremor（Vercel 傘下）★推奨の見た目の供給源

- **2026年に Blocks・公式テンプレート（300+）が全部無料・MIT 化**（Vercel による買収に伴う。コンポーネント本体は Apache 2.0）
- React + Tailwind + Radix。**ダッシュボード／数値の盤面に特化**した 35+ コンポーネント。
  ブロックの分類が KPI カード・チャート・チャート内ツールチップ・テーブル・ページシェル・フィルタバーと、
  **このサイトが必要とするものとほぼ一致する**
- 創業者は Vercel の Design Engineering チームに合流＝保守の継続性は現状もっとも堅い
- **要検証（着手前30分で潰す）**: Tremor コンポーネント本体の **Tailwind v4 対応が公式に明記されていない**。
  テンプレートの一部に「Tailwind v4 で構築済み」の記載があるだけ。空プロジェクトで先に確認する

#### A-3. Tailwind Plus（旧 Tailwind UI）— $299 買い切り

- Tailwind 本家製。Catalyst（React の UI キット）+ サイトテンプレート13本。買い切り・将来の追加分も込み
- 品質と日本語耐性は最上位クラス（レイアウトが文字幅に依存しにくい作り）
- **弱点: データ／統計ダッシュボード向けのテンプレートが無い**。13本は SaaS マーケ・ドキュメント・ポッドキャスト等。
  Application UI コンポーネントは使えるが、「盤面」は自分で組むことになる
- 位置づけ: **Tremor の不足を埋める保険**。単独で第一候補にはならない

#### A-4. 有料 shadcn 系管理画面テンプレート（shadcnblocks / Shadcn UI Kit / ShadcnDashboard 等）

- Next 16 / React 19 / Tailwind v4 対応を明記するものが複数あり、完成画面がそのまま手に入る
- **弱点（重要）**: これらは**社内管理画面**の見た目。サイドバー＋アバター＋通知ベルの体裁を公開サイトに持ち込むと、
  「一般公開の統計サイト」ではなく「誰かの管理ツール」に見える。採用するなら**シェルは捨ててブロックだけ使う**前提

### Tier B — 統計サイト特化の SSG（フレームワークごと乗り換える）

**timeline / kinship 廃止で「移植コストで失格」ではなくなった。** 中身で評価し直す。

#### B-1. Observable Framework

- ISC・無料。**データアプリ向けの静的サイトジェネレータ**そのもの。
  データローダーがビルド時にデータを事前計算して静的スナップショット化する設計は、本プロジェクトの構造と思想が一致する
- Markdown + JavaScript。図表（Observable Plot）の**既定の質が高い＝自分で図表の見た目を決めなくてよい**。
  ダッシュボード18面だけを見るなら、これは推奨案より有利ですらある
- パラメータ付きルート（`[id].md` + `dynamicPaths`）があるので **365ページの静的生成は可能**
- **弱点1（決定的）**: 上の表の**下2行**——かな検索・フィルタ・ダイアログ・URL同期を持つ一覧1面と、
  肖像・引用・JSON-LD・OGP画像を持つ**読み物365ページ**——が Observable の守備範囲外。
  React エコシステムが無いので**全部素の JS で手書き**になる。ここが全体の作業量の大半を占める
- **弱点2**: 見た目を深く作り込むと、既定テーマから外れて**結局「自分でデザイン言語を書く」に戻る**。
  今回失敗したのはまさにそれ。ダッシュボード以外の面ほどこの引力が強い
- **弱点3**: `deploy` コマンドが**非推奨化**済み。自前ホスティングなら実害は無いが、
  プロダクトとしての投資方向を示すサインではある（リリース頻度そのものは未確認）
- **判定**: 18面のダッシュボードだけのサイトなら第一候補。**366ページの公開プロダクトとしては合わない**

#### B-2. Evidence.dev

- SQL + Markdown で BI レポートを書く方式。データソース接続が前提で、**7MB の JSON を直読みする本プロジェクトとは噛み合いが悪い**
- 「分析レポート」であって「一般公開の作品」向けではない。**却下寄り**

### 却下（1行ずつ）

- **Nextra / Starlight / Fumadocs** — ドキュメントサイト用。統計の盤面ではない
- **Mantine / Chakra** — 十分に良いが、Tailwind から離れる分の移植コストに見合う上積みが無い
- **管理画面テンプレートをシェルごと採用** — 公開サイトが管理ツールに見える（A-4 の弱点）

## 2. 推奨

> **Next.js 16 + Tailwind v4 + shadcn/ui（正式採用）を土台に、
> 見た目の正解は Tremor の Blocks / テンプレートから持ってくる。図表は Nivo → Recharts へ寄せる。**
> Tremor の Tailwind v4 対応が実測で駄目だった場合の第二案は
> **shadcn/ui 公式 Charts + Blocks ギャラリー**（＝盤面のブロックを供給できる無料の代替）。
> Tailwind Plus はさらにその上に足す「版面の質の保険」であって、Tremor の代替ではない
> （データ／統計ダッシュボードのテンプレートを持たないため。A-3 の弱点）。

理由（timeline / kinship 廃止を織り込んで再評価した結果、**推奨は変わらない**。ただし根拠は差し替わった）:

1. **残る面の重心が「読み物365ページ + アプリ的な一覧」側にある**。ダッシュボード18面だけなら Observable Framework が有利だが、
   ページ数でも作業量でも大半を占めるのは個別ページと一覧で、そこは React エコシステムが効く領域。
   （旧版の理由「移植コストを払わなくてよい」は廃止決定により失効）
2. **今回の失敗の原因だけを正確に外せる**。失敗したのは技術選定ではなく「自分で書いた規範を完了の定義にしたこと」。
   Tremor は**完成した画面**を供給するので、面の階調・影・文字サイズを自分で決める必要がなくなる
3. **無料・MIT で、保守主体が Vercel**。Next.js と同じ主体が面倒を見る構成は、この先の陳腐化リスクが最も低い
4. Tremor のブロック分類（KPI カード／チャート／テーブル／フィルタバー）が、
   このサイトの実際の面（概況の盤面・11本のランキング・365人一覧）と**そのまま対応する**

### 費用の判断ポイント（ユーザー決定事項）

- **$0 案**: shadcn/ui + Tremor のみ。ブロックは揃うが、トップの「作品としての第一印象」は自分で組む部分が残る
- **$299 案**: 上に Tailwind Plus を足す。Catalyst の完成度と13テンプレートの版面設計が入る。買い切り・追加費用なし

**私の推奨は $0 案で着手し、2. のベイクオフでトップ画面が「弱い」と判定されたときに $299 を出す**順。
先に買うと、買った理由に引きずられて選定が歪む。

### 受け入れ基準の棚卸し（廃止で失効した項目があるか確認した結果）

申し送りの「21件」は内訳が2つに分かれており、**廃止後は次のとおり**:

- **`REVIEW_2026-07-31.md` §E の15件 — 失効0件、全て存続。**
  15件を1件ずつ見たが、`/timeline`・`/kinship` を名指しする項目は無い
  （A-1 が名指すのは `/ages`・`/military`・404、A-2 と B-2 はランキング、C-5 は `/emperors`）
  - ただし **B-4「タップ標的 30〜32px」の実測16件には廃止ページ由来が混じり得る**ので、実装時に測り直す
- **`RETROSPECTIVE_2026-07-31.md` 第1部 §1 の6件は「足かせ1〜6」＝ `DESIGN.md` の制約そのもの**
  （静止影の禁止・面の階調上限1.3・`--popover` が地色と同値・body 14px・1px/150ms 上限・`AGENTS.md` の書き方）。
  **`DESIGN.md` を破棄する時点で自動的に解消**するので、達成すべき項目としては数えない

→ **合否判定は §E の15件に対して行う。** 落とす項目があれば理由を明記する（黙って落とさない）。

### 見落としやすい最大の隠れコスト: 図表層（Nivo → Recharts）

**廃止後も、このコストは目減りしない**（`LazyMount` / `useTipOutlet` / 行ウィンドウイングの所在を grep で確認済み）:
`LazyMount` は `death-accession`・`dynasties`・`rankings/[metric]`・`home-panels`・各テーブルに、
行ウィンドウイングは `scroll-bar-chart.tsx`（＝ランキングの実体）にある。**いずれも存続する面**であって、
timeline 側に偏っていたわけではない。

推奨案（A-1 も A-2 も Recharts ベース）を採る以上、**この移行は回避できない**。
制約3と同じ扱いで先に値札を付けておく — ここには実測で獲得した調整が最も濃く溜まっている:

- `nice: false` 必須（付けないと軸が勝手に丸まる）
- スクロール枠内は**自前の fixed ツールチップ**（ライブラリ標準は枠で切り取られる）
- ランキングは **1カラム + グラフ内スクロールで全件**（2カラム案は却下済み）
- **LazyMount・行ウィンドウイング・transform 配置・`useTipOutlet` 分離** — これを外すと **TBT 18秒 / CLS 1.1**。
  WSL2 は TBT を 10〜20倍に増幅するので、ローカル計測の数字をそのまま信じない

→ **ベイクオフの合否項目に入れる**: Recharts でランキング1ページ分の「グラフ内スクロール全件」を描いて、
この TBT / CLS の回帰が再発しないか。再発するなら Nivo 据え置き（shadcn/Tremor は図表以外に使う）が正しい判断になる。

## 3.5. スパイク結果（2026-07-31 実測・§4-1 の宿題は完了）

**結論: Next 16.2.12 + React 19.2.4 + Tailwind v4 + Tremor コンポーネント37本 で `next build` が通り、静的プリレンダーまで到達した。**
使い捨ての検証用プロジェクトで実施（リポジトリには入れていない）。

### 出典の実体

| リポジトリ | ライセンス | 中身 |
|---|---|---|
| `tremorlabs/tremor-blocks` | **MIT** | **ブロック323本・29カテゴリ**の実ソース（KPIカード・棒/線/面/ドーナツ/スパーク・チャート内ツールチップ・テーブル・ページシェル・フィルタバー・ダイアログ・空状態…） |
| `tremorlabs/template-dashboard` ほか5本 | MIT | 完成テンプレート |
| `tremorlabs/tremor` | Apache-2.0 | コンポーネント本体 |

**CLI は無い（`npx tremor add` は存在しない）。shadcn と同じくコードを自分のリポジトリに持つ方式**なので、
上流の更新が止まっても自分たちのコードとして維持できる。

### 実測で分かった落とし穴（ドキュメントの記載と食い違う）

公式は「Tremor Raw は Tailwind v4 以上が必要」と書いているが、**配布されているブロックとテンプレートの実体は
Next 14 / React 18 / Tailwind v3 世代**（`template-dashboard`: next 14.2.23・react 18.2.0・tailwindcss ^3.4）。
実際に Next 16 / React 19 / Tailwind v4 に載せると、次の**5点**を直す必要があった（いずれも軽微・所要は分単位）:

| # | 事象 | 対処 |
|---|---|---|
| 1 | **recharts 3 系だと `AreaChart.tsx` が型エラー**（`label` が `string \| number \| undefined` に変更された） | **recharts を `^2.15` に固定**。npm の既定は 3.x なので明示的にピン留めする |
| 2 | `TabNavigation.tsx` が React 19 の型で落ちる（`ReactElement` の props 既定が `unknown` 化） | `React.ReactElement<any>` に1箇所修正 |
| 3 | `Toaster.tsx` の import が `@/lib/useToast.js`（拡張子付き）で解決できない | 拡張子を落とす |

### 採用テーマ（2026-07-31・ユーザー自作ビルダー）

上の5案は提示のみで採用せず、**ユーザーが自作ビルダーで生成したテーマを採用**した。
受領した shadcn 標準トークン（`--background`〜`--sidebar-ring`・`--chart-1〜5`・`--radius: 0.45rem`）は
**値を1つも変えずに** `globals.css` の `@palette` 区間へ入れてある。`.dark` ブロックも受領値のまま入れたが、
このサイトはダークモードを実装していない（`.dark` を付与する導線が無い）ため現状は不活性。

受領CSSに対応物が無かったサイト固有トークンの対応付け:

| トークン | 対応 |
|---|---|
| `--seal`（117箇所から参照） | `var(--primary)` |
| `--kinship-minor` | `oklch(0.708 0 0)` |
| **`--series-1〜8`** | **`--chart-*` は使わない**（下記） |

**`--chart-1〜5` を分類に使わない理由（ユーザー判断・2026-07-31）**:
受領テーマの `--chart-1〜5` は淡い黄→濃い赤茶の**連続ランプ（sequential）**で、
「死因」「即位経路」「87王朝→8スロット」のような**分類**に使うと隣接区分が見分けられない。
分類用には**色相の離れたカテゴリカル配色**を使う。値は dataviz スキルの検証済みリファレンス配色そのままで、
**面 `#ffffff` に対して `validate_palette.js` を実行して確認済み**:

```
[PASS] 明度帯 / 彩度下限
[PASS] CVD分離        最悪隣接 #eda100↔#1baf7a ΔE 9.1
[PASS] 通常視力下限   最悪隣接 #e87ba4↔#eda100 ΔE 19.6
[WARN] コントラスト   #1baf7a(2.82) #eda100(2.17) #e87ba4(2.69) が 3:1 未満
```

WARN は「relief（可視ラベルまたは表ビュー）」が条件。トップの内訳は**凡例に区分名と実数を必ず併記**して
いるので満たしている。**ラベルを外す変更をするときは、この条件が崩れないか必ず確認する。**

なお `--background` と `--card` はどちらも `oklch(1 0 0)`（純白）で、面の分離は**罫線と影だけ**が担う。
現状は Tremor の Card が両方持っているので成立している（ユーザー確認済み・2026-07-31）が、
**影や罫線を弱める変更は「のっぺり」の再発に直結する**ので単独では行わない。

### 概要ダッシュボードのパネル選定（2026-07-31・ユーザー判断）

比較用に `/lab`（noindex・sitemap 非掲載・`src/app/lab/page.tsx`）へ実データ入りで9案を並べ、そこから採用を決めた。

いったんドーナツ + 中央ラベル + タブで実装した（円グラフ pie と中央ラベルは Tremor では両立しない —
中央ラベルは穴があることが前提で、実装上も `showLabel && isDonut` の条件付き）が、**内訳は A-3 に差し替えたので

**帯の幅は count をそのまま `CategoryBar` に渡す**（内部で合計で割る）。`/lab` の A-3 は上位6件だけを渡していたので
残りが消えて幅が水増しされていた。トップでは「その他（N区分）」まで畳んだ**全区分**を渡すので合計が必ず全体に一致する。

**タブは見出し「皇帝ランキング」の真横**（2026-07-31 ユーザー指示）。見出しの主語を切り替える操作なので、
両端揃えにしてカード幅（660px）ぶん離すと結び付きが切れる。`TabsTrigger` は `TabsList` の中にしか
置けないため、**見出しごと `Tabs` の中**へ入れている（見出し行が1行減り、1段目は 584px → 568px。
右列の内訳2枚 256+16+296＝568px とちょうど揃う）。

**ランキングのタブは3枚とも上位10名ちょうど**（`topByValue`）。当初は同値を切らずに伸ばしていたが、
10位に同値が並ぶと12行になってカードの高さが変わるため、**同値は「日まで」下りて順序を決めて必ず10名で切る**
（ユーザー判断・2026-07-31）。日数は `ages.birthDate`/`deathDate`/`reigns[0].startDate` が
**どちらも日精度のときだけ**求まる（没年齢269名中71名・即位年齢172名中62名）ので、
求まらない場合は在位日数→id の順で必ず一意に決める。同率を含む正しい順位は各ランキングページが持つ
（トップの説明文に「同じ年齢は実日数の順」と明記）。

**内訳は死因・即位経路の2枚のカードに分け、凡例は1区分＝1枚の小カード（2列）**にした。
区分名は末尾の丸括弧を落とす（「受禅（易姓）」→「受禅」・「その他（3区分）」→「その他」）。
落とした全文と、畳んだ区分の内訳は `title` に残してある。現行カタログでは括弧を落としても重複は出ない
（括弧つきは「受禅（易姓）」「継承（経緯記載なし）」の2つだけ）。

**畳む位置は区分ごとに違う**（2026-07-31 ユーザー指示）。**即位経路は8区分すべてを出す** —
末尾の「継承」17名・「内禅」14名は合わせて8.5%あり、「その他」に消すと分類そのものが見えなくなる。
死因は末尾が自尽15・戦死7・事故死1と細いので上位5＋その他のまま。
**どちらも上限は8**（`--series-1〜8` が8色で、9区分目は色を作らず必ず畳む＝dataviz の
「9本目のカテゴリ色は生成しない」に従う）。即位経路を8区分にすると右列の2枚が
ランキングと**ちょうど下端まで埋まる**（死因256px＋即位経路296px＋gap＝ランキング584px）。

**ランキングの棒には専用トークン `--bar`（`oklch(0.68 0.115 38)` = 赤茶）を新設した。** 経緯は2段階:

1. 朱の15%網掛け（Tremor 既定を朱に置き換えたもの）→ **淡いピンクで浮く**とユーザー指摘
2. 朱そのまま（`bg-seal`）→ 白文字が必要になり、**棒が名前より短い指標で破綻する**構造になるため却下

**条件は「黒文字（`--foreground`）が乗る明るさ」**。`--seal` と同じ暖色系で色相だけずらしてあるので、
朱のアクセントと喧嘩しない。実測は**本文色とのコントラスト 6.57**（AA 合格）・**白地との明度差 3.01**。
値は目視でなく OKLab→sRGB 変換で計算して選んでいる。

**タブごとに棒の色を変える**（2026-07-31 ユーザー指示）。3指標はタブで排他表示なので同時には並ばず、
隣接ペアの CVD 分離ではなく **`--bar` と同じ読みやすさに揃える**ことが選定条件になる。
明度を上げれば黒文字は読みやすくなるが棒が白地へ溶けるので、両方を計算で確認して同じ帯に置いた:

| タブ | トークン | 値 | 黒文字とのコントラスト | 白地との明度差 |
|---|---|---|---|---|
| 在位期間 | `--bar` | `oklch(0.68 0.115 38)` 赤茶 | 6.57 | 3.01 |
| 即位年齢 | `--bar-accession` | `oklch(0.66 0.1 240)` 藍 | 6.46 | 3.07 |
| 没年齢 | `--bar-death` | `oklch(0.66 0.095 150)` 苔緑 | 6.63 | 2.99 |

差し替え口は vendored `BarList` に足した `barClassName`（既定 `bg-bar`）で、
指標キー→クラスの対応は `overview-board.tsx` の `BAR_CLASS_BY_METRIC`。
タブを増やすときは**この表と `globals.css` の両方**にトークンを足す（未定義キーは `--bar` に落ちる）。

**盤面は 3:2 の2段構成**（2026-07-31 の最終形）:

| 段 | 左 3/5 | 右 2/5 |
|---|---|---|
| 1 | 皇帝ランキング（タブ3枚） | 死因 ＋ 即位経路 |
| 2 | 世紀ごとの即位人数 | 在位年数と死因 |

1段目は**左右の下端を揃える**。右列を `h-full` + `justify-between` にして、余った高さは
2枚のカードの「間」へ逃がす（カードの中に空白を作らない）。これが成立するのは
**凡例1枚＝1行**にしてからで、名前と数値を2行に分けていた版は凡例だけで縦を200px超使い、
ランキングと高さが合わなかった（ユーザー指摘）。

2段目の右（旧プレースホルダー）は **「在位年数と死因」** で埋めた（2026-07-31）。下の節を参照。

**ランキングは10位で切らず、10位と同値のところまで伸ばす。**
8位と同じ値の9位を落とすと「上位8名の表」が嘘になるため。年齢は同値が多く、実際に境界で並ぶ
（即位年齢 6〜8位が57歳で3人）。年齢は判明者のみが母集団（即位年齢172名・没年齢269名）なので、
**その人数を説明文と「N名の順位 →」リンクの両方に出す**（365名と誤読させない）。

**タブの高さは固定していない。** 同値を切らない以上タブごとに行数が違うので、いちばん多いタブに高さを合わせると
既定タブ（在位期間）の下に2行分の空白が戻る。空白を消すことを優先し、切り替えでカードが伸縮するのを許容している。

**内訳の凡例は3列グリッド**（区分名・実数・割合）で、列幅を内容に合わせて左に寄せる。
両端揃えにするとカード幅ぶん離れて行を目で追えない（ユーザー指摘・2026-07-31）。

**世紀は「即位した年」で数える。** 復位した皇帝は最初の即位で1回だけ（在位期間の分布ではなく即位という
出来事の分布なので、世紀をまたぐ在位は割らない）。**空の世紀も0本として残す** — 詰めると横軸の間隔が嘘になる。
軸ラベルは「前3」〜「20」と短くし単位は `xAxisLabel="世紀"` に出す。それだとツールチップの見出しが
「前3」だけになるので、`customTooltip` で「前3世紀・3名が即位」を出している。

### 2段目右「在位年数と死因」（2026-07-31）

予約スロット（実測 434×398px）に何を置くかを、既存12項目の総当たりで決めた。生カウントの相関は
**ほぼ全部「長く在位すれば回数が増える」の反映**なので、年あたり頻度へ直した相関と偏相関まで見て選んでいる。

採用したのは在位年数帯 × 死因の100%積み上げ（5行）。非業の死（暗殺・処刑・戦死・自尽）の割合が
**単調に 71 → 66 → 33 → 27 → 9%** と落ちる:

| 在位年数 | n | 非業の死 | 病死 | 不詳ほか |
|---|---|---|---|---|
| 1年未満 | 70 | 50 (71%) | 12 | 8 |
| 1〜3年 | 71 | 47 (66%) | 15 | 9 |
| 3〜10年 | 90 | 30 (33%) | 46 | 14 |
| 10〜20年 | 78 | 21 (27%) | 47 | 10 |
| 20年以上 | 56 | 5 (9%) | 41 | 10 |

**「殺されたから在位が短いだけ」ではない。** 非業死率と自然死率が年あたり一定なら、治世が非業死で
終わる割合は在位年数によらず**帯をまたいで横一線**になる（打ち切りは在位年数の分布を歪めるだけ）。
7.9倍の勾配が出ているのは、長く在位できた皇帝が**年あたりのリスクの低い集団だった**ということ。
言えるのは「短い在位が死を招いた」ではなく「治世が続く状況にいた皇帝とそうでない皇帝がいた」まで。

**落とした候補**（同じ検討で計算済み・再提案しない）:

| 候補 | 数字 | 落とした理由 |
|---|---|---|
| 即位経路 × 死因のヒートマップ | 8×8＝64セル中48が非ゼロ・**うち18が2件以下** | 434px幅では1セル37px。件数では1セルだけ濃い面になる |
| 即位時年齢 × 在位年数の散布図 | **r = −0.188 / n=172（47%）** | 関係がほぼ無く、母集団も半分 |
| 時代別の非業の死 | 東晋十六国60%〜清15% | 成立するが**在位年数版と同じ発見の別断面**（乱世＝短い在位＝非業の死）。両方は出さない |
| 改元/年 × 大赦/年 の散布図 | 率どうし r=+0.50・**偏相関 r=+0.55**（在位年数を統制） | 本物の相関だが、改元・大赦は説明が要る語で盤面向きでない。`/court-events` 行き |
| 被反乱回数 × 死因 | 0回46% / 1回60% / 2〜3回46% / 4回以上28% | 在位長との交絡で符号が反転（4回受けるには長く在位が要る）。説明できない |

**実装の要点**:

- 集計は `lib/emperors.ts` の `reignDeathBands()`。区分の単一情報源は `REIGN_DEATH_SEGMENTS` で、
  **カタログに死因区分が増えたら throw する**（黙って「不詳ほか」に混ぜない）。
  帯の境界は `REIGN_BANDS`（動かすと n の痩せた帯が出る。現状の最小は56名）
- 在位年数は他ページと同じ `reignYears = approxDays / 365` を使う。母集団は**365名全員**
  （在位0日の金末帝＝承麟も「1年未満」に入る）
- **割合は帯の中でなく行見出しの右端**に出す。帯は高さ8pxで文字が入らず、赤面（`--series-8`）に
  白文字を乗せてもコントラストは 3.95 で本文サイズには足りない
- **病死は隣の「死因」カードと同じ `--series-1`**（2枚のカードで同じ死因が違う色になると色が意味を失う）。
  不詳ほかは系列色を使わず灰 — 調査結果ではなく「分からない」の枠
- 余った高さは `justify-between` で**行の間**へ逃がす（1段目の内訳カードと同じ考え方）
- **「詳しく」リンクは付けていない。** この集計を持つ下層ページがまだ無く、`/death-accession` へ
  送っても同じ図は無いため。作ったら張る

検討時のモック（matplotlib・スロット実測サイズで描画）は `tools/plot-chart-candidates.py`、
出力は `tools/rebuild-shots/plan*.png`。実装後の実物は `tools/rebuild-shots/impl-reign-death-*.png`。

**取り込んだ Tremor コードの lint 違反4件も直した**（`npm run lint` が通らなくなっていた）:
`BarChart` の effect 内同期 setState、`CategoryBar` の描画中の変数再代入、`chartUtils` の `any` 2件。
いずれも上流のコードが React 19 の lint ルールに掛かるもので、**取り込んだ以上こちらの責任**として直している。

### この1枚について、はっきりさせておくこと

- **判定できるのはトップ1画面だけ。** 他の17面（統計カテゴリ・ランキング・一覧・個別365ページ）は未着手
- 外枠（サイドバー・ヘッダー・フッター）は**旧サイトのまま**。差し替えたのは本文の盤面だけ
- **「§E の15件はページ単位の項目だから新トップには掛からない」は誤り**だった。
  15件のうち **C-2（弧が色頼み）・C-3（閉じるボタンの英語名）・C-5（11/12px の多用）・A-3（スクリム10%）は
  ページではなく部品の所見**で、**部品ごと作り直しても一緒に付いてくる**。
  実際 C-2 は新トップのドーナツで再生産していた（上の #4）。残り17面でも、部品単位の項目は毎回点検する
- **それでも、この1枚の「見て良いか」を裏づけるゲートは存在しない。** §E は個別の欠陥を潰す道具であって、
  第一印象の合否は測らない。**判定の根拠はユーザーの目だけ**（ここをゲートの通過数で代用しない）
