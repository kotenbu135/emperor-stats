## A. データの読み取りが成立しない

### A-1. モバイル375pxで内訳カードの区分名が半分潰れる

`BreakdownBar` の凡例は `grid-cols-2` + `truncate` 固定なので、375px では1セルが約160pxしか
なく、色玉・件数・百分率を引いた残りが名前の枠になる。実測で **14ラベル中8が clipped**：

| ラベル | 必要幅 | 実幅 |
|---|---|---|
| 病死 | 28px | **12px** |
| 世襲 | 28px | **12px** |
| 暗殺・不詳・処刑・擁立・自立 | 28px | 20px |
| その他 | 42px | 27px |

「病死」が12pxの枠に入るので**「病…」としか出ない**。死因・即位経路の2枚は、モバイルでは
帯の色と数字だけが残り、何の内訳なのかが読めない。

補完手段が `title` 属性しか無いのも効いている（`breakdown-panel.tsx:71`）。`title` は
タッチでは開かずキーボードからも届かないので、**いちばん名前が読めない環境でだけ
補完が働かない**。「その他（3区分）」の中身も同じ経路にしか無い。

### A-2. 即位経路8区分は、8色パレットの分離限界を超えている

`validate_palette.js` に `--series-1〜8` を掛けた結果（surface #ffffff）：

```
隣接ペアのみ  → ALL CHECKS PASS
全ペア        → [FAIL] CVD separation    受禅#008300 ↔ 擁立#eb6834  ΔE 3.2 (protan)
                [FAIL] Normal-vision     内禅#e34948 ↔ 擁立#eb6834  ΔE 7.1 (normal)
```

ΔE 7.1 は「**フルカラー視でも見分けにくい**」としてハードFAILになる水準（下限15）。
帯と凡例を突き合わせる読み方では隣接ペアではなく全ペアが問題になるので、この判定が効く。
実際、即位経路の帯では2番目（擁立97名・橙）と8番目（内禅14名・赤）が並んでいる。

`overview-board.tsx:182` の「上限は8（--series-1〜8 が8色）」というコメントは、
**8色あることと8区分を1枚で見分けられることを同一視している**。8区分を出す判断自体は
（末尾2区分が8.5%ある以上）妥当だが、色だけでは支えられない。

なお `--series-3/4/5` は白カード面に対して 2.82 / 2.17 / 2.69 と 3:1 を下回る
（validator の WARN）。凡例に名前と実数が併記されているので relief は成立している。

### A-3. 世紀チャートの値がホバー/タップでしか取れない

A-1 と同じ「補完手段が到達できない場所にしか無い」型が、世紀チャートにもある。

- 世紀ごとの人数は `CenturyTooltip` にしか無く、**キーボードからは一切読めない**。
  実測で `.recharts-bar-rectangle` 23本のうち `tabindex` を持つものは **0本**。
- チャート SVG に `role` も `aria-label` も無い（`<desc>` はあるが recharts の既定文）。
  `site/AGENTS.md` は「Nivo SVG には `ariaLabel`（pie はコンテナ `role="img"`）を付ける」を
  規約にしていて、Tremor/recharts へ移した際にこれが落ちている。
- 表ビューの代替も無い（旧実装のランキング系が持っていた「表で見る」に相当するものが無い）。

y軸の目盛りが 0/15/30/45/60名 の5段しか無いので、棒を見て「51名」を読み取ることもできない。
つまり**この図の数値は、マウスを持っている人にしか存在しない**。

## B. 実装バグ

### B-1. ランキング行のリンクが新規タブで開く

`main` 内23本のリンクのうち **11本（ランキングの行すべて）に `target="_blank" rel="noreferrer"`**
が付いている。vendored `BarList` の既定値で、`overview-board.tsx` 側では指定していない。

```html
<a href="/emperors/qing-shengzu" target="_blank" rel="noreferrer">聖祖・康熙帝（清）</a>
```

同一サイト内の遷移なので新規タブは想定外のはず。加えて `next/link` ではない素の `<a>` なので
クライアント遷移にならず、新窓で開くことの告知（`aria-label` や視覚的な印）も無い。

### B-2. 棒のうち12%しかクリックできない

行のリンク矩形は**名前テキストぶんだけ**（実測 126×20px）で、棒の本体は別 div。
1位の棒は約1000px あるが、反応するのは左端の126pxだけ。棒を押しても何も起きない。

高さ20pxは WCAG 2.2 の 2.5.8（24×24px）も下回る。旧実装の `scroll-bar-chart.tsx` は
これを避けるために行全体を覆う `RowOverlay` を持っていた（`site/AGENTS.md` に
「バーが短い行でも操作できる」と明記）。Tremor へ移す際にこの配慮が落ちている。

## C. 色の意味が盤面の中で揃っていない

### C-1. 「不詳」の記号が隣り合う2枚で違う

- 死因カード: 不詳35名 = `--series-3`（緑）。病死・暗殺と同格のカテゴリ色。
- 在位年数と死因: 不詳ほか = 灰（`reign-death-panel.tsx:30` に「調査結果ではなく
  『分からない』の枠」と明記）。

後者の判断が正しい。同じ盤面に「分からない」の記号が2つあり、片方は実データと同格に見える。

### C-2. 同じ死因が2枚で違う色

在位年数と死因の「非業の死」は暗殺・処刑・戦死・自尽の合成だが、色は `--series-8`（赤）。
一方 死因カードでは 暗殺=橙、処刑=黄、自尽=桃 で、**赤はどれにも割り当たっていない**。
病死だけ両カードとも `--series-1` に揃えてある（`reign-death-panel.tsx:28-30` の意図どおり）ので、
「色を揃える」方針はあるのに3区分ぶん達成できていない。読者が左で覚えた色が右で通じない。

### C-3. 世紀チャートが単系列なのにカテゴリ枠1番の色を使っている

`colors={["series1"]}`。単系列の量チャートに**カテゴリ配色のスロットを割り当てている**。
結果として、隣のカードで「青＝病死／世襲」を学習した直後に、無関係な世紀の棒が同じ青で出る。

副作用として、盤面でいちばん大きな色面（2段目左の棒グラフ全体）がブランドの朱ではなく
青になっている。ランキングの棒はテラコッタ（`--bar`）、アクセントは朱（`--seal`）、
内訳は汎用8色 — **1画面に系統の違う配色が4つ**同居していて、統計サイト固有の見えではなく
汎用BIツールの見えに寄っている。

## D. 図の妥当性

### D-1. 即位年齢・没年齢タブの横棒はゼロ基線が意味を持たない

棒長は `ratio = 値 / 最大値` で、原点は0。即位年齢タブの実測は 68歳→53歳、
つまり **幅1.00→0.78** で、11本がほぼ同じ長さに並ぶ。

- 差が読めない — 右端の数字が仕事のすべてをしている。
- そもそも「53歳は68歳の78%」という比率に意味が無い。年齢は比率尺度として扱えない
  （0歳で即位した人はいない）。

在位期間タブは「在位0年」が実在するので同じ描き方で正当。**3タブで同じ型を使うという
前提が、年齢2タブでは成立していない**。

## E. 体裁・細部

- **E-1** 「詳しく →」の位置が5枚でばらばら（死因・即位経路＝見出し行の右、世紀＝見出し行の右、
  ランキング＝説明行の右、在位年数と死因＝無し）。カード右端が揃わない。
  在位年数と死因にリンクが無いのは意図的（下層ページが未作成）と記録済み。
- **E-2** 凡例の様式が2種類。内訳カードは枠付き小カードの2列グリッド、
  在位年数と死因は色玉+名前の1行。同じ盤面で凡例の読み方を2回学ばせている。
- **E-3** 死因の凡例が降順で終わらない（…自尽15名 → その他23名）。
  「その他は最後」の慣習との衝突で、帯でも最終セグメントが直前より太い。
- **E-4** 数値カード4枚のうち「対象年代」だけ値が2行に折れる（前221年〜／1945年）。
  4枚の上端は揃うが、値と注記の位置が1枚だけずれる。
- **E-5** フォーカスリングが `outline-blue-500` のハードコード（vendored BarList / Tabs の既定）。
  **見えてはいる**のでa11y上の欠落ではないが、`--ring` を使っていないので
  テーマを変えると取り残される。
- **E-6** `globals.css:95` のコメント「ダークモードは実装しない方針のため `.dark` は未定義」が、
  208行目の `.dark` 定義と矛盾している（受領テーマ導入時の取り残し）。
- **E-7** 世紀チャートの棒は recharts の JS アニメーション（`BarChart.tsx:788` の
  `isAnimationActive={true}` / `animationDuration={100}`）で描かれる。`globals.css` の
  `prefers-reduced-motion` 一括指定は CSS アニメーションしか止められないので**素通りする**。
  ただし 100ms なので実害は小さく、実測でも `reducedMotion: 'reduce'` と既定とで
  棒の高さの推移に差は観測できなかった。規約から外れている事実の記録として。

## 問題が無かった項目（確認済み）

- **本文テキストのコントラスト**: 全サンプルがAA合格。最小は `--muted-foreground` の **4.74:1**
  （14px・通常テキストの下限4.5をクリア）。朱リンクは6.03:1。
  SVG の目盛りラベルは `color` でなく `fill` で着色されるため別途 `fill` で測り直したが、
  同じ **4.74:1**（12px）で合格。軸ラベル「世紀」は19.8:1。
- **横スクロール**: 4幅すべてで発生しない（375pxで scrollWidth 365 < clientWidth 375）。
- **タブ切り替えでのレイアウト移動**: ランキングカードは3タブとも **568px 固定**で、
  右列の即位経路カードの位置も動かない（`accessionTop` 639px で一致）。
  行数が10/11で違うにもかかわらず跳ねない。
- **キーボード操作**: `role="tablist"` 1つ・`role="tab"` 3つ。Tabキーでタブへ到達し、
  青のフォーカスリングが見える（`st-tab-keyboard-focus.png`）。
- **凡例の網羅性**: 帯のセグメントと凡例が1対1（`foldRest` が「その他」まで畳んでから渡す）。
  色だけが手掛かりの区分は無い（モバイルの名前潰れは別問題＝A-1）。
- **在位年数と死因の3色**: validator では灰の彩度が floor 未満・灰↔青が ΔE 13.8 と出るが、
  帯の中で位置が固定（赤→青→灰の順）で名前と実数が併記されるため、読みは崩れていない。
