# 追加スキーマ設計（死因を除く9項目 + 遷都）

`data/emperors.json` の各人物レコードに追加する、死因（[DEATH_CAUSE_SCHEMA.md](DEATH_CAUSE_SCHEMA.md)）以外の追加調査項目のスキーマ設計ドキュメント（調査の経緯・完了記録は [docs/PROJECT_STATUS.md](../../docs/PROJECT_STATUS.md) と `meta.status.phases` を参照）。

対応する `meta.status.phases` のキー：`accessionRoute` / `eraChangeCount` / `amnestyCount` / `empressInstallationCount` / `crownPrinceDepositionCount` / `capitalRelocationCount` / `personalCampaignCount` / `rebellionSuppressionCount` / `rebellionSufferedCount` / `ages`。

**進捗は `meta.status.phases` を参照（このファイル自体はフィールド構造・カテゴリ・数え方の基準を定義するドキュメント）。1〜10節（即位経路・改元・大赦・立后・皇太子廃立・遷都・親征・反乱鎮圧・被反乱・年齢）すべて365人全員完了（2026-07-18 に当時の364人で完了、2026-07-20 追加の唐哀帝も全項目調査済み）。**

## 情報源・調査方針（共通）

[DEATH_CAUSE_SCHEMA.md](DEATH_CAUSE_SCHEMA.md) と同じ方針に従う。原典（正史の本紀・列伝）を第一次情報源とし、WebSearchの要約のみを根拠に確定しない。[docs/process/RESEARCH_PROCESS.md](../../docs/process/RESEARCH_PROCESS.md) を参照。

- グループ1（即位経路）は在位データ調査で読んだ即位記事・崩御記事の再確認で済むことが多い。
- グループ2（改元・大赦・立后・皇太子廃立）は本紀の通読で4項目同時に埋める。
- グループ3（親征・反乱鎮圧・被反乱）は本紀の軍事記事を数える。**このドキュメントで定めた数え方の基準に従う**（下記参照）。
- グループ4（遷都）は王朝単位の集計になりがちだが、本スキーマでは個人レコード単位（「自分の在位中に何回遷都したか」）で持たせる。
- グループ5（即位時年齢・没年齢）は当初生年データ確保がネックのため `deferred` としていたが、2026-07-17 に悉皆調査へ格上げし 2026-07-18 に全員完了済み。

## 回数系指標の計上期間（本人の実権掌握期・2026-07-22 明文化）

改元・大赦・立后・皇太子廃立・遷都・親征・反乱鎮圧・被反乱の8つの回数系指標は、**その人物自身が君主として実権を掌握していた期間（実権掌握期）に本人が行った行為**を計上する。皇帝号を正式に称する前でも、王・天王・僭号などの称号のもとで君主権を行使していた期間の行為を含める。

- **理由**: 石虎（後趙、長く「趙天王」）・李元昊（西夏、称帝前は「西平王」）・劉淵（漢、「漢王」期）・楊溥（呉、「呉王」期）・黄巣（「王」自称期）など、建国者は皇帝号を称する前から君主として改元・大赦等を行っており、皇帝在位期間のみに限ると統治実態を著しく過小評価する。各フィールド定義中の「（皇帝）在位中」という表現は皇帝号確立後に限る趣旨ではなく、**本人が君主権を行使した期間**を指す（この運用を 2026-07-22 に確定・明文化。8フィールドすべてに一律に適用し、フィールドによって計上期間を変えることはしない）。
- **他者の行為は含めない**: 本人でなく先代・父などが行った行為は、後にその人物が皇帝となっても計上しない（例: 前燕・慕容儁の遷都から、父・慕容皝が燕王期に行った 0341 年の龍城遷都を除外した。2026-07-22。原文『晋書』載記第九「皝遷都龍城」）。
- 該当する称帝前イベントには `note` に【皇帝即位前】等の明示を付す。CI（`scripts/validate_emperors.py` の `check_event_reign_range`）は在位 ISO 年範囲外に出るこれらを `KNOWN_PREACCESSION_EVENTS` として許容する（在位範囲内に落ちる称帝前イベントは検出対象外だが同じ方針で計上する）。
- 経緯: 2026-07-22 のデータ QA で、称帝前イベント計上を「遷都のみ在位中に限定・他は包括」とする折衷案が一度検討されたが、改元・遷都とも定義文言が同一（ともに「在位中」）で折衷に原理的根拠がないため撤回し、全フィールド一律「本人の実権掌握期」で統一した。

## 1. 即位経路（`accessionRoute`）

個人ページ・本紀の即位記事を読めば判明する。死因調査（グループ1）とセットで調査すると効率的。

```json
"accessionRoute": {
  "categoryId": "hereditary",
  "axes": {
    "throneSource": "inherited",
    "titleOrigin": "inherited",
    "decidedBy": ["predecessor"],
    "decidedByAgents": [],
    "decidedByBasis": "source-reread",
    "predecessorFate": "natural-death",
    "relationToPredecessor": "son",
    "procedure": "normal"
  },
  "note": "自然文での説明（先帝との関係、擁立者の有無など）",
  "confidence": "high",
  "source": { "page": "...", "lang": "ja" }
}
```

**v3（2026-07-29）で値はすべて安定 ID になった。** 日本語ラベルは `meta.catalogs.enums` にのみ置く。以下の解説は読みやすさのため日本語ラベルで書いているので、JSON に書き込む値は次表で引く。

| フィールド | ID → ラベル |
|---|---|
| `categoryId` | `hereditary` 世襲 / `enthroned` 擁立 / `self-established` 自立 / `usurpation` 簒奪 / `acclamation` 推戴 / `abdication-received` 受禅（易姓） / `succession-unspecified` 継承（経緯記載なし） / `inner-abdication` 内禅 |
| `axes.throneSource` | `inherited` 前代君主から継承 / `abdication-received` 他政権から受禅 / `self-established` 自立 |
| `axes.titleOrigin` | `inherited` 継承 / `new` 新称 |
| `axes.decidedBy` | `self` 本人 / `predecessor` 先帝 / `third-party` 第三者 / `undetermined` 史料から決着不能 |
| `axes.decidedByAgents` | `officials` 臣下 / `military` 軍 / `eunuchs` 宦官 / `consort-kin` 外戚 / `empress-dowager` 母后 / `imperial-clan` 宗室 |
| `axes.decidedByBasis` | `existing-note` 既存note / `source-reread` 原典再読 |
| `axes.predecessorFate` | `natural-death` 崩御 / `violent-death` 横死 / `abdicated` 生前譲位 / `deposed` 廃位・追放 / `none` 該当なし |
| `axes.relationToPredecessor` | `son` 子 / `younger-brother` 弟 / `elder-brother` 兄 / `father` 父 / `grandson` 孫 / `nephew` 甥 / `uncle-younger` 叔父 / `uncle-elder` 伯父 / `mother` 母 / `cousin` 従兄弟 / `adopted-son` 養子 / `distant-kin` 同族（遠縁） / `affinal-kin` 外戚（その他） / `unrelated` 無血縁 / `other` その他 / `none` 該当なし（kinship 側の `great-grandson` 曾孫 / `niece` 姪 / `grandfather` 祖父 / `maternal-grandfather` 外祖父 / `son-in-law` 女婿 / `father-in-law` 舅（妻の父） / `unknown` 不明 を含む共有語彙） |
| `axes.procedure` | `abdication-ceremony` 禅譲儀礼 / `inner-abdication` 内禅 / `normal` 通常の践祚 / `no-ceremony` 儀礼なし・自称 / `forged-edict` 偽詔・矯詔 |

- `axes.conflicts`: 任意。軸の値が史料で割れるときの置き場（[EMPERORS_SCHEMA.md](EMPERORS_SCHEMA.md) の「`conflicts`」節）。`field` は同じコンテナに実在するフィールド名でなければならないため、続柄（`relationToPredecessor`）のように軸の中にしか実フィールドが無い対立は `accessionRoute` 直下ではなくここに置く。
- `categoryId`: 表示用の単一ラベル（の ID）。**`axes` から機械的に導出される派生値**（下記「導出ルール」）。手で書き換えず、軸を直せば追随する。サイトはこの値をそのまま表示すればよく、優先順位ロジックを持たない。
- `axes`: 4軸＋2補助。詳細は「軸の定義」節。
- `note`: 経緯を自然文で記述（例：「先帝の嫡長子として遺詔により即位」「宦官○○に擁立され即位」）。
- `confidence` / `source`: `deathCause` と同じ運用。

### 多軸化の経緯（2026-07-26）

旧スキーマは単一 enum 9値だったが、次の**互いに独立した4つの問い**への答えが1列に混在していた: ①政権は連続したか（建国・禅譲・簒奪）②先帝と血縁があるか（世襲）③誰の意思で即位したか（擁立・内禅）④何度目か（復位）。軸が違うものを排他選択させていたため、以下の破綻が生じていた。

- **同型事象が2カテゴリに割れる**: 受禅による王朝創始が、曹丕・楊堅・李淵・趙匡胤は `禅譲`、劉裕・蕭道成・蕭衍・陳霸先・高洋は `建国`（後者の note には「王朝創始者のため建国に分類」とあるが、前者も王朝創始者であり方針が守られていない）。
- **`建国` の基準が揺れる**: 父から王位を継いで称帝した苻健・李元昊・後唐荘宗は `建国`、同じ構図の始皇帝は `世襲`。
- **`世襲`(134) と `擁立`(105) の線引きが主観に依存**: 擁立の9割近くは先帝の血縁者で、差は「誰が決めたか」だけ。史料から決着しない問いに全体の65%の分類を預けていた。
- **建前と実態を note に逃がしていた**: 「形式は禅譲だが実質は簒奪」「正史は内禅と記すが実態は擁立」。

**設計方針**: 単一ラベルへの同意は取れないが、事実への同意は取れる。ラベルを当てにいくのをやめ、独立した軸に事実を分解して並べ、表示ラベルはそこから導出する。読者の分類感覚と食い違っても、どの軸で判断が違うのかが読者に見える。

### 軸の定義

#### 軸1 `throneSource`（君主位の出所）

| 値 | 定義 | 例 |
|---|---|---|
| `前代君主から継承` | 同一政権の前代君主（皇帝・王・天王等）から位を得た | 漢恵帝・清乾隆帝・始皇帝・石虎 |
| `他政権から受禅` | 別姓・別政権の皇帝、**または皇帝位を保持する立場にあった者**から皇位を受けた（王朝交代を伴う受禅・征服） | 曹丕・劉裕・楊堅・趙匡胤・王莽 |
| `自立` | 先行する君主から位を受けず、自ら称した | 劉邦・光武帝・劉淵・張献忠・袁世凱 |

**皇帝号ではなく君主位で見る**。これは「回数系指標は本人の実権掌握期＝君主権を行使した期間で数える」（2026-07-22 確定）と同じ発想で、プロジェクト内で一貫する。旧 `建国` は政権の属性であって君主位の出所ではなかったため、この軸には存在しない。

**`自立` と `前代君主から継承` の境界（2026-07-26 確定）**: **正統の継承を掲げただけでは `前代君主から継承` にしない。前代君主から実際に位を受けたか（受禅・伝位・襲位の記事があるか）で決める。** 光武帝（更始帝から位を受けていない）・劉備（曹丕の受禅を認めず自ら漢の正統を名乗る）・南宋高宗（欽宗から位を受けていない）はいずれも `自立`。この争点は東晋元帝・北漢劉崇・南明諸帝・北元・西遼など「前政権の継承を掲げて自立した」型で繰り返し生じる。

- **kinship.json に succession エッジがないことは `自立` の根拠ではない**。孫権は兄・孫策から江東の支配権を継いだが、孫策は君主号を持たない後漢の将軍（討逆将軍・呉侯）であり君主位の継承ではないため `自立` になる。逆に、succession エッジがあっても受けたものが君主位でなければ `自立` を採る。
- **判別は原典の継承動詞で行う（2026-07-26 五代十国ブロックで確定）**。「嗣位」「嗣王位」「襲位」「代立」「立」＝**位そのものを受けた**（→ `前代君主から継承`）。「代領其眾」「代董其眾」「主其軍」＝**軍の指揮だけを受けた**（→ `自立`）。「除○○節度使」「拜○○」など**上位政権からの任命**で得た地位、および「自号」「自立」は前任者からの継承ではない（→ `自立`）。**帝号の新旧はこの軸では問わない**（王・天王・節度使の座を継いで帝号だけ新たに称した場合も `前代君主から継承` で、称号の更新は軸1b `新称` が担う）。実例: 後唐荘宗＝「及武皇厌代，帝乃嗣王位于晋阳」「虽承遗命」で晋王位を継承（15年後の称帝は帝号の新称）→ `前代君主から継承`／南漢高祖＝「隐卒，代立」（新五代史）「奉遗命权知清海军留后」（十国春秋）「袭封南海王」→ `前代君主から継承`／後晋高祖・北漢世祖・後蜀高祖・前蜀高祖＝いずれも節度使への任命から出発し前任の君主がいない → `自立`。この線を引かないと、始皇帝（父から秦王位を継ぎ帝号を新称）と苻健（父から三秦王位を継ぎ帝号を新称）と後唐荘宗が別ラベルに割れる。
- **`自立` の場合、軸3 `predecessorFate` と軸4 `relationToPredecessor` は `該当なし` になる**（`check_axes_sync` が強制する）。**例外**: 軸1が `自立` でも kinship に主 succession エッジがある場合は、軸4はエッジの値に合わせる（`check_axes_sync` が一致を要求するため）。軸3は `該当なし` のまま。実例は隋末群雄の林士弘（操師乞から継いだのは「代董其眾」＝軍の指揮であって君主位ではないため軸1は `自立` だが、kinship はリーダー交代として succession エッジを引いている）。この2軸は「**位を受けた前帝**」についての値であり、「前任者が存在しない」という意味ではない（孫権には兄・孫策、南宋高宗には兄・欽宗という前任者が実在する）。サイト表示でも「前帝なし」ではなく「該当なし（位を受けた前帝がいない）」の含意で扱う。

**譲位元が皇帝を称していない場合も `他政権から受禅` に含める**（2026-07-26 パイロットで確定）。王莽の受禅元・孺子嬰は居摂期の皇太子で皇帝位に即いていないが、漢の帝位を保持する立場にあり、易姓の受禅として扱う。同型の争点は隋末群雄・五代十国（譲位側の地位が係争的な例）でも生じるため、ここで一律に決める。

**前帝が既に死んでいる場合の `他政権から受禅` と `前代君主から継承` の境界（2026-07-26 後周太祖で確定）**: 授位の文書が**王朝交代を明示する禅代文書**（「受命相継，是不一姓」「鼎革」「奉符宝授」など、姓の交代と符宝の移譲を述べる語を含む）なら `他政権から受禅`。**同一王朝内で次の君主を据える廃立の詔・令**なら `前代君主から継承`。実例の対比:

- 後周太祖・郭威 → `他政権から受禅`。漢太后誥「邃古以来，受命相继，是不一姓」「鼎革斯契，图箓有归，予作佳宾」「今奉符宝授监国，可即皇帝位」（旧五代史 巻一百十）。前帝・隠帝は既に横死しており譲位行為そのものは存在しないが、文書の性格は高洋・楊堅の受禅と同型。太后誥が易姓を宣言している以上、澶州の兵変（黄旗加身）を理由に `自立` へ寄せない
- 後唐末帝・李従珂 → `前代君主から継承`。曹太后令は「降闵帝为鄂王」と「宜即皇帝位」を同一王朝内の廃立として行っており（旧五代史 巻四十六）、易姓の語はない

この境界を置かないと、後周太祖が「軍に担がれて自立した」のか「漢から禅を受けた」のかで判定者ごとに割れる。**判定の根拠は原文の文書の語であって、実力関係の評価ではない**（実力で押し切った事実は軸2 `本人` が担う）。

#### 軸1b `titleOrigin`（帝号の由来・バッジとして表示）

| 値 | 定義 | 例 |
|---|---|---|
| `継承` | 先行する皇帝から皇帝号を受け継いだ | 漢恵帝・曹丕 |
| `新称` | 皇帝号を自ら新たに称した（王・天王からの昇格、新政権樹立を含む） | 始皇帝・苻健・李元昊・後唐荘宗・劉淵 |

軸1の値にせず独立させているのは、**軸1に置くと石虎（前代君主を殺害して奪取）と始皇帝（父の死により継承）が同一ラベルに潰れ、簒奪と世襲の区別が消える**ため。バッジに分離することで軸2の弁別力が全人物で効く。

#### 軸2 `decidedBy`（即位を決めた主体・**配列**）

| 値 | 定義 |
|---|---|
| `本人` | 自ら挙兵・実力行使・自立して位を得た |
| `先帝` | 先帝自身の意思（遺詔・顧命・立太子・生前譲位）による |
| `第三者` | 臣下・軍・宦官・外戚・母后・宗室会議などが立てた |
| `史料から決着不能` | 原典が主導者を記さず、どれとも確定できない（**単独でのみ使用**） |

**建前ではなく実態で取る**（形式は補助1 `procedure` に保存されるので情報は失われない）。**複数値を許容**する（例: 趙匡胤＝`["本人","第三者"]`。陳橋の推戴を経た受禅）。ここを排他にしないことが設計の要。

##### 軸2の判定基準（原典に照らして検証可能な形で固定する）

旧 `世襲` / `擁立` の線引きは実質この軸だけを見ていた。既存判定をそのまま移し替えると**主観性を新スキーマに持ち込むだけ**なので、原典の記述に対応づけて判定する。

| 判定 | 原典上の根拠（本紀・列伝に次のいずれかが存在すること） |
|---|---|
| `先帝` | 先帝の遺詔・顧命・立太子の記事があり、その効力を覆す介入の記述がない／先帝自身が譲位の詔を出している |
| `第三者` | 即位を主導した人物・集団が**名指しで**記される（「〜等立之」「〜矯詔立」「〜迎立」「群臣議立」等） |
| `本人` | 本人の挙兵・実力行使・自立の記事がある（「自立為帝」「僭号」「勒兵入宮」等） |
| `史料から決着不能` | 上のいずれの記述も原典に見当たらない（例: 幼帝の即位で「即皇帝位」としか記されない場合、当然の継承として経緯が書かれない場合） |

**`本人` の境界（2026-07-26 五胡十六国ブロックで確定）**: `本人` は**位そのものを自ら取得した場合**に限る——すなわち (a) 自称・僭号による即位、または (b) 前帝を排除し、その排除と同一の行為でその座に就いた場合。**前帝の排除と自身の即位が別事象で、即位が第三者の授与（奉表上尊号・勧進・迎立・詔による立）を経ている場合は `本人` を立てず、授与した側で取る**（排除の事実は軸3 `predecessorFate` と note に残るので情報は失われない）。

- 例（`本人` が残る）: 石虎「废勒子弘」→そのまま尊号／石遵「假劉氏令曰……其以遵嗣位」／李寿「寿矫任氏令，废期为邛都县公」／張祚「命废耀灵为凉宁侯而立祚」——いずれも**位を空けた行為と座に就けた行為が同一**で、第三者の勧進は後追いの儀礼。慕容盛・石祗・慕容詳・慕容麟・赫連定のように授与者がまったく記されない自称型も `本人`。
- 例（`本人` を立てない）: 劉聡は兄・劉和を武力で排除したが、即位は「群臣勸即尊位」「乂與公卿泣涕固請」を経ており排除と別事象のため `第三者`。宋孝武帝も「上率眾入討」で元凶劉劭を滅ぼしたが、即位は「大將軍江夏王義恭來奔，奉表上尊號」の翌日で別事象のため `第三者`。
- この境界を置かないと、簒奪者の討伐者（宋孝武帝）と簒奪者本人（石虎）が同じ `簒奪` に潰れる。**`簒奪` は「前帝の位を自ら奪った」という事実の要約であって正統性の評価ではない**ため、事実の側で線を引く。
- **「別事象」の判定は攻守で行う（2026-07-26 五代十国ブロックで追加）**。上の (b) をそのまま読むと、挙兵して都を落とし前帝を追い出した者まで「排除と即位が別事象」として `第三者` に落ちてしまう。そこで次で切る——**本人（またはその指揮下の軍）が攻勢に出て前帝の所在地を制圧し、その場で即位した場合は `本人`**。**排除を他者が他所で実行し、本人は事後に位を届けられた場合、および本人が攻撃を受けた側で返り討ちにした場合は `第三者`**。実例の対比: 後唐末帝李従珂は自ら挙兵して洛陽に入り、閔帝が出奔した後にその場で曹太后令を得て即位＝`本人`／後梁末帝朱友貞は謀議を主導したが東京を動かず、洛陽の政変は袁象先が実行し「象先遣赵岩赍传国宝至东京，请帝即位于洛阳」と伝国璽を届けられた＝`第三者`（宋孝武帝と同型）／劉聡は劉和の襲撃を返り討ちにした側＝`第三者`。

**「当然の継承だから」を理由に `先帝` を埋めない。** 秦漢パイロットでは始皇帝がこれに当たり、原文は「年十三歳，庄襄王死，政代立為秦王」のみで遺詔・顧命・立太子の記述がない（史記・秦始皇本紀）。血縁上の嫡子であることを根拠に `先帝` を推定すると、旧スキーマで `世襲` に押し込んでいたのと同じことを軸2で繰り返すことになるため、`史料から決着不能` を採る。前漢の他の13名は本紀に立太子・遺詔・迎立のいずれかが明記されており、この値になったのは始皇帝のみ。

**`史料から決着不能` を潰さないこと。** 旧 enum は「わからない」を表現できず（`不詳` は経緯全体が不明の意味で使用実績0人）、史料が語らない即位を `世襲`/`擁立` のどちらかに押し込んでいた。原典が記していないことを正直に表示するのが、この再設計で最も読者の信頼に効く。

#### 軸2補助 `decidedByAgents`（第三者の類型・配列・任意）

`臣下` / `軍` / `宦官` / `外戚` / `母后` / `宗室` から該当するものを列挙する。`decidedBy` に `第三者` を含まない場合は空配列。

#### 軸2補助 `decidedByBasis`（判定の根拠経路・**記録必須**）

`既存note` / `原典再読` のいずれか。**`史料から決着不能` の件数がこの再設計で最も説得力を持つ数字であり、それが「調べた上での結論」なのか「既存判定の引き写し」なのかを後から検証できるようにする**ため、人物ごとに必ず記録する。

#### 軸3 `predecessorFate`（前帝の去就）

`崩御` / `横死（殺害・戦死・自尽）` / `生前譲位` / `廃位・追放` / `該当なし`

旧スキーマで主観的だった「内禅 vs 世襲」の境界を、先帝の生死という客観的事実で決着させる。

- **先帝の `deathCause.category` が `諸説あり`／`不詳` の場合は `崩御` を採る**（2026-07-26 確定）。晋恵帝（毒殺説がある）のように死因が確定していない在位中の死去を `横死` とすると、データセットが意図的に保存している不確実性をこの軸が勝手に解消してしまうため。`横死` は殺害・戦死・自尽が原典または `deathCause` で確定している場合に限る。

#### 軸4 `relationToPredecessor`（先帝との血縁）

`data/kinship.json` の succession エッジと**同じ語彙**を使う（`子`/`弟`/`兄`/`父`/`孫`/`甥`/`叔父`/`伯父`/`母`/`従兄弟`/`養子`/`同族（遠縁）`/`外戚（その他）`/`無血縁`/`その他`/`該当なし`）。365人中302人は kinship.json で確定済み（Wikidata P22/P25/P26/P1365 突合済み）であり、そこから転記する。**両ファイルの値の一致は `scripts/validate_kinship.py` で機械検査する**（片方だけ直すと落ちる）。

表示時は `直系`（子・孫）/ `傍系`（弟・兄・甥・叔父・伯父・従兄弟・同族）/ `養子` / `外戚` / `無血縁` / `該当なし` にまとめてよい。

#### 補助1 `procedure`（手続きの形式・建前を保存する軸）

`禅譲儀礼` / `内禅` / `通常の践祚` / `儀礼なし・自称` / `偽詔・矯詔`

「形式は禅譲・実態は簒奪」を軸1＋軸2＋この軸で表現でき、note への逃がしが不要になる。

**`内禅` の範囲（2026-07-26 宋遼西夏金ブロックで確定）**: 同一政権内の生前譲位のうち、**位を渡す行為が前帝の側から出ているもの**を `内禅` とする。典型は父子・直系間で、第三者が主導していても前帝が詔を出す形を取れば `内禅`（唐憲宗＝順宗の内禅を宦官俱文珍が主導）。**血縁が直系でなくても、前帝自身が百官を集めて伝位した場合は `内禅`**（金哀宗→完顔承麟「上集百官，传位于东面元帅承麟」、両者は同族の遠縁）。逆に、前帝の側に譲位の主体性がまったくなく第三者が君主をすげ替えた場合は `禅譲儀礼` とし、ラベルは軸2で決める（北魏節閔帝＝爾朱世隆が元曄を退けて据えた／南宋寧宗＝光宗は譲位の行為を行わず太皇太后が命じたため `通常の践祚`）。当初は「父子・直系間に限る」としていたが、直系という血縁条件では金哀宗の伝位を取りこぼすため、譲位行為の主体で切り直した。

#### 補助2 復位

`category` から外し、既存の `reigns[].isRestoration` に一本化する（旧スキーマは復位を経路カテゴリに混ぜていたため、初回即位の経路が note に退避していた）。表示は「復位」バッジ。

### 導出ルール（`categoryId` の算出）

上から順に最初に一致したものを採る。

`decidedBy` が複数値のときは **`本人` > `先帝` > `第三者`** の優先順位で1つに畳む（実力行使があれば実態は簒奪、先帝の指名が効いていれば第三者の推戴があっても世襲、先帝の意思がなく第三者のみなら擁立）。この優先順位は秦漢パイロットで漢哀帝が `["先帝","第三者"]`（成帝自身が嗣に立てたが、傅太后の賄賂と趙昭儀・王根の働きかけが本紀に明記される）となり、単値前提のルールでは導出不能になったことから確定した。畳んだ値を `decidedBy*` と書く。

| # | `throneSource` | 条件 | `categoryId` |
|---|---|---|---|
| 1 | `abdication-received`（他政権から受禅） | `decidedBy*` = `self`（本人） | `abdication-received`（受禅（易姓）） |
| 2 | `self-established`（自立） | `decidedBy*` = `self` | `self-established`（自立） |
| 3 | `self-established` | それ以外 | `acclamation`（推戴） |
| 4 | `inherited`（前代君主から継承） | `procedure` = `inner-abdication` | `inner-abdication`（内禅） |
| 5 | `inherited` | `decidedBy*` = `self` | `usurpation`（簒奪） |
| 6 | `inherited` | `decidedBy*` = `predecessor`（先帝） | `hereditary`（世襲） |
| 7 | `inherited` | `decidedBy*` = `third-party`（第三者） | `enthroned`（擁立） |
| 8 | `inherited` | `decidedBy*` = `undetermined`（史料から決着不能） | `succession-unspecified`（継承（経緯記載なし）） |

旧ルールにあった「`他政権から受禅` × 本人以外 → `受禅（擁立）`」は**実データ 0 件**のため v3 の enum から削除した（該当が生じたら enum ごと復活させる）。

**軸1のすべてのバケットで軸2が効く**ことがこの表の要件（`内禅` のみ形式優先で軸2に依らないが、これは意図的。唐憲宗＝宦官主導の内禅と清仁宗＝先帝主導の内禅は同じラベルになり、差は軸2の表示で見せる）。当初案は軸1だけでラベルを決める行（受禅・自立）を持っていたが、秦漢パイロットで更始帝（「諸将遂共議立更始為天子」＝諸将の議立で自立政権の帝位に就いた）が本人主導の劉邦・光武帝と同一ラベルに潰れることが判明したため、全バケットを軸2で細分する形に修正した。

**ラベル名の改称（2026-07-26 南朝ブロック着手時）**: 行3・4 は当初 `自立・建国` / `推戴・建国` としていたが、`自立` バケットには王朝創始者だけでなく**対抗政権の帝位僭称者**が入ることが南朝で判明したため（劉子勛＝義嘉政権・蕭正德・蕭紀・蕭荘、および後趙石祗）、`建国` の語を落として `自立` / `推戴` にした。「王朝を創始したか」は `dynasty` と在位順から導ける政権の属性であり、即位経路のラベルが担う情報ではない（旧 `建国` を軸から排除したのと同じ理由）。

バッジ（`categoryId` を置き換えない）: `titleOrigin` = `新称` → **帝号新称** ／ `reigns[].isRestoration` → **復位**。

このルールは軸1の3値 × 軸2の4値（＋`procedure`）で**全域**であり、かつ軸1のすべてのバケットで軸2が効く（**弁別的**）。`scripts/validate_emperors.py` が `axes` から `categoryId` を再計算して突合する。

### 旧設計判断（移行前・参照用）

以下は旧 enum 時代の境界判断。新体系では **禅譲/簒奪の境界＝軸1×軸2、内禅/世襲の境界＝軸3、内禅/擁立の境界＝軸2×補助1、復位＝`isRestoration`** に分解されており、判定者の重み付けを要する境界そのものが解消されている。

- **反乱・自称政権の皇帝でも `世襲` になり得る**（例：ある政権内での2代目以降は父からの世襲）。`accessionRoute` は「その人物個人の即位経路」であり、政権の性格（`meta.catalogs.regimes[].category`）や政権内の位置づけ（`standing`）とは独立した軸（v3 で `flags.selfProclaimed` を廃止し、この3軸に整理した）。
- **禅譲と簒奪の境界**：形式上の譲位儀礼を経ていれば `禅譲`、実力行使のみで即位すれば `簒奪`。両者が併存するケース（禅譲の形式を取った事実上の簒奪、例：曹丕・司馬炎）は `禅譲` を採用し、`note` に「実質的には簒奪」である旨を明記する（史書の記述上の建前と実態を区別して残す）。
- **`禅譲` と `内禅` の境界（王朝交代の有無）**：譲位により即位した場合、譲位元が**別姓・別政権（前王朝）**なら `禅譲`（＝王朝交代を伴う受禅）、**同一王朝内**の先帝からの生前譲位なら `内禅`。この2つは史学的に別概念（禅譲＝堯舜・曹丕型の易姓、内禅＝父子等への生前譲位）であり、旧スキーマは両者を `禅譲` に混在させていたため2026-07-22に `内禅` を分離した。
- **`内禅` と `世襲` の境界（先帝の生死）**：先帝が**在世のまま譲位した**（太上皇となる等）＝ `内禅`、先帝の**崩御に伴う継承**（遺詔・立太子からの践祚）＝ `世襲`。受け手が正規の皇太子・嫡子であっても、生前譲位で即位したなら `内禅` とする（例：北魏孝文帝・清仁宗は皇太子だが献文帝・乾隆の生前譲位のため `内禅`）。養子への生前譲位（南宋孝宗＝高宗の養子）も `内禅`。
- **`内禅` と `擁立` の境界（譲位行為の有無）**：先帝自身が譲位の行為を行った（強要・宦官主導でも、詔や璽の授受という譲位形式を踏む。例：唐憲宗＝順宗の内禅を宦官が主導）なら `内禅`、先帝が譲位行為を行わず第三者が新帝を立てた（例：南宋寧宗＝光宗は病で譲位行為をせず大臣が擁立、正史は「内禅」と粉飾するが実態は擁立）なら `擁立`。
- **`復位` が優先**：一度廃位・退位した後の再即位は、たとえ先帝の生前譲位（内禅）を伴っても `復位` を採用し、内禅の経緯は `note` に記す（例：武則天の生前譲位を経た唐中宗・睿宗の第2次在位は `復位`）。
- **複数回即位した人物**：`reigns` 配列に対応させず、`accessionRoute` はレコード直下に単一値で持たせる（初回即位の経路を主とし、復位がある場合は `category: "復位"` を採用、初回の経路は `note` に記す）。理由：即位経路は「その人物の皇帝としてのキャリアの始まり方」を表す代表値としての性格が強く、`deathCause` 同様レコード単位の集約情報として扱うほうが `reignSummary` の設計思想と一貫する。

## 2〜5. 本紀通読カウント系（改元・大赦・立后・皇太子廃立）

いずれも「回数（`count`）＋明細配列（`events`）」の同じ構造を持つ。本紀を1回通読すれば4項目同時に埋められる。

```json
"eraChangeCount": {
  "count": 3,
  "events": [
    { "date": "-0133-01-01", "datePrecision": "year", "note": "建元→元光に改元（元光元年＝前134年）", "source": { "page": "...", "lang": "ja" } }
  ],
  "confidence": "high",
  "note": "総括コメント（不確実な件数がある場合など）"
}
```

- `count`: `events` 配列の要素数と一致させる（一致しない場合は不確実な件数が別途あることを意味し、`note` で説明する）。
- `events[].date` / `.datePrecision`: `reigns[].startDate`/`datePrecision` と同形式。日付が特定できない場合は `date: null`, `datePrecision` は省略可。
  - **`datePrecision` の語彙は `year`/`month`/`day`/`null` のみ**（2026-07-22 統一・CI で完全一致検査）。説明的文言・不確実性は `note` に書く。
  - **期間イベント（`startDate`/`endDate`）で開始と終了の実確認精度が異なる場合**（2026-07-23 確定）は、`reigns[]` と同形式のオブジェクト `"datePrecision": {"start": "year", "end": "month"}` を使う。両端が同精度なら従来どおり単一トークン（オブジェクトで同値を書くのは CI エラー）。単一日付 `date` にオブジェクト形式は使えない。各日付は宣言精度以上の深さが必須（`scripts/validate_emperors.py` の `check_event_date_format()` がエラー検査）。
  - **紀元前の年規約（2026-07-22 統一）**: `reigns` と同じ ISO 8601 天文年（前n年 → `-(n-1)`。例: 前134年 → `-0133`）で表記する。歴史年直記（前n年 → `-n`）は使わない。month/day precision では実際のユリウス暦時点が属する年を使う（漢初〈太初改暦・前104年より前〉は年始が冬十月のため、冬十月〜十二月・閏九月のイベントは紀年の対応年より1年前の ISO 年に落ちる。例: 文帝元年冬十月 → `-0179-10`）。year precision では紀年（元号の元年等）の対応年を使う。`scripts/validate_emperors.py` の `check_bce_event_years()` が在位 ISO 年範囲チェックと note の「前n年」明記との突合を行う。
- `events[].note`: 自然文で事由を記す。
- `confidence`: レコード全体（`count` の確からしさ）に対して `high`/`medium`/`low`。
- 該当なし（0回）の場合も `count: 0`, `events: []` で明示する（フィールド自体を省略しない。調査未実施と0回を区別するため、未調査の人物は `phases` の `status` で管理し、フィールド自体を付与しない）。

### 2. 改元回数（`eraChangeCount`）

- 「1回」＝新しい年号（元号）への切り替え1回。即位に伴う最初の建元は含めるか要判断が分かれるため、**即位に伴う最初の元号制定も1回としてカウントする**（皇帝在位中に何種類の年号を使ったか、という実質を反映するため）。`events[0]` に即位時の建元を含める。
- 年号を持たない王朝・時代（改元制度が未整備な秦など）は `count: 0` とし `note` に「年号制度なし」等と明記する。

#### `events[].date` はどの日か（2026-08-03 確定・Issue #66）

**本紀（正史）がその改元という行為に日付を付けている条の日**＝改元の宣言が載っている条の日を採る。**適用範囲は `eraChangeCount` だけ**で、他の7つの回数系フィールドには掛からない（同じ「どの条を採るか」の問いはあるが、実測していない。広げるかは別途の判断）。

- **「詔の日」という言い方では判定しない。** 踰年改元で正月朔の条に改元記事そのものが立つ形（晋懐帝「永嘉元年春正月癸丑朔，大赦，改元」・金哀宗「正大元年正月戊戌朔，诏改元正大」）や、前年の詔を挟まない即時改元（元成宗の大徳）があり、「詔」を語として当てると逸脱に見えてしまう。判定は**原文がその改元に日付を付けているか**で行う
- **元号が実際に施行される日（多くは翌年正月朔）は採らない。** 原文はその日に改元の記事を置いていないので、`dateRaw`（干支）と `source.conversion` を持てず、`verify_calendar.py` の B-5 で再演できない（→ `R-EVENT-DATE-RAW`）。翌年施行であることは `note` に書く
- **即位日と一致する場合は、一致であって別規約ではない。** 清は11人とも「上即位…以明年為○○元年」と即位と建元が同一条に書かれており、採っているのは即位日ではなく改元記事の条の日である
- 遡って紀年される元号（明光宗の泰昌・北魏道武帝の天興）も、`date` は**宣言が載っている条の日**とし、遡及の事実は `note` に書く
- **既知の例外は1件**（2026-08-03 ユーザー決定）。`qing-shengzu.eraChangeCount.e001` の `1661-02-05` は、聖祖本紀「順治十八年正月**丙辰**，世祖崩，帝即位，改元康熙」の丙辰＝`1661-02-04` ではなく `reigns[0].startDate` に合わせた値。**清史稿の中で崩日が丙辰と丁巳に割れており**（丙辰を即位日とすると崩御より前になる）、原典側が割れているものを規約の一貫性のために動かさない、という判断で現状のまま残す

### 3. 大赦回数（`amnestyCount`）

- 「1回」＝本紀に**全国規模の赦**として明記された1件。部分的な恩赦（特定地域・特定罪状のみの減刑）は含めない。
- **「大赦」という語で判定しない。定型句は書によって違う**（2026-08-03 ユーザー決定・Issue #59）。漢書は前漢の各帝を通じて「赦天下」と書き（`han-wudi` 18件・`han-zhaodi` 7件・`han-wendi` 3件はいずれもこの表記で、本紀に「大赦」は1件も出ない）、後漢書はほぼ全件が「大赦天下」だが順帝紀 永建四年正月丙寅の1件だけが「其赦天下」と書く。語で当てると、**同じ行為が書を跨いだ瞬間に計上されたりされなかったりする**。見るのは「本紀がその条で天下に赦を及ぼしたと書いているか」。
- 判定基準の詳細な線引きが必要な曖昧ケースが出た場合は `verification.notes` 相当として `note` に残し、実調査開始時にユーザーに確認する。

### 4. 立后（皇后冊立）回数（`empressInstallationCount`）

- 「1回」＝皇后として正式に冊立された1件。同一人物の再冊立（廃后後の復位）も別カウントとする。皇后不在のまま在位した場合は `count: 0`。
- `events[].note` に冊立された皇后の名（分かれば）を記す。

### 5. 皇太子廃立回数（`crownPrinceDepositionCount`）

- 「1回」＝立てられていた皇太子（または皇太弟等の法定推定継承者）を廃した1件。立太子そのものの回数ではなく**廃立（廃止）のみ**をカウントする（フィールド名どおり）。
- `events[].note` に廃された皇太子の名・理由を記す。

## 6. 遷都回数（`capitalRelocationCount`）

個人レコード単位で「自分の在位中に何回遷都したか」を持たせる（王朝単位の集計はサイト側で `regimeId` によりグループ集計する）。

```json
"capitalRelocationCount": {
  "count": 1,
  "events": [
    { "date": "-0210-01-01", "datePrecision": "year", "from": "咸陽", "to": "洛陽", "note": "..." }
  ],
  "confidence": "high",
  "note": ""
}
```

- 構造はグループ2の4項目と共通（`count` + `events`）。`events[].from`/`.to` に遷都前後の都名を追加する点のみ異なる。
- 同一王朝内の先代皇帝が定めた都をそのまま使い続けた場合は `count: 0`。

### 「1回」の数え方の基準（2026-07-17確定）

- **正式な遷都（恒久的な主都機能移転）のみカウントする。** 戦乱による一時的な避難・行幸（例：唐玄宗の蜀行幸、北宋徽宗・欽宗の金への連行、南宋高宗初期の転々とした行在）は、恒久的な遷都と認められない限りカウントしない。
- **副都・陪都制度は対象外。** 唐の東都洛陽、元の上都、遼・金の五京制など複都制の王朝で副都を新設・行幸しても、正式な「主都」自体が変更されない限りカウントしない。ただし主都機能が事実上恒久的に移った場合（例：武則天による洛陽への遷都、南宋の臨安）は例外的に主都変更とみなしカウントする。
- **建国時の最初の定都は対象外。** 先行する自王朝の都からの移転ではなく、新王朝の初代皇帝が新規に都を選定した場合（`events[].from` に相当する自王朝の先代都が存在しない場合）は `count` に含めない。
- **短期間の連続移転はそれぞれ独立カウントする。** 同一皇帝の在位中に複数回都が変わった場合（例：後漢献帝期の洛陽→長安→許昌）は、一連の戦乱下の移動であっても `events` に個別に記録し、それぞれ1回として数える。

### 調査方法（トークン効率、2026-07-17確定）

グループ2・3の「人物ごとに1エージェント」方式は遷都には非効率（364人中大半が`count: 0`になる離散的な王朝単位の事象のため）。代わりに以下の2段階方式を採る。

1. **王朝（群）単位で遷都イベント年表を先に確定する**（グループ2/3と同じ12ブロック区分を流用し、複数政権が併存するブロック（南北朝・五胡十六国・五代十国等）はさらに王朝ごとに細分化してよい）。各エージェントは「その王朝で正式な遷都が何回あったか」を本紀から調査し、`date`/`datePrecision`/`from`/`to`/出典を伴うイベントリストのみを返す（人物への割当はこの時点で行わない）。
2. **既存の `reigns[].startDate`/`.endDate`（在位データ調査で確定済み）を使い、イベントの日付がどの皇帝の在位期間に該当するかをPythonスクリプトで機械的に割り当てる**。該当なしの皇帝には `count: 0, events: []` を一括付与する（`note`はテンプレ文言で可）。日付が皇帝交代の直前直後で判定が割れる境界事例のみ、個別に追加確認する。

この方式により、実際のLLM呼び出しは「王朝(群)単位のイベント列挙」十数〜数十件程度で完結し、364人分の個別調査より大幅に少ないトークン消費で済む。マージ時のホワイトリスト検証・`count == events.length`チェックは既存の運用（`merge-validation-automation`）をそのまま適用する。

## 7〜9. 軍事系カウント（親征・反乱鎮圧・被反乱）

判定基準を先に確定してから調査に着手する方針で進めた（経緯は [docs/PROJECT_STATUS.md](../../docs/PROJECT_STATUS.md) グループ3の節を参照）。基準は以下の通り確定：

### `events[].outcome` の主張範囲（3容器に共通・2026-08-07 ユーザー決定・Issue #97）

`outcome` は、**その event が名乗る書が、その事件について書いている範囲を超えない**。名乗る書とは、その event の `note`・`outcome` 自身・`source` が挙げている書で、**複数あるときは合わせた範囲でよい**（載記が捕縛までしか書かず資治通鑑が結末まで書いているとき、通鑑を名乗っていれば結末を書いてよい）。

- **どの名乗る書も言っていないことを足さない** — 他書からの補い・後世の通説・年の推定（「后主亡之日」から陳の滅亡年を当てる類）がここで落ちる
- **判定の単位は「条」ではなくその事件の記事** — 同じ書の中で節が分かれるのは構わない（李寿の成都急襲は晋書載記の李寿の節と李期の節に分かれて載る）。**別の事件の条から採った内容は `note` へ回す**
- **訂正の経緯・捨てた値・保留の理由は `note` の領分**で、`outcome` に書かない（`R-NOTE-CLAIM` の向きと同じ）
- **`count` はこの制約に影響されない。** 8節のとおり鎮圧の成否は数え方に入らないので、`outcome` を原文の範囲まで弱めても件数は動かない
- **結果が原文から読めないときは、無理に結果の形にしない** — 原文が書いている行為のところ（「靳準を行車騎大将軍として派遣し討たせた」）で止めてよい。「不詳」を使うのは、勝敗そのものが原文に書かれていて読み取れないときだけ
- **欄が書名を1つも名乗っていないときは、この定義では判定できない** — `events[]` の `source` は全件 `null` なので、名乗る書は事実上 `note` の散文から読む。record 側の `source.page` や史料マッピングを「名乗る書」として使ってよいかは**未決**で、走査の検出器はこの答えが要る（Issue #97 に継続）
- なぜこの制約があるか: `outcome` は配布データに出る主張なのに自然文で、`date` の `*Raw`＋`conversion` のような再演できる witness を持たない（[EMPERORS_SCHEMA.md](EMPERORS_SCHEMA.md) の「note と claim」の節が `outcome` を witness の側に数えているのは、**この制約があって初めて成り立つ**）。範囲を原典に縛ることで、引用と突き合わせられる欄になる
- **既存の3,638件を一度には直せない** — 検出済みのぶんから直し、未走査の残りは [RESIDUAL.md](../../docs/process/RESIDUAL.md) の行で持つ。検出器は未作成

### 7. 親征回数（`personalCampaignCount`）

- **「1回」＝同一の目的地・同一の相手に対する一連の軍事行動（出征〜帰還または現地での終結まで）を1回とする。** 同一遠征中に複数の敵を破っても1回、年をまたいでも同一目的の継続なら1回。年を空けて同じ相手に再度出征した場合は別カウント。
- **途中で一度帰還していても、中断の前と後で行き先（相手）が同じであれば中断とみなして1回とする**（2026-08-03 ユーザー決定・Issue #63）。**帰還が起きたことは分割の理由にならない** — 分割の理由になるのは「相手が違う」か「年を空けた」のどちらかで、上の条項がそのまま境目になる。起点は北周武帝の第二次東伐で、建徳五年十一月に斉主の来援を受けて班師・帰京し（十一月癸巳「至自东伐」）、その4日後の丁酉に同じ北斉へ再出発している（周書巻六武帝紀下）。これを2回に割ると**北斉を滅ぼした遠征がどちらの区間にも収まらない**。
  - 両条項の間隔上の境目は `python3 scripts/screens/campaign_interrupt.py` で測る。**2026-08-03 時点で、隣接する2 event が同一の相手で再出発間隔1か月未満というペアは1件も無い**（同一相手60ペアのうち間隔が測れる38ペアの最短は2か月）ので、この条項で動く既存の `count` は無い。**間隔が測れない22ペアと、`target` の表記揺れによる取りこぼしは未測定** — [RESIDUAL.md](../../docs/process/RESIDUAL.md) の行を参照。
- 親征＝皇帝自身が軍を率いて戦場に赴いた場合のみ。将軍への派遣・勅命のみ（皇帝本人が出陣しない）は含めない。

```json
"personalCampaignCount": {
  "count": 2,
  "events": [
    { "startDate": "-0200-01-01", "endDate": "-0200-12-31", "datePrecision": "year", "target": "匈奴", "outcome": "敗北（白登山の戦い）", "note": "..." }
  ],
  "confidence": "high",
  "note": ""
}
```

- `events[].target`: 遠征相手（民族名・政権名・人物名など）。
- `events[].outcome`: 自然文または短句で結果を記す（勝敗が不明瞭な場合は「不詳」）。**書ける範囲は上の「`events[].outcome` の主張範囲」に従う**（名乗る原典がその条で書いている範囲を超えない）。

### 8. 反乱鎮圧回数（`rebellionSuppressionCount`）

- **「1回」＝独立した首謀者・独立した蜂起地点を1件とする。** 同じ反乱が複数地域に飛び火しても首謀者が同一なら1件、鎮圧に複数年かかっても1件。
- 皇帝側（政権側）が鎮圧の主体だった件数。実際に鎮圧に成功したか否かは問わない（鎮圧を試みて失敗し王朝崩壊に至った場合もカウントし、`note` に結末を記す）。

```json
"rebellionSuppressionCount": {
  "count": 1,
  "events": [
    { "startDate": "0184-01-01", "endDate": "0184-12-31", "datePrecision": "year", "leader": "張角", "name": "黄巾の乱", "outcome": "鎮圧成功", "note": "..." }
  ],
  "confidence": "high",
  "note": ""
}
```

### 9. 被反乱回数（`rebellionSufferedCount`）

- 数え方の単位は反乱鎮圧回数と同じ（首謀者/蜂起単位＝1件）。
- 皇帝に対して起こされた反乱の件数。鎮圧の成否は問わない。自身が反乱により廃位・殺害された場合もその反乱をカウントし、`deathCause`（`category: "暗殺"`/`"戦死"` 等）や退位経緯（`reigns[].note`）と内容が重複してよい（別軸の集計のため重複を許容する）。
- **`rebellionSuppressionCount` と `rebellionSufferedCount` は原則として同一の反乱群を両面から集計したものであり、通常はほぼ同じ件数・同じ反乱が両方に計上される（2026-07-16確定）。** 反乱者の社会的身分・政治的地位（無位無官の農民か、諸侯王か、丞相か等）や規模の大小は問わない。飢民・盗賊による蜂起（例: 黄巾の乱、赤眉の乱）であっても、実際に武装し政権への反抗行動（挙兵）を取り、政権側がそれを鎮圧の対象とした（＝`rebellionSuppressionCount`に計上した）のであれば、原則として`rebellionSufferedCount`にも同じ反乱を計上する。「反乱の標的が皇帝個人の廃位・弑逆を意図していたかどうか」を被反乱算入の判定基準にしてはならない（反乱の目的が地方での自立・自衛・略奪等であっても、皇帝の統治権に対する武力反抗である限り被反乱に含める）。
- 両者が食い違ってよい正当な理由は以下に限定する。これ以外の理由で一方のみに計上する場合は誤りを疑うこと：
  1. **集計単位の粒度差** — 鎮圧側は複数の首謀者・地域を1つの軍事行動として合算したが、被反乱側は首謀者ごとに個別カウントした（またはその逆）場合。
  2. **未鎮圧のまま在位終了** — 反乱が皇帝の在位終了（崩御・退位）までに鎮圧行動が着手・完了しなかった場合、`rebellionSuppressionCount`には含めなくても`rebellionSufferedCount`には含める。
  3. **皇帝自身が攻撃の主体だった場合** — 皇帝が権臣・宦官等を先制的に武力で打倒した場合（相手はまだ反乱を起こしていない）は、反乱そのものが成立していないため両方から除外する。
  4. **朝廷内部の権力者による兵力を伴う弑逆・クーデター** — 丞相・宦官・外戚等が兵力を用いて皇帝を弑逆・廃位に追い込んだ場合は`rebellionSufferedCount`に含めるが、鎮圧の主体が皇帝側ではなく反乱者側であるため`rebellionSuppressionCount`には計上しない（例: 望夷宮の変）。
- 対象が皇帝の統治下にない独立勢力・対等な群雄との抗争（統一戦争）や、服属していない外国勢力との対外戦争は、鎮圧・被反乱いずれの対象にもならない（`rebellionSuppressionCount`の基準と対称）。ただし辺境の郡県・属国等、皇帝の統治機構下にある集団（例: 属国の異民族）による蜂起は「服属民の反乱」として両方に含める。
- 実際の兵力行使（挙兵）に至らず、密告・摘発のみで終わった謀反計画は、鎮圧・被反乱いずれにも含めない（この基準は変更なし）。

```json
"rebellionSufferedCount": {
  "count": 1,
  "events": [
    { "startDate": "0755-01-01", "endDate": null, "datePrecision": "year", "leader": "安禄山", "name": "安史の乱", "outcome": "退位に追い込まれた", "note": "..." }
  ],
  "confidence": "high",
  "note": ""
}
```

- `rebellionSuppressionCount` と `rebellionSufferedCount` は独立フィールド。同一の反乱イベントが（鎮圧に関わった別の皇帝の）`rebellionSuppressionCount` と（対象にされた皇帝の）`rebellionSufferedCount` の両方に登場することは想定内であり、突き合わせの整合性チェックは行わない。
- **朝廷内部の権力者（丞相・宦官・権臣・近衛兵など）による、実力（兵力）を伴う弑逆・クーデターも `rebellionSufferedCount` に含める**（2026-07-16確定）。首謀者が外部の蜂起勢力か内部の権力者かは問わない。「兵力を用いて皇帝を弑逆・廃位に追い込んだか」を基準とする（例: 秦二世に対する望夷宮の変）。単なる暗殺未遂（刺客による単独犯行等、組織的な兵力を伴わないもの）は含めない。

## 10. 即位時年齢・没年齢（`ages`）

グループ1〜3（即位経路・死因・改元・大赦・立后・皇太子廃立・親征・反乱関連）調査の副産物として、2026-07-17時点で364人中213人分がすでに部分的に埋まっている（機会的補完の運用ルール、下記参照）。2026-07-17、能動的な悉皆調査の対象に正式に格上げした（`meta.status.phases.ages.status` は `deferred` から着手ステータスに変更する）。

**運用ルール（継続）**: グループ1〜4調査中に読んでいる原典・列伝の中で生年月日・没年月日・即位時年齢・没年齢が判明した場合は、その都度このフィールドを埋める（これに加えて、専用の調査ブロックでも悉皆的に埋めていく）。

```json
"ages": {
  "birthDate": "-0259",
  "birthDatePrecision": "year",
  "deathDate": "-0210-09-10",
  "deathDatePrecision": "day",
  "accessionAge": 13,
  "deathAge": 49,
  "confidence": "medium",
  "note": "生年は諸説あり。"
}
```

- `birthDate`/`deathDate`: ISO8601、不明部分は `null`。**保存値の深さそのものが主張**で、年しか分からなければ `"-0259"`、月まで分かれば `"-0259-06"` と書く（2026-08-03・Issue #69。`events` と同じ規約で、`-01-01` の埋め草は置かない）。深さは `birthDatePrecision`/`deathDatePrecision` **以下**でなければならず、超えると `validate_emperors.py` の `check_ages` が落ちる。浅い側は自由（主張を弱めるだけ）。`deathDate` は原則 `reigns` の最終 `endDate` と一致するはずだが、退位後に別途没した場合はそちらを優先する（機械的な自動転記はせず、`deathCause` の記述で個別に確認する）。**`reigns[]` はこの規約の対象外**でフル ISO のまま
- `accessionAge`/`deathAge`: **数え年（中国伝統の年齢計算）で統一する（2026-07-17確定）**。既存213人分の実データはすでに数え年で統一されており（原文の「時年◯◯」「年◯◯」等の直接記載を数え年としてそのまま採用）、この既存実績に合わせる。原文に満年齢由来の記載がある場合は `note` にその旨を明記した上で数え年に換算するか、換算不能なら `confidence: low` として両論併記する。
- **直接記載を最優先、次点で確度の高い逆算値を採用する**（三国ブロックで確立済みのルール）。同一人物について「特定の年号年における年齢」が原文に直接記載され、かつ知りたい時点（即位年・没年等）の年号年も確定している場合、両者の**年号年ラベルの差分**を直接記載の年齢に加減して逆算してよい（暦月をまたぐ誤差が生じないため）。逆算値は可能な限り別の独立した直接記載値とクロスチェックし、不一致の場合は無理に一方を採用せず `note` に不一致を明記して該当フィールドの追加自体を保留する。
- **生年・没年齢が判明しない人物も、調査済みであることを明示する。** 調査した結果、原典に手がかりが見当たらなかった場合は、`ages` オブジェクト自体は付与し、`birthDate`/`deathDate`/`accessionAge`/`deathAge` は `null` のまま、`note` に「調査したが原典に生年月日・享年の直接記載が見当たらなかった」旨を記す（「未調査」と「調査済みだが不明」を区別するため。既存の安禄山・後周恭帝・劉豫の3例が先例）。フィールド自体を省略するのは「まだそのブロックの調査に着手していない」場合のみとする。
- 調査ブロックの完了管理は他グループと同じく `meta.agesCompletedBlocks`（新設）とこのファイルの進捗記録で行う。ブロック内の全員について「データが埋まっている」か「調査済みだが不明」のいずれかの状態になった時点でそのブロックを完了とする。

### 調査方法（トークン効率、2026-07-17確定）

既存213人分の実データの多くは、`deathCause.note`/`accessionRoute.note`（死因・即位経路調査で既に読んだ原典の引用）に「時年◯◯」等の年齢記載がそのまま含まれていたものを転記して得られている。残る151人（2026-07-17時点、明16・前漢14・後漢14・清11など大ブロックが未着手のまま丸ごと残っている）についても、この「既存フィールドの再利用」を起点にした以下の方式で調査する。

1. **既存ノートの再確認を起点にする**：対象者の`deathCause.note`/`accessionRoute.note`/`reigns[].note`/`raw`/`startDateRaw`/`endDateRaw`（すでにJSONに存在し、新規の原典アクセス不要）をエージェントへのプロンプトにそのまま含め、年齢・生年に関する記載がすでに含まれていないか確認させる。
2. **不足分のみ、既知の一次史料箇所を再訪する**：それでも見つからない場合、`deathCause.source.page`/`accessionRoute.source.page`（死因・即位経路調査で既に特定済みの巻・篇）と同じ箇所を対象に、崩御記事・即位記事付近の「時年」「年◯◯」「享年」等の記載のみを確認する（無関係な列伝への探索範囲拡大はしない）。
3. **見つからない場合は「調査済みだが不明」として確定し、無理な深追いはしない**（五胡十六国・十国等の小勢力の君主は原典に生年記録が存在しないことが多く、これ自体が正しい調査結果である）。
4. **ブロック着手順**：まず既存データが丸ごと欠落している大ブロック（明16人・前漢14人・後漢14人・清11人、計55人）を優先する（明・清は実録等により生年月日の記載率が高く収穫が見込める）。その後、五胡十六国・五代十国等の断片的な小勢力（計約96人）を同じブロック区分（グループ2/3と同一の12ブロック）で順次処理する。
5. Workflow運用（並列エージェント・id固定・summary-only return・journal.jsonl経由マージ・ホワイトリスト検証）は既存インフラ（`group2-workflow-token-efficiency`・`merge-validation-automation`・`workflow-id-pinning`）をそのまま流用する。

## 全項目共通の設計判断

- **回数系フィールド（2〜9）はすべて `count` + `events[]` の同型構造**。将来のサイト実装でグラフ化する際に統一的に扱える。
- **`count` は `events.length` と一致させる**。不一致（「少なくともN回」等、正確な件数が確定できない場合）は `count` に判明している最小件数を置き、`note` に不確実性を明記する。
- **0回は明示的に `count: 0, events: []` で記録し、未調査とは区別する**。人物レコードにフィールド自体が存在しない＝その項目が未調査であることを意味する（`meta.status.phases.<key>.status` が `completed` になるまでの間、一部人物のみフィールドを持つ状態が生じる。これは `deathCause` と同じ運用）。
- **各フィールドの `confidence`** は `verification.confidence` と同じ3段階（`high`/`medium`/`low`）。
