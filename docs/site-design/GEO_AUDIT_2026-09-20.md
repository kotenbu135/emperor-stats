# 生成AI経由の被引用の実測（2026-09-20）

X の投稿（[@irabukht 2026-09-19](https://x.com/irabukht/status/2101375295152652372)・Ryze AI / Jev の宣伝スレッド）が
挙げていた7つの SEO/GEO ワークフローのうち、**③「人が AI に実際に聞く質問に自分のページが答えているか」・
④「答えていないなら AI は代わりに誰を引用しているか」だけ**がこのサイトに当てはまると判断し、製品を使わずに
手で実測した記録。他の5項目（競合ページの採点とコピー、買い手クエリの仕分け、内部リンク設計ほか）は
収益もコンバージョンも無いこのサイトでは前提が合わず、「コピー対象の選定」は Issue #16 の
「他サイトからのコピペ禁止」と `R-PRIMARY-SOURCE` に反するため採らない。

## 測り方と、測れなかったもの

**測ったもの** — 検索層（generative engine が grounding に使う retrieval）に9問を投げ、
`emperorstats.com` が結果に立つか、立たないなら何が代わりに引用されるかを記録した。

**測れなかったもの** — ChatGPT・Gemini の被引用を直接は測れていない。実行環境に両者の API キーが無く、
ブラウザ経由もログイン済みセッションが要るため。**したがって以下の「引用されない」は検索層の観察からの
推論であって、ChatGPT の画面で確かめた事実ではない。** 確定させるには本人の端末で同じ9問を叩く必要がある。

正解はすべて `data/emperors.json` 由来（`emperor-stats-video/data/stats.json` の書き出し・commit 9edb282）。

## 読み取れたこと

### A. 看板の数字が、公開面のどこにも文になっていない

`非業の死 153名・41.9%` はこのデータセットで最も引用されやすい1文だが、**公開ページに出ていない。**
概要ダッシュボードにあるのは死因の内訳（病死162名44%・暗殺96名26%…）と、在位年数で割った非業の死率
（1年未満71%・1〜3年66%…）だけで、総数と全体の率は読み取れる形で置かれていない。
retriever は読める文しか引用できない。

### B. 最も差別化される数字が noindex の中にある

`統一王朝 21.2% / 分裂期 50.8%` は `getRegimeFateStats()` にあるが、出ているのは `/lab` だけで、
`/lab` は意図的に `robots: { index: false, follow: false }`（`site/src/app/lab/page.tsx:42`）。
**問い9は検索層が「該当なし」を返した無競合の問いで、いま誰も答えを持っていない。**
公開面に出すかどうかは SITE_DESIGN の決定に触るので、ここでは提案に留める。

### C. 平均在位年数（9.8年）は内容ではなく順位の問題

問い3で検索層は平均寿命（39.2歳）の答えは返したが、平均在位年数には「データが無い」と答えた。
一方サイトの概要ダッシュボードには「平均在位期間 9.8年」が文で出ている。**書いてあるのに拾われていない。**

### D. GitHub リポジトリが自サイトを食っている

9問中2問（2・5）で立ったのはリポジトリであってサイトではなく、ブランド名指しの問い8でさえ1位はリポジトリ。
README がプロジェクトについて最も内容の濃い1ページになっているため。プロジェクトとしては拾われているが、
引用先がサイトにならない。

### E. 個別ページは索引されているが、皇帝名では上がらない

問い8で個別ページ3本が出たので索引自体は効いている。一方、皇帝名で直接引いた問い6・7では出ない
（Wikipedia・百度百科が占める）。Issue #16 の前提は正しいが、紹介文が未執筆の人物が大半である以上、
ここは #16 の進捗待ちの面が大きい。

## 手の入れどころ（提案・未着手）

1. **`site/public/llms.txt` に主要な数字そのものを書き足す。**
   現在の llms.txt は導線リンクと注意書きだけで、**数字が1つも入っていない**。
   LLM の読み取りを目的に置いたファイルなので、ここが最も安く効く。A・C の両方に効く。
2. **非業の死の総数と率（153名・41.9%）を概要ダッシュボードに1文で出す。**（A）
3. **統一王朝と分裂期の非業率を公開面に出すか決める。**（B・ユーザー判断）

**2026-09-20 にユーザー判断で1だけ実施した。**2と3は見送り（3は SITE_DESIGN の決定に触るのでユーザー判断のまま）。

1の実装は `site/src/app/llms.txt/route.ts` で、手書きの `site/public/llms.txt` は削除した。
数字はそこで数え直さず、トップページと同じ `getOverviewStats()`・`getHomeHighlights()` の
戻り値をそのまま文にしている（データを訂正すると llms.txt の数字も一緒に動く）。
非業の死の区分も `reignDeath.segments[0]` から引いていて、定義は `emperors.ts` の
`REIGN_DEATH_SEGMENTS` 1か所にしかない。これで A と C の両方に効く。

## 余談: `meta.generatedAt` が古い

llms.txt へ「◯◯時点」と鮮度を書こうとして気づいた点。`data/emperors.json` の
`meta.generatedAt` は **2026-08-03** のままだが、ファイル自体の最終更新は **2026-08-21** で、
データ訂正のたびには更新されていない。配布物に鮮度の主張として載せると嘘になるので、
llms.txt では日付を書かないことにした。直すかどうかは別途。
