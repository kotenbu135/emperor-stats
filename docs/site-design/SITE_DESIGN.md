## 3. スタック

Next.js 16（App Router / Turbopack）＋ React 19 ＋ Tailwind v4 ＋ **shadcn/ui**。
図表は用途に応じて Tremor（vendored）と Recharts。Node は nvm の v26.4.0。

### どこで何を使っているか

**層が違う。** shadcn/ui は**操作する部品と外枠**、Tremor は**盤面（数値を見せる面）**。同じ画面に両方載る。

| 層 | 供給元 | 使っている場所 |
|---|---|---|
| 外枠（サイドバー・ヘッダー・フッター・ナビ） | **shadcn/ui**（`Sheet`・`Accordion`・`Button`） | 全ページ・**旧実装** |
| 操作する部品（検索・フィルタ・ダイアログ） | **shadcn/ui**（`InputGroup`・`Select`・`Command`＋`Popover`・`HoverCard`・`Dialog`・`DropdownMenu`・`ToggleGroup`・`Switch`・`Tooltip`・`Badge`・`Empty`・`Spinner`） | 皇帝一覧・データベース・シェル |
| 表（365行） | **shadcn/ui `ui/table.tsx`** ＋ TanStack Table | データベース |
| 盤面（カード・KPI・ランキング・帯・棒グラフ） | **Tremor**（`Card`・`BarList`・`BarChart`・`Tabs`・`CategoryBar`） | 概要ダッシュボードのみ |
| アイコン | `lucide-react` | 全ページ |

**「ブロックの分類」をしているのは Tremor 側**（KPI カード・チャート・ツールチップ・テーブル・
ページシェル・フィルタバー）。shadcn/ui は部品の詰め合わせで、盤面の組み立て方は供給しない。

vendored の Tremor は `src/components/tremor/` の**6ファイルだけ**（上の5つ ＋ `CategoryBar` が内部で使う
`Tooltip`）。`/lab` の削除に伴い、そこだけが使っていた `Table`・`DonutChart`・`ProgressCircle`・`Badge`・
`Divider`・`ProgressBar`・`Tracker` の7つは削除した。**使わない部品を先に取り込まない。**

導入済みの shadcn 部品のうち、アプリのコードから直接使っていないのは `card`・`separator` の2つ
（`textarea` は `command.tsx` 経由でだけ使われている）。ダッシュボードが `tremor/Card` を
使っているため `ui/card.tsx` は誰も使っていない。`ui/table.tsx` はデータベースの主役
（ただし `Table` ラッパーだけは使わない — 「6. データベース」節）。

### インタラクションの強化（2026-08-01・ユーザー決定）

**部品を足す前に「押した／打った反応」を足す。** 2026-07-30 に出した診断
（のっぺりの主因は active/pending 状態の欠落）に対する実装で、**新しい面・新しい情報は
1つも増やしていない**。既にある操作に反応と出口を付けただけ。入れたのは次の8点:

| # | 何を | どこ | 部品 |
|---|---|---|---|
| 1 | **押せるものはポインタが指に変わる**・**乗せたら見た目が変わる** | 全ページ | `globals.css` ＋各部品 |
| 2 | 絞り込みの**結果が古いあいだ**スピナーを出す | 一覧・データベース | `Spinner` |
| 3 | 並べ替え見出しに**次にどちら向きに回るか**を出す | データベース | `Tooltip` |
| 4 | 検索窓を `InputGroup` へ寄せ、**クリア（×）**を付ける | 一覧・データベース | `InputGroup` |
| 5 | 列の表示切替を**チェック項目のメニュー**へ | データベース | `DropdownMenu` |
| 6 | 2択の絞り込みを**地続きのトグル**へ | データベース（在位回数） | `ToggleGroup` |
| 7 | ふりがなの ON/OFF を**スイッチ**へ | シェル | `Switch`＋`Label` |
| 8 | 効いている条件の**チップ**と、0件のときの**解除導線** | 一覧・データベース | `Badge`・`Empty` |

#### 1 の中身（2026-08-01 ユーザー指摘・実測して直した）

**Tailwind v4 の preflight は `button` の cursor を `default` にする**（v3 まではブラウザ既定の
pointer）。このため shadcn の Button・Select・Popover・DropdownMenu・Switch・ToggleGroup、
Tremor の Tabs まで、**押せる部品のほぼ全部が矢印カーソルのまま**だった。加えて、
選択中の項目（現在地のナビ・選択中のタブ／トグル・押されている種別チップ）は
「非選択時の見た目＝ hover 後の見た目」だったため、**乗せても何も起きない**状態だった。

実測は `site/tools/hover-audit.mjs`（各ページの操作要素を種類ごとに1つ拾い、hover 前後の
計算済みスタイルを比べる）。**70種類中46種類が不合格 → 0**。部品を足したら流し直す。

hover の言い方は2つに統一する: **面がわずかに沈む（`hover:bg-accent`）**か、
**文字が朱になる（`hover:text-seal`）**。選択中で面が既に沈んでいるものは文字を朱にする。

判断の記録:

- **後追いさせる対象を検索語だけでなく絞り込み条件まとめへ広げた。** それまで
  `useDeferredValue` に載せていたのは検索語だけで、王朝・時代・区分のセレクトは即時反映
  だった（選んだ瞬間に365件の再レンダリングが割り込み、ポップオーバーの閉じ方が固まる）。
  条件を1つのオブジェクトに束ねて `useMemo`→`useDeferredValue` へ通し、
  **コントロールの表示は生の state（即時）・結果は deferred（後追い）**と持ち場を分ける
- **グリッドと表そのものは薄く（opacity）しない。** 「古い結果」を示す定石だが、
  5万px級の箱に opacity を掛けると合成レイヤーが跳ね、この面が過去に踏んだ TBT/CLS の
  失敗に近づく。**反応は件数行のスピナーだけに置く**（実測せずに大きな箱へ視覚効果を
  足さない、という判断）
- **スピナーは `motion-reduce:hidden`。** globals.css の reduced-motion 一括指定は
  `animation-iteration-count: 1` なので、無限ループのスピナーは1回転して中途半端な角度で
  固まる。その環境では出さず、`sr-only` の文言と面の変化で伝える
- **リンクの遷移待ち（`useLinkStatus`）は入れない**（2026-08-01 ユーザー決定）。
  一度は入れたが、静的書き出し＋プリフェッチで遷移が速く、**待ちがそもそも起きない**。
  出ない表示のために365枚ぶんのフックを持つ理由が無い
- **ツールチップは `title` の置き換えではない。** 即位経路の全文・復位者の全期間は
  セルの `title` と読み上げ用テキストが持ち続ける（Radix のツールチップはタッチで出ない）。
  足したのは**次にどちら向きに並ぶか**だけで、**「並べ替えの鍵は◯◯」の説明は出さない**
  （2026-08-01 ユーザー決定）。`TooltipProvider` は layout ではなく表の見出しに置く
  （全ページに client 境界を増やさない）
- **列のメニューは選んでも閉じない**（`onSelect` を止める）。2列・3列と続けて隠すのが
  普通の使い方なので、1つ押すたびに開き直させない
- **チップのラベルは deferred ではなく選択の生の値から作る** — 外した瞬間に消えないと、
  効いていない条件が残って見える
- **0件の面には必ず解除ボタンを置く。** それまでは素の1行で、条件を外す導線が
  どこにも無かった（行き止まり）

### shadcn/ui と Tremor の使い分け

**土台は shadcn/ui。Tremor は「shadcn に無い部品」だけ。**
「見た目の正解を Tremor の Blocks から持ってくる」という方針は、**Blocks を視覚の参照**（余白・構成・
情報密度）として使うことで満たす。部品そのものを Tremor で揃える必要はない。

いま実際に Tremor を使っているのは概要ダッシュボードだけで、対応関係はこうなっている:

| Tremor（使用中） | shadcn/ui に同等品があるか |
|---|---|
| `Card` | **ある**（`ui/card.tsx`・導入済み） |
| `Tabs` | **ある**（未導入・`npx shadcn add tabs` で足せる） |
| `BarChart` | **ある**（`Chart` = Recharts ラッパー）。ただし後述のバージョン制約あり |
| `BarList` | **無い**。176行だが中身は幅を持つ div で、チャートではない |
| `CategoryBar` | **無い**。237行。これも div |

図表があるのはダッシュボードだけなので、この選択はほぼ論点にならない
（皇帝一覧＝カードグリッド＋フィルタ、データベース＝表、このサイトについて＝文章）。
**ダッシュボードを shadcn へ載せ替えることはしない**（完成扱い）。

### なぜ Nivo ではなく Tremor だったのか

**Nivo と Tremor は競合していない。** Nivo は D3 ベースのチャート**だけ**を供給するライブラリで、
チャートの外側（カード・KPI・余白・タイポグラフィ・盤面の並べ方）は何も供給しない。
それを自分で設計するのが 2026-07-30 に失敗した工程そのものだった（自前でデザイン言語を書く）。

再構築の目的は**「見た目の正解を外部から持ってくる」**なので、必要だったのは
チャートライブラリではなく**ダッシュボードの完成画面**。Tremor（Vercel 傘下・Blocks と
テンプレート300+ が MIT で無料）は KPI カード・チャート・ツールチップ・テーブル・
ページシェル・フィルタバーという分類が、このサイトの必要とほぼ一致していた。

つまり Nivo を捨てて Tremor にしたのではなく、**チャート層（Nivo → Recharts）は
土台の選択に付いてきたコスト**。shadcn/ui の公式 Charts も Tremor も Recharts ベースなので、
shadcn/ui を土台に選んだ時点でこの移行は避けられなかった。

### Recharts は 2.15.4 に固定（shadcn の Chart は入れられない）

`package.json` は `"recharts": "2.15.4"` と**完全固定**している。3.x では vendored した Tremor のチャートが動かない。

一方、**shadcn の `chart` レジストリ項目は `recharts@3.8.0` を要求する**
（`npx shadcn@latest view @shadcn/chart` で確認。`ResponsiveContainer` の `initialDimension` など
Recharts 3 の API を使っている）。

→ **ダッシュボードを Tremor で動かしたまま shadcn の `Chart` を足すことはできない。** 二者択一になる。
新しくチャートが要る面が出てきたら、Tremor の `BarChart` を再利用するのが唯一の低コスト路線。

### Nivo は採らない（2026-07-31 ユーザー決定・再提案しない）

**技術的には可能だった。** Nivo は SVG/D3 で Recharts と何も共有しないため、図の描画だけ差し替えても
バージョンの衝突は起きない。実際に概要ダッシュボードの4つの図（ランキング横棒・内訳の帯・
世紀の縦棒・在位年数×死因）を `@nivo/bar` で描き直した比較版を作って確認したが、**採らないと決めた**。

作ってみて分かった Nivo 側のコスト（同じ判断を繰り返さないための記録）:

- **軸ラベルの幅を測ってくれない。** 左マージンを px で固定するしかなく、長い名前は黙って切れる。
  CSS で詰められないので画面幅の分岐を JS で持つことになる
- **`enableLabel` は棒の内側にしか置けない。** 「61年332日」は短い棒に入らず、値ラベルは独自レイヤー送り
- **行のリンクが自前になる。** `BarList` の各行は `/emperors/[id]` へのリンクだったが、
  Nivo では軸ラベルを SVG の `<a>` で包む必要がある
- **横棒は data の先頭を下端から積む。** 1位を上に出すには配列を反転して渡す
- **`nice: false` が必須**（既定だとドメイン上限が丸められ、1位の棒が右端に届かない）

比較用の `/lab` と `src/components/home-v2/nivo-board.tsx` は削除済み。
`@nivo/*` 5パッケージは `/reign` の削除で丸ごと落ちた。チャートは Recharts（vendored Tremor 経由）で統一する。

### ページを消したあとの掃除（`/reign` 廃止で学んだこと）

**ESLint の `no-unused-vars` は使われていない export を報告しない。** ページを消したあとは
export ごとに `grep -rn '<名前>' src/` で消費者を数えること（lint が 0 error でも死んだ export は残る）。

`/reign` の削除では、ページ本体のほかに次が落ちた: `charts/ranking-bar-chart.tsx`・`scroll-bar-chart.tsx`・
`nivo-theme.ts`・`emperor-tooltip.tsx`・`chart-takeaway.tsx`・`tables/restoration-table.tsx`・
`top-ranked-table.tsx`・`lazy-mount.tsx`・`lib/ranking-metrics.ts`、`lib/emperors.ts` の
`getRestorationRows`/`getChartTakeaway`、`lib/emperor-types.ts` の `RestorationRow`。
`lib/dynasty-colors.ts` は淡彩を作る道具（`DYNASTY_FILL_MIX`・`dynastyColorMix` ほか）を失い、
`DYNASTY_COLOR_SLOT`・`dynastyColorSlot`・`dynastyColorHex` の3つだけが残った。

旧サイトの性能対策（`LazyMount`・行ウィンドウイング・`transform` 配置・`useTipOutlet`）は

## 4. 配色と書体

**`site/src/app/globals.css` の `/* @palette:start */`〜`end` が唯一の正。** ここ以外に色を書かない。
CSS 変数が使えず実値を焼き込んでいる箇所の一覧は [`site/AGENTS.md`](../../site/AGENTS.md) にある（同時に直す契約）。

- **shadcn 標準トークン**（`--background`〜`--sidebar-ring`・`--chart-1〜5`・`--radius: 0.45rem`）は
  ユーザーが自作ビルダーで生成したテーマの**受領値を1つも変えずに**入れてある（2026-07-31 採用）
- **書体は本文も見出しも同じサンセリフ**（`--font-heading: var(--font-sans)`）
- **地 `--background` と面 `--card` はどちらも純白** `oklch(1 0 0)`。面の分離は**罫線と影だけ**が担う。
  → **影や罫線を弱める変更は「のっぺり」の再発に直結する**ので単独で行わない
- `.dark` ブロックは受領値のまま入っているが、**ダークモードは実装していない**（`.dark` を付ける導線が無い）

### サイト固有トークン（受領テーマに対応物が無いもの）

| トークン | 値・条件 |
|---|---|
| `--seal` / `--seal-foreground` | 朱アクセント。`var(--primary)` と同値。**100箇所以上から参照**されているので、アクセント色を変えたいときはこの1行を動かす |
| `--series-1〜8` | **分類用のカテゴリカル配色**。死因・即位経路・89政権→8スロットに使う |
| `--bar` / `--bar-campaign` / `--bar-era-change` | ランキング横棒の面（在位期間・親征回数・改元回数の3タブ）。棒の中に黒文字が乗る |
| `--kinship-minor` | 無彩色寄り。系列色のどれとも被らせない |

**`--chart-1〜5` を分類に使わない**（2026-07-31 ユーザー判断）— 受領テーマの `--chart-*` は
淡い黄→濃い赤茶の**連続ランプ（sequential）**で、分類に使うと隣接区分が見分けられない。

`--series-1〜8` は dataviz スキルの検証済みリファレンス配色そのままで、面 `#ffffff` に対して
`validate_palette.js` を通してある:

```
[PASS] 明度帯 / 彩度下限
[PASS] CVD分離        最悪隣接 #eda100↔#1baf7a ΔE 9.1
[PASS] 通常視力下限   最悪隣接 #e87ba4↔#eda100 ΔE 19.6
[WARN] コントラスト   #1baf7a(2.82) #eda100(2.17) #e87ba4(2.69) が 3:1 未満
```

**WARN は「可視ラベルまたは表ビューがあること」が免除条件。**
現状は凡例に区分名と実数を必ず併記しているので満たしている。**ラベルを外す変更をするときは必ず再確認する。**

**9区分目に色を作らない。** `--series-*` は8色。9つ目のカテゴリは必ず「その他」へ畳むか、面を分ける。

棒の色は**目視で選ばない** — OKLab→sRGB を計算して、黒文字とのコントラストと白地との明度差の両方を見る。
実測値は `--bar` 6.57/3.01、`--bar-campaign` 6.46/3.07、`--bar-era-change` 6.63/2.99（同じ帯に揃えてある）。
後ろ2つは**旧 `--bar-accession` / `--bar-death` を改名しただけで値は同一**（2026-08-01・タブを親征/改元へ
差し替えた際に名前と用途がずれたまま残さないため）なので、上の実測値はそのまま生きている。
**改名するときは `:root` と `@theme` の `--color-bar-*` を対で直す** — `:root` だけ変えても
Tailwind v4 は `@theme` から utility を生やすので `bg-bar-*` の規則が生成されず、
棒が無色のまま tsc・lint・build がすべて通る。確認は `out/_next/static/chunks/*.css` に
`.bg-bar-<名前>{...}` の規則があること。

**`dynasty-colors.ts` の `SLOT_HEX` の番号は `--series-N` の N ではない。** 王朝の性格に色を当てる
意味ベースの割り当て（漢系=4金・北族=1青・晋系=7紫・宋=2緑・明=8赤・隋/梁系=5青緑）で、
スロット0は割拠政権用の無彩色。色を足すときは番号ではなく意味の側から決める。

## 5. 概要ダッシュボード（`/`）

**完成扱い**（2026-07-31 ユーザー判断）。構成を変える提案はしない。以下は「なぜこうなっているか」の記録。
**2026-08-01 にユーザー指示で3段目（折れ線2枚）を足した** — こちらから盤面の入れ替えや増設を持ち出さない方針は変わらない。

### 盤面は 3:2 の3段構成

| 段 | 左 3/5 | 右 2/5 |
|---|---|---|
| — | KPI カード ×4（横一列） | |
| 1 | 皇帝ランキング（タブ3枚） | 死因 ＋ 即位経路 |
| 2 | 世紀ごとの即位人数 | 在位年数と死因 |
| 3 | 同時に帝号を持っていた人数 | 在位継続率 |

1段目は**左右の下端を揃える**。右列を `h-full` + `justify-between` にして、余った高さは
2枚のカードの「間」へ逃がす（カードの中に空白を作らない）。

### 確定している判断

- **内訳（死因・即位経路）は積み上げ1本帯（`CategoryBar`）× 2枚のカード。** ドーナツ案・タブ案は不採用
- **凡例は「1区分＝1行」の3列グリッド**（区分名・実数・割合）で左寄せ。
  両端揃えにするとカード幅ぶん離れて行が追えない。名前と数値を2行に分けた版は凡例だけで縦200px超使い、
  ランキングと高さが合わなかった
- **凡例に出す区分と帯のセグメントを必ず一致させる。** 上位N件だけ凡例に出して残りを描くと「凡例に無い区分」が生まれる
- **畳む位置は区分ごとに違う** — 即位経路は**8区分すべて出す**（末尾の「継承」17名・「内禅」14名で8.5%あり、
  畳むと分類そのものが見えない）。死因は上位5＋その他（末尾が自尽15・戦死7・事故死1と細い）。**どちらも上限は8**
- **ランキングはタブ切り替え**（在位期間・**親征回数**・**改元回数**）で、**タブは見出し「皇帝ランキング」の真横**。
  見出しの主語を切り替える操作なので、両端揃えでカード幅ぶん離すと結び付きが切れる。
  `TabsTrigger` は `TabsList` の中にしか置けないので、**見出しごと `Tabs` の中**へ入れてある
- **3枚とも上位10名ちょうど。** 同値でも枠は広げない（広げるとタブ切り替えでカードの高さが動く）。
  回数系は「日まで下りる」ような副次キーを持たないので、同値の順序は**在位日数→id**で一意にする。
  これは表示順を安定させるためだけの順序で順位の主張ではない。**この切り捨てで枠外に出る人数は指標ごとに違う**
  （2026-08-01 実測: 親征は10位が6回で同値4名のうち1名、改元は10位が7回で同値5名のうち**4名**が枠外）
- **回数系2指標は365名全員が母集団**（0回が実在する）。説明文に **1回以上／0回の内訳**を出す
  （親征112/253・改元332/33）。この人数は `topByValue` の `total` から取れない
  — `total` は「値が null でない人数」＝365名を返す（`computeRanks` の `isRanked` は0回を順位から外しており基準が違う）。
  **文言に数字を焼き込まず `records.filter(...)` で数える**（データ訂正で動くため）
- **親征・改元は下層の行き先を持たない**（`/database` に回数系の列が無い）ので `href` は `null`。
  在位期間だけ `/database?sort=reignApproxDays&order=desc` へ出す
- **タブの高さは固定しない。** タブごとに行数が違うので、いちばん多いタブに合わせると既定タブの下に空白が戻る
- **棒の長さは `ratio`（1位を1とした相対長）を使う。** `valueLabel`（「61年332日」）から数字を抜くと
  61332 と 5433 のように桁が揃わず、近い在位が10倍違う長さで描かれる
- **世紀は「即位した年」で数える。** 復位した皇帝は最初の即位で1回だけ。**空の世紀も0本として残す**（詰めると横軸の間隔が嘘になる）
- **2段目右は「在位年数 × 死因」の100%積み上げ（5行）。** 非業の死（暗殺・処刑・戦死・自尽）の割合が
  71 → 66 → 33 → 27 → 9% と単調に落ちる。**病死は隣の「死因」カードと同じ `--series-1`**
  （2枚のカードで同じ死因が違う色になると色が意味を失う）。不詳ほかは系列色を使わず灰＝「分からない」の枠
- **割合は帯の中でなく行見出しの右端**に出す（帯は高さ8pxで文字が入らない）

### ランキングタブの指標を年齢2枚から親征・改元へ差し替えた（2026-08-01・[Issue #28](https://github.com/kotenbu135/emperor-stats/issues/28)）

**年齢は比率尺度として扱えないので、ゼロ基線の横棒で描くこと自体が成立していなかった。**
棒の長さは `ratio = 値 / 最大値` で原点が0だが、即位年齢の実測は 68歳→53歳＝幅 1.00→0.78 で
10本がほぼ同じ長さに並び、右端の数字だけが情報を持っていた。しかも「53歳は68歳の78%」という比率に意味がない
（0歳で即位した人はいない）。在位期間タブが同じ描き方で正当なのは**在位0年が実在する**ため。

**棒の広がりは選定基準ではない** — 在位期間タブ自身の 10位/1位比は 0.73 で即位年齢の 0.78 とほぼ同じ。
判定は「比率尺度として成立するか」で行う。

落とした候補（365名全件で実測済み・再提案しない）:

| 候補 | 在位日数との相関 | 10位/1位比 | 信頼度 high の割合（1回以上） | 在位トップ10との重複 | 判定 |
|---|---:|---:|---:|---:|---|
| **親征** | **+0.11** | 0.40 | 63%（70/112） | **0名** | **採用** |
| **改元** | +0.51 | 0.50 | **92%**（304/332） | 2名 | **採用** |
| 大赦 | +0.62 | 0.49 | 85%（226/267） | 2名 | 改元と役割が重なり交絡が強い |
| 反乱鎮圧 | +0.51 | 0.27 | 未計測 | 1名 | 被反乱と r=0.96・史料粒度 |
| 被反乱 | +0.44 | 0.22 | 25%（low 4件） | 1名 | 史料粒度（下記） |
| 立后・遷都・皇太子廃立 | — | — | — | — | 値域が狭すぎる（最大8/3/4回・皇太子廃立は92%が0回）。10位が1〜3回で同値が並びランキングにならない |

- **親征**: 在位長との交絡がほぼ無い（r=+0.11）。隣に在位期間タブがある以上、r=0.44〜0.62 の指標を並べると
  「1枚目を別の単位で見せ直す」ことになる。在位トップ10との顔ぶれの重複が親征だけ0名なのはその裏返しで、
  盤面に新しい断面（北族と十六国が7/10）が出る
- **反乱系を採らない理由は史料粒度**。棒の広がりだけなら最良（0.22）だが、南宋高宗の被反乱114回は
  宋史が小規模な蜂起まで列挙するためで、十六国の君主とは記録の細かさが違う。データ側も `confidence: low` 2件・`medium` 7件
- **改元の説明文には「即位に伴う建元も1回に数える」を必ず入れる** — `eraChangeCount.count >= 2` の意味は
  「即位後に元号を変えた」であって「2回改元した」ではない（規約は [CHART_CANDIDATES_2026-07-31.md](CHART_CANDIDATES_2026-07-31.md)）

これは**タブの中身の差し替えであって盤面の構成は動かしていない**（3:2の2段・カード配置はそのまま）。

### 3段目に折れ線2枚を足した（2026-08-01 ユーザー指示・`/lab` の候補7・8を採用）

グラフ候補の検討面（`/lab`）で実物にした9件のうち、**同時在位数**と**在位継続率**の2枚を
盤面へ載せた。集計は `lib/lab-stats.ts` から **`lib/emperors.ts` へ移してある**
（`getConcurrentReigns()`・`getReignSurvival()`）。`/lab` はページごと畳む前提の面なので、
公開ページが `lab-stats` を参照したままにしない。表示部品も `components/home-v2/` 側にある。

- **横長の図を2枚とも3段目に置き、3:2 は崩していない。** 同時在位数が左（3/5）なのは
  横軸が2100年超あるためで、入れ替えると「前200」「1800」の目盛りが潰れる。
  継続率は横軸0〜50年なので 2/5 で足りる
- **どちらも線は1本**（2026-08-01 ユーザー決定）。`/lab` は2本ずつだったが、
  盤面には `/lab` の「但し書き」欄が無く、2本目の説明を置く場所が無い
- **同時在位数は「日付があればその日付、無ければ在位年」で区間を作る**（ユーザー指示:
  なるべく日単位、無理なら月、それでもだめなら年）。実データは374在位のうち324件が
  日まで、残り50件は片側または両側の日付が無い（月止まりの在位は無い）。
  **日付の無い在位を落とすと秦・新・317年の33年が0人に見える** — 折れ線では
  「皇帝がいなかった年」の嘘になるので、年で埋めて全374在位を区間にした。
  埋めは区間を伸ばす向き（開始側1月1日・終了側12月28日）なので**人数は上限側の見積り**
- **この埋め方でも最大は変わらず10人（618年11月26日）** — 618年の在位はすべて日まで
  下りているため。年単位で数えた「14人」は採らない（煬帝は4月に殺され、恭帝侑は6月に譲位している）
- **表示範囲は前221年〜1912年。** 袁世凱の洪憲（1915-16）と満洲国（1934-45）の隙間は
  収録基準の産物で歴史的空位ではないため切る。切ったあとに残る0人の年は
  前206〜前203年（楚漢戦争期）と7年（居摂）の5年だけで、これは実在の空位
- **継続率は全365名の1本**（`approxDays`＝年365換算の概算）。「日まで確定した270名」を
  重ねると曲線は上へ持ち上がるが、その線は**「どの人物の日付を復元できたか」の分布**を混ぜる。
  差は5年で6ポイントで、`/lab` の実装所見でも「図では小さく見え、表の数値のほうが差を伝える」
- **同時在位数の点は「顔ぶれが変わる年」だけ**（2133点 → 360点）。`stepAfter` は次の点まで
  値を保つので、描画は1年刻みと**ピクセル単位で同一**（撮り比べで確認済み）。捨てる理由は
  描画ではなくツールチップで、点が多いと Recharts が最寄りの点しか拾えない
- **人数ではなく顔ぶれで切る。** 人数が同じまま代替わりする段がある（隋の590〜616年は
  1人のまま文帝→煬帝と替わる）ので、人数で切ると段の途中を指したときに
  ツールチップの「誰が」が嘘になる。見出しも「590〜604年」と**段の範囲**で出す
- **ツールチップに在位者名を出す**（2026-08-01 ユーザー指示）。**名前の数は必ず人数と一致する**
  — 集計側が持たせているのは「その年でいちばん人数が多かった瞬間」の顔ぶれで、
  618年なら10名（その年に帝号を持った14名ではない。煬帝は4月に殺され、恭帝侑は6月に譲位している）。
  **表示名は `dynastyLabel()`** を通す — 政権と1対1であることをビルド時に検査している唯一の
  王朝ラベルで、隋末の梁2つ・楚2つもここで割れる（「梁・蕭銑」「梁・梁師都」）。
  10名並ぶ年があるので1行1名にはせず、折り返す1段落にまとめる
- **系列が1本のツールチップには系列名を出さない**（2026-08-01 ユーザー指摘「長くて野暮ったい」）。
  カードの見出しが同じことを言っているので「同時に帝号を持っていた人数 10人」と2度読ませることになる。
  1本のときは値だけを置く（`618年 / 10人 / 名前…`）。色の見本も区別する相手がいないので置かない
- **代替わりの日は次帝のものにする**（2026-08-01 ユーザー指摘「通常の帝位継承なのに2人に増える」）。
  データは**「前帝の崩御日＝次帝の即位日」**で入っている（光武帝 0057-03-29 崩御・明帝 0057-03-29 即位）ため、
  そのまま重ねると**通常の父子継承でその年が2人になる**。位が動いたのはその日の中の一点であって、
  2人が並んだ日ではない。対象は94在位で、**1日在位で末日を譲ると消えてしまう場合だけ残す**
  （金の末帝＝完顔承麟の1件。哀宗の自尽と同日に立ち同日に戦死しており、そもそも同日の2人）。
  **ピークは変わらない**（618年11月26日の10人）。1人だけの年は1320年→1340年（62%→63%）、
  5人の年は62年→47年に減る。**これはデータの訂正ではなく「同時」の数え方の定義**で、
  `data/emperors.json` には触っていない
- **同じ年に人数が並ぶときの取り方**: 604年は文帝の崩御と煬帝の即位が同年だが同時に並んでは
  いないので、最大人数は1のまま。同数のときは**先に立った側**を採るので604年は文帝になる
- **同一人物の在位区間が重なったら throw する。** 在位者集合は Set なので、復位者の区間が
  重なると1人のまま先に来た終了で消える（現状の8名はどれも重なっていないが、静かに壊れる形）
- **全体表示ではホバーで年を1つずつ指せない。** 描画幅609pxに対し横軸は2133年で
  **1px＝3.8年**。隋末〜唐初は毎年段が変わる区間なので、実測すると `617年` の次が
  `623〜624年` に飛び、**618〜622年は1pxに潰れて到達不能**（点を間引いても消えない。
  609通りしか指せる位置が無いため）。**図の主張になっている値はツールチップに頼らず
  図の上へ焼き付ける** — `line-chart.tsx` の `markers`（`ReferenceDot` ＋ `Label`）で
  ピークに「618年11月26日 10人」を出してある。**`Label` には `stroke="none"` が要る**
  （親の `ReferenceDot` の stroke を文字が受け継ぎ、塗り無しの袋文字になって読めなくなる）

#### 拡大（2026-08-01 ユーザー決定・「このままでは受け入れ水準に満たない」）

上の解像度の制約への答えが拡大で、**範囲を絞れば1年ずつ読める**（隋末12年なら1年50px）。
入口は2つあり、**ドラッグは近道・時代プリセットが本線**:

- **図の上をドラッグして範囲選択**（`onDragZoom`）。**マウス専用**で、タッチではページ
  スクロールと競合し、キーボードでは操作できない。これ単独にしないこと
- **時代プリセット**。**畳んでポップオーバーで開く** — 横一列のピルは 1440px でも11個しか
  入らず（一覧の時代ジャンプバーが 2026-07-31 に同じ理由でこの形へ変わっている）、
  縦スクロールの中に横スクロールの帯を作ることになる
- **プリセットの時代ラベルは `ERA_BY_SECTION` の15区分**（`eraPresets`）。`catalogs.eras` の
  11区分でも新しい呼び名でもない — **同じ物に3つ目の呼び方を作らない**。年の範囲は
  レコードの実測値で、表示範囲の上限1912年で頭を切る（清は溥儀の満洲国で1945年まで伸びる）
- **ドラッグの両端はピクセルから値へ直す。** Recharts の `activeLabel` は最寄りの点へ
  吸着するので、点が疎な区間（14〜16世紀）では選んだ範囲と数十年ずれる
- **ドラッグ中の帯は Recharts の外にオーバーレイで描く。** 中の `ReferenceArea` にすると
  マウスが1px動くたびに360点の折れ線ごと再描画される。あわせて**チャート本体を
  `useMemo` で固めてある**（`band` を依存に入れると意味が無くなる）
- **拡大時は `allowDataOverflow` が要る**（既定では `domain` を無視して全部描く）。

## 6. データベース（`/database`）

**全365名を表形式で見せる面。** `/reign` の内容（在位ランキング・復位表）はここへ吸収した。

### パスを `/database` にした理由

`/data` は使えない。`scripts/build-data-distribution.mjs` が配布用データを `public/data/` へ
書き出しており、`output: "export"` では `out/data/` で衝突する。

### 列

| 列 | 揃え | 並べ替え | 備考 |
|---|---|---|---|
| 皇帝 | 左 | ○ | 個別ページへのリンク。**非表示にできない**（行の主語が消えるため） |
| 王朝 | 左 | ○ | |
| 在位期間 | 右 | ○ | **並べ替えキーは最初の在位の開始年**（`firstStartYear`）。「前221–前210年」は文字列として並べても年代順にならない。数値列だが1回目のクリックは**昇順**（年代順が自然な向き） |
| 在位年数 | 右 | ○ | **並べ替えキーは日数**（`reignApproxDays`）で表示は `reignDurationLabel`。表示文字列で並べると `9年` > `61年` になる |
| 即位経路 | 中央 | ○ | 表示は短縮形（`shortCategoryLabel`）。全文は `title` |
| 死因 | 中央 | ○ | |
| 即位年齢 | 右 | ○ | 不明は `—`。`accessorFn` で `undefined` に落として `sortUndefined: "last"` へ委ねる（`null` のままだと 0 相当で先頭に来る） |
| 没年齢 | 右 | ○ | 同上 |

**揃えは `ColumnMeta.align` の一点から見出しとセルの両方へ当てる**（片方だけ動かすと見出しが
列の上に乗っていないように見える）。左＝読み始めをそろえる名前・王朝、右＝桁が縦にそろう
年・年数・年齢、中央＝2〜4文字の区分名（左右どちらに寄せても短い語が壁から浮く）。
右寄せの列だけ並べ替えの矢印を見出しの左に置く（右端は数値の揃え位置なので、
そこに記号を挟むと桁の縦線が濁る）。

**復位者の在位期間は「最初の期間＋ほか2期」の2行**にする（2026-07-31 ユーザー指示）。
宣統帝の「1908–1912年 / 1917年 / 1934–1945年」を1行に出すとこの1名が列幅を決めてしまい、
357名の「1850–1861年」型に対して2.5倍を専有する。全期間は `title` と読み上げ用テキストに残す。
該当は8名（`reignCount >= 2`）。

**即位経路の「受禅（易姓）」「継承（経緯記載なし）」は括弧を落として出す**（2026-07-31 ユーザー指示）。
この2つだけが突出して長く、列幅を押し広げていた。短縮規則 `shortCategoryLabel()`（`lib/emperor-types.ts`）は
概要ダッシュボードの内訳凡例と共用。**括弧の中身は分類の根拠**（「経緯記載なし」＝原典が書いていない）
なので `title` に全文を残し、検索は短縮形・全文のどちらでも当てる。

### 既定順は在位開始年の昇順（2026-07-31 ユーザー決定）

`data/emperors.json` の**収録順は年代順ではなく調査ブロック順**で、ブロック内は
「正統政権を全部置いてから並立政権・対立皇帝を後ろにまとめる」並びになっている。
そのまま出すと**呉周（1678–1681）が清の宣統帝（〜1945）の後ろに来る**ような、
先行政権の在位年幅に入れ子なのにその後ろへ置かれる箇所が**20件**生じる
（最大は呉周の264年、次いで武周202年・赤眉軍193年・張邦昌152年）。

`getEmperorTableRecords()` で**最初の在位の開始年**で並べ直す。同年は収録順で安定させる。
`meta.catalogs.regimes.sortOrder` で並べても呉周は動かない（sortOrder が既に清の後ろ）ので、
この案は採らなかった。**収録順そのものは変えていない** — `/emperors` 一覧と個別ページの
前後ナビは従来どおり収録順。

**時代と在位回数は列に出さない**（2026-07-31 ユーザー指示）。どちらも絞り込みには残してある —
時代は王朝の上位区分で王朝列から概ね読め、在位回数は2以上が8名しかおらず1列を専有するに
見合わないため、選ぶ側だけ残した。`EmperorTableRecord` は両フィールドを持ち続ける（絞り込み専用）。

絞り込みは検索（空白区切りの AND・**表に出ている値＋諱**が対象）・時代・王朝・在位回数（復位した皇帝だけ）。
諱は列に出ていないが同一人物の別名なので、当たっても「なぜこの行が残ったか」が分からなくならない
（時代・在位回数を検索対象から外したのはここが違う — あれは行の属性で、見えないまま当たると理由が読めない）。
**問い合わせ側だけでなく対象側も NFKC 正規化する** — 片方だけだと「継承（経緯記載なし）」のような
全角括弧を含む語がどうやっても当たらない（NFKC が全角括弧を半角へ畳むため）。
**在位年数の降順ソートが旧 `/reign` の在位年数ランキング**にあたり、**「復位した皇帝だけ」が旧復位者一覧**にあたる。
復位の経緯（旧 `RestorationRow.restorationReasons`）はこの表には持ち込んでいない — 個別ページの担当。

### 判断の記録

- **並べ替えと列の表示切替は TanStack Table、絞り込みは素の `useMemo`。**
  検索は「空白区切りの全語がヒットした行だけ残す」AND だが、TanStack の `globalFilter` は
  列ごとに評価して OR で畳むためこの意味にならない（「唐 病死」のような列を跨ぐ組み合わせが落ちる）
- **列は主要項目だけ（8列）。** 列数は `DATABASE_COLUMN_COUNT`（`lib/emperor-types.ts`）が単一情報源で、
  OGP画像の事実カードがこの値を出す。`COLUMNS.length` との突合 assert があり、列を増減すると
  ビルドが落ちる。全12項目を並べない。回数系8指標（改元・大赦・立后・皇太子廃立・
  親征・反乱鎮圧・被反乱・遷都）は列にしていない。詳細は行から `/emperors/[id]` へ送る
- 表の**見た目は Tremor Blocks の表を参照**したが、**部品は shadcn の `ui/table.tsx`**。
  vendored の `tremor/Table.tsx` は見た目だけの部品なので TanStack と組む相手としては等価で、
  新しく Tremor 依存を増やす理由がない。ただし `Table` ラッパーだけは使っていない —
  内側に `overflow-x-auto` の div を固定で持っており、**この箱の overflow を状況で
  切り替えられない**（下の「見出しの固定」の項）
- **`EmperorListRecord` を流用しない。** 表が描く列＋絞り込みに要る値だけを持つ
  `EmperorTableRecord` を新設した。実測: `/database` の RSC ペイロードは 132KB で
  `/emperors` の 188KB より小さい
- **縦スクロールはページに一本化する（2026-07-31 ユーザー指示・2重スクロールを避ける）。**
  表の枠は当初 `max-h-[70dvh]` で縦にも止めていたが、ページのスクロールバーと二重になり
  「どちらを動かしているのか」が手元で分からなくなるため撤回した。365行はページに素直に流す
- **横スクロールは表の中だけ。** 8列の自然幅は約858px（在位期間の2行化と即位経路の短縮で
  1066px から縮んだ）。**1200px 以上の画面なら収まり**、1180px 以下でははみ出す
  （本文列の幅＝画面幅−332px：サイドバー240px＋左右の余白92px）。
  枠の中で流し、**ページ本体は横スクロールさせない**（実測で確認済み）。
  右端のフェードと「横スクロールで続き →」で続きがあることを示す。左端のフェードは出さない
  （固定した先頭列の皇帝名にかぶるため）
- **見出しの固定は「表が枠に収まっている幅」だけ。** `overflow-x: auto` を当てた箱は、
  縦に溢れていなくても**スクロールコンテナ**になり、`position: sticky` の基準が
  ビューポートからその箱の中の縦スクロール（存在しない）へ移る。結果、見出しは固定されず
  ただ流れ去る（実測で確認。`overflow-y: clip` を併せても変わらない）。
  そのため**収まっている間は `overflow-x: clip`**（スクロールコンテナを作らない）にして
  見出しをページ基準で `top: var(--chrome-top)` に貼り付け、**溢れた幅でだけ `auto`** に切り替えて
  横スクロールを許し、そのときは見出しの固定を諦める。判定は `<table>` の実幅と枠の
  `clientWidth` の比較で行う（clip のとき枠の `scrollWidth` は `clientWidth` と同じ値を返すため、
  枠側では測れない）。列を隠して収まれば固定は復活する
- **1180px 以下では横スクロールバーが表の最下端（＝ページの最下部）に付く。**
  枠に高さの上限が無くなったため。ホイール横送り・トラックパッド・タッチでは動かせるが、
  マウスでバーをつかむ操作だけは実質できない。さらに詰めるなら狭い幅で列を既定で隠す案
  （`列` から戻せる）だが、既定で情報を隠す判断なので保留している
- **朱の色味は見出し帯だけに置く。** 地に `color-mix(in oklch, var(--seal) 7%, var(--card))`、
  下端に2pxの朱線（2026-07-31 ユーザー指示・画面に色味が無いため）。
  **半透明（`bg-seal/7` 等）にしないこと** — 行が見出しの裏を通り抜けるので地色は不透明でなければならない。
  線はすべて inset shadow で描く（border-collapse の表では sticky にした th の border がスクロール時に消える）
- **365行を一度に描く。** 仮想化は入れていない（実測してから決める方針）
- lint の warning「Compilation Skipped: Use of incompatible library」は既知で消せない。
  `useReactTable()` が毎回新しい関数を返すため React Compiler が自動メモ化を諦める

### URL 同期

`?q=` `?era=` `?dynasty=` `?reign=restoration` `?sort=<列id>&order=asc|desc` を持つ。
**旧 `/reign` の2本のリンクの着地点**として要ったため、`/reign` の廃止と同時に入れた。
復元は hydration 不一致を避けてマウント後の effect で行い、書き込みはマウント直後の1回だけ
スキップする（`/emperors` のグリッドと同じ形）。`?sort=` は `COLUMN_IDS`（`COLUMNS` の
id/accessorKey から作る集合）で照合してから state に入れる — 実在しない列 id を渡すと
TanStack が無言で並べ替えを落とすため。

**3:4 なのは肖像ではなくカード全体**（肖像＋名前・王朝・在位期間）。
それまでは肖像だけが3:4で、そこに文字ブロック68pxが丸ごと足されてカード全体は3:5になり、
1440pxの1画面に**2行＋αしか入らなかった**（実測12.7人）。比率をカードへ移して15.6人。

| 幅 | 列 | カード | 肖像枠の比率 | 1画面 |
|---|---:|---|---:|---:|
| 1920 | 6 | 190×253 | 1.03 | 22.1人 |
| 1440 | 5 | 212×283 | 0.99 | 15.6人 |
| 768 | 2 | 213×284 | 0.99 | 6.2人 |
| 390 | 2 | 160×213 | 1.11 | 6.6人 |
| 320 | 2 | 125×167 | 1.28 | 6.0人 |

**肖像側を固定比にせず、カードを3:4にして余りを肖像へ渡している。**
文字ブロックの高さは幅に比例しない（3行の行高で常に68px）ため、肖像を固定比にすると
狭い画面ほどカードが縦に伸びる。この持ち方なら肖像枠は 0.99〜1.11 のほぼ正方形に収まる
（320pxだけ1.28まで横長になるが、下限として許容する）。実装は Link を `flex aspect-[3/4] flex-col`、
肖像を `min-h-0 flex-1`、文字を `shrink-0`。**`min-h-0` を外すと flex の既定 `min-height:auto` で
肖像が縮まず、カードが3:4を超えて伸びる。**

**jpg/webp は切り直していない**（実体は 360×480＝3:4 のまま）。枠が実体より横長のあいだ
`object-cover` は縦だけを切るので、**どこを切るかを決めさえすれば切り直した場合と同じ絵が出る**
（撮り比べで確認）。むしろ実体を正方形に詰めると、枠が1:1より縦長になる幅で左右が切られて顔が欠ける。
実体を全ての枠より縦長に保つ＝縦切り一本にする、が安全側。詳細ダイアログは3:4のまま出すので、
詰めると下1/4がどこにも出なくなるという損もある。

**「カード全体を3:2」は不成立として落とした。** 文字ブロック68pxが幅に比例しないため、
縦積みだと肖像が 1440px で73px（2.9:1）・1920px で58px（3.3:1）・390px で**38px**（4.2:1）の帯になる。
撮り比べで昭帝・元帝・成帝が何の絵か判別できなくなることを確認した。
横並び（肖像左・文字右）なら3:2は成立し密度も最大（約30人）だが、文字が下でなくなり
5列では名前が「二世皇帝…」と切れるため採らなかった。

### 顔の位置は1枚ずつ決める（2026-07-31 ユーザー指摘）

**「上寄せ」という固定ルールが不格好の原因だった。** 比率を3:4にした直後は `object-top` のままで、
題字が上端に入る版本（三才圖會の「漢武帝像」など）や顔が中央にある元の御容は、
題字と余白が枠を占めて**顔が下半分に沈んでいた**。切る位置は絵ごとに違うので固定ルールでは決まらない。

肖像 `manifest.json` の各エントリに **`focusY`（顔の中心が画像の上端から何割か・0〜1）** を持たせ、
`portrait.tsx` の `focusObjectPositionY` が `object-position` の Y へ直す。
**値は144枚を1枚ずつ実見して入れた**（10%刻みの目盛を重ねたコンタクトシートから読む）。
肖像を足したら `focusY` も入れること — 欠けるとビルドが落ちる（`emperors.ts`）。

- `focusY` ≲ 0.26 は変換後が0に丸まり従来どおりの上寄せ。**顔が沈んでいる肖像だけが動く**
- `focusY` ≳ 0.51 は下寄せでも狙いに届かない（webp の下端が既に切れている）。
  該当が出たら jpg から切り直すのが筋だが、145枚では発生していない
- 枠の比率は幅で 0.99〜1.28 と動くが、代表値1.0で出した値を他へ持って行っても顔は数%しかずれない

**同じ作業でカード表示のまま全件を見直し、場面図・群像図5件と判読不能1件を除外した**
（150→144枚）。判定基準は2026-07-21のQAと同じ「どの人物が該当人物かを画像から特定できない」で、
題字で特定できるもの・帝王図巻のように主人公が明らかに大きいものは残している。
一覧が肖像なしのカードは 215→221枚（59%→61%）。除外の一覧は [PORTRAITS.md](PORTRAITS.md)。

### 時代ジャンプバー（2026-07-31 ユーザー決定）

**横スクロールをやめ、「押したら開く」形にした。**
それまでは15時代を丸ピルで横一列に並べていたが、**1440px でも11個しか入らず**
（`scrollWidth 1390 / clientWidth 1015`）、390px では3つ。縦にスクロールするページの中に
横スクロールする帯があるのは、`/database` の表で避けたのと同じ形だった。

いまはバーに**現在地の1つだけ**を出し、押すと15時代を2列のポップオーバーで一覧する
（どの幅でも全部が一度に見え、縦にも横にもスクロールしない）。バーの高さは48pxのまま。
現在地が未確定のあいだは先頭の節を出す — 空文字で出すとトリガーの幅がゼロから実幅へ跳ねて CLS になる。

この変更で `HorizontalScrollHint`・`VerticalScrollHint`（端フェードの描画部品）の
呼び出し元が全部消えたので削除した（`useHorizontalScrollEdges` は `/database` が使うので残る）。

### 画面上端に固定される帯

モバイルはサイトヘッダー（`--chrome-top` 56px）＋ ジャンプバー（`SECTION_NAV_H` 48px）＋
時代見出しの sticky（`BELOW_SECTION_NAV`）で最大3段。`/database` は sticky の基準を
`--chrome-top` 一本にしたが、**この面は `BELOW_SECTION_NAV` という2本目の基準を持つ**
（ジャンプバーの下に見出しを貼るため）。統一していないのは意図的で、`BELOW_SECTION_NAV` は
`--chrome-top` から計算する式なので二重管理にはならない。

### 肖像そのものの質はそろわない

彩色の絹本・白黒の線画・版本のページ（縦組みの文字が写っている）が隣り合う。145枚は
PD/CC0 の制約下で集めた実物で、切り抜き・トリミングの作り直しはデータ側の作業。
**枠の中で揃えられるのは背景・余白・比率まで**で、絵柄の統一は約束しない。

### 在位中の出来事は先頭20件＋素の `<details>`（2026-08-01 ユーザー決定）

件数は中央値9件だが**最大223件（宋高宗）**・100件以上3名・50件以上21名・20件以上102名。

### 紹介文（GitHub Issue #16）

> SEO対策として皇帝名でWeb検索をかけたときに皇帝の紹介文が検索結果に出るようにする。
> 一人ずつ作成する。他サイトからのコピペ禁止。

- **格納先は `data/emperor-profiles.json`（新設）。** `data/emperors.json` に足さないのは、

  並行セッションの read-modify-write と衝突し、CC BY 4.0 の配布物の中身も変わるため
- **2フィールド**: 本文用 `lead`（200〜300字）と、`description`（検索結果・OGP に出る1文・120字前後）。

- **未執筆でもページが成立する。** 着手時点では365人中ほぼ全員が空なので、`lead` が無ければ節ごと出さず、

## 9. このサイトについて（`/about`）

サイトで唯一の**記事型ページ**。収録基準・各項目の数え方・典拠史料・データ配布（CC BY 4.0）・正誤表・
肖像画の出典・関連動画・運営者・免責の9節を持つ。

**文章はほぼそのまま**（ユーザー指示）。作り替えたのは組み方だけで、実際に変えたのは次の1文だけ:
「各**グラフ**で「0回」の皇帝は…」→「各**項目**で…」（集計グラフを載せていた統計5面を同日廃止したため）。
残りの本文にはもう廃止ページへの言及は無い（URL・機能名の両方で確認済み）。

### 組み方

| 何を | どう |
|---|---|
| 本文列 | **読み物幅 `max-w-3xl`（768px）**。データページの `max-w-content`（1200px）ではない。`ARTICLE_WIDTH` が単一情報源で、`PageHeader` の `containedWidth`・`SectionJumpNav` の `innerWidth`・各 `Section` の `containedWidth` に同じ値を渡す |
| 本文の級数 | **16px・行間 1.75**（`text-base leading-7`）。データページの 14px ではない。導入だけ md 以上で 18px |
| 節へのジャンプ | `SectionJumpNav`（`/emperors` と共用）を9節で使う。**目次として上から読ませたいので `popoverColumns={1}`**（既定の2列は15時代を1画面に収めるための形） |
| 各項目の数え方（11項目） | 用語を左の桁に出す**定義リスト**。元は項目ごとに h3 ＋ 段落を積んでいて、どの項目があるか一覧できなかった |
| 配布ファイル3本 | カード。押せる場所が文の途中（ファイル名だけ）にあり、サイズが括弧に埋まっていたのを直した |
| 正誤表 | 日付を左の桁に固定した2列 |
| 肖像画クレジット145件 | **素の `<details>`** で畳む |

**畳んでよいのは肖像画クレジットだけ。** 数え方11項目を Accordion にすると閉じている本文が DOM から消える
（`ui/accordion.tsx` は radix で `forceMount` を渡していない）。この節はサイトで唯一「数え方」を書いている
場所で、フッターからも「収録基準・数え方・出典の詳細」として名指しでリンクされている。
静的書き出しに本文が載っているかは `grep 大赦天下 out/about.html` で確かめられる。

### 節の id は外部契約

`#operator` は `lib/seo.tsx` の `OPERATOR_ID`（JSON-LD の Person ノードの `@id`）、`#dataset` は
`DATASET_ID` が指している。9つ（criteria / counting / sources / dataset / errata / portraits /
videos / operator / disclaimer）はどれも変えないこと。**id は見出しではなく節の本体（`<section>`）に付ける**
— 見出しに付けると `SectionJumpNav` の現在地判定（IntersectionObserver）が節を拾えない。

ページ丈は 1440px で約6650px・390px で約11800px。節へのジャンプは「節の上端＝固定バーの下端」に
着地すること（`Section` の `scrollMt` に `BELOW_SECTION_NAV` を渡していないと見出しがバーに隠れる）。
