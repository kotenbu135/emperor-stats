## 確定方針（2026-07-25）

- **構成**: 章スタック（1枚SVGにはしない）。時代ごとの章を縦に積み、時間は章をまたいで
  下へ連続。章ごとに独立SVG＋独立`<Section>`。交差問題は章内に閉じ込める。
- **当面のスコープ**: 五代十国まで。有効化する章は6つ:
  `qin-han`（済）→ `sanguo-xijin` → `dongjin-shiliuguo` → `nanbeichao` → `sui-tang` →
  **五代十国だけの章**（後述の分割）。宋遼金西夏以降は生母データ未完のため保留。
- **作業単位**: 1章ずつ・時代順。次は `nanbeichao`（南北朝）。
- **公開**: 五代十国まで揃うまで noindex 維持（`nav-data.ts`/`SITE_SECTIONS` 未登録）。
- **五代十国の章境界**: 章枠 `wudai-song` は「五代十国＋宋遼金西夏」を束ねている。
  データ完了線に合わせ **五代十国だけの章に分割**し、宋遼金西夏は後日の別章にする。
- **並立が多い章（十六国・南北朝・十国）**: まず横スクロール許容で素直に並べ、
  破綻したらその章だけ群雄をクラスタ化する。
- **各章の完成基準（DoD）**: `npm run build` 緑（4ゲート通過）＋
  `python3 scripts/validate_kinship.py` 緑＋目視で下記「規範」遵守。

## 配色

- 主要王朝は `--series-1〜8`（globals.css）を **章内で使い回す**（章は視覚的に分離するので
  スロットの意味が章ごとに変わってよい）。`KINSHIP_COLOR_BY_DYNKEY`（chapters.ts）で割当。
  **未登録は灰へ silent fallback（throwしない）** ので、章追加時は全dynastyKeyへ意図的に割当てる。
- **群雄・並立政権は専用の1色に統一**（灰は非皇帝の破線ピルと紛らわしいため廃止）。
  `--series-1〜8` と被らない **専用トークン `--kinship-minor` = くすんだ藤(#8d7c94)** に確定
  （globals.css）。スレート青は qin-han の新=青(slot1)と干渉するため回避。全時代の群雄に共通適用。
  ※非皇帝のつなぎ人物ノードは従来どおり灰＋破線（皇帝カプセルは実線＋藤色で区別可）。
  nodeFill/nodeEdge は kind===person を先に灰へ分岐してから colorSlot===0 を藤色にする
  （人物ノードが藤色にならないように）。

## レイアウト規範（全章で一貫適用）

- カプセル高さ＝在位期間／破線枠＝非皇帝つなぎ人物／丸枠＝配偶者（相手の在位に整列）。
- **生母の連結線**: 夫にattachする母が1人なら夫カプセルの上下中央から、2人以上なら上下対称に
  振り分ける（`consortCountByHusband` 判定。`CONSORT_BOTTOM_ATTACH` で個別に下辺指定）。
- 王朝内の継承＝カプセル内「第N代・即位経路」表記。**矢印は王朝間の交代（受禅・簒奪など）だけ**。
  - 図中の経路名は括弧の限定を落とした短縮形（`受禅（易姓）`→`受禅`、`継承（経緯記載なし）`→`継承`。layout.ts の `shortCategory`）。2026-07-26の多軸化で語が2字から6〜10字に伸び、幅96pxのカプセルから溢れる／矢印ラベルが両端のカプセルに埋もれて読めなくなったため。正式名はツールチップ・凡例・統計ページに出す。
  - **矢印ラベルは〔形式〕＋〔続柄は例外時のみ〕**（ユーザー確定・2026-07-26。`arrowForm`）。
    矢印が指すのは「位がどんな形で移ったか」という2政権間の出来事で、カプセル2行目（新帝個人の
    即位経路）とは役割が違うのに同じ語が出ていた。形式は**新帝の補助1 `procedure`** から決める:
    `禅譲儀礼`→**禅譲**（矢印は先帝→新帝の向きなので渡す側視点の語。正式名 `受禅（易姓）` は
    ツールチップ1行目に出る）／`偽詔・矯詔`→**矯詔の禅譲**（隋恭帝侗→王世充だけが該当し、
    他の禅譲と同じ表記に潰れていた）／`儀礼なし・自称`＋軸2に`本人`→**簒奪**／それ以外は
    `category` の短縮形（擁立・世襲・推戴・復位）。続柄は**子・無血縁・その他・不明を出さない**
    （王朝をまたぐ23本中10本が同じ「受禅・無血縁」で、情報量のある外戚4・同族1・母1が埋もれていた）。
  - **矢印を出すかどうかを決める「王朝コンテキスト」は、人物ノードも自分の section で解決する**
    （`dynContext`。ユーザー指摘・2026-07-26）。複数王朝を束ねたバンド（燕＝前燕/後燕/西燕/南燕）で
    バンド先頭の dynastyKey に固定していたため、**慕容泓〔西燕初代・人物ノード〕→慕容沖〔西燕2代〕**が
    前燕→西燕の交代と判定されて赤矢印が出ていた。同一政権内の継承なのでカプセルの「第2代・擁立」で
    足りる。修正後、第3章の矢印は東晋安帝→桓玄の禅譲1本だけになる（十六国の建国者はすべて
    自立・推戴＝根ノードなので、そもそも交代矢印を持たない）。
- **皇帝カプセルの1行目は「皇帝号・通用名」**（`二世皇帝・胡亥`）。通用名は /emperors の
  一覧カードと同じ導出（`lib/card-subtitle.ts` の `cardSubtitleOf`。諱の括弧前を取り、皇帝号に
  含まれていれば出さない。遼の漢風名・清の諱などは人物別上書き）で、`KinshipSourceEmperor.subName`
  として渡す。**カプセル幅は固定（`EMPEROR_W`=96px）なのでパッキングには影響しない**が、
  1行目は11pxなので**8字を超える併記はカプセルに出さずツールチップだけに出す**（女性皇帝の
  「♀」も1字ぶん数える）
  （`LABEL_CHAR_W`。第1〜4章では139人中124人が併記され、`廃帝・東昏侯・蕭宝巻` のように
  `displayName` が既に「皇帝号・別号」を中黒でつないでいる15人が溢れる側）。
  **ツールチップ（`empTip.name`）は幅に余裕があるので常に併記**する。
  `emp.name` 自体は書き換えない — `nameOf()` 経由で矢印ツールチップ・「父：」「母：」行・
  品質ゲートのメッセージにも出るため、そこまで併記になるとノイズになる。
- 二重線＝皇后との夫婦／細線＝妃嬪等の生母／点線＋?＝諸説あり。
  **子の垂下線は二重線の「下側の線」から出す**（中心から出すと2本の線の間から子が生えて
  見える。ユーザー指摘・2026-07-26）。二重線の間隔 `TIE_DOUBLE_GAP` は layout.ts が持ち、
  描画側（kinship-chart.tsx）と共用する。
- **図の下端・年目盛りは「実際に描かれたノードの下端」で決める**（`bottomPx`）。パッキングが
  出した占有区間の最大（旧 `maxEff`）は自動配置の値なので、手動配置の章では実配置よりずっと
  下になる（第4章は目盛りが650年まで伸び、589年より下が空白だった）。
- **図の上端も同じく「実際に描かれた一番上の要素」で決める**（`viewTop`）。`M_TOP`＋圧縮領域
  `preH` は自動配置の祖先の年から決まるので、手動配置の章では図の頭に空白が残る
  （第1章133px・第2章98px・第3章65px・第4章50px。ユーザー指摘・2026-07-26）。
  **座標は動かさず SVG の viewBox で切り落とすだけ**にすること — manual-layout.json は
  y を年で持つので上下シフトしても壊れないが、編集モードのハンドル・スナップ・
  年ラベルのstickyオーバーレイまで一斉に直す必要が出る。viewBox を切る方式なら
  ドラッグ量は差分計算なので影響なし、直すのは**年ラベルの `top` から `viewTop` を引く1箇所だけ**。
- **凡例は図版**（`components/kinship/kinship-legend.tsx`）。以前は長い説明文を各章の下に
  置いていたが、読まれない長文より図で示すほうが伝わる（ユーザー指示・2026-07-26
  「凡例の文章は廃止 図で表す」）。色・線幅・破線は `lib/kinship/style.ts` をチャート本体と
  共用するので、**凡例だけ古くなることがない**。ページ先頭に1つだけ置く（章ごとの繰り返しはしない）。
  **既定は閉じる**（`details`。図が主役で、凡例は必要なときだけ開く。ユーザー指示・2026-07-26）。
  補足の文章行（縦スケール・ツールチップの案内）は同日の指示で削除した — 縦スケールは
  「縦の長さ＝在位期間」の年グリッドが図として示している。凡例の交代矢印のラベルは
  **図中の矢印と同じ語**（`禅譲`。カプセル2行目の即位経路 `受禅` とは別語なので、凡例の
  カプセル例には `受禅` を使わない）。
- **ページ文言は最小限**。ページ説明は1文（「皇帝間の血縁や王朝間の交代の系譜関係を表しています。」）、
  章の説明は**掲載範囲だけ**（「秦（始皇帝）から後漢（献帝）までの系譜」）にする
  （ユーザー指示・2026-07-26）。章の範囲は手書きせず**章の皇帝の実データから導出**する
  （`KinshipChapterLayout.range`。最も早く即位した皇帝→最も遅く在位を終えた皇帝。
  収録追加や章の増減で説明文だけ古くなるのを防ぐ）。
- **章ジャンプは画面上部に固定**（`components/kinship/kinship-chapter-nav.tsx`）。時代が
  下るほど1章が縦に長くスクロールが大変なため（ユーザー指示・2026-07-26）。
  - **sticky が効く範囲は親要素の箱に限られる**ので、ヘッダー用 div の中ではなく
    **章と同じ最上位の並び**に置くこと（div の中に入れると、その div が画面外へ出た時点で
    固定が外れる）。z順は 固定バー `z-30` ＞ 図の年ラベル `z-20` ＞ 端フェード `z-10`、
    ツールチップは `z-50` なので固定バーに隠れない。
  - **見た目はボタン（丸ピル）**にする。テキストリンクだと押せることが伝わらなかった
    （ユーザー指摘）。現在の章はハイライトし、判定はサイドバーメニューの `useActiveSection` と
    **同じ IntersectionObserver・同じ帯（`-20% 0px -55% 0px`）**にして両者の強調をずらさない。
  - **バーの高さ（`KINSHIP_NAV_H`）と章の `scroll-margin-top` を必ず同じ値にする**。大きいと
    ジャンプ後の画面上部に前の章の横スクロールバーが覗き、小さいとバーに隠れる
    （`Section` の `scrollMt` prop。他ページの既定は `scroll-mt-20`）。
  - **章は左サイドバーのメニューにも他ページのセクションと同じ形で並べる**（`nav-data.ts` の
    `items`）。ラベル・idは `KINSHIP_ENABLED_CHAPTER_IDS` から導出し、章を増やしても
    メニューだけ古くならないようにする。
- **横スクロールできることは端のフェードで示す**（`kinship-chart.tsx`）。図が枠で切れているのか
  続きがあるのか分からない、というユーザー指摘（2026-07-26）。スクロール位置に応じて
  出し入れし、**続きがある側だけ**を光らせる（右端には「横スクロールで続き →」のバッジも出す）。
  state は端をまたぐ瞬間しか変わらないので、スクロール中の再レンダリングは起きない。
- **実線＝血縁・破線＝養子縁組**（ユーザー確定・2026-07-25）。家系図のどこにぶら下げるか
  （＝垂下線の構造）は帝位・家督の継承側で決める（養子は養家の家系図に入る）ため、主親が
  養父の子は**垂下線が破線**になり、実父へは別に**実線の補助線**を引く（司馬攸＝司馬昭の実子・
  司馬師の嗣子、曹芳＝曹楷の実子・明帝の養子、石虎＝石寇覓の実子・周曷朱の養子）。
  **破線の垂下線にはツールチップを付ける**（養子縁組の典拠が読めないと関係が分からない。
  実線＝血縁の垂下線には付けない）。`KinshipDropOut.tipLines`。
- **遠祖の系譜主張＝皇帝カプセルのツールチップに全文**（`wrap`。グラフ内バッジ・末尾一覧はしない）。
- バンド見出し・王朝見出しは補助線・矢印より後に描画し、**ハローで交差線を隠す**。
- 縦1年＝8px の等間隔（`PX_PER_YEAR`）。章頭以前の祖先は圧縮領域（`PRE_RATE`＝2px/年）に置く。
  **圧縮領域の人物ピルは年空間の占有を 4倍（`PX_PER_YEAR/PRE_RATE`）にする**（`tree.ts`の
  `yearSpan`。ピル高は固定なので、年で非重複でも実描画では重なる。章頭が祖先より
  ずっと後になる章ほど効く）。
- **「第N代」は調査済み `reigns[].dynastyOrder` が最優先**、無い在位だけ在位開始順から導出する
  （`emperors.ts`）。dynastyOrder は王朝自身の代数で、皇帝収録者だけを数えた導出値とは
  一致しないのが普通（前涼張祚＝涼王を含めて第7代・成漢李雄＝第3代・前秦苻健＝第2代、
  同年即位が複数いる後趙349年や西燕386年は startDate が揃わず機械ソートでは前後が入れ替わる）。
  整合性チェックは「同一王朝内で第N代が重複しないこと」だけなので、**値が一意でありさえすれば
  誤った dynastyOrder は素通りする**（旧来の「導出値と一致」assertは廃止）。
  **null の意味は王朝単位で変わる**（2026-07-25 確定）: 同じ王朝に1つでも調査済みの値があれば
  null は「歴代に数えない在位」（宋の元凶劭・梁の侯景政権・北魏の南安王余など）を意味し、
  第N代を出さずに即位経路だけを表示する。全在位が null の王朝（＝未調査）のときだけ在位開始順から
  導出する。以前は混在王朝でも導出で埋めていたため、宋（元凶劭＝4が孝武帝と）・梁（侯景政権＝2が
  簡文帝と）で「第N代が重複」してビルドが落ちた。
- **第N代の判定基準は「その王朝の正史が帝紀を立てた君主を歴代とする」**（2026-07-25・ユーザー承認）。
  宋1..8・斉1..7・陳1..5 の既存調査値と完全に一致する基準で、第4章の北朝5王朝34在位はこれで付与した
  （北魏12代・東魏1・北斉6・西魏3・北周5。帝紀のない南安王余・幼主釗・長広王曄・元愉・元法僧・元顥・
  安徳王延宗・高紹義は null）。**唯一の例外が梁**（豫章王蕭棟を第3代に数えるが梁書・南史に帝紀なし。
  承認済みの調査結果なので変更していない）。第5章以降（隋唐・五代十国）も全 null なので、
  章を有効化する前にこの基準で dynastyOrder を埋める。
- **複数在位(廃位→復位)**: レイアウト・系譜機構は先頭即位〜末回退位の「統合矩形」1つで扱い、
  可視カプセルのみ在位期間ごとに分割＋点線コネクタ(buildNodeの`segments`)。年粒度で連続する
  廃位(西晋恵帝の301年内)は`SEG_GAP_MIN`でマージし単一カプセル、年をまたぐ廃位(唐中宗の
  684→705等)は分割。簒奪者(司馬倫)は統合矩形が時間帯を占有するのでパッキングが別カラムへ分離。
- **1人が複数の系譜主張**を持つ場合(蜀漢昭烈帝・魏文帝)は全件をツールチップに折り返し表示
  (`claimsByClaimant`は配列。Mapで単純にkey化すると最後の1件しか残らないので注意)。
- **兄弟バーは親カプセルの下辺からも6px空ける**（`layout.ts` の `clearTop`）。品質ゲートは
  「線を当事者ノードとの接触では落とさない」（線が箱に届くために必要な除外）ので、
  **自分の親の箱に貼り付いたバーはゲートでは検出できない**。構造側で確保する
  （ユーザー指摘の「箱と線がほぼ重なっている」＝明帝・孝武帝の兄弟バーが下辺の2px下）。
- **王朝交代の横向き矢印のラベルは矢印の水平区間の真上**（両カプセルの間隔がラベル幅＋16px
  以上あるとき）。間隔が足りない場合だけ両カプセルの上端より上へ逃がす。中心間でなく
  **枠間の空隙の中央**に置く（安帝→桓玄のラベルが孝武帝の箱の下辺に載っていた）。
- **配偶者の左右**: 子のいる妃は子側、**子のいない妃は実家（父のバンド）側**へ置く
  （`SpouseAttach.preferSide`）。実家側でないと父からの親エッジが夫や内側の妃をすり抜けて入り、
  連結線と重なって「妃と妃の間から生まれた」ように見える（桓温═馬氏═南康公主）。
- **王朝の代数を持つが皇帝を称さなかった君主は、灰ピルの肩書き行に「第N代・称号」を出す**
  （`PERSON_DISPLAY_OVERRIDES.role`）。カプセルの「第N代」だけだと初代や途中の代が抜けて見え、
  「初代がいないので困惑する」（ユーザー指摘・2026-07-25。前燕＝慕容皝〔燕王〕・西燕＝慕容泓
  〔済北王〕・前秦＝苻洪〔三秦王〕と苻堅〔第4代・大秦天王〕・成漢＝李特・前涼＝張駿/重華/耀霊
  〔西平公〕）。**代数は emperors.json の dynastyOrder と整合させ**、称号・在位は kinship.json の
  人物noteの原典調査に依拠する。収録基準（王・公・天王号どまりは非収録）は tipNote で補う。
- **代数の欠番はノードで埋める**（2026-07-26・ユーザー指摘「成漢の代数がおかしい」「後燕の
  第5代がいない」）。`dynastyOrder` の欠番に対応する君主が図にいないと、カプセルが
  初代→第3代のように飛んで見える。kinship.json 側に**スコープルール6「歴代君主」**を新設して
  収録し、`PERSON_DISPLAY_OVERRIDES.role` に「第N代・称号」を出す。第3章で埋めた欠番は
  成漢2（李流）・前涼1〜3（張軌・張寔・張茂）と**前涼8〜9（張玄靚・張天錫）**・後燕5（蘭汗）・
  西燕3〜4（段随・慕容顗）。**欠番の機械的な洗い出しは末尾の代を取りこぼす**（`max(dynastyOrder)`
  が上限になるため。前涼は収録皇帝が張祚＝第7代の1人だけで7止まりに見えるが実際は9代ある）ので、
  王朝ごとに最後の君主を原典で確認する。十六国の代数の基準は「その政権の統治を継いだ君主
  （皇帝号の有無を問わない）」で、**帝系を滅ぼして別政権を立てた簒奪者は数えない**
  （前趙の靳準。詳細は KINSHIP_SCHEMA.md のスコープルール6）。
  **血縁エッジを1本も持たない君主がありうる**（段随＝慕容沖の将で、慕容氏との血縁が原典にない）。
  `included` の推移閉包に乗らないので `emperors.ts` 側で先に入れ、`PERSON_BAND_OVERRIDES` で
  バンドを明示する（主親→主子→隣接の伝播では決まらない。蘭汗も兄弟姉妹エッジ1本だけで同じ）。
- **実父の名が史料に無い皇帝は `遠祖` エッジで判明分の祖先へ破線でつなぐ**（2026-07-26・
  ユーザー決定）。慕容詳→曾祖父 慕容皝、慕容永→祖父 慕容運。中間世代の名がない以上ブリッジを
  立てられないので世代を飛ばして1本引く。実装は既存の「兄弟姉妹など＝破線の補助線」の
  フォールバックにそのまま乗る（layout.ts に描画分岐を足していない）。**線だけでは何世代離れて
  いるか読めない**ので、ツールチップを「血縁〔遠祖・曾祖父〕」にし、子孫側のカプセルの
  details に「祖先：慕容皝（曾祖父・間の世代は史料に名を欠く）」の行を出す（`父：` の行が
  出ないのが調査もれではないことを示す）。**劉曜には引かない** — 祖父以上（劉防・劉広・劉亮）は
  判明しているが前趙の帝系に接続せず、孤立した鎖ができるだけだから。
- **同じ図に同姓の后妃が複数出るときは、肩書き行で呼び分ける**（2026-07-26・ユーザー指摘
  「慕容の皇后として出てくる段氏は全員別人であっているか」）。后妃は名が伝わらず「段氏」「竇氏」
  のような姓＋氏の表記しか作れないため、**同一人物の重複に見える**。`PERSON_DISPLAY_OVERRIDES`
  の `role` に諡号・尊号を入れて2行目に出す（配偶者ピルは `CONSORT_ROLE_H`＝34px の2行ピルになる。
  第3章の燕は 文明皇后／成昭皇后／皇太后 の3人）。**`label` で「段氏（文明皇后）」と横に伸ばす形は
  採らない** — 配偶者ピルの幅が48→106pxに膨らみ、凍結済みの配置で夫カプセル・垂下線・遠祖の破線と
  ぶつかって品質ゲート違反が出る（実測5件）。肩書き行なら幅は据え置き〜+6pxで済む。**幅が変わる
  ぶんは manual-layout.json の x を「右辺を保つ」ように引く**（左辺を保つと夫との連結線が短くなり
  垂下点が子のxからずれて「垂下点の段差」になる）。
- **バンドを跨ぐ子も、両親の兄弟バーを伸ばして垂下させる**（`crossKids`。他家に嫁いで夫の脇に
  配偶者として置かれた娘など）。補助線1本にすると妃の連結線の延長に見え、**女性どうしが婚姻した
  ように読める**（ユーザー指摘・2026-07-25の明帝／庾文君／南康公主／桓温）。兄弟バーから垂らせば
  同母の兄弟（成帝・康帝）と同じ形になり関係が一目で分かる。前提として**娘を父と水平整列させない**
  （皇帝→人物の妻の水平整列は廃止した。親が上・子が下を崩さない）。バーより上に来てしまう子だけ
  従来の補助線にフォールバックする。
- **横向きの親子線には続柄ラベル**「◯◯の子／娘」を線の上に出す（`kinAux`）。上記の垂下に
  できなかった横線（副親・諸説ありの実父など）に残る。上下関係が出る通常形には付けない。
- **見出しとノードの重なりは開発ログに報告**（`console.error`・ビルドは落とさない）。潰し方は
  `PERSON_HEAD_ROOM_PX`（chapters.ts）で人物ピルを持ち上げること。**祖先側も同量持ち上がる**
  （パッキングの親子チェーン押し下げで子は親の直下に貼り付くため、本人だけ上げても押し戻される）。
  皇帝以外の配置は時代に厳密でなくてよい（ユーザー確認・2026-07-25）。妃ピルは夫の年区間に
  整列するので、指定するのは**夫のid**。
- **品質ゲート（線が当事者以外を横断／ノード重なり／垂下点の段差／年線整合）は絶対に緩めない**。
  違反はキュレーション表で解消する: バンド順・`CHILD_ORDER_OVERRIDES`・`CONSORT_BOTTOM_ATTACH`・
  `BAND_X_EXTRA`・`PERSON_BAND_OVERRIDES`・`DYNASTY_HEAD_OFFSET`・`BAND_LABEL_ANCHOR`・
  `CLAIM_LINE_DEFS`（すべて chapters.ts）。← 章追加時の作業量の主因はここ。

## 章のスコープ（誰をその章に出すか・2026-07-25）

kinship.json は王朝をまたぐ1つのグラフなので、親子関係の伝播だけで章の帰属を決めると、
ある章の傍系が祖先を共有する別の章へ流れ込む（実例: 西晋八王は司馬懿・司馬防の子孫なので
第3章「東晋」にも入り、東晋の系統に無関係なまま品質ゲート違反を出した）。規則:

1. **既定は「章の皇帝＋その祖先鎖」だけ**（主親をたどって遡る）。
2. **傍系は章ごとに `CHAPTER_EXTRA_PERSONS`（chapters.ts）へ明示列挙**する（＋列挙した人物の
   祖先鎖）。存在しないid・その章のバンドに解決できないidはビルドを落とす。
3. **祖先鎖の打ち切りは `CHAPTER_ANCESTOR_STOPS`**（「この章の系図はここから始める」）。
   例: 第3章は司馬懿で打ち切る（父・司馬防は第2章で八王の結節点として必要だが、東晋の系図
   には寄与せず、生没年不明のまま圧縮領域に入ると懿と伷が縦に潰れて重なる）。
4. **配偶者ピル**は上の表の対象外で自動判定: 夫が章内にいて、かつ「婚姻エッジを持つ
   （生前の皇后・婚姻当事者）」または「子（実母・養母）が章内にいる」。子だけを条件にすると
   曹節・孝平王皇后・南康公主のような婚姻当事者が落ち、婚姻だけだと柏夫人（子＝司馬倫）の
   ような生母が別章へ付いて回る。
5. **単独ノードとして立つ女性の例外2つ**: 章内ノードの母（夫が原典で不明だと配偶者ピルに
   ならない。前趙劉曜の母・胡氏）と、章内ノードの娘（他家へ嫁いだ婚姻当事者。後燕慕容宝の娘で
   北魏道武帝の妻・慕容氏。相手の王朝が未実装の章だと `getKinshipSource` の連結スコープで
   婚姻エッジ自体が落ちるため、婚姻の有無では判定できない）。**男性の子に広げない**
   （司馬昭・八王のような傍系が戻る）。
6. **前王朝の最後の皇帝は `CHAPTER_EXTRA_EMPERORS`（chapters.ts）でこの章にも出す**
   （2026-07-26）。王朝交代の矢印は**両端が同じ章に揃ったときだけ描かれる**（layout.ts の
   `arrows` は片端が章スコープ外だと落とす）ので、章をまたぐ交代——後漢献帝→魏文帝の
   受禅——はそれまでどの章にも出ていなかった。値は皇帝idと置き場所のバンドlabel。
   dynastyKey をバンドに足す方法は採れない（その王朝の皇帝が全員入り、バンド間の重複assertにも
   当たる）。**祖先鎖は辿らない**（辿ると後漢の系統がまるごと第2章へ流れ込む）。
   **章の年目盛りの開始年（`startHist`）の計算からも除く** — 前王朝の皇帝は章頭より前に即位して
   いるのが普通で、含めると圧縮領域の境界が動いて凍結済みの配置がずれる（献帝の189年で第2章の
   開始年が200→175に後退する）。カプセルの色・第N代・ツールチップは本人の王朝のまま
   （`dynContext()` は皇帝を dynastyKey で見るので、置き場所のバンドは純粋に見た目の問題）。
   **副作用**: その皇帝の后妃が規則5の救済（下の6→7）から外れて配偶者ピルに変わる
   （曹節＝曹操の娘・献帝の皇后。第2章では実家側の単独ノードだったものが献帝の丸枠ピルになり、
   曹操からの親エッジは垂下線から横向きの補助線に変わる）。
7. **夫が章内にいない配偶者は、その章では通常のノード（＝実家の家系図の娘）として扱う**
   （`orphanSpouses`・layout.ts）。バンド伝播は既定で「attachedTo に載っていない人物」だけを
   対象にするため、相手の章を有効化した瞬間に婚姻エッジが `src` に入り、実家側の章から
   ノードが消える（第4章の追加で、凍結済みの第3章から慕容氏が1ノード落ちた）。この救済で
   規則5の実装がドキュメントどおりになり、同時に第2章へ曹節（曹操の娘・漢献帝の皇后）が
   1ノード増える（それまでは同じ理由で落ちていた）。

8. **位を受けた側が皇帝でない交代は `CHAPTER_EXTRA_ARROWS`（chapters.ts）で図の側に足す**
   （2026-07-27）。succession エッジは「収録皇帝が誰から位を受けたか」の記録なので `to` は必ず
   365人の皇帝でなければならず（`validate_kinship.py` が弾く）、**西魏恭帝→宇文覚**（北周初代・
   天王号どまりで皇帝非収録）はデータでは表せない。足せば「宇文覚は皇帝として即位した」という
   誤った主張になるので、**データではなく図のキュレーション**として持つ。書いた行は layout.ts で
   succession エッジと同じ形に組み立てられ、キー（`s:<from>→<to>`）・手動ルート・ラベルの
   ドラッグまで通常の赤矢印と同一に扱われる。**ラベルだけは明示指定**（`arrowForm()` は新帝の
   即位経路軸から語を決めるので、皇帝として非収録の相手では「受禅」に落ちてしまう）。
   端点が章スコープ外ならビルドを落とす。
9. **逆に、描かない矢印は `CHAPTER_HIDDEN_ARROWS`／ラベルの上書きは `CHAPTER_ARROW_LABELS`**
   （2026-07-27・ユーザー指示）。矢印は dynastyKey が変わる succession エッジすべてに出るため、
   **同じ一族が分裂して別政権になった交代**——北魏孝武帝→東魏孝静帝／西魏文帝（534年の東西分裂・
   どちらも高歓／宇文泰による擁立）——にも出てしまう。これらは同じ「魏（拓跋・元氏）」バンドの
   中に血縁線で並んでおり、赤矢印（禅譲・簒奪）と役割が揃わないので描かない。**同一バンドの
   一括ルールにはできない**（斉→梁の禅譲のように、同じ蕭氏バンド内でも本物の王朝交代がある）ため
   1本ずつ挙げる。ラベル上書きは東魏孝静帝→北斉文宣帝の「禅譲・外戚」→「禅譲」。
   どちらも**指定が空振りしたらビルドを落とす**（データ側の訂正でエッジが消えたのに指定だけ残る、
   を検出する）。

計測用に開発フラグ `KINSHIP_GATE=warn` がある（自動配置の章でも品質ゲートを警告に落とす）。
違反があるまま章の構成を測りたいときだけ使い、**合否の判定は必ず素の `npm run build` で行う**。

## 手動レイアウト（編集モード）

自動配置の間接的なつまみ（`CHILD_ORDER_OVERRIDES` 等）ではユーザーの品質要求に届かないため、
**最終座標をユーザーがドラッグで決めて凍結する**方式を用意した（2026-07-25）。

```bash
cd site && npm run dev
cd site && npm run kinship-editor   # 別ターミナル: 保存サーバ(:4123)
# http://localhost:3000/kinship?edit=<章id>
```

- 動かせるもの: 皇帝カプセル（横のみ・縦＝在位期間は年目盛りに固定）／非皇帝のピル・配偶者（縦横）／
  見出し・ラベルの文字／線の付け根（補助線・遠祖主張の点線・**王朝交代の赤矢印**の両端）・
  折れ線の通り道・垂下線の降り口。赤矢印は既定ではベジェ曲線だが、**付け根を動かすと補助線と同じ
  直交の折れ線に切り替わる**（家系図の直交線と揃うほうが読みやすいため）。通り道のハンドルは
  折れ線になってから出る。
- **赤矢印の直線化**（2026-07-27）: 直交の折れ線しか選べないと、斜めに離れたバンド間の交代が
  遠回りして他のカプセルを横切る（ユーザー指摘）。**矢印そのものをクリックすると選択**され、
  パネルの「直線にする／直角に戻す」で切り替わる（`manual-layout.json` の `edges.<key>.straight`）。
  直線は付け根どうしを直に結ぶので `mid`（通り道）は使わず、通り道のハンドルも消える。
  付け根をまだ動かしていない矢印でも直線を選べる（既定のベジェの端点をそのまま両端に使う）。
- **凍結後にデータへ追加されたノードは青枠**で示し、パネルに件数と名前が出る（自動配置のまま＝
  未配置。ドラッグして保存すると青枠が消える）。
- 操作: ドラッグ＝移動、Shift+ドラッグ＝子孫と配偶者ごと、Alt＝吸着解除、クリックで選択して矢印キー
  1px（Shift+8px）、Ctrl+Z＝取り消し。他ノードの辺・中心に6pxで吸着しガイド線が出る。
- 保存すると `site/src/lib/kinship/manual-layout.json` に書かれ、その章は `mode:"manual"` ＝**凍結**。
  以後レイアウトエンジンを直してもその章は動かない。表に無いノード（後から追加した人物）は
  自動配置にフォールバックする。
- 座標は x＝章内の絶対px、y＝**年**（人物追加で時間軸が伸びても意味が保たれる）。
- **`manual` の章では品質ゲートはビルドを落とさず警告**（配置の決定権はユーザーにあるため）。
  違反ノードは編集モードで朱の破線で強調され、パネルに一覧が出る。
- 仕組み: ドラッグ中はSVG要素にtransformを当てるだけ。離した時点でブラウザ側で
  `buildKinshipLayout` をやり直す（入力は `/kinship-source`＝開発時のみ実データ）。
  第1章107ノードで再計算31ms。

## 章を1つ有効化する手順

1. `KINSHIP_CHAPTER_DEFS`（chapters.ts）で当該章の `bands` をキュレーション
   （対象皇帝の全dynastyKeyを重複なく被覆。未割当はビルドがthrowして気づける）。
2. `KINSHIP_ENABLED_CHAPTER_IDS` に章idを追加（emperors.ts のスコープはここから自動導出）。
3. `KINSHIP_COLOR_BY_DYNKEY` に新dynastyKeyの配色を割当（主要王朝＝series枠、群雄＝`--kinship-minor`）。
4. `npm run build` を回し、品質ゲート違反をキュレーション表の調整で潰す（違反メッセージに
   横断・重なりの当事者と座標が出る）。1章分の違反が0になるまで反復。
5. **見出しの重なりを0件にする**。`npm run dev` のログ（またはbuild出力）の
   「見出しがノードに重なっています」は**ビルドを落とさない報告専用**なので、明示的に確認して
   `PERSON_HEAD_ROOM_PX`／`BAND_LABEL_ANCHOR`のdx/dyで潰す。
6. `validate_kinship.py` 緑＋目視で規範遵守を確認。次の章へ。

反復のコツ: `npm run dev` を上げて `curl "localhost:3000/kinship?cb=$RANDOM"` → devログのゲート違反を読む
（フルbuildは最後の1回でよい）。**devサーバはページ描画をキャッシュするので、編集が反映されない
ときはクエリを変えるかサーバを再起動する**（古い違反ログを見て空振りしやすい）。幾何の機械照合は
curlしたSVGを`data-kid`属性でノードidに対応づけて行う（章追加前後のdiffで既存章の無変化も確認できる）。

1. ルートが存在し静的書き出しされる（main にマージすれば自動）← **2026-07-31 現在ここ**
2. ~~`src/lib/nav-data.ts` にメニュー項目「系譜・家系図（一部公開）」を追加~~ ← **2026-07-31 に削除**
3. ~~`src/lib/seo.tsx` の `SITE_SECTIONS` に登録し `robots: { index: false }` を外す~~ ← **行わない**

3 を先にやってはいけない理由: `sitemap.ts` が `SITE_SECTIONS` を map するので、登録した時点で
noindex と sitemap 掲載が矛盾する（未完成ページをクローラに主張することになる）。また
`sectionDescription()` は `SITE_SECTIONS` に無い href で throw するため、片方だけ足すとビルドが落ちる。

ページの掲載範囲の文言（ヘッダ下の暫定公開版バナー・meta description）は
`KINSHIP_ENABLED_CHAPTER_IDS` から導出しているので、**章を増やしたときに文言を直す必要はない**。
