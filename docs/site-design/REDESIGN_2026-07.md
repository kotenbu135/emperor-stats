## 王朝色システムとチャートの淡彩化（2026-07-27・design-plans/01）

サイトの主要な軸である「王朝」が色で表現されておらず、一方でランキング棒グラフ11本すべてが `--seal`（朱 `#a6321c`）の単色で塗られていて、色の印象を朱一色が支配していた。`/dynasties` は同一画面の上半分が朱一色・下半分が8色パレットで色の言語が割れていた。ユーザー決定「王朝ごとに色を決めて皇帝はその色を利用する」を受けて実施。

- **新規パレットは作らない**。`--series-1〜8` は dataviz skill の手順で surface `#f5f1e8` に対して検証済み（CVD安全性・コントラスト全項目PASS）なので、そこへ87王朝を割り当てるだけにした。割当も新規に考えず、**それまでコード内に重複して存在していた2つの意味ベース対応表を統合**して導出した（`lib/kinship/chapters.ts` の `KINSHIP_COLOR_BY_DYNKEY` 37キーと `lib/timeline-river.ts` の `STREAM_DEFS[].colorSlot` 87キー）。両者は18キーで食い違うが、その全てが「年表では群雄バンドに束ねるため灰にする」等の**描画都合の差**なので、政権ごとに色を持つ系譜図側を優先した。
- **所有者は `site/src/lib/dynasty-colors.ts` の1箇所だけ**（`DYNASTY_COLOR_SLOT`）。`chapters.ts` はここからの再エクスポートに変わり、`timeline-river.ts` の `colorSlot` は「ストリームの表示スロットであって王朝の識別色ではない」とコメントで明示して残した。**未知の dynastyKey は throw する**（皇帝を追加収録したときに気づけるようにする）。
- **スロット0（`--kinship-minor` 藤）に落ちる37王朝は全て `dynasty.category` が「並立政権」か「反乱・自称政権」**で、正統王朝は1つも含まれない。既存の「群雄・並立政権カプセル専用色」という定義とそのまま一致する。
- **生の彩度で塗らない**。`--series-N` は識別性を優先した値なので宣紙色の地に直接置くとクロームから浮く。`/timeline`（塗り42%/縁82%）・`/kinship`（同）と同じく `color-mix` で地色に混ぜる。混合比は面積に応じて **ランキング棒・王朝集計棒＝塗り55%/縁82%、円グラフ・積み上げ棒＝同55%/82%、カードのモノグラム背景＝22%**。
- **Nivo は CSS 変数も `color-mix` も解決できない**ため、チャートに渡す色は JS 側で混色した16進値にする。CSS Color 4 の `in srgb` は**ガンマ補正済みの sRGB 値をそのまま補間する**ので、0〜255のチャンネルごとの線形補間で一致する（線形光空間で混ぜると値がずれ、CSSで塗った面とNivoに渡した面の濃度感が食い違う）。ブラウザ実測で45ケース中43ケース完全一致・2ケースが1/255差であることを確認済み。
- **凡例が成立しない**（87王朝）ため凡例は付けない。各行に王朝名がラベルされているので、色は「どの王朝か」を解読する鍵ではなく「同じ王朝の皇帝がどこに固まっているか」を見せるグルーピングの手掛かりとして働く。実データでの隣接同色率は上位20で16%・全365件で17%。
- **塗りの上の文字色は混色後の実値からコントラスト比で選ぶ**。生の彩度を前提にした固定リスト（旧 `darkSlices`）は淡彩化後には当てはまらない（`readableTextOn`）。
- **凡例・表・ツールチップのスウォッチは、実際の弧・セグメントとまったく同じ塗り＋縁で描く**（`/kinship` の凡例と同じ原則）。片方だけ生の値のまま残すと色の言語が割れる。
- **`/timeline` と `/kinship` は描画を1ピクセルも変えていない**。フルページスクリーンショットのバイト比較（デスクトップ・モバイル）で確認した。`/kinship` は第1〜4章の配置がユーザーのドラッグ編集で凍結済みのため、これは絶対条件。なお `cmp` によるバイト比較は、この構成では**未変更ツリーを2回撮って26枚全て一致する**（＝偽陽性が出ない）ことを事前に検証してから使っている。

## 面の3段化とホバーの持ち上がり（2026-07-27・design-plans/02）

ユーザーの「今のデザインに古臭さを感じる／長く滞在しようという気になれない」に対する `baseline-ui` の分析結果への対応。世界観（水墨文人）は変えていない。

- **原因**: `--card` と `--background` が同一値（`#f5f1e8`）で、カードが1pxの罫線と角丸だけで存在を示していた。加えてサイト全体の `hover:*` 91件がすべて色の変化と下線だけで、`transform` を伴うホバーが1件も無かった（触れた手応えが返らない）。
- **面は明度で3段**: `--sidebar #ede7d8` < `--background #f5f1e8` < `--card #faf7f0`。すでにサイドバーで「明度で面を分ける」方針は実装済みだったので、その反対側（1段明るい面）を埋めただけ。**静止状態に影は置かない**（365枚のカードが並ぶ `/emperors` で画面がざらつく）。
- **影はホバーのときだけ1段**（Tailwind 既定スケールの `shadow-sm`）。持ち上がりは `-translate-y-px`・150ms。
- **Tailwind v4 の罠**: `-translate-y-*` は `transform` ではなく **`translate` プロパティ**を書く。そのため遷移対象は `transition-[translate,…]` と書く必要がある（`transition-[transform,…]` だとホバーが瞬間移動になる。実際に一度これで実装して実測で気づいた）。v4 の `transition-transform` ユーティリティは `transform, translate, scale, rotate` に展開されるので単体なら正しいが、`cn()`（tailwind-merge）は利用側が渡した `transition-*` で基底を上書きするため、`Card` に渡す className 側でも遷移対象を明示すること。
- **`prefers-reduced-motion` は `motion-safe:` で書く**。`hover:shadow-sm` ＋ `motion-reduce:hover:shadow-none` の打ち消しはバリアントの出力順に勝てず影が残った。`motion-safe:hover:-translate-y-px` のように「動いてよいときだけ規則を作る」書き方なら打ち消し合戦にならない。実測で確認済み（reduced-motion 時は translate も影も出ない）。
- **性能**: `/emperors` はグリッド全365枚が DOM に載る（行ウィンドウイングの対象外）ため実測した。ポインタをグリッド上に置いたまま60回スクロールして **Long Task 0件・CLS 0.0000**。
- StatTile（表示専用・クリックできない）にはホバーの反応を与えない。

390×844（iPhone 14 相当）で全12ルートを目視して見つかった、**モバイルでのみ発現する実装漏れ**をまとめて解消した。デザイン判断は含まない。

## タイポ／スペーシングのトークン化（2026-07-27・design-plans/05）

承認済みのスケール（DESIGN.md の typography 6段・spacing 5段）のうち、**実体のある段だけ**をコードへ落とした。既存の Tailwind 既定値と同値になる段はトークン化していない（1つの値に2つの名前ができると、どちらを書くべきかが揺れる）。

- **`--text-micro`（0.6875rem = 11px）を新設**。極小テキストが `text-[9px]` から `text-[13px]` まで7種類の生ピクセル値で書かれていたのを、`/kinship`・`/timeline` の SVG 内ラベルを除いて1つに集約した。10px は日本語の可読性の下限を割っており、11px に上げた3箇所（ツールチップの補助文2種・順位の注記）は実測で読めるようになった。`text-[11px]` からの3箇所は同値。
- **`text-[11px]` と `text-micro` は完全な等価置換**。Tailwind v4 の `text-*` は、テーマ値に `--*--line-height` が無いと `line-height` 宣言を出さない。arbitrary の `text-[11px]` も同じく font-size 単独なので、行送りの副作用がない（コンパイル出力で実測）。root font-size を変える指定はプロジェクト内に1つも無く、0.6875 = 11/16 は2進で厳密表現できるため丸め誤差も出ない。
- **`--spacing-block` は使えない（Tailwind v4 の名前空間衝突）**。`--spacing-*` は `inline-*`（`inline-size`）ユーティリティにも供給されるため、`--spacing-block: 1.5rem` を足すと **`.inline-block{inline-size:1.5rem}` が生成され、display ユーティリティの `.inline-block` と同名衝突する**。`inline-block` は `/timeline` に5箇所・`/kinship` に2箇所・円グラフに2箇所あり、凍結面の描画が壊れる。ビルド出力の差分で検出した（型チェックもビルドも通ってしまう）。`{spacing.block}` はトークン化せず、同値の既定クラス `mt-6` のまま残す判断（ユーザー確定）。`gutter` / `gutter-wide` / `section` は衝突しない。
- **余白トークンの所有者は `PageHeader` / `Section` に限る**。この2つがサイト全体の余白を供給するので、ここだけ名前で書けば契約がコードに現れる。ページ側の `px-6 py-8 md:px-10` は同値の既定クラスのまま残す。
- **同一性確認**: `/kinship`・`/timeline` はデスクトップ・モバイルともスクリーンショットがバイト単位で一致。差分が出たのは `/emperors/[id]` と `/emperors`（13バイト＝検索欄のサブピクセル描画ゆれ）のみ。
- **`/emperors/[id]` の回数グリッドは375pxで2セルが2行になる**（ページ全高 4405→4438px）。ラベルが長い「皇太子廃立」「反乱鎮圧」の行で、注記が 11px になったぶん `dd` の幅に収まらなくなる。**`whitespace-nowrap` で防ごうとすると 375px でページが34px 横にはみ出す**ため採らない（実測）。すぐ上の基本情報ブロックの注記（`text-xs`）は変更前から375pxで2〜3行に折り返しており、狭い画面での折り返しはこの部品の既存の挙動。横スクロールも切れも発生しないため許容した。1440px では全セル1行のまま。
- **`emperor-tooltip` の hint は `/kinship` でも使われる**（`kinship-chart.tsx` → `EmperorTooltip`）。ホバー時のツールチップ内補助文だけは `/kinship` でも 10px→11px になる。静止画のスクリーンショットには現れず、ノード・ラベルの配置は不変。
- **Tailwind のソース走査は `design-plans/*.md` の散文も拾う**。計画書に書いたクラス名（`px-gutter` 等）が実装前からビルド出力に現れる。CSS の grep で実装状況を判定しないこと。

## 円グラフのラベルを列幅で出し分ける（2026-07-27・design-plans/06）

`/death-accession` の外側ラベル（`arcLinkLabel`）が切れて「処刑 10%」→「刑 10%」、「継承（経緯記載なし） 5%」→「し）5%」になっていた問題。**計画の「左右 margin を広げる」解法は成立しないことが実測で判明した**ため、列幅に応じてラベルの出し方を切り替える形に変えた。

### なぜ margin では直らないか（幾何の実測）

@nivo/pie の外側ラベルが弧の縁から水平に消費する幅は `(R + 6 + 16)·sinθ + 24 + 6 + 文字幅`。真横に出るラベル（sinθ=1）が最悪ケースなので、**片側に `R + 52 + 文字幅` が要る**。ラベル幅は `labels.text.fontSize = 11px` 基準で、最長の「継承（経緯記載なし） 100%」が約141px（計画の「12px相当で約160px」は誤り）。

コンテナ幅 W は `md:grid-cols-2` のため **1440px で535px・1024px で327px・768px で199px**、モバイル1カラムで **375px→317px**。したがって:

- **375px**: 必要な片側 = 52+141 = 193px に対し半幅は158px。**半径0の円でも収まらない**（margin では原理的に不可能）
- **768〜1024px**: 計画の初期値 `left/right=120` は描画幅を負にしてチャートを消す
- **1440px**: 全ラベルを収めると直径 364→149px となり、計画自身の停止条件（160px）を割る

### 採った解法（ユーザー確定「幅で出し分ける」）

`ResizeObserver` で**列の実測幅**を取り、そのチャートの分類で最も長いラベルから外側ラベルが成立するかを判定する。

- **成立する幅** — 外側ラベルを出し、`margin.left/right` を実測幅とラベル幅から算出する（固定値では 768〜1024px を必ず壊すため、静的値は使えない）。弧の中は従来どおり人数
- **成立しない幅** — `arcLinkLabelsSkipAngle` を 360 にして外側ラベルを消し、弧の中に割合を置く。**弧に入るならカテゴリ名も併記する**（リングの厚みと弦の小さいほうを使える幅とみなす）。入らないスライスは直下の凡例（色丸＋名前＋説明の HoverCard）と「表で見る」で識別させる
- **モードの判定材料から絞り込みの影響を完全に外す**。割合は常に3桁（100%）で見積もり、カテゴリは表示中のものでなく `categoryOrder` の**全件**で測る。どちらかでも実データを使うと、王朝で絞り込むたびに内側/外側が入れ替わる（実測で確認: 「継承（経緯記載なし）」を持たない王朝に絞ると次に長いラベルが97pxになり、1440pxで外側モードへ飛ぶ）
- 弧の中でラベルが使える幅は**リングの厚みと弦の小さいほう**だが、弦は半円を超えると再び縮んで100%で0になる。**π で頭打ちにする** — しないと、最も大きいスライス（1人だけの王朝に絞ったときの100%）でだけ名前が消える
- ラベル幅は Canvas でなく**全角1em・半角0.56em の字幅見積もり**で出す（実測との誤差3px以内・フォント読み込み前でも外さない）
- **割合は `datum` に持たせる**。ラベル関数の中で live な合計から割ると、絞り込みで消えるスライスが退場アニメーション中（実測で約0.7秒）だけ「世襲 6000%」のような値を出す — 古い人数を新しい合計で割るため。これは外側ラベルにもとから在った不具合で、内側ラベル化で目に付きやすくなったため同時に直した

### トップページ — リンク集をやめ、実データの抜粋にする

旧トップはサイドバーと同じ8項目をカード化して「見る」ボタンを添えたリンク集だった。
ナビゲーションと1対1に重複するぶん情報量が増えず、365人分の集計を持つサイトの入口として
中身を何も見せていない。カードを各ページの実データの抜粋（概況の4値・在位上位6名の肖像＋
王朝色のミニ棒・死因と即位経路の100%積み上げ帯＋全区分の一覧・時代ごとの人数）に置き換え、
抜粋のない4ページだけを行型リンクに落とした。

- **レイアウトを `contained`(max-w-4xl) から全幅・左寄せへ。** DESIGN.md は「統計ページは
  全幅を使い、見出しを左寄せにする。散文が主体の記事型ページのみ列幅を制限して中央寄せ」と
  定めており、概要ダッシュボードは前者。旧トップは中央寄せで、240pxのサイドバーの右に
  死んだ余白が残っていた
- **朱は代表値1つだけ。** 旧トップは6枚のタイルの数値すべてを朱にしており、DESIGN.md の
  「印章の朱はここぞという箇所に限る／複数要素へ同時に当てると水墨基調の抑制が失われる」に
  反していた
- **帯と一覧は必ず対で出す。** 100%積み上げ帯だけでは1〜4%の区分が読めず、一覧だけでは
  全体に占める重みが分からない。1名しかいない区分は `0%` ではなく `0.3%` と出す
- `reigns[].startYear` は**天文年ではなく歴史年**（-221 = 前221年）。天文年として扱うと
  「前222年」になる。なお `datasetTemporalCoverage`（Dataset JSON-LD）は ISO 8601＝天文年の
  はずが同じ値をそのまま出しており、意味としては1年ずれている（未修正・要判断）

## 共通シェルと /kinship の横方向の見やすさ（2026-07-27・第2弾）

ブランチ `design-shell-kinship`。系譜そのもの（ノードの座標・描画）には手を触れていない。

### 共通シェル

- **モバイルのサイトヘッダーを sticky に。** `/emperors` は全高5万px級で、固定しないと
  一度スクロールした時点でナビゲーションへ戻る手段が無くなる（サイドバーはこの画面幅では
  ハンバーガーの中にしか無い）。重なりは「画面に固定される要素」の段（z-50）。ページ内の
  固定索引（z-30）より上に出す必要があり、ダイアログ等はポータルでこの後ろのDOMに出るため
  同じ段でも上に描かれる
- **画面上端のクローム高さを `--chrome-top` に集約**（モバイル 3.5rem / md以上 0）。
  ヘッダーの高さは `h-14`(56px) に固定してこの変数と一致させる。固定索引の `top` と、
  ジャンプ先の `scroll-margin-top`（`BELOW_SECTION_NAV` / `BELOW_KINSHIP_NAV`）は
  すべてこの変数から導く。**直値で書くとヘッダー高さを変えたときにジャンプ先が索引の下へ潜る**
- **スキップリンクを追加**（`本文へスキップ` → `#main`）。フォーカス時のみ現れる
- サイドバーの幅は変えていない。240→200pxにしても6228px幅の系譜図に対して40pxしか増えず、
  一方で `/timeline` の「全体」表示は `pxy` をコンテナ実測幅から算出しているため再フィットする。
  割に合わないと判断した

### /kinship の横方向

1章の系譜図は最大6228px。デスクトップの表示領域は約1150px（18%）、390pxでは約345px（5.5%）
しか映らない。バンド見出し（「前漢」など）は図の最上部に描かれているため、少し下へ
スクロールすると「いまどの王朝を見ているか」を示すものが画面から消えていた。

- **王朝バンドへのジャンプバー**（`kinship-band-nav.tsx`）を章ごとに追加。章ジャンプの
  真下に貼り付く。ピルは図の左から順（`layout.bands` の並びは描画都合で左右順ではないため
  x昇順に並べ替える）
- **現在地の判定は「表示範囲と重なる面積が最大のバンド」。** 中央点だけで判定すると、
  狭いバンドは枠の中央に来る前に通り過ぎて一度も点灯しない。図全体が枠に収まっている
  ときは何も点灯させない（見ていない王朝を現在地と誤って示すため）
- **現在地の更新に React state を使わない。** 使うと1章あたり最大445ノードのSVGが
  スクロールのたびに再描画される。rAF の中で DOM を直接書き換える（`/timeline` の
  ラベルクランプと同じ手法）
- **ピルを押した直後は800msだけ再判定を止める。** 枠が広いと、飛んだ先の狭いバンドより
  隣の大きなバンドのほうが面積で勝ち、押した王朝の点灯がすぐ奪われる
- **表示倍率（100%/60%/35%）を追加。** 既定100%は従来と1ピクセルも変わらない描画で、
  `viewBox` は据え置き、SVGの描画サイズだけを変える。年ラベルのstickyオーバーレイは
  CSS px 配置なので同じ倍率を掛ける。編集モードのドラッグ換算は
  `getBoundingClientRect().width / viewBox.width` の比なので自動で追従する（dev限定）
- **狭い画面では右端の年ラベルを出さない。** 表示幅が345pxしかなく左端のラベルとの間に
  カプセルが入る余地が無いため重なる（390pxで実測1件）

**重なりの落とし穴**: 王朝ジャンプは章ジャンプと同じ段（z-30）だが DOM 順では後ろにあるため、
章の枠が上へ抜けて sticky が押し出される瞬間に章ジャンプへ被さる。**図の枠ごと z-20 の
重ね合わせコンテキストへ閉じ込めて解決した。** この箱の中にツールチップ・詳細ダイアログ・
編集パネル（z-50）を入れてはいけない（同じ理由で章ジャンプの下へ潜る）。端フェードの位置基準は
図の枠だけを囲む内側の箱で、王朝ジャンプの高さを含めない。

## /kinship の交代矢印: 皇帝でない相手への矢印と、直線ルート（2026-07-27）

- **西魏恭帝→宇文覚の禅譲矢印が図に無かった**。原因は kinship.json の succession エッジが
  「収録皇帝が誰から位を受けたか」の記録で、`to` は365人の皇帝に限られること（宇文覚は
  天王号どまりで非収録）。データに足すと収録基準に反する主張になるため、**図のキュレーション**
  `CHAPTER_EXTRA_ARROWS`（chapters.ts）を新設し、layout.ts で succession エッジと同じ形に
  組み立てて同じ経路に流した（キー・手動ルート・ラベルドラッグは通常の赤矢印と同一）。
  詳細と判断根拠は [KINSHIP.md](./KINSHIP.md)「章のスコープ」規則8。
- **描かない矢印・ラベル上書きの表も同時に用意**（`CHAPTER_HIDDEN_ARROWS`／`CHAPTER_ARROW_LABELS`）。
  534年の北魏東西分裂（孝武帝→東魏孝静帝・西魏文帝）は擁立であって禅譲でも簒奪でもなく、同じ
  元氏バンド内に血縁線で並んでいるため矢印を落とす。東魏孝静帝→北斉文宣帝は「禅譲・外戚」→
  「禅譲」に上書き。指定の空振りはビルドを落とす。
- **赤矢印に直線ルートを追加**。従来は「既定のベジェ」か「直交の折れ線」の二択で、斜めに離れた
  バンド間（魏バンド→北斉バンドを越えて北周バンド）では折れ線が遠回りして他のカプセルを横切る。
  編集モードで**矢印をクリックして選択→パネルで直線/直角を切り替える**方式にし、
  `manual-layout.json` の `edges.<key>.straight` に保存する。付け根の手動指定がまだ無い矢印でも
  選べるよう、ルート判定（`routedPoints` と矢印側の `routed`）を `from`/`to` だけでなく
  `straight` でも立つようにした（ここを直さないと「直線にしても曲線のまま」になる）。
