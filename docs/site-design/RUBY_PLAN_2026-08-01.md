## 1. 「総ルビ」とは何か / Issue の要求の読み方

総ルビ（そうルビ）は、文中の**すべての漢字**に読みを振る組み方。江戸期の草双紙から戦前の新聞・少年雑誌まで一般的だったが、戦後の当用漢字政策（読めない漢字は使わない＝ルビで救う必要をなくす方針）と、活版・写植でのコスト増によって廃れた。現在も残るのは学参・児童書・一部の新聞用語（難読地名）など。ルビ財団はこれを「専門知識へのアクセス障壁を下げる」ものとして再普及させようとしている。

対義は**パラルビ**（難読字だけに部分的に振る）。学校図書館では「初出のみ振る」運用も多い。

Issue の目的文は「名前などの漢字が読めないことに起因する」で、**読めなくて止まる場所は固有名詞に集中している**（「拓跋燾」は読めないが「即位した」は読める）。ただし作業開始前の指示として「総ルビに対する理解をすること」が明示されているので、総ルビを一度は正面から評価した上で、下の実測値をもって段階案を提示する。

## 2. 実測（このデータセットに対して）

### 2-1. 機械的に読みを決められるか → 決められない（44%が多候補）

サイトには既に `site/src/lib/kana-readings.ts` に**漢字→音読みテーブル562字**がある（かな検索 `searchKana` 用）。これを**実際に画面へ出ている名称717文字列**（表示名・諱・廟号・諡号＋政権ラベル89＋時代ラベル11。`aliases`・`regnalTitle` は現状どのページにも出していないので除外した）に当てた結果：

| 判定 | 件数 | 割合 |
|------|-----:|-----:|
| 候補が一意に決まる | 377 | 52.6% |
| 候補が複数ある（人が選ぶ必要） | 322 | 44.9% |
| テーブルに無い字を含む | 18 | 2.5% |

複数候補の例：`宇文贇`＝宇:う／文:**ぶん|もん**／贇:**いん|うん**、`完顔亶`＝完:かん／顔:がん／亶:**たん|せん**、`則天大聖皇帝`＝2×2×2＝8通り。最大は `承天応運啓聖睿文宣武皇帝黄巣` の32通り。

「表に無い字を含む」18件は、字が未登録なのではなく**カタカナ音写や記号を含む複合ラベル**だった（`クビライ（忽必烈）`・`トゴン・テムル（妥懽帖睦爾）`・`愛新覚羅皇太極（ホンタイジ）`・`太宗/成祖（永楽帝）`・`秦→漢（朱泚）` など）。**元朝の皇帝はほぼ全員がこの形**で、下の判断待ち5（音写名にどう振るか）がそのまま該当する。

重要なのは、**一意に決まる404件も「正しい」保証はない**こと。このテーブルは検索用で、余分な候補が混じっても実害がない（むしろ表記ゆれを拾えて有利）という前提で作られている。ルビは1つに決め打つので、要求される精度が違う。→ **読みは全件を人が確認する前提**で組む。テーブルは下書き生成にしか使えない。

なお `searchKana` は**置き換えない**。組み合わせ展開は「うろ覚えの読みでも引っかかる」ための機能で、ルビ用の確定読みとは目的が別。読みデータができたら searchKana に**足す**のが正しい。

### 2-2. 総ルビの分量 → 和文だけで125万字

皇帝個別ページに表示している調査 note の実文字数：

| フィールド | 文字数 |
|-----------|-------:|
| events[].note（年表の各行） | 482,577 |
| 在位日付の典拠 conversion | 100,211 |
| ages.note | 93,108 |
| 各種 count の note 8種 合計 | 463,420 |
| accessionRoute.note / deathCause.note | 78,072 |
| reigns[].note / verification.notes | 32,856 |
| **和文合計** | **約1,250,000字** |
| （参考）漢文引用 quote＝ルビ対象外 | 41,584 |

**1人あたり平均3,425字。** これに手作業で総ルビは不可能で、形態素解析による自動ルビは後述の理由で精度が出ない。**既存 note は総ルビの対象から外す**のが現実的な線。

一方、**紹介文（Issue #16）は1本あたり数百字×365本で、まだ1本も書かれていない**（`data/emperor-profiles.json` は未作成）。ここは執筆時にルビを織り込めば総ルビが成立する唯一の本文。

## 3. ルビふるボタン（ルビ財団）の評価 → 不採用を推奨

公式ページ（https://rubizaidan.jp/rubyful-button/ ）から読み取れた事実：

- 導入は `<head>` に1行追加するだけ。**ただしコードは利用登録申請 → 財団の審査 → 完了後に導入ガイドで渡される**
- 適用範囲はクラス指定。**範囲内は全部に適用され、一部だけ除外はできない**
- 財団自身が「複数読みがある場合、**異なったルビが振られる可能性があります**」と明記。手動で HTML タグで囲えば指定可能
- 解析方式（クライアント形態素解析か外部 API か）・料金・ライセンスの詳細は非公開

不採用の理由（「劣っている」ではなく「**評価できないまま依存を負う**」という判断）：

1. **審査を通すまで中身を評価できない。** 外部スクリプトを本番に入れる判断を、コードを見ずに先に確定させることになる
2. **精度の弱点がサイトの中核に直撃する。** 財団が明示している「複数読みで外れる」は、2-1で測ったとおり本サイトの名称の44%が該当し、2-3の非漢族系人名はほぼ全滅が見込まれる。手動指定で救えるが、それは結局756件の読みを自前で持つのと同じ作業量
3. **静的書き出し＋React と相性が悪い。** 実行時に DOM を書き換えるスクリプトは、ハイドレーション後の再レンダリングで消えたり二重適用されたりする。行の高さも実行時に変わるのでレイアウトシフトが出る（このサイトは WSL 環境で TBT が10〜20倍に増幅される計測経験があり、実行時 DOM 走査の追加は避けたい）
4. **申請は対外的な行為。** サイトの身元を出して財団に登録する判断はユーザーのもの。こちらでは申請していない

**ただし「まず申請して導入ガイドを見てから判断する」という選択肢は潰していない。** 見てから決めたい場合は、申請はユーザー自身で行うか、明示の依頼があれば内容を用意する。

## 4. 自前実装の設計論点

### 4-1. データの持ち方

`data/emperors.json` は**拡張しない**。理由は紹介文と同じで、読み（日本語慣用音）は正史原典から出てこない編集判断だから。原典調査の結果と編集物を同じファイルに混ぜると、`meta.status` やゲート（`validate_emperors.py`）の意味が濁る。

```
data/name-readings.json
{
  "emperors": { "beiwei-taiwudi": { "name": "たくばつとう", "commonName": "たいぶてい" } },
  "regimes":  { "beiwei": "ほくぎ" },
  "kanji":    { ... }   // 総ルビ用に持つ場合のみ
}
```

- 読み単位は**文字列単位（名前まるごと）**にする。漢字単位に分解して持つと `<ruby>` の分割位置（熟字訓的な「愛新覚羅＝あいしんかくら」）を表現できない。分割位置を持たせるなら `[["拓跋","たくばつ"],["燾","とう"]]` のような**ペア配列**が要る
- 出典・確信度をどこまで持つか（`source: "jawiki" | "editorial"`, `confidence`）は判断待ち。このプロジェクトの売りが出典明示である以上、最低限「読みは慣用であり原典由来ではない」旨をこのサイトについてのページに1行書く必要はある
- id の打ち間違いで黙って落ちないよう、`kana-readings` / `emperor-profiles` と同じく**未知 id で例外を投げる**assert を入れる

### 4-2. 表示方式

`<ruby>拓跋燾<rt>たくばつとう</rt></ruby>` をビルド時に出力する。

- **rt は常に DOM に置き、CSS で出し入れする。** 実行時に要素を足すとその行の高さが変わり、レイアウトシフトになる
- **行の高さはルビの ON/OFF に関わらず確保する。** `globals.css` に line-height の定義はなく、行間は各コンポーネントの Tailwind `leading-*` 任せなので、ルビを入れる箇所の leading を先に洗って固定する必要がある
- トグルは `<html data-ruby="off">` 属性＋`[data-ruby="off"] rt { display: none }` の1行で済む。設定は localStorage、`layout.tsx` のインラインスクリプトで初期描画前に属性を当てて FOUC を防ぐ（静的書き出しなので SSR で分岐できない）
- 初期状態は **ON を推奨**。Issue の趣旨は「読めない人が来る前提」なので、既定で消えていると発見されない

### 4-3. 織り込み済みのコスト（回避不能・許容するか決める）

- **コピペに読みが混ざる。** テキスト選択時、多くのブラウザで rt もコピーされる（「拓跋燾たくばつとう」）。`<rp>` では解決しない。**引用・出典明示を目的に名前をコピーする使い方があるサイトなので実害がある。** 緩和は `user-select: none` を rt に当てる程度（ブラウザ差あり）
- **スクリーンリーダーの二重読み。** 実装差が大きく、漢字と読みを両方読む環境がある。`rt` に `aria-hidden` を当てる回避があるが、支援技術での実機確認が要る（要検証項目）
- **本文テキスト抽出への影響。** metadata・JSON-LD は生データから組んでいるので影響なし。影響を受けるのはページ本文のみで、Google はルビを解釈するとされるが保証はない。**既知のコストとして受け入れる**という整理（未解決の懸念ではない）

### 4-4. ルビを振らない範囲（明示的な線引き）

- **漢文の原文引用（`source.quote`・約4.2万字）**。原文ママ表示が方針で、日本語読みを付けるのは筋が違う
- 数字・アルファベット・既にカタカナの音写名
- 適用範囲はコンテナ単位でスコープする（引用ブロックの外側だけに適用）

### 4-5. T1 で受け入れることになる穴（先に明示しておく）

T1 は**構造化されたフィールドにしかルビを振れない**。同じ皇帝ページの中で、見出しの `拓跋燾` にはルビが付き、その下の経緯本文に出てくる次のものには付かない：

- **地名・宮殿名** — 沙丘平台・望夷宮・遷都先の都城名
- **皇帝以外の人名** — 趙高・桓温・賈皇后・楊堅
- **年号** — 建元元年・開皇九年

「読めなくて止まるのは固有名詞」という本文書の前提からすれば、これらも本来は対象。T1 が外すのは**読めるからではなく、構造化されていない地の文の中にあって機械的に切り出せないから**で、技術的な妥協である。読者からは「ルビが付いたり付かなかったりする」ように見える。

これを埋める道は2つしかない：(a) 地の文に対する自動ルビ（＝2-3で否定した精度問題に戻る）、(b) **本文を書くときにルビを織り込む＝T2**。**T2 が単なる「追加範囲」ではなく、T1 の穴に対する唯一の現実的な答えでもある**のはこのため。

## 5. 範囲（T1・T2 を採用／T4 は対象外）

| 段階 | 範囲 | 対象量 | 採否 |
|------|------|-------:|------|
| **T1** | 皇帝の表示名・諱・廟号・諡号・政権ラベル・時代ラベル。ヒーロー h1、一覧カード、データベース表、基本情報 dl | 717文字列 | **採用** |
| **T2** | 紹介文365本（Issue #16）を**執筆時に総ルビ前提で書く** | 未執筆 | **採用** |
| **T3** | サイト固定文言（ナビ・見出し・凡例・このサイトについて） | 小 | 難読がほぼ無く優先度は低い。T1 のあとで判断 |
| **T4** | 既存の調査 note 全文 | 125万字 | **対象外**。手作業は不可能、自動ルビは 2-3 の理由で精度が出ずデータ正確性最優先の方針に反する |

T1 の作業量の目安：717件を人が確認する前提で、ブロック単位（王朝ごと）に分けて典拠（日本語版 Wikipedia・漢和辞典の人名読み）と突き合わせる。既存テーブルからの下書き生成があるので、1件あたりの判断は数秒〜十数秒。

## 6. 実装の順序（未着手）

1. **紹介文の執筆規約にルビ記法を入れる**（最優先。365本を書き始める前でないと retrofit になる）。記法は `data/emperor-profiles.json` に生テキストで持つ以上、`｜漢字《かんじ》` のような**軽量マークアップをビルド時に `<ruby>` へ変換する**形になる見込み。記法の最終決定は実装時
2. **`data/name-readings.json` の器と、未知 id で落ちる assert**（`kana-readings` / `emperor-profiles` と同じ設計）
3. **717件の読み確定**（下書き生成 → 王朝ブロック単位で確認）
4. **`<ruby>` 出力とトグル UI**。`<html data-ruby>` 属性＋localStorage＋初期描画前のインラインスクリプト（静的書き出しなので SSR で分岐できない）。トグルの置き場所（ヘッダーか設定か）は実装時に決める
5. **ルビを入れる箇所の `leading-*` を洗って行高を固定**（ON/OFF で行が動かないように）
6. **「このサイトについて」に慣用読みである旨を明記**
7. スクリーンリーダーでの二重読みを実機確認（`rt` への `aria-hidden` 適用可否）
