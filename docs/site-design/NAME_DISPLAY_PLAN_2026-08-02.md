## 1. 呼称の慣行（Web調査のまとめ）

日本語圏で中国皇帝をどう呼ぶかは、時代によって使う名前の**種類**が変わる。

| 時代 | 通用する呼称 | 理由 |
|---|---|---|
| 前漢〜隋 | **諡号**（武帝・煬帝） | この時代の廟号は全員に付くものではなく、個人の呼び名は諡号が担った |
| 唐〜元 | **廟号**（太宗・徽宗・世祖） | 全員が固有の廟号を持つようになり、逆に諡号が長大化して呼称に使えなくなった |
| 明・清 | **元号＋帝**（洪武帝・康熙帝） | 一世一元の制で在位＝元号が1対1になり、重複の多い廟号より通りが良くなった |

- 諡 — https://ja.wikipedia.org/wiki/%E8%AB%A1
- 廟号 — https://ja.wikipedia.org/wiki/%E5%BB%9F%E5%8F%B7
- 一世一元の制 — https://ja.wikipedia.org/wiki/%E4%B8%80%E4%B8%96%E4%B8%80%E5%85%83%E3%81%AE%E5%88%B6
- 皇帝(中国)（世界史の窓） — https://www.y-history.net/appendix/wh0203-074.html
- 同諡号廟号一覧 — https://ja.wikipedia.org/wiki/%E5%90%8C%E8%AB%A1%E5%8F%B7%E5%BB%9F%E5%8F%B7%E4%B8%80%E8%A6%A7

清の元号呼称が定着するのは中国支配後（順治帝以降）で、ホンタイジは元号が2つ（天聰・崇徳）
あり例外。明の英宗も復位で元号が2つ（正統・天順）ある。

## 2. 現状の診断

カード1行目は `name.commonName`（＋補助名＝諱、`card-subtitle.ts`）。365件の内訳:

| 形 | 件数 | 例 |
|---|---:|---|
| 諡号型「〜帝」 | 124 | 武帝・煬帝 |
| 廟号型「〜祖 / 〜宗」 | 69 | 太宗・徽宗 |
| **括弧つき** | **95** | 太祖（洪武帝）・廃帝（昌邑王） |
| その他（諱・自称号＋諱など） | 74 | 王莽・黄巣・安禄山 |
| 「〜王 / 〜公」 | 3 | |

**「どの種類の名前を使うか」は概ね正しい。** 前漢〜隋は諡号、唐〜元は廟号が入っていて、
1節の慣行と一致する（そこは直す必要がない）。壊れているのは次の4つ。

### (a) 明・清だけ慣行と逆になっている（29人）

`太祖（洪武帝）`・`聖祖（康熙帝）`・`恭宗（宣統帝）` のように**廟号が主・元号帝が括弧の中**。
日本で通っているのは括弧の中の方。明15人・南明3人・清11人が該当。

### (b) 括弧の中身に意味が6種類混在している（95件）

| 括弧の中身 | 件数 | 例 |
|---|---:|---|
| 諱 | 36 | 太祖（朱全忠）・荘宗（李存勗） |
| 元号＋帝 | 29 | 太祖（洪武帝）・聖祖（康熙帝） |
| 爵位・封号 | 13 | 廃帝（昌邑王）・廃帝（東昏侯） |
| 別の諡号・別称 | 8 | 元帝（孝元帝）・孝武帝（出帝） |
| 政権名・注記 | 7 | 侯景政権（正平）・泰定帝（通称） |
| 並列（スラッシュ） | 2 | 太宗/成祖（永楽帝）・英宗（正統帝/天順帝） |

読者はカードの括弧を見ても、それが諱なのか元号なのか爵位なのか判断できない。
**同じ記号が6つの別の役をしている**のが「納得がいかない」の実体。

### (c) 括弧なしの74件に、名前でないものが混ざる

`承天応運啓聖睿文宣武皇帝黄巣`（14字）・`雄武皇帝安禄山`・`応天皇帝史思明` は
**自称の帝号と諱を連結した文字列**で、名前として通っている呼び名ではない。
カード1行目に入るのは全角13字前後なので、黄巣は今この場で切れている。
同型は8件（他に `幼主元釗`・`東海王元曄`・`安徳王高延宗`・`秦王楊浩`・`襄王李熅`）。

### (d) 同名の区別がカードの外で効かない

通用名が重複するのは **37種・104人**（武帝9人、明帝8人、文帝6人…）。ただしこの数字は
括弧が区別に効いている前提で、**括弧を外すと 52種・179人**に増える。
カードは2行目に王朝が出るので判別できるが、`<title>`・OGP・チャートの軸ラベル・検索結果は
1行目の文字列しか持たない。`emperors.ts:1881` が1箇所だけ場当たりで `武帝（漢）` を作っている。

### (e) データからは型駆動で決められない

`posthumousName` は 98/365、`templeName` は 70/365 しか埋まっていない。しかも
**隋文帝は `templeName: 高祖` なのに通用名は「文帝」**、**唐の中宗以降は `templeName: null` なのに
通用名が廟号**。「時代で名前の種類を切り替える」規則を今のデータから計算することはできない。
→ **時代判定のロジックは書かない。** `commonName` を素材に、括弧の処理と上書き表で決める。

## 3. 提案

### 3-1. 文法をひとつに決める

```
1行目:  〈通用名ひとつ〉  〈諱〉        ← 括弧を使わない
2行目:  王朝（時代）
3行目:  在位期間
```

- **通用名は1人につき1つだけ**。別の呼び名（別廟号・別諡号・爵位・元号）はカードに出さない
- **補助スロットに入るのは諱だけ**（現行どおり。`card-subtitle.ts` の上書き表は引き継ぐ）
- カードに載らない名前は**個別ページの「名前」ブロック**へ送り、諱・廟号・諡号・元号・
  民族名・別名を種類のラベル付きで出す。今カッコに詰め込まれている情報の行き先はここ。
  新設ではなく、**`emperor-facts.tsx` の「基本情報」にある名前4行（諱・女真名・廟号・諡号）を
  切り出して独立させる**（在位・死因と同じ dl に名前が混ざっている現状を解く）
- **ラベルの「諱（本名）」は「諱」にする**（2026-08-02 ユーザー指示）。
  `emperor-facts.tsx:168` の1箇所

### 3-2. 決め方は「括弧の処理3規則＋上書き15件＋例外表」

時代で分岐させる必要はない（2-(e)）。次の3規則で **350/365 が決まる**。

| | 規則 | 件数 |
|---|---|---:|
| R1 | 括弧の中が諱 → 括弧を外し、諱は補助スロットへ | 36 |
| R2 | 明・南明・清で括弧の中が「〜帝」→ **括弧の中を1行目に上げる**（廟号は名前表へ） | 29 |
| R3 | それ以外の括弧（爵位・別諡号・別称）→ 括弧ごと落として名前表へ | 21 |
| — | 括弧なしはそのまま | 264 |

残る **15件は id 単位の上書き**（内訳は 2-(c) の自称号＋諱8件、政権名5件、スラッシュ2件）。
これに**例外表**（慣行より知名度を優先するもの: ホンタイジ・明英宗・フビライほか、下の論点）が
数件加わる。**上書き表は 20件前後**に収まり、365人分のレビューは要らない。

**これは1行目（`commonName` 側）だけの数**。補助スロット（`personalName` 側）には
`CARD_SUBTITLE_OVERRIDES` の22件が別に要る（3-7）。表は2つ、と数える。

### 3-3. 明清の反転は同名衝突も減らす

括弧を外すことが前提なら、1行目の文字列の衝突は次のとおり（実測）。

| | 衝突する名前 | 衝突する人数 |
|---|---:|---:|
| 現行（括弧が区別に効いている） | 37種 | 104人 |
| 括弧を外すだけ | 52種 | 179人 |
| **括弧を外す＋明清を元号帝へ反転** | **46種** | **149人** |

**読み違えないこと: 提案は1行目の衝突を「増やす」**（104人 → 149人）。今の104人という数字は
**括弧が識別子として働いている**ことによるもので、その括弧が6つの意味を兼ねているのが
2-(b) の問題そのものだった。提案は識別の役を括弧から**王朝の冠称と諱**へ移す（3-4）。
明清の反転は、R1〜R3 を当てたあとの 179人 → 149人 ぶんの改善で、
**廟号（太祖・世宗・仁宗・高宗…）が既存の衝突名と正面からぶつかるのを避けられる**。

### 3-4. 王朝を冠するのは「カードの外」だけ

- カード内 … 冠さない（2行目の王朝と二重になる）
- `<title>`・OGP・`/database`・チャート軸・検索結果 … **「漢の武帝」形式**で冠する

`emperors.ts:1881` の場当たりを含め、**表示名の決定を1モジュールに集約**する
（`src/lib/display-name.ts` 新設 → `displayName()`・`card-subtitle.ts` を吸収）。

**同一王朝の中で1行目がぶつかる組がある**（実測3組7人）。王朝を冠しても区別できないので、
**冠称形にだけ諱を足す**（カードは2行目の王朝＋補助名で区別できるのでそのまま）。

| 王朝 | 1行目 | 該当 | 冠称形 |
|---|---|---|---|
| 斉（南斉） | 廃帝 ×3 | 蕭昭業・蕭昭文・蕭宝巻 | 斉の廃帝 蕭昭業 … |
| 後漢 | 少帝 ×2 | 劉懿・劉辯 | 後漢の少帝 劉懿 … |
| 梁（蕭梁） | 北斉擁立政権 ×2 | 蕭淵明・蕭荘 | **解消済み**（2026-08-02・Issue #35 で「蕭淵明」「蕭荘」へ改名し衝突しなくなった） |

**ビルド時 assert を置く: 冠称形は365人で一意**。重複したら id を並べて throw する
（`DYNASTY_COLOR_SLOT`・`kana-readings` と同じ種類の検出器）。5節でデータを足したときに
黙って重複が戻るのを防ぐ。

## 4. 実装の注意（着手時）

- **表示文字列を変えると `rubyOf` が throw してビルドが落ちる**。`data/name-readings.json` への
  追記と `site/.ruby-displayed.json` での洗い出し、かな検索 `kana-readings.ts` の確認が必ず要る
- 判断は「日本での知名度」という編集判断なので**サイト側のテーブルに置く**
  （`card-subtitle.ts` の先例。データ本体 `data/emperors.json` は原典準拠のまま触らない）
- カード1行目に使える幅は 1440px・5列で約190px＝全角13字前後。
  現行「太祖（洪武帝）　朱元璋」は12字で切れかけ、提案の「洪武帝　朱元璋」は8字で余裕が出る
- 「恭帝侑 / 恭帝侗（皇泰主）」のように**諡号に諱1字を足して同名を分けている形**が隋に2件ある。
  R3 で括弧を外すのは可だが、`恭帝侑` の「侑」は落とさない（落とすと隋の恭帝が2人重なる）
- **名前ブロックの「元号」行の出所は R2 が消費する括弧の中だけ**（`太祖（洪武帝）`→ 洪武）。
  `regnalTitle` は365人全員が「皇帝」なので使えず、`eraChangeCount.events` は改元イベントで
  文字列の形が別物なので**確認せずに流用しない**。よって元号行が出るのは当面**明清の29人だけ**で、
  それ以外は5節でデータが埋まるまで行を出さない
- **表示から落とす名前（昌邑王・出帝・皇泰主など）は `alternateName` に残す**
  （`app/emperors/[id]/page.tsx:108` の JSON-LD）。カードから消えても記録からは消さない

### 3-8. 名前ブロックの置き方 ― 2カラムに入れない（2026-08-02 実装後の是正）

最初の実装で「名前」を `基本情報`・`回数で見る在位` と同じ `lg:grid-cols-2` の中へ3枚目の
カードとして入れたところ、**配置が崩壊した**（ユーザー指摘）。原因は2つで、どちらも
中身の量を測らずにカードの体裁だけ合わせたことによる。

- **カードが3枚だと2列の格子に収まらない**。1行目が `名前｜基本情報`、2行目が
  `回数｜空` になり、右下に半面ぶん（約370px）の空白が残る
- **中身が少なすぎる**。行数を実測すると **0行56人・1行163人・2行105人・3行39人・4行2人**
  （最大4行）で、**6割が0〜1行**。縦の `dl` に流すと「諱」と「劉盈」が幅の両端へ離れ、
  カードの下半分が空く

是正は**全幅の帯**へ変更（`emperor-facts.tsx`）。「ラベル＋値」を `flex-wrap` で横に流し、
その下に `基本情報｜回数` の2カラムを置く。1行でも4行でも、0行の56人で帯ごと消えても
穴が残らない。同じラベルの重複（「別名 秦始皇」「別名 趙政」）は
`groupEmperorNameEntries` で1行にまとめる（該当3人・並ぶと不具合に見えるため）。

**教訓**: 新しいブロックを既存の格子へ足すときは、**先に中身の量の分布を測る**。
「1件だけ見て体裁を合わせる」と多数派（ここでは0〜1行の219人）の見た目を外す。

### 3-9. 名前ブロックは廃止し、ヒーローの要約チップと入れ替えた（2026-08-02 ユーザー決定・現行）

3-8 の全幅の帯でも**右側が空いたまま**だった（多くの皇帝で行が1つしか無いので当然で、
帯にしても解決していない）。同時にユーザーから、ヒーローの要約チップ
（`死因 暗殺`・`即位 擁立`・`年齢 5歳で即位、38歳で没`）が**直下の「基本情報」と
同じ値を出しているだけ**という指摘があり、**両者を入れ替えて決着**した。

- `emperor-facts.tsx` の「名前」ブロックは**廃止**（`基本情報｜回数で見る在位` の2枚に戻す）
- `emperor-hero.tsx` の要約チップの中身を**名前**（諱・廟号・諡号・元号・別称・別名）に差し替え。
  チップの体裁（角丸・枠・`bg-muted/50`・12px）はそのまま踏襲し、ルビのぶんの行間
  （`leading-ruby`）を確保するため縦の内余白だけ `py-1` → `py-0.5` に詰めた
- 名前は**種類ごとに独立した短い語**なので、ラベルと値が幅の両端へ離れる `dl` より、
  粒で流れるチップのほうが合う。値の最長は14字（黄巣の `別称 承天応運啓聖睿文宣武皇帝`）で
  390px でも1つのチップが折り返さない
- **h1 の脇の補助名と同じ値のチップは落とす**（`e.value !== subtitle`）。諱は多くの皇帝で
  補助名そのもの（「武帝 劉徹」の劉徹）なので、出すと同じ名前が1行下に二度並ぶ。
  この除外でチップが出るのは**160人**（3チップ12人＝清の11人と漢の高祖・2チップ29人・1チップ119人）で、
  残り205人はチップ行ごと出ない（**穴は空かない** — チップは flow なので行が消えるだけ）
- 死因・即位経路・年齢はヒーローから消えるが、**すべて「基本情報」に順位付きで残っている**

**教訓**: 同じ値が2箇所に出ているとき、**足す側だけを見て置き場所を探しても解けない**。
先に「その面で重複している要素」を数え、空いた枠を使い回す。

## 5. 次の段: 名前データを揃える（2026-08-02 ユーザー方針）

**「Wikipedia 並みに名前の情報が一通り揃っている状態にしたい」**（諡号を含む）。
現状は `posthumousName` 98/365・`templeName` 70/365 で、**205人は名前のチップが1つも出ない**
（諱は h1 の脇に出ているので除外される・3-9）。**表示の直し（3節）とは別の作業**として起票する。

- 全365人の諡号・廟号・元号を原典（正史の本紀）から埋める。件数は Issue #16（紹介文365本）級
- `data/emperors.json` の `name` へ入れる。`personalName` の括弧（民族名・改名）も
  `ethnicName { kind, value }` などへ分けると、3-7 のサイト側テーブルが不要になる
- スキーマ変更を伴うので v3 の作法（`docs/schema/V3_MIGRATION_PLAN.md`）に従う
- 埋まったぶんだけ名前のチップが増える作りにしておく（3節の実装で先に器を用意する）

### 5-1. 字・幼名のチップ（2026-08-03・Issue #37 単位4・5）

`name.courtesyName`（字・92人）と `name.childhoodName`（幼名＝原文の「小字」・30人）を
データ側に立て、**名前のチップに出した**。並びは **諱 → 字 → 幼名 → 廟号 → 諡号** で、
原典の書き出し「諱〈諱〉，字〈字〉，小字〈小字〉」の順に合わせてある（廟号・諡号は死後に
贈られる名なので後ろ）。実装は `display-name.ts` の `emperorNameEntries`。

- **`data/name-readings.json` へ116文字列の追記が要った**（`rubyOf` が未登録の漢字表示名で
  throw する）。対象は自分で数えず `site/.ruby-displayed.json` から引く
- **金章宗・衛紹王では幼名のチップが出ない。** 女真語の名を金史が「小字」として載せており
  `ethnicName` と同じ値になるので、`push` の重複排除（同じ名前がラベル違いで2つ並ぶのを
  避ける既存の作り）が落とす。**データ側の欠落ではない**ので、2人だけの例外として許容する
- **遼の8人は「契丹名 耶律堯骨」と「幼名 堯骨」が並ぶ。** 前者は姓を冠した通用形で
  別の文字列なので重複排除に掛からない。**冗長に見えるが両方とも真**で、契丹名がどこから
  来ているかが読める形になる
- 一覧の検索文字列 `searchText`・`/database` の表には**足していない**（かな検索は
  `kana-readings.ts` の手書きテーブルが別に要り、表は `DATABASE_COLUMN_COUNT` を含む
  3箇所の同期が要るため。足すなら別の単位）

  の 2-9・2-10
