## 4. 実測比較（全10章・union 合成後のグラフ）

`node layout.mjs <章…>`。交差数は辺を直線とみなした線分交差の総数。
**ELK のモデル順序は配列の並びそのもの**（`childOrder` を辺の属性で渡しても読まれない）なので、
兄弟を `childOrder` 順に並べて配列へ入れた条件で測っている。

| エンジン | 交差の合計 | 最大の章の幅 | 全10章のレイアウト時間 |
|---|---|---|---|
| dagre | **335** | **6499px** | 185ms |
| ELK（既定） | 10 | 3675px | 486ms |
| ELK（`forceNodeModelOrder`） | **568** | 4891px | 491ms |
| **ELK（`considerModelOrder=PREFER_EDGES`）** | **8** | **3398px** | 348ms |

章ごとに見ると差はもっと露骨で、**dagre は横一列に潰れる**。

| 章 | dagre | ELK（PREFER_EDGES） |
|---|---|---|
| 東晋・十六国（160ノード） | 6499×646px・交差 **107** | 1998×1428px・交差 **1** |
| 南北朝（232ノード） | 6208×1660px・交差 110 | 3398×2192px・交差 **5** |
| 五代十国（99ノード） | 4284×572px・交差 68 | 1594×1220px・交差 **1** |

目視も同じ結論（`site/tools/shots/kinship-spike-*.svg`）。南北朝は ELK だと**王朝ごとの家族が
自然に固まって**並ぶが、dagre では全政権が1本の帯に混ざって横 6256px に伸びる。

**`forceNodeModelOrder` は罠。** 「並び順を厳密に守らせる」オプションだが、交差が
8 → 568 に増える（＝順序を守るために線を交差させる）。使えない。
`considerModelOrder=PREFER_EDGES` は**順序をヒントとして扱う**だけで、交差は増えないまま幅は最小になる。

**そして `childOrder` は、そもそも渡しても渡さなくても結果を動かさない。**
兄弟を id 昇順で渡した対照条件（`ORDERED=0`）は PREFER_EDGES で交差 10・最大幅 3841px、
`childOrder` 順で 8・3398px。理由は**データ側**にあって、
**兄弟が2人以上いる親セット 68 のうち、`childOrder` で順序が決まるのは 14 しかない**
（`childOrder` を持つ子は 152 いるが、多くは一人っ子か、兄弟の片方にしか入っていない）。
→ **兄弟順は「配列に入れる順で渡すだけ」でよく、設計上の論点にならない。**

**性能は論点にならない。** 全10章で 348ms、これは**ビルド時に1回**走るだけ。
出力 SVG は最大の南北朝で 76KB（gzip 後 **7.3KB**）。

## 6. 推奨する構成

**レイアウト＝ elkjs（ビルド時のみ）／描画＝自前 SVG（Server Component）。**

1. **ビルド時に Node で ELK を回して座標を確定し、SVG を静的 HTML へ焼く。**
   クライアントに送るのは HTML と CSS だけ（レイアウトの JS も座標 JSON も送らない）。
   `output: "export"` と `src/lib/emperors.ts` の「データ読み込みはビルド時のみ」契約にそのまま乗る
2. **elkjs は `devDependencies`。** ライセンスが EPL-2.0 OR GPL-3.0-or-later なので、
   **配布物（`out/`）に混ぜない**。ビルド時に座標を計算するだけなら出力は ELK の派生物ではなく、
   論点自体が立たない。クライアントへ持ち込むと（React Flow 併用など）ここが論点になる
3. **オプションは `elk.layered` ＋ `considerModelOrder.strategy: PREFER_EDGES`。**
   `forceNodeModelOrder` は使わない（4節）
4. **union ノードは自前で合成する。** 同じ親集合を持つ子を1つの union にまとめ、親→union→子で張る。
   兄弟は `childOrder` 順で配列へ入れる（ELK のモデル順序は配列の並びそのもの）
5. **継承辺・婚姻辺はレイアウトに渡さず、オーバーレイで描く**（2節）
6. **王朝は色とラベルで表す。枠で囲わない**（5節）
7. **章は `eraId` の11区分をそのまま使う。** 最大でも 232ノードで、旧実装のような章の再定義は要らない
8. **描画は旧 `kinship-chart.tsx`（556行）を下敷きにする。** カプセル・破線ノード・凡例の作りは
   そのまま使え、配色は `globals.css` のトークンから引く

コードの見込み: 消えるのが `layout.ts` 2220行 ＋ `manual-layout.json` 2142行 ＋ `kinship-editor.tsx` 970行、
足すのが**グラフ構築＋ELK 呼び出しで 200行程度**（スパイクの `build_graph.py` ＋ `layout.mjs` が
合わせて約190行で、そこまで動いている）。

ページを足すときの契約（`SITE_SECTIONS` を先に足す・OGP 画像・`nav-data.ts`・
`tools/capture-site.mjs` の `SHOTS`）は `site/AGENTS.md` のとおり。

## 6-2. 見た目（2026-08-01・1回目の却下を受けて）

**最初に出したスパイクの図はデザインとして却下された。** 却下の対象は**見た目だけ**で、
箱と線の家系図という形自体は良い、というユーザー判断（2026-08-01）。ELK の選定は動かない。

作り直したモックの生成は `site/tools/kinship-layout-spike/mock.mjs`
（`node mock.mjs` で前漢の幹の拡大図、`node mock.mjs <eraId>` で章まるごと）。

**値を書き写さない。** 配色は `globals.css` の `@palette` ブロックを、政権色は
`src/lib/dynasty-colors.ts` の `DYNASTY_COLOR_SLOT` を、モック生成時にファイルから読んで流し込む。
スパイクの図が浮いていた原因は `#f4f5f7` のような実値をレンダラに直書きしていたことなので、
本実装でも同じ規律を守る（旧 `kinship/style.ts` も `color-mix(in srgb, var(--series-N) …)` で書かれていた）。

### 図の文法（旧 `/kinship` で承認済みのものを移植）

- **夫と妃を1つの「家族箱」にまとめてレイアウトに渡す。** 妃を独立ノードとして ELK に渡すと
  横に散らばる。箱にすると子は夫婦の下に来る。**これで秦漢の章幅が 2525px → 1519px に落ちた**
- 皇帝＝実線カプセル（政権色）／非皇帝のつなぎ＝破線ピル（灰）／配偶者＝丸ピル
- カプセルは2行。1行目＝皇帝号・通用名、2行目＝**第N代・即位経路の短縮形**（`（易姓）`等の括弧は落とす）
- 皇后＝二重線、妃嬪＝単線。**子は妃ごとの連結線の中点から垂下**し、兄弟は横バーで束ねる
- 養子縁組は破線（実母と養母は別々に夫の脇へ付く。明帝＝賈貴人〔実母〕＋明徳馬皇后〔養母〕→章帝）
- **箱の幅は中の文字から決める**（固定幅だと「竇氏〔孝文竇皇后〕」が溢れる）

### 見た目のために決めたこと（実測が根拠）

| 決めたこと | 理由 |
|---|---|
| `elk.aspectRatio` は **0.7**（既定 1.6 のまま使わない） | 既定だと連結成分が横へ広がり、秦漢が 2575×2038 になる。0.7 で 1519×2368 の縦長になり、縦スクロールで読む面に合う |
| **章は縮めず横スクロール**（`flex-shrink: 0`） | 幅を詰めると SVG が letterbox されて上下に巨大な余白が出る。秦漢 1519px・南北朝 2573px は 1200px の面に収まらない |
| **遠い政権交代は矢印にしない**。受けた側のカプセルに朱の「◯◯から」タグを出す | 図を斜めに横断する線は途中のカプセルを突き抜けて、何と何を結んでいるか読めない。近い（中心間420px以内）交代だけ直交矢印にする |
| **線が1本もつながらない人は図に出さない** | 「採らなかったエッジ」しか持たない人（呂不韋の異説など）が、線のない箱として最上段に並ぶ |
| **実親・確定を異説・養親より優先して1本に決める** | 素直に上書きすると始皇帝の父が荘襄王→呂不韋（異説）に、章帝の母が賈貴人（実母）→明徳馬皇后（養母）に置き換わり、**実親が図から消える** |
| **交代矢印の判定は非皇帝にも政権を割り当ててから**（子→親の順に借りる） | やらないと荘襄王→始皇帝（同じ秦の中の継承）にまで矢印が出る |

### 見た目の残課題

- **1つの章に11政権出ると色が足りない**（南北朝）。`--series-*` は8色で、
  **9区分目の色は作らない**のが `site/AGENTS.md` の契約。宋と陳、斉と西魏が近い色になる。
  章内で使い回すか、隣接しない政権に同じ色を割り当てるかを決める必要がある
- モバイル幅での見せ方は未検討

## 7. 決める必要が残っていること

**ユーザー判断が要るのは #1 の1件だけ**で、残りは実装中に決められる。

### #1（着手前に決める）— 生母エッジ0の宋以降をどうするか

2節のとおり、**宋・元・明・清の4章には実母エッジが1本も無い**。この4章は父だけの縦鎖になり、
他の6章とは図の形が違う。選べるのは:

- **(a) 五代十国までで区切って公開する** — 全10章のうち6章。旧ページが `noindex` の暫定公開のまま
  4章で止まったのと同じ形だが、**止まる位置がデータの完了線と一致する**
- **(b) 全10章を出し、宋以降は「父系のみ」と明示する** — 図の形が章によって変わることを引き受ける
- **(c) 生母調査（ブロック13〜23）を先に終える** — サイト着手が調査完了待ちになる

**先に決めないと、また同じ止まり方をする。**

### 実装中に決めればよいもの

| # | 論点 | 状況 |
|---|---|---|
| 2 | **同名の衝突** | 章内に「武帝」「文帝」「後主」が複数出る。カプセルに政権名を出すか、旧実装の `cardSubtitleOf`（通用名）に頼るか |
| 3 | **61ある連結成分の並び順** | いまは ELK の詰め込み任せ（結果的に王朝ごとに固まってはいる）。政権順をモデル順序で与えて明示的に決めることもできる |
| 4 | **インタラクション** | ノードから `/emperors/[id]` への遷移は静的 `<a>` で足りる。ホバー詳細・ハイライトを入れるならそこだけクライアント側 |

**兄弟順（`childOrder`）は論点から外れた** — 4節の実測のとおり、順序を決められる親セットが14しか
無く、配列へ入れる順で渡す以上のことをする理由が無い。

## 8. 再現手順

```bash
cd site/tools/kinship-layout-spike
npm i --no-save --no-package-lock elkjs@0.12.0 @dagrejs/dagre@3.0.0

for e in qin-han three-kingdoms-jin eastern-jin-sixteen northern-southern sui-tang \
         five-dynasties song-liao-jin-xia yuan ming qing; do python3 build_graph.py $e; done

node layout.mjs qin-han three-kingdoms-jin eastern-jin-sixteen northern-southern sui-tang \
                five-dynasties song-liao-jin-xia yuan ming qing   # 4節の表
node group.mjs northern-southern                                   # 5節の表
node render.mjs northern-southern 'elk(順序ヒント)' ../shots/kinship-spike-northern-southern-elk.svg
```

| スクリプト | 何をするか |
|---|---|
| `build_graph.py` | kinship.json ＋ emperors.json → 章ごとのレイアウト入力（union 合成・継承/婚姻は除外）。**`ORDERED=0` で兄弟順を渡さない対照条件**になる |
| `layout.mjs` | dagre と ELK 4通りを同じグラフに掛け、幅・高さ・交差数・時間を出す |
| `group.mjs` | 政権ごとの compound node（王朝バンド）を試す |
| `render.mjs` | 結果を目視用 SVG に落とす（配色は当てていない・構造だけ） |
| `mock.mjs` | **デザイン検討用のモック**（6-2節）。`node mock.mjs` で拡大図、`node mock.mjs <eraId>` で章まるごと。`FIT=1` で図の全幅が入るページにする（レビュー用スクショ向け） |

モックのスクリーンショット（`site/tools/shots/`・`.gitignore` 対象）:

```bash
node mock.mjs > ../shots/kinship-mock.html                      # 前漢の幹（拡大）
FIT=1 node mock.mjs qin-han > ../shots/kinship-mock-qin-han.html
FIT=1 node mock.mjs northern-southern > ../shots/kinship-mock-nanbeichao.html
```

生成物（`graph-*.json`・`groups-*.json`・`pos-*.json`・`node_modules/`）は `.gitignore` 済み。
SVG の出力先 `site/tools/shots/` も `.gitignore` 対象。
