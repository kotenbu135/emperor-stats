## 2. 残作業: Issue #16「各皇帝の紹介文」

> SEO対策として皇帝名でWeb検索をかけたときに皇帝の紹介文が検索結果に出るようにする。
> 一人ずつ作成する。他サイトからのコピペ禁止。

方針（格納先・分量・出典の扱い）は SITE_DESIGN の8節に移した。ここには**執筆の段取り**を置く。

### いまある受け口（2026-08-01・秦2人の試作で全周を通した）

- `data/emperor-profiles.json` — `profiles: { "<皇帝id>": { lead, description } }`。
  執筆規約は同ファイルの `meta.policy`（素材の範囲・引用・ルビ・文字数の数え方）。
  存在しない皇帝idを書くとビルドが落ちる
- `getEmperorProfile(id)`（`site/src/lib/emperors.ts`）— 未執筆は null。
  読み込み時に `lead` のルビ記法を `assertValidRubySource` で、`description` に
  ルビ記法が混ざっていないことを assert で見る
- ページ側 — `lead` は `<RubyText>` 経由で**ヒーロー内（要約チップの下）**に16pxで出す
  （2026-08-01 ユーザー指示。肖像は sm 以上で float し、長い本文は肖像の下へ回り込む）。
  **200px の肖像の右に入るのは実質2行までで、3行目は肖像の下からフル幅で始まる。
  これはこのままでよい**（2026-08-01 ユーザー判断・前漢14本の実物を見て決定。
  上限を下げて2行に収める案・肖像を160pxに縮める案はいずれも不採用）。
  **行送りは `leading-ruby`**（`leading-loose` のままだとルビのある行だけ高くなって
  段落の中で行間がばらつく）。段落の区切りは空行。
  `description` は `generateMetadata` と Person JSON-LD の両方に効く

### 執筆規約（2026-08-01 確定・全文は `emperor-profiles.json` の `meta.policy`）

書き方の下敷きは Wikipedia のスタイルマニュアル（[導入部](https://ja.wikipedia.org/wiki/Wikipedia:%E3%82%B9%E3%82%BF%E3%82%A4%E3%83%AB%E3%83%9E%E3%83%8B%E3%83%A5%E3%82%A2%E3%83%AB/%E5%B0%8E%E5%85%A5%E9%83%A8)・
[人物伝](https://ja.wikipedia.org/wiki/Wikipedia:%E3%82%B9%E3%82%BF%E3%82%A4%E3%83%AB%E3%83%9E%E3%83%8B%E3%83%A5%E3%82%A2%E3%83%AB/%E4%BA%BA%E7%89%A9%E4%BC%9D)）。

- **第1文は定義文**。主語は皇帝名で「〜は、…の皇帝（人物）である」。そのあとに即位の経緯・在位・
  死の経緯を流れのある散文で続ける。**年譜形式にしない。** 敬称・賛辞・主観的評価を書かない
- **回数8項目の集計値は書かない**（2026-08-01 ユーザー指示）。「改元0回」「反乱8件」の類はすぐ下の
  「回数で見る在位」と重複し、読み物にならない。**個々の事件**（陳勝・呉広の挙兵、沙丘の変…）は
  集計値ではなく事実なので書いてよい。在位年・在位期間・即位/没年齢は書く（君主は在位期間を
  明記するのが人物伝の標準）
- **原文の和訳を `「」` で括って引かない。** 原文でないので引用の規約の字面には触れないが、
  `verify_quotes.py` の台帳が担保しているのは原文で、和訳は誰も検証しない。括弧を外して地の文に溶かす
- **逸話を交える**（2026-08-01 ユーザー指示・「既存の調査結果の範囲内だけ」の決定を撤回）。
  素材に**本紀の原文キャッシュ `_corpus_cache/<皇帝id>.txt`** を足す。ただし**原文で裏が取れた
  事実だけ**書き、有名な逸話でも記憶のまま書かない。**キャッシュは簡体字**なので検索も簡体字で
  （「焚書」0件／当たるのは「非博士官所职」の条・変換は `scripts/hanzi_norm.py`）
- **何を読んで書いたかを `basis` に残す。** 「素材は調査結果だけ」という制約が持っていた検証手段が
  逸話を入れた時点で消えたので、出所は書き手が残すしかない（`verify_quotes.py` は原文引用しか見ず、
  `validate_profiles.py` は文字数と n-gram しか見ない）。lead があって basis が空だとゲートが落ちる
- **confidence が high でなくても通常は言い切り**、史料同士が直接矛盾している場合だけ本文で1句触れる
  （確度の議論は emperors.json 側の note と「典拠・調査メモ」節が担う）
- **`description` は先頭70字に皇帝名・政権・在位年を収める**。スマートフォンの検索結果は70字前後で切れる

**書ける量は人物によって桁で違う。** 本紀の原文キャッシュのサイズ分布は
中央値14.9KB・p25 5.0KB・**p10 1.8KB・最小180バイト**（漢廃帝劉賀の60字）。
素材 note が365人中で最小（108字）の東晋明帝でも、本紀には「日と長安はどちらが遠いか」の問答・
王敦の廃立の企て・単騎の偵察と七宝の鞭が載っていて500字級が書ける一方、
西遼仁宗は『遼史』が「即位し、改元し、在位13年で没した」しか伝えない。
**下位10%（約36人）は逸話が無い**ので、lead の下限を上に置くと骨組みの使い回しが起きる
（それはまさに12-gram ゲートが検出するもの）。150〜600字の幅はこのため。

### 素材の出し方

```bash
python3 scripts/extract_profile_material.py --section '秦（始皇帝以降）'   # 区分ごと
python3 scripts/extract_profile_material.py qin-shi-huang                 # 個別
```

`data/emperors.json`（約7MB）を会話へ読み込まずに、素材フィールド
（`accessionRoute.note`・`deathCause.note`・`reignSummary`・`reigns[].duration.source`・
events・ages の note・回数8項目）だけを Markdown で出す。**原典の再調査は発生しない**ので
コーパス参照・引用ゲートの手順は要らない。ただし**素材の note には正史の直接引用が含まれる**
（`verify_quotes.py` の照合対象）ので、紹介文へそのまま持ち出さず地の文で書く。

### 工程

365人を一度には書けないので、**時代15区分（`ERA_BY_SECTION`）のブロック単位**で進める。
1ブロックごとに次を通す:

```bash
# 1人ぶんの書き上がりは本体へ入れる前に見る（下の「断片単位のゲート」）
python3 scripts/check_profile_fragment.py <断片.json> --basis-corpus
python3 scripts/check_profile_ngram.py <断片.json> --frag-dir <断片の置き場>

python3 scripts/add_profile.py <断片.json>   # 1人ぶんを JSON へ入れる（下記）
python3 scripts/validate_profiles.py   # 文字数・平文・件数・定型文の n-gram
python3 scripts/validate_readings.py   # 総ルビ充足・固有名詞の読み（Issue #20）
cd site && npm run build
PORT=46xx node tools/capture-profile.mjs <id>...   # 表示の確認（並行セッション対策で PORT を変える）
```

`data/emperor-profiles.json` を直接編集せず `scripts/add_profile.py` を通す。指定 id の
キーだけを差し替える read-modify-write（並行セッション対策）で、**かなの前に付いた裸の ｜ を
落とし、漢字の前にあれば止める**。前者は「｜のちに」のような書き癖で毎回起き、後者はルビの
書き漏れなので黙って消してはいけない。入れた直後にルビを剥がした字数も出る。

ブロックは独立して完成した単位で、未執筆の皇帝はページが成立する作りなので、
**ブロック単位で main へマージしてよい**（365本を1ブランチで抱えると並行セッションと衝突する）。

### 機械ゲート（`scripts/validate_profiles.py`・実装済み）

- 文字数の上下限（`lead` 70〜110字・`body` 100〜700字〔任意〕・`description` 100〜140字）。
  **ルビを剥がした長さで数える** — 記法込みだと500字が1200字級になり上下限が意味を失う
- `description` が平文であること（`<meta>`・JSON-LD にしか出ないのでルビは書かない）
- `meta.counts.written` が実数と一致すること
- 全 lead の12-gram を数え、3本以上で共通する箇所を**報告**（エラーにはしない）。
  Issue #16 の「一人ずつ作成する」に対する唯一の機械的な担保
- 本文の年が `emperors.json` の生没年・在位年から作った**範囲の外**にあるときに報告
  （在位期間外への言及はありうるのでエラーにしない）。端の年しか照合しない実装だと、
  在位中の出来事の年——呉楚七国の乱の前154年——が正しくても全部報告に上がり、
  365本ぶん積み上がった時点で本物の当たりが埋もれる。範囲判定にしても、
  `ages` を天文年表記から直した「前209年」型のずれ（このリポジトリが2回踏んだ誤り）は
  1年ぶん外へ出るので捕まる（2026-08-01 に前漢ブロックで実測）
- 空フィールド・存在しない皇帝id（後者はビルド側の assert と二重）

### 断片単位のゲート（2026-08-01・晋ブロックで足した）

既存の2本（`validate_profiles.py`・`validate_readings.py`）は**ファイル全体**にしか掛からず、
1人ぶんの検品には `add_profile.py` で共有 JSON へ入れてしまう必要があった。**並行して15人を書くと
これが成り立たない**（他人の原稿が入った状態でしかゲートを回せない）ので、断片のまま見る2本を足した。

- **`scripts/check_profile_fragment.py <断片.json> [--basis-corpus]`** — 字数（ルビを剥がした長さ）・
  総ルビ充足・裸の ｜・読みテーブルとの切り方一致・`description` の平文性・`basis` の有無。
  **`--basis-corpus` は `basis` に並べた原文断片が本紀キャッシュに実在するかを報告する**（エラーにしない）。
  逸話を入れる方針にしてから、素材の範囲という制約が持っていた検証手段が消えている。
  「コーパス読みが空振りしたまま記憶で書いた原稿」を機械側で疑える唯一の手段がこれ。
  **完全一致では判定できない** — `hanzi_norm` の新字体表は常用漢字を網羅しておらず（郷→乡・舎→舍 が抜けている）、
  正しく引き写した断片でも1〜2字ぶん外れる。最長共通部分列の被覆率が 0.5 未満のものだけを未検出として出す
  （既存の3本で 28/29・24/24・18/19。外れたのは裴注由来と行またぎだけだった）
- **`scripts/check_profile_ngram.py <断片.json> [--frag-dir <dir>]`** — 既存の紹介文と、
  **並行して書かれている他の断片**に対して 12-gram の重複を報告する。`validate_profiles.py` の重複報告は
  **本体へ入れたあと・3本以上で共有された場合だけ**なので気づくのが遅い。実際、晋武帝の初稿は
  「縛めを解き棺を焼いて迎え」を `wu-modi`・`shuhan-liushan` と共有していた
  （同じ280年の孫晧降伏を、降す側と降る側から書いた2本に一字一句同じ節が並ぶところだった）

### ふりがなゲートの向き（2026-08-01・執筆着手時に直した）

`validate_readings.py` の「固有名詞整合」は**本文で振ったルビ → 読みテーブル**の向きで照合する。
逆向き（テーブルのキーが本文に現れたら同じ literal を要求する）は素の部分文字列一致になり、
885キー中352キーが2字以下・**21キーが1字**（元・唐・漢・明・清…）という実データでは
総ルビの本文がまず通らない — 「光武帝」は「武帝」キーで、「前漢」は「漢」キーで、
一般語彙の「元号」まで「元」キーで落ちる。1字キーは照合対象から外してある。

## 4. 執筆の進め方（2026-08-01・晋ブロックで確立）

15人を**1人1エージェント**で並行執筆し、**執筆 → 敵対的検証 → 修正**の3段で回した。効いたのは検証段で、
高い指摘が実際に出ている: 晋武帝で原文「以帝弟攸为嗣」の「帝」を文帝と読み違えて司馬攸を一世代上げていた／
懐帝で五月の倉垣行きと六月の長安逃亡を1つに混ぜていた／恭帝で禅譲詔を起草した主体（傅亮）を恭帝にしていた／
孝武帝で「晋書の志が弑と明記する」という**素材由来の誤りをそのまま本文にしていた**。
**書き手だけでは出ない誤りなので、この段を省かないこと。**

- **`severity` は誤りの重さで付けさせる**（事実の誤り・出所の無い記述＝high、誤読を招く書き方・重複＝medium、文章の質＝low）。
  試作では high/medium だけ修正へ回したが、**事実に触れる low が3件残った**（「加」官を歴任と書く・
  即位当日の大赦と5日後の封建が同日に読める・本紀内で官名が矛盾するのに片方を断定）。**low も修正へ回す**
- **`add_profile.py` を走らせるのは親セッションだけ。** 共有ファイルの read-modify-write なので、
  並行実行すると他人の原稿が黙って消える。エージェントは断片ファイルだけを書く
- **`body` は毎回上限に張り付く。** 晋15本のうち9本が 690〜700字で、指摘を反映するたびに
  「指摘に無い箇所を削る」ことになった。骨子を4段落で先に決める運用は変わらず有効
