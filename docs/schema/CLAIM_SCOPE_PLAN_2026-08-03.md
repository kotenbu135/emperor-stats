# 主張範囲とスキーマの改修計画（2026-08-03・Issue #69）

**この文書の目的**: `events` の日付を「年精度＋在位境界年の月日」へ絞る移行（#69）に入る前に、
**同じ移行でまとめて直すべきスキーマ上の弱点**を洗い、二度と再調査が発散しない形を決める。

決定済み（#69・2026-08-03 ユーザー決定）:

- **B を採用**（値は消さず、主張する精度を絞る）。丸めた月日は `data/internal/event-date-archive.json` へ退避し、内部側はこれ以上精度を追求しない
- **埋め草を廃止**し、保存値の深さそのものを主張にする（年 `"1211"`・月 `"1211-05"`・日 `"1211-05-07"`）
- **散文の新規記入規約を採用**（構造フィールド ＋ `claim` ＋ 構造化した引用で書き、自由記述の長い `note` を新しく作らない。既存には遡及しない）
- \#62 の未訂正9件は訂正せずアーカイブへ入れる（#67 は閉じて `RESIDUAL.md` へ吸収済み）

---

## 1. 診断 — 再調査が発散した共通形は「検査できない主張を作った」

系統ごとに違う話に見えていたものが、実際には同じ形をしている。

| 事例 | 作った主張 | 検査が無い／効かない理由 |
|---|---|---|
| `events` の日付 | 6,026件すべての月日が正しい | 原表記 `*Raw` が無いので機械では真偽を区別できない（`verify_calendar` の `B5=0`） |
| `*Raw`／`conversion`（#56 で新設） | 換算は再演できる | **器を作って中身が0件**。1件も検査していない |
| `source.page`（#53・#60） | 出典はこの書のこの巻 | `--check-books` は**書名しか見ない**ので、巻番号の誤りは全ゲートを緑で通る |
| `confidence`（#42） | 確信度は high/medium/low | **欄ごとに「何に対する確信か」が違う**ので、値を横断で読めない |
| 引用（#38・#52） | 6,504断片すべてが底本に実在する | 88.8%が散文の中にあり、**書名は名乗るが巻は名乗らない** |
| `dynastyOrder`（#24） | 第N代である | 204/365人が `null` のまま欄だけ在り、**未調査と該当なしを区別できない** |

**共通形**: 検査できない主張を配布物に置くと、後から検出器を作るたびに母集団が現れ、
その母集団は「主張している以上ゼロにするしかない」ので終わらない。**発散していたのは欠陥ではなく主張の面積。**

## 2. 規則の提案 — `R-CLAIM-GATED`

> **配布物に新しい主張の欄を作るときは、その欄を検査するゲートを同じ変更で足す。
> ゲートが書けない主張は配布物に置かず、内部側（アーカイブ）に置く。**

- **scope**: `data/emperors.json`・`data/kinship.json` に**新しい欄・新しい意味を足すとき**。既存の欄には遡及しない
- **evidence**: 上の表の6件。とくに `*Raw`（器だけ作って `B5=0`）と `source.page`（巻を照合しない）と `confidence`（欄ごとに意味が違う）は、**ゲートが無い／浅いまま欄だけ増えた**という同型の失敗
- **強制層の正直な評価**: **L3 が上限**。「新しい欄にゲートがあるか」は機械では判定しきれない。実際に効かせられるのは
  - `data/schema/` に**スキーマ変更のチェックリスト**を置き、「この欄を検査するのはどのスクリプトか」を書けない欄は追加しない
  - `check_rules.py` に「RULES.yml の各規則が enforcement を持つ」ことに加え、**スキーマ文書のチェックリストが空欄でない**ことを見せる
  - つまり **L4 に近い**。だからこそ台帳に載せて一覧性を持たせる（RULES.yml の趣旨どおり）

## 3. 端の形（この計画が向かう先）

```
data/emperors.json（配布物・ここに在るものは全部ゲートの対象）
  ├ 値は構造フィールド             … 形が主張（日付は深さ＝粒度）
  ├ claim（前向き1〜2文）          … 突合の向きが反転しない witness
  ├ quotes[]（構造化引用）          … book id ＋ 巻 ＋ 原文断片。巻までゲートで照合
  └ 安定 id（events）              … 参照が index でずれない

data/internal/（配布しない・ゲート対象外・追記しない）
  ├ event-date-archive.json        … 丸めた月日
  └ （第2段）作業ログの散文 note     … 判断の理由・捨てた推論・読んだ形跡としての引用
```

配布物の側に「読めば分かるが機械では確かめられないもの」を置かない。**置きたくなったら内部側へ。**

## 4. 個別項目 — 同梱する／別段にする

**同梱**＝#69 の移行と同じ変更で入れる（どうせ破壊的変更なので、後からやると二度手間）。
**別段**＝独立した作業として順番待ちにする。

### A. `events[]` に安定 id を振る — **同梱**

- **なぜ**: いまの参照はすべて `フィールド[index]` で、event を1件挿入すると全部ずれる。
  `data/screenings.json` に34箇所・`RESIDUAL.md` の #62 の9件・アーカイブの鍵がこの形
- **形**: `events[].id`（`<皇帝id>.<フィールド>.<連番>` を一度だけ焼き、以後 index が変わっても不変）
- **費用**: 6,026件に1フィールド（機械的な転記）＋ **参照側の移行を同じ変更に含める**
  （`screenings.json` の34箇所・`RESIDUAL.md` の9件の一覧・`check_screenings.py`）。
  **参照を移さないなら id を振る意味は無い**

### B. `ages` の日付の深さを揃える — **同梱**

- **実測**: `ages` は既に深さが混在している。年精度で深さ1が66・**深さ3（埋め草）が31**、
  月精度で深さ2が43・**深さ3が11**。合計42値が規約と食い違う
- **なぜ同梱**: 3-2 の「深さ＝主張」を `events` に入れる変更と同じ規則で揃う。
  `birthDate`／`deathDate` は **CSV の列**なのでどのみち破壊的変更に含まれる
- **費用**: 42値の切り詰めとバリデータ1本

### C. `reigns[]` は触らない — **据え置き（明記する）**

- 在位日は集計の根（`exactDays`・`reignSummary`・B-1〜B-4）で、主張を絞る対象にしない。
  埋め草も669値中10件しかない
- **`EMPERORS_SCHEMA.md` に「`events` と `ages` は深さ＝主張、`reigns` はフル ISO ＋ `datePrecision`」と明記する**
  （1ファイルに2つの規約が同居するので、書かなければ次に読む人が取り違える）

### D. `dynastyOrder` の `null` を整理する — **同梱（安い）**

- **実測**: 365人中 **204人が `null`**。既存規約は「フィールド自体が無い＝未調査」なので、
  `null` が「未調査」と「該当なし」を兼ねてしまっている（#43 の「測れないと書き忘れたを区別する形で null を置く」に反する）
- **形**: 未調査は欄を持たない。#24 は「190人が未調査」という**残量表の行**になる（Issue の器ではない）

### E. 出典 `source` の構造化 — **器は同梱・中身は別段**

- **実測**: event 6,026件のうち `source.page` を持つのは **1,940件**、うち巻を含むのは **959件**。
  残りは「旧唐書巻三、貞観十九年条」のように**散文の中**
- **形**: `source: {bookId, volume, section?, lines?}`。`bookId` は `meta.catalogs.books`（新設）を引く。
  **巻をコーパスの巻ファイルと突き合わせられるので、#53 の穴（巻番号の誤りが全ゲートを緑で通る）が閉じる**
- **同梱するのは器とカタログとゲートだけ**。既存4,086件の掘り起こしは別段で、
  **主張する 1,173件から**（日付の主張範囲とそろえる）

### F. 引用 `quotes[]` の構造化 — **器は同梱・中身は別段**（5節で詳述）

### G. `confidence` の意味を欄ごとに定義する — **別段（安い）**

- 語彙は high/medium/low で統一されているが、**何に対する確信かが欄で違う**。
  スキーマ文書に欄ごとの定義を書くだけで、データは動かない（#48 の残件と一緒に片づける）

### H. `count` の不確実性 — **やらない**

- 規約は「`count` に最小件数を置き `note` に不確実性を書く」だが、**実測では 365×8 の全容器で
  `count == events.length`** が成立しており、この運用は使われていない。欄を足す理由が無い
  （#59 の「本紀7件に対し events 6件」は取りこぼしであって、この運用の話ではない）

### 5-2. 当てる問い

> **この引用は、配布物が「底本に実在する」と主張しているのか。それとも読んだ形跡なのか。**

日付と同じで、いまは**全部を主張している**（`verify_quotes --check` が 6,504ユニット全件を対象にし、
未解決が 234 ＋ 57 残っている）。

### 5-3. 提案 — 主張は「構造フィールドに在る引用」に絞る。ただし**床を引く**

**床（これは絶対に主張し続ける）**: 集計に効く判定は、**構造化引用を1断片以上持つことをゲート条件にする。**

| 主張 | 対象 | いまの構造化引用 |
|---|---:|---|
| `reigns` の在位日 | 365人 | 776件（既に構造フィールド） |
| `deathCause` | 365人 | **0**（散文に233件） |
| `accessionRoute` | 365人 | **0**（散文に398件） |
| 8つの `count` | 2,920容器 | **0**（容器 note に1,166件） |
| 主張する日付（#69） | 1,173 event | **0**（`*Raw` と同時に入る） |

**これは件数を減らす提案ではない。**（むしろ床を満たすには新しい転記が要る。）
減るのは**脆さ**で、構造化した引用は `bookId` ＋ 巻を持つので **#53 の穴が閉じ、巻番号までゲートで照合できる**。

**散文の中の引用は「読んだ形跡」として残し、ゲートの対象から外す。**
根拠は3つ:

1. 散文は**新規で書かない**と決まった（規約採用済み）ので、この母集団はもう増えない
2. 年表を1行化すると **note はサイトに出なくなる**（改元・大赦・立后・廃太子の 2,331件だけが残り、それも第2段で構造フィールドへ移す）
3. 第2段で note 自体が内部側へ移るので、**散文の引用は最終的に配布物から消える**

### 5-4. 段取り

1. **器**（`quotes: [{bookId, volume, text}]` と `meta.catalogs.books`）と、**床のゲート**を作る（同梱）
2. 床を満たす転記（`deathCause` 365 ＋ `accessionRoute` 365）— **散文の中から選び直して構造フィールドへ写す**。原典へ戻る必要は無い
3. 8つの `count` は容器 note の引用から1断片ずつ（2,920容器。ここが一番重いので、政権単位で分割する）
4. `verify_quotes --check` の対象を構造フィールドへ切り替える。散文側は `--legacy` で残し、**参考として数えるが CI では落とさない**

## 6. 決定（2026-08-03・ユーザー決定）

**#38 は完走しない。** 未解決234件（＋ #52 の57件）は**主張から落とす**。

- 散文の中の引用は「読んだ形跡」であって配布物の主張ではない、という 5-3 の線引きをそのまま過去にも適用する
- **これは「誤りと知って載せる」ではない。** 234件は「底本で確認できなかった」ものであって誤りと確定したものではなく、
  落とすのは**主張のほう**（値を消さず、直したことにもしない）
- **ただし取り下げは無言でやらない**: `/about` に主張範囲の1文を出し、`data/schema/` に線引きを書く。
  散文の引用がゲート対象外であることを配布物の側から読めるようにする
- \#38・#52 は閉じ、**残量は `RESIDUAL.md` の行**として「構造化引用の床を満たす転記」に置き換える
  （量は Issue の本数ではなく表の行数で増やす＝ `R-RESIDUAL-TABLE`）
