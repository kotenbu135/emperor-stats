## 1. 単位2 — 元号

### 1-1. 人物側に欄を作らない（改元 event から導出する）

**新しい主張は `events[].eraName` の1つだけ**で、「この皇帝の元号一覧」は
`reignSummary` と同じ**導出値**にする。人物側の欄を作ると、同じ事実に対して
主張が2つ・ゲートが2つになるが、片方は他方から計算できるので独立の主張ではない。

導出できることは実測で確かめた（2026-08-03）。

| 測ったこと | 結果 |
|---|---|
| `commonName` の括弧に元号帝を持つ35人（誤検出4人を含む）の元号名が、その人の `eraChangeCount[].events[]` の中にあるか | **31/31**（誤検出4人＝`元帝（孝元帝）` などの諡号を除く） |
| Issue #35 で検索から落ちた5件（義嘉・正平・天正・天成・天啓） | **5/5** 改元記事の中にある |
| 改元 event が0件の皇帝 | 33人。うち `commonName` に元号帝を持つ人は**0人**・清は0人 |

**素の文字列一致では4件が落ちる**（`ming-xuanzong` 宣徳／`ming-shenzong` 万暦／
`ming-xizong` 天啓／`qing-wenzong` 咸豊）。`commonName` が新字体、note の中の原文引用が
底本の字体（宣德・萬曆・天啟・咸豐）で、**同じ元号が別の文字列になっている**ためで、
`scripts/hanzi_norm.py` の `norm_for_match` を通すと4件とも一致する。
**この字体の食い違いこそが構造フィールドを立てる理由**で、いま書けるゲートが
散文の文字列一致では弱い、という Issue 本文の見立てはここでも当たっている。

### 1-2. 欄

改元 event（`eraChangeCount[].events[]`・**681件**）に足す。

| 欄 | 型 | 内容 |
|---|---|---|
| `eraName` | string \| なし | **この event が建てた元号の名**。日本語の新字体（「万暦」「天啓」）。表示に出る側。**任意**（元号制以前の建元・改元には名前が無い＝1-4） |
| `eraNameRaw` | string \| null | 同じ元号の**底本の字体**（「萬曆」「天啟」）。任意・遡及しない。**書くのは底本の字体が `hanzi_norm` の変換で出てこないときだけ**（実装時に絞った・下） |

- **欄名を `eraName` にする理由**: 既存の `eraId` は中身が時代区分（`qin-han`・`yuan`）で
  年号ではない。`era` を人物側で再利用すると読み違えるので、**人物レコードには足さない**
  （1-1）ことで衝突そのものを避ける
- **`eraNameRaw` は `R-EVENT-DATE-RAW` と同じ作法**（原表記を同じ要素に残し、
  再演できる形にする）。日付の `*Raw` が「換算の再演」を可能にするのと同じく、
  ここでは**新字体への書き換えの再演**を可能にする。
  **実装時に「いつ書くか」を絞った（2026-08-03）**: 简体コーパスの「天启」は
  `opencc` が機械的に出す形＝**導出値であって主張ではない**ので書かない。書くのは
  底本が変換の写す先と違う字を使っているとき（繁体の版が「曆／歷」「啟／啓」で割れる形）だけで、
  この線を引かないと681件ぜんぶに機械で作れる値が並び、`R-CLAIM-GATED` が畳んだ
  「器を作って中身は導出値」がもう一度生える
- **改元されて捨てられた側の元号は書かない**。`eraName` が指すのは新しく建てた元号1つ

### 1-5. Issue #35 の5件の回収

`commonName` を政権名から人物名へ直したとき、括弧の中にしか無かった元号が
`searchTextOf` から落ちた。**`aliases` へ逃がすのは誤り**（個別ページで「別称」チップとして
出て名前の種類が合わない）ので、この欄で回収する。

サイト側は `searchTextOf` に**改元 event の `eraName` を足す**。表示（名前チップの「元号」行）は
いま明清29人だけが `commonName` の括弧から出しているが、`eraName` が入った皇帝から
順に増える（NAME_DISPLAY_PLAN 4節の「元号行が出るのは当面明清29人だけ」はこれで解ける）。

**「どの元号で呼ぶか」は編集判断としてサイト側に残す。** 明英宗（正統／天順）・
清太宗（天聰／崇徳）のように元号を2つ持つ皇帝がいて、導出で出るのは**集合**である。
呼称に使う1つを選ぶのは `display-name.ts` の上書き表の仕事で、データ側の主張ではない。

### 1-6. 決めていないこと

- **`eraName` を持つのは改元 event だけか**。前帝が建てた元号を在位中ずっと使った皇帝
  （改元 event 0件の33人）には元号名の置き場が無い。実測で「`commonName` に元号帝を持つ人は
  この33人に0人」なので**当面は要らない**が、単位1で元号の表示を全員に広げるなら再検討する
- **元号の期間（開始年・終了年）を持つか**。持たない。期間は改元 event の `date` から
  導出でき、`R-DATE-CLAIM-SCOPE`（深さそのものが主張）と衝突しない形にするには
  別の設計が要る。**元号の名前だけを主張する**

## 2. 単位3 — `name.ethnicName`

**実装済み**（2026-08-03・下の 2-7 に設計から変えた点）。形と検査はこの節で決めた。

### 2-1. 形

```jsonc
"name": {
  "personalName": "耶律徳光",              // 漢字の諱（漢風名・漢名・漢字音写・漢字諱）
  "ethnicName": { "kind": "khitan", "value": "耶律堯骨" },
  ...
}
```

- `kind` は `meta.catalogs.ethnicNameKinds` の ID。**ラベルはカタログ側**（v3 の作法）
- 括弧つき **32件**（実測・2026-08-03）の内訳は **民族名31**（遼9・金9・元11・北元1・清1）と
  **改名1**（`shiguo-beihan-liuchong`）。Issue 本文の「遼10・元12」は数え方の食い違いで、
  合計32は一致する

### 2-2. 対応表 — 相手側の種類は `kind` から一意に決まる

**同じ括弧が別の現象を指している**（`耶律徳光` は契丹名とは別の漢風の諱、`忽必烈` は
同じ名前の漢字音写）ので、`ethnicName` だけでは相手側のラベルが決まらない。
**`kind` から1対1で決まる4行の表**にすることで、サイト側の政権別テーブル
（`display-name.ts` の `ETHNIC_NAME_LABEL`）を消せる。

| `kind` | ラベル | `value` の字種 | `personalName` の性格 | ラベル | 該当 |
|---|---|---|---|---|---|
| `khitan` | 契丹名 | 漢字 | **別の諱**（漢風名） | 漢風名 | 遼9 |
| `jurchen` | 女真名 | 漢字 | **別の諱**（漢名） | 漢名 | 金9 |
| `mongol` | モンゴル語名 | カナ | **同じ名前の漢字音写** | 漢字音写 | 元11・北元1 |
| `manchu` | 満洲語名 | カナ | 漢字の諱 | 諱 | 清1 |

これで個別ページの名前チップは**データだけで**組める:

```
遼 太宗   契丹名 耶律堯骨 ／ 漢風名 耶律徳光
金 世宗   女真名 烏禄 ／ 漢名 完顔雍
元 世祖   モンゴル語名 クビライ ／ 漢字音写 忽必烈
清 太宗   満洲語名 ホンタイジ ／ 諱 愛新覚羅皇太極
```

### 2-3. これは「欄を1つ足す」ではない — `personalName` が21件動く

**遼9件と元・北元12件の `personalName` の値そのものが変わる**（`耶律堯骨（耶律徳光）` →
`耶律徳光`、`クビライ（忽必烈）` → `忽必烈`）。金9・清1は括弧を落とすだけで前半が残る。

`personalName` は365人全員で h1 の脇に出る補助名の素材なので、**移行の影響は32件に閉じない**:

- **カードの補助名が変わる**。遼8件は現行のサイト側規則（`regimeId === "liao"` なら
  括弧の中）が不要になり**規則どおりに通る**＝上書きが減る。逆に**元・北元12件は
  「カードにはカナを出す」ため、`ethnicName` を出す規則が新たに要る**（政権別1行）
- **ふりがな**（`data/name-readings.json`）・**かな検索**（`kana-readings.ts` の `TABLE_SOURCE`）に
  `忽必烈`・`妥懽帖睦爾` などの漢字音写が新しい表示文字列として出る。`rubyOf` は
  未登録で throw するので、移行と同じ変更で足す（`R-COUPLING`）
- **`resolveQualifiedNameCollisions`** を通す（冠称形の一意性）

**32件は機械の一括置換にしない。** 括弧の前後を入れ替える形が政権ごとに違い、下の3件は
規則の外にある（2-5）。単位1と同じ「1件ずつ原典で確かめて転記」で進める。

### 2-4. 主張と検査

主張は「**この人物の `ethnicName.value` は `kind` の言語・民族の名である**」。

| # | 検査 | 実装先 | 嘘なら落ちる条件 |
|---|---|---|---|
| A | `kind` の実在 | `validate_emperors.py::check_ethnic_name` | `meta.catalogs.ethnicNameKinds` に在る |
| B | **`kind` と政権の整合** | 同上 | カタログ側の `regimes` と レコードの `regimeId` が一致する（`khitan` は遼・西遼のみ／`jurchen` は金のみ／`mongol` は元・北元のみ／`manchu` は清のみ）。**取り違えを落とす主力** |
| C | 字種の整合 | 同上 | `kind` ごとに `value` の字種を検査（`khitan`・`jurchen` は漢字のみ／`mongol`・`manchu` はカナのみ）。2-2 の表が壊れたら落ちる |
| D | 底本に在る | `verify_quotes.py::cmd_check_ethnic_names`（ローカル専用） | **漢字の側**がその人物の名乗る巻の底本に実在する。`khitan`・`jurchen` は `value` を、`mongol`・`manchu` は `personalName`（漢字音写・漢字諱）を照合する。**カナは底本に在り得ないので `kind` 単位で免除**し、そのことを明文にする |
| E | 移行のラチェット | `validate_emperors.py` | `personalName` に `（` を含むレコード数が増えたら落ちる（移行中は減る方向だけ許す）。完了後は0を強制 |

**D が効く範囲**: 全4 kind で**必ず片側は漢字**なので、免除しても「どのレコードも
底本照合を1本は通る」が保てる。**ただし `mongol`・`manchu` で照合するのは相手側
（`personalName` の漢字音写・漢字諱）であって、`ethnicName.value` そのものではない** —
「クビライ」が「忽必烈」の正しいカナかどうかは**どのゲートも見ていない**。
カナ表記は原典に無い編集上の読み下しなので底本では検査できず、
**この欄について D が担保するのは漢字側の実在までである**と明示しておく。

**検出力テスト** `scripts/test_ethnic_name.py`（テストは `scripts/` に置く。`tests/` ディレクトリはこのリポジトリに無い）:

1. 元の皇帝に `kind: "jurchen"` を入れると B が落ちる（クビライに「女真名」が生える形）
2. `mongol` の `value` に漢字を入れると C が落ちる
3. 底本に無い漢字名で D が落ちる
4. `personalName` に括弧を戻すと E が落ちる

## 2-9. 単位4 — 字 `name.courtesyName`（2026-08-03）

遼太祖で「字と小字を取り違えるとゲートが全部緑のまま誤る」形が出たので、字を独立の欄に
した。**任意・遡及しない。**

### 進め方（原典先行・Webは使っていない）

着手前に「Web から先に集めて裏取りするほうが速いか」を測った。答えは**否**で、理由は
2つある。

1. **字は帝紀・列伝の書き出しの定型に入る。** 「諱〈諱〉，字〈字〉」の形なので、
   本人の原文キャッシュに正規表現を当てるだけで365人ぶんが数秒で出る（102人が当たった）。
   Web はこれより速くならない
2. **`R-PRIMARY-SOURCE` が掛かる欄**（`emperors.json` のフィールド判定）なので、Web で
   拾っても結局その1行を原文で読むことになる。**工程が1つ増えるだけ**

一方、**機械が何も見つけなかった側（248人）を「字が無い」と言う段では Web／Wikidata が
効く**。負の主張は原文からは安く出せないので、外部が字を挙げていたら原文を読み直す
引き金にする、という使い方（Wikidata の P25 突合と同じ形）。**根拠にはしない。**
いまは種つき標本6人を原典で読んで取りこぼし率 17%（95%区間 0〜64%）と測ってあり、
そこから先は残量表の行。

### ゲート

| | 見るもの | 実装 |
|---|---|---|
| A | 漢字1〜4字・「字」「諱」を含まない | `validate_emperors.py::check_courtesy_names` |
| B | 諱・民族名・廟号・諡号のどれとも同じでない | 同上 |
| C | 本人の原文に**「字〈値〉」の形で**在る | `verify_quotes.py::cmd_check_courtesy_names` |

**C の隣接がこの欄の主力。** 値だけを本文に探す実装だと2字の断片が本紀のどこにでも
当たって実在検査にならず、**小字を字の欄へ入れた取り違えが素通りする**。
検出力は `scripts/test_courtesy_name.py`（24件）。

### 実装中に測って直したこと

- **「字」の直前で弾く文字表に一般語を入れてはいけない。** 正規化本文は漢字だけになって
  句読点が落ちるので、「字」の直前はたいてい**諱の末字**になる。「文」を弾く表にしていた
  あいだ、東晋恭帝（諱德文・字德文）と南斉海陵王（諱昭文・字季尚）の2件が**正しい字なのに
  落ちていた**。表は名乗りの種類を作る接頭字（小・表・別）だけに絞った
- **本文の先頭に来る字が必ず弾かれていた。** 直前の文字を空文字にしていたが、
  **空文字はどの文字列にも含まれる**ので判定が常に真になる。番兵を置いて直した
  （前燕慕容暐のキャッシュが「字景茂，俊第三子也」で始まる）
- **`hanzi_norm` に `隣`→`鄰` を1字足した**（遼道宗の字「涅隣」・底本は「涅邻」）。
  表を触ると引用台帳の鍵が変わるので `--backfill` を流し直してある

### 当たり102件のうち10件は字ではなかった

**当たりを転記として扱わない理由。** 内訳は動詞用法1（前漢成帝「宣帝愛之，字曰太孫」＝
「字之曰太孫」で名付けたの意）・**本人のキャッシュに同居する他人の伝**8（北魏明元帝の
位置に拓跋燾の字・呉世璠の位置に呉三桂の字・南燕慕容超の位置に慕容鍾の字など）・
一般語1（西夏景宗の「文字」「字形」・清聖祖の「字句」）。

**確定92人**（東晋11・南朝と北朝が中心・遼6・唐以降は明太祖と呉三桂など少数）。
唐24人・北宋9人・元11人・清11人は**帝紀の冒頭定型に字の欄が無い**ので空のまま。

## 2-10. 単位5 — 幼名 `name.childhoodName`（2026-08-03）

単位4で「**小字（幼名）は字ではない**」と決めた側の置き場所。遼太祖は
「字阿保機，小字啜里只」で両方を持ち、単位3の時点では**啜里只がどの欄にも入らなかった**。

### 民族名と同じ軸にしなかった理由

`ethnicName`（単位3）へ寄せる案もあったが採らなかった。**2つは別の軸を測っている**:

- `ethnicName` は**その名が何語か**（`kind`＝契丹語・女真語・モンゴル語・満洲語）
- `childhoodName` は**本紀がその名をどの名乗りの枠に置いたか**（原文の語は「小字」）

金史の書き方が一定しないことがこの分離の証拠になる — 太祖・太宗・熙宗・世宗は
「本讳」、章宗・衛紹王は「小字」、宣宗は「本名」、哀宗は「又讳」で、**同じ女真語の名でも
本紀が置く枠は違う**。だから金章宗の麻達葛は女真名かつ小字で、**両方の欄が同じ値を持つのが
正しい**。ゲートBの突合から民族名を外したのはこのためで、**字の欄とは非対称**になっている
（字の側は民族名と同値なら取り違えなので落とす）。

**この穴が開かない理由はゲートCが持っている。** B から民族名を外しても、民族名を
そのまま幼名の欄へ写した誤りは C で落ちる — 金太祖の阿骨打は金史が「本讳阿骨打」と
書いており、「小字阿骨打」の並びは原文に無いので当たらない。**分離を1つ緩めても
底本照合が判別器として残る**という形で、B と C の役割が分かれている。

**移行はしていない。** 遼の8人が `ethnicName` に持つ「耶律堯骨」などは姓を冠した契丹名の
通用形で、小字そのもの（堯骨）とは別の文字列。両方が名前チップに並ぶ。

### 進め方（単位4と同じ・原典先行）

小字も帝紀の書き出しの定型に入るので、絞り込みは正規表現1本で足りた。**字の絞り込みとの
違いは2つ**:

- **母集団から `courtesyName` の埋まった人物を外さない**（遼太祖は両方を持つ）
- **直前に句読点を要求しない**。「小字」の2字がそれ自体で名乗りの種類を決めており、
  「文字」「名字」のような複合語の後半に当たらない（字の側はここで苦労した）

代わりに**注釈と動詞用法を落とす必要が出た** — 「〈名〉，〈人〉小字也」（劉裕紀の
「駒，愉小字也」）と「小字曰〈…〉」は、直後の1字を値にすると「也」「曰」を拾う。

### ゲート

  A 形           漢字1〜4字・「字」「諱」を含まない        validate_emperors.py
  B 名乗りの分離  諱・**字**・廟号・諡号と同じでない        同上（**民族名は見ない**）
  C 底本         本人の原文に「小字〈値〉」の形で在る      verify_quotes.py（要コーパス）

検出力は `scripts/test_childhood_name.py`（26件）。B の非対称が意図的であることは、
**同じレコードを字のゲートに掛けると落ちる**ことを測って裏を取っている。

### 隣接を要求した代償を1件測った

南漢の劉玢は高祖の遺言が「呼洪度、洪熙小字曰：『寿、俊虽长，然皆不足任吾事』」で、
読めば劉玢（初名 洪度）の小字が「寿」だと分かる。**しかしゲートCの「小字〈値〉」に
ならないので欄に入れられない。** 取りこぼす側に倒した選択で、テストにも明示してある
（残量表の行）。

### 確定30人

宋斉梁陳13・遼9・金2・隋唐五代3・十六国1・南明1・北魏以外の北朝0。**小字を冒頭定型に
載せる書が字よりさらに少ない**（宋書・南斉書・梁書・陳書・隋書・遼史・金史にほぼ限られる）
ことがそのまま出た。当たり32件のうち1件は本人の小字ではなく（梁豫章王のキャッシュが
簡文帝紀を指す）、**免除0件・`hanzi_norm` の追加0件**で通った。

**absent 側の取りこぼしは標本6人で0件**（95%上限46%）。字の17%より低いのは、字が
「帝紀に無くても列伝に在る」形を持つのに対し、**小字は載せない書では列伝側にも出ない**ため。
**鍵が0件の書は証人にならない**ので、6人とも当たりが1件以上ある書で判定してある
（周書は西魏恭帝を「讳廓」「元廓」のどちらでも呼んでおらず、北史の当たりで判定した）。

### 句読点が無い版で確定した1件は別の書で境界を裏取りした

赫連定の底本（十六国春秋）は句読点が1つも無く「赫连定小字直獖勃勃之第五子也」と続くため、
**ゲートCでは語の切れ目を見られない**（「小字直獖」は「小字直獖勃」の部分文字列でもある）。
魏書に「昌弟定，小字直獖。」・北史に「昌弟定，小字直獖，」と**句読点付きの同じ記事**が
在るので、2字で切れることはそちらで確かめた。

### 字と幼名をサイトの画面に出した（同じ turn）

単位4で「ふりがなが要るので出していない」と書いた側を、この単位で片づけた。
名前チップの並びは **諱 → 字 → 幼名 → 廟号 → 諡号**（原典の書き出し「諱〈諱〉，
字〈字〉，小字〈小字〉」の順で、死後に贈られる名より前）。

- **116文字列のふりがなが要った**。数え方は自分で数えず `site/.ruby-displayed.json`
  （ビルドが書き出す）から引く。振り方の規則は2つで、漢語の名は音読み、
  **非漢語の名の漢字音写も音読み**（契丹名・女真名は漢字で伝わるので、モンゴル語名・
  満洲語名のカナ表記とは扱いが違う）。**読みの正しさを見るゲートは無い**ので残量表の行
- **金章宗・衛紹王では幼名のチップが出ない**。女真名と同じ値なので、既存の重複排除が
  落とす（同じ名前がラベル違いで2つ並ぶのを避ける作り）。落ちるのは2人だけ
- **一覧の検索文字列 `searchText` には足していない**（`/emperors` の絞り込み）。
  かな検索は `kana-readings.ts` の手書きテーブルが別に要るため、足すなら別の単位
