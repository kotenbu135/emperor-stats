# 絶対に守るべき制約

## この文書の位置づけ（削ってよい指示との区別）

ここに書かれているのは**このリポジトリで実際に失敗が観測された結果として決まった運用方針**であり、モデルの判断力を補うための一般的な行動指示ではありません。2つは扱いが違います。

- **運用方針（本文書・モデル世代に依らない）**: 自動生成禁止（過去2回失敗）・原文引用の手打ち禁止（引用6,504件の全件検証で約0.4%の改変率を実証）・ゲートスクリプトの合格をコミット条件とすること・並行セッション前提の read-modify-write・外部 API の段階実行。**新しいモデル世代に合わせてドキュメントを整理するときも削らない。** 削ると同じ失敗が再発する
- **モデルの判断力を補う指示（削ってよい）**: 「〜を必ず3回読み直せ」のような念押しの反復、コードスタイルの細かい規定、同じ内容の重複記載、ファイルを開けば分かること、網羅的な例示。これらは Claude 5 世代では不要（むしろ探索の幅を狭める）ため、[AI_RESEARCH_LESSONS.md](AI_RESEARCH_LESSONS.md) 10節の方針に従って整理してよい

判断に迷ったら「これは誰かが失敗して書かれた行か？」で分けてください。本文書の各節には、その根拠になった失敗が併記されています。

## スクリプトによる自動生成禁止

**スクリプトで JSON データを自動生成することは禁止**です。過去2回失敗しています。

人物ごとに個別調査・判定した結果を書き込んでください。

### 計算補助スクリプトはOK

日数計算（ユリウス通日の差分など）のような **purely mechanical な計算補助** にスクリプトを使うのは可です。

**ただし**: 実際に調査・確定した日付を入力する場合に限ります。

### 禁止される使い方

- 史料からの人物リスト抽出をスクリプトに代行させる
- 判定そのものをスクリプトに代行させる

## データセットの一度きりの構築

`data/emperors.json` は一度きりの出力です。

- パイプライン化は行いません
- 自動再生成の仕組みは作りません

## 並行セッションとの共存（read-modify-write の徹底）

同じ作業ツリーで複数の Claude Code セッションが `data/emperors.json` を同時に編集することがあります（2026-07-21 のフェーズB調査で実際に複数回発生）。

- マージスクリプトは必ず「**実行直前に最新のファイルを読み込む**」「**対象 id のフィールドだけ更新する**」「**それ以外のレコード・キーには一切触らない**」を徹底する。ファイル全体を読み込んでメモリ上で書き換えて丸ごと書き戻す方式は、他セッションの並行成果を上書き消失させるリスクがある
- 作業完了時に `git status` / `git diff` で、自分が触っていないはずの id や `meta` ブロックが差分に含まれていたら、他セッションの並行作業の可能性が高い。自分の変更として説明したり、コミットに含めたりしない
- `task.md`・`docs/PROJECT_STATUS.md` のような進捗ドキュメントも同様に混在しうるため、自分が作業した範囲だけを追記する

## 外部 API への一括リクエスト禁止（小規模検証 → 明示的許可）

外部 API（Wikimedia 等）へ大量（100件超など）のリクエストを投げる作業は、いきなり全件実行しない。過去に肖像画調査で Wikimedia API へ364人分を並列実行して 429 と乱用警告を受けた事故があります。

- まず API のレート制限ポリシー（User-Agent 要件・推奨間隔）を確認し、可能なら**公式の一括データダンプ**（オフライン処理）を優先する
- ライブ API を使う場合は数件〜十数件でパイロットし、結果と想定リクエスト数をユーザーに提示して**明示的な許可を得てから**本実行する
- 429 やレート制限警告を受けたら、リトライ・バックオフで粘らず**即座に停止**して報告する
- 成功実績: Wikidata QID 紐付け（2026-07-21）は直列・maxlag=5・専用 User-Agent・計約12リクエストで 429 ゼロ

2026-08-03 から `.claude/hooks/guard.py` が実行の直前に止めます（L1）。**止めるのは件数ではなく形**
です — 反復構文（`for … in` / `while … ; do` / `xargs` / `parallel` / `seq`）か curl の URL グロブ
（`{a,b,c}`・`[1-100]`）に curl／wget を差した Bash が deny になります。閾値を決め打ちすると
正当な調査まで止まるため、件数は見ていません。1本ずつの curl・WebFetch・`gh api` は通りますが、
**分母**（守るべき操作が何回起きたか）として `.claude/hook-log.jsonl` に残ります。localhost と
`gh` は対象外です（適用範囲は [RULES.yml](RULES.yml) の `R-API-BATCH` が正）。

許可を得た本実行はこの形になるので、`EMPSTATS_ALLOW=R-API-BATCH:<理由>` の**理由に件数を書いて**
ください。そうすると escaped の記録がそのまま「何件を許可されて流したか」の台帳になります。

## 原文引用の手打ち禁止（引用の取り扱い規約）

note/quote に入れる正史原文の引用は、モデルが記憶・文脈から打ち直すと約0.4%の率で誤字・改変が混入する
ことが全件検証で実証されています（2026-07-22・22件検出）。引用は必ずツール出力（`scripts/quote_helper.py`
／grep）からコピーし、字体変換・要約・語順変更をしないこと。引用・日付を変更したら
`scripts/verify_quotes.py --backfill && --check` と `scripts/verify_calendar.py` の合格をコミット条件とします。
詳細な5項の規約: [RESEARCH_PROCESS.md](RESEARCH_PROCESS.md) の「引用の取り扱い規約」。

## データ正確性の最優先

**データの正確性が最優先です**。絶対に誤りのないデータが完成するまでサイト構築には着手しません。

`meta.status.overall` が `"in-progress"` の間は、公開・可視化には進みません。2026-07-18に364人全員・全12項目のデータ収集・検証が完了し `"completed"` になりましたが、この方針自体は今後データに誤りが見つかり訂正作業が必要になった場合にも引き続き適用されます。
