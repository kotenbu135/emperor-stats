## 3. すでに取れている証拠 — C類型の機械スイープ（実測）

`quote-refs.json` は、引用が**実際にどのファイルで見つかったか**を記録している。
これと note が名乗る書名を突き合わせた（調査トークン0・所要3分）:

- コーパス直参照の引用 **1,325件**のうち、**309件**で「台帳の書名」と「note の書名」が違う
  （ほとんどは『資治通鑑』と『通鑑紀事本末』のような等価な異本で、無害）
- そのうち **71件（61人）** は、**note が名乗る書の実ファイルに引用断片が存在しない**
- 既知の #32（`dongjin-xiaowudi`）はこのスイープで再現された

ただし**スポットチェック4件のうち3件が誤検出**だった。原因は3つとも機械的で、直せる:
- 引用に `…` を含むと断片が分断される（`tang-gaozu`「（貞観）九年五月庚子…年七十」→ 旧唐書に実在）
- 新字体→簡体の変換漏れ（`歳` が `岁` に落ちない → 史記の「年十三歲」に当たらない）
- 書名辞書の不足（`yuan-tianshundi` は note が正しく『元史紀事本末』を名乗っているのに、
  辞書に無いため「新元史を名乗っている」と誤読した）

**現時点の71件は上限値**であり、正規化と辞書を直せば実欠陥に絞り込める
（残った1件 `han-huidi` は「『漢書』恵帝紀」と名乗るが「七年秋八月戊寅」は漢書に無く史記にある、
という #32 と同型の候補）。
スイープ本体: `/tmp/.../scratchpad/sweep_claimed_book.py`（採用が決まればリポジトリへ移す）。

## 4. 提案 — 「ゲート」と「プロセス」を分ける

`gates-freeze-unvalidated-assumptions` の教訓に従い、**決着済みの機械判定だけをゲートにする**。
「note の散文が原典と一致すること」を主張するゲートは作らない（判断のゲート化＝2026-07-30 の失敗）。

### 4-1. ゲート化できるもの（機械・決着済み・調査トークン0）

| # | 検査 | 潰す類型 | 備考 |
|---|---|---|---|
| **G1** | 台帳の `corpusFile` から導いた書名と、note／`source.page` が名乗る書名の整合 | C | 3節のスイープを `verify_quotes.py` へ。`…` と `歳/岁` の正規化を先に直す |
| **G2** | **既存の note 陳腐化検出の適用範囲を広げる。** 現状は `accessionRoute.note` だけを対象に、「〜と判定／〜に分類／〜を採用」の3表現×7ラベルしか見ていない（`validate_emperors.py:918`）。これを **note 本文に現れる日付・西暦年・年齢を抜き出して同レコードの実フィールド値と突合**する向きへ拡張する | D | #36・#33 の D 4件はいずれも「日付・西暦年を書いた note と実フィールドの乖離」で、現行の3表現には1件もかからない |
| **G3** | note の続柄語（従兄弟・甥・伯父…）と `accessionRoute.axes.relationToPredecessor`・`kinship.json` のエッジの整合 | A | **`validate_kinship.py:404` に同趣旨の TODO が既にある**。散文中の続柄語は **564件／223人**に出現し、母集団は十分 |
| **G4** | 系譜グラフの内部整合（往復エッジ・世代パリティ・親子の生没年可能性） | A（系譜） | 既存の循環検出・軸同期の延長。下記5節 |

### 4-2. プロセスで扱うもの（判断が要る・ゲートにしない）

- **P1（最重要）続柄は「グラフパス」で記録し、漢語の続柄名は機械生成する。**
  エージェントに「従叔父」と書かせない。`father > elder-brother > son` のようなパスを出力させ、
  日本語・漢語の呼称はパスから導出する。A類型は**呼称を選ぶ工程そのものを消す**ことで構造的に無くなる。
  （#36 A の6件は、いずれも同一レコードの他フィールドがパスを正しく持っていた）
- **P2 引用と一緒に「読んだ場所」を必須で持たせる。**
  現状 `source.page` は自由記述で、note の散文と二重に書かれ、片方だけ古くなる。
  台帳（`quote-refs.json`）側が事実上の正になっているので、**note は台帳から生成される情報を参照する**向きに寄せる。
- **P3 史料対立の置き場を作る（E類型）。** いまは「対立に気づいた調査者が note の散文に書く」しかなく、
  書かなければ**気づかなかったのか対立が無いのかを区別できない**。
  採用値・対立値・採否理由を持つ構造フィールドにすれば、少なくとも**空欄が検出可能な状態**になる。
- **P4 第二読解は「別目的」で行う。** 今回の30件は、同じフィールドを2回調べたのではなく、
  **紹介文という別目的で原典を読んだ**から出た。同じ設問での再検証は同じ誤りを再生産する。
  → 検証段のプロンプトは「この判定は正しいか」ではなく「**この人物の一生を原文から書き起こせ**」型にする。

## 5. 系譜・家系図調査への適用

系譜調査は、**A類型（続柄）が主題そのもの**であり、かつ**冗長性がタダで手に入る**という特殊性がある。

1. **調査単位はエッジではなく人物**。1人1エージェントで父・母・兄弟・子をまとめて取らせると、
   相互チェック（A の父が B ⟺ B の子に A が含まれる）が**副産物として**手に入る。
   エッジ単位で割ると、この冗長性が消える。
2. **出力はグラフパス必須**（P1）。呼称は生成物として扱う。
3. **G4 の内部整合を CI へ**: 往復エッジ・世代パリティ（親子で世代差1・兄弟で同世代）・
   親子の生没年可能性（父の没年 < 子の生年 −1年 などは要確認フラグ）・既存の循環検出。
   これらは**原典を読まずに矛盾を出す**ので、掘り起こし自体を調査コストゼロで進められる。
4. **既投入分（生母ブロック1〜16・唐/五代/十国まで）をどうするか**は判断が要る。
   G3/G4 は既存データにもそのまま掛かるので、**遡及スイープは追加調査コストなしで可能**。
   出た矛盾だけ原典に当てるのが最も安い。
