### 3-0c. 混入の実数は 684 字・431フィールド・181人だった（2026-08-02・訂正済み）

**70件も過小だった。** 「底本のどこにも存在しない字形」は、`応`（底本に0回）のような
極端な字しか拾わない。`広` は史藏に1回、`廃` は3回だけ現れる（別の書の異体・OCR ノイズ）ので
この網からこぼれる。`込`・`実` の多くは note の**日本語の地の文**を数えていた分で、混入ではない。

**判定は字形でも全体頻度でもなく、その引用が実際に引いている底本との突き合わせで決まる。**
採った方法は**断片単位のアブレーション**——断片が「新字体表を当てないと当たらない」とき、
表から1字ずつ外して当たらなくなる字を特定する。この字だけが混入である。

| 数え方 | 件数 | 妥当性 |
|---|---:|---|
| 新字体表のキーを含む | 2,983 | ✕ 将・国・号は簡体字と同形 |
| 日本固有の字形を含む（簡体化しても自分自身にならない） | 1,305 | ✕ `為` 761件は繁体の正字 |
| 底本のどこにも存在しない字形 | 50 | ✕ `広`(史藏に1回)・`廃`(3回)を落とす |
| **断片アブレーション（採用）** | **684字** | 底本そのものが基準。431フィールド・181人・96字種 |

内訳は 徳62・歳40・広38・撃36・廃29・応26・県21・挙18・従18・総17…。
`為`・`国`・`号`・`将`・`与`・`万`・`乱` は**アブレーションで全て消えた**（底本に実在する＝版差）。
置換はすべて1字対1字で、文字数の変わった箇所は無い。

置換は該当 span の範囲内だけに限った。フィールド全体を対象にすると、note の日本語
（「継続」「廃位」「事実」）まで壊れる。手当てが要ったのは、底本参照を持たない
`manual`/`external`/`unresolved` の10件（全書走査で底本の字を確認してから置換）。

**この10件のうち2件は引用ではなく日本語の地の文で、2026-08-02 に新字体へ戻した**
（`yuanmo-xushouhui` の「諡号「応天啓運献武皇帝」」・`shiguo-nanhan-liusheng` の
`conversion` が引く「既存note「応乾元年3月9日即位」」）。底本参照を持たないユニットは
**その断片が原文引用なのか、原文を持たない換算メモ・要約なのかを先に決める**。
前者だけが底本の字体に従い、後者は他の日本語と同じく新字体で書く。徐寿輝の諡は同じ
レコードの `verification.notes` 側が新字体のままで、直した側だけが表記の孤立点になっていた。

**底本のほうが壊れていた2件は触っていない**（`quote-refs.json` の `glyphAllow` に理由付きで登録）:

- 北周明帝 `帝因食糖䊚遇毒` — 底本（北史）は「糖**追**」と字が化けている
- 夏の赫連定 `神䴥四年` — 底本（魏書）は `䴥` が落ちて「神四年」になっている

**ゲートは「底本に存在しない字を含むか」ではなく「新字体表の助けなしに底本へ当たるか」で書いた**
（`verify_quotes.py --check`）。表の網羅性に依存せず、`込` のような想定外の字も止まる。
逃げ道は `glyphAllow` の1本だけで、理由の記述を強制する。

**訂正はゲートを回しながら4周した**（368 → 45 → 16 → 2 → 0）。取りこぼしはいずれも
「どの断片を見ているか」のズレで、修復側とゲート側が別の断片を見ていた:

1. 台帳の `span` は40字で切って保存されている → 41字目以降の混入が見えない（実データから取り直す）
2. 台帳は節分割 `fragments()` と6字ずらし `sliding_fragments()` のどちらの断片も使う
   → 片方だけ見ると127件を取りこぼす
3. 字体だけ直すと**ハッシュは変わらない**ので台帳エントリがそのまま残り、
   記録済みの断片が古い字のままになる → `--backfill` に「span を貼り直す」処理を足した

最後に残った2件は**逆向き**で、引用のほうが正字・底本の側が新字体寄りの字形だった
（陸氏南唐書が「顕徳」、通鑑紀事本末が「乗馬」）。`glyphAllow` へ理由付きで登録した。
**逃げ道の無いゲートは、正しい引用を落とすか、最初にぶつかった人に無効化されるかのどちらかになる。**

## 3. すでに取れている証拠 — C類型の機械スイープ（実測）

`quote-refs.json` は、引用が**実際にどのファイルで見つかったか**を記録している。
これと note が名乗る書名を突き合わせた（調査トークン0・所要3分）:

- コーパス直参照の引用 **1,325件**のうち、**309件**で「台帳の書名」と「note の書名」が違う
  （ほとんどは『資治通鑑』と『通鑑紀事本末』のような等価な異本で、無害）
- そのうち **71件（61人）** は、**note が名乗る書の実ファイルに引用断片が存在しない**
- 既知の #32（`dongjin-xiaowudi`）はこのスイープで再現された

ただし**スポットチェック4件のうち3件が誤検出**だった。原因は3つとも機械的で、直せる:
- 引用に `…` を含むと断片が分断される（`tang-gaozu`「（貞観）九年五月庚子…年七十」→ 旧唐書に実在）
- 新字体→簡体の変換漏れ（`歳` が `岁` に落ちない → 史記の「年十三歲」に当たらない）
- 書名辞書の不足（`yuan-tianshundi` は note が正しく『元史紀事本末』を名乗っているのに、
  辞書に無いため「新元史を名乗っている」と誤読した）

**現時点の71件は上限値**であり、正規化と辞書を直せば実欠陥に絞り込める
（残った1件 `han-huidi` は「『漢書』恵帝紀」と名乗るが「七年秋八月戊寅」は漢書に無く史記にある、
という #32 と同型の候補）。
スイープ本体: `/tmp/.../scratchpad/sweep_claimed_book.py`（採用が決まればリポジトリへ移す）。

## 4. 提案 — 「ゲート」と「プロセス」を分ける

`gates-freeze-unvalidated-assumptions` の教訓に従い、**決着済みの機械判定だけをゲートにする**。
「note の散文が原典と一致すること」を主張するゲートは作らない（判断のゲート化＝2026-07-30 の失敗）。

### 4-1. ゲート化できるもの（機械・決着済み・調査トークン0）

| # | 検査 | 潰す類型 | 備考 |
|---|---|---|---|
| **G1** | 台帳の `corpusFile` から導いた書名と、note／`source.page` が名乗る書名の整合 | C | 3節のスイープを `verify_quotes.py` へ。`…` と `歳/岁` の正規化を先に直す |
| **G2**〔**この案は 4-3 で測定により否定。実装は「null とした」「旧→新」の宣言だけ**〕 | **既存の note 陳腐化検出の適用範囲を広げる。** 現状は `accessionRoute.note` だけを対象に、「〜と判定／〜に分類／〜を採用」の3表現×7ラベルしか見ていない（`validate_emperors.py:918`）。これを **note 本文に現れる日付・西暦年・年齢を抜き出して同レコードの実フィールド値と突合**する向きへ拡張する | D | #36・#33 の D 4件はいずれも「日付・西暦年を書いた note と実フィールドの乖離」で、現行の3表現には1件もかからない |

### 4-2. プロセスで扱うもの（判断が要る・ゲートにしない）

- **P1（最重要）続柄は「グラフパス」で記録し、漢語の続柄名は機械生成する。**
  エージェントに「従叔父」と書かせない。`father > elder-brother > son` のようなパスを出力させ、
  日本語・漢語の呼称はパスから導出する。A類型は**呼称を選ぶ工程そのものを消す**ことで構造的に無くなる。
  （#36 A の6件は、いずれも同一レコードの他フィールドがパスを正しく持っていた）
- **P2 引用と一緒に「読んだ場所」を必須で持たせる。**
  現状 `source.page` は自由記述で、note の散文と二重に書かれ、片方だけ古くなる。
  台帳（`quote-refs.json`）側が事実上の正になっているので、**note は台帳から生成される情報を参照する**向きに寄せる。
- **P3 史料対立の置き場を作る（E類型）。** いまは「対立に気づいた調査者が note の散文に書く」しかなく、
  書かなければ**気づかなかったのか対立が無いのかを区別できない**。
  採用値・対立値・採否理由を持つ構造フィールドにすれば、少なくとも**空欄が検出可能な状態**になる。
- **P4 第二読解は「別目的」で行う。** 今回の30件は、同じフィールドを2回調べたのではなく、
  **紹介文という別目的で原典を読んだ**から出た。同じ設問での再検証は同じ誤りを再生産する。
  → 検証段のプロンプトは「この判定は正しいか」ではなく「**この人物の一生を原文から書き起こせ**」型にする。

### 4-3. 実装した結果（2026-08-02・Issue #40・ブランチ `gates-issue40-2026-08-02`）

**G1** — 4-1 の想定どおり、3つの誤検出原因（`…` の分断・`歳/岁`・書名辞書）は照合器の改修で

測り方は3つ試し、**「note が名乗るどれか1つの書に在れば合格」**を採った:

- 引用の位置に**最も近い**書名だけを見る案 → 260件。`三国志魏書` が2書に割れて「魏書を名乗っている」

  この数字を出さないと「全部見て綺麗だった」に読めるので `--check-books` は毎回内訳を出す

**G2 は当初案が成立しなかった。** note の散文にある日付・年・年齢を実フィールドと突き合わせる案は、
3通りの書き方で測って3通りとも誤検出だらけだった:

| 測り方 | 母集団 | 不一致 | 実欠陥 |
|---|---|---|---|
| conversion 中の ISO 日付 vs 在位日付 | 306 | 10 | ほぼ0 |
| 欄名に隣接する ISO 日付 vs その欄 | 153 | 21 | ほぼ0 |
| 年齢語（享年・数え N 歳）vs `ages` | 260 | 57 | 0 |

原因は1つ。**これらの note は「作業ログ」であって、欄の値の主張ではない。**
主用途が「現行 X → Y に訂正した」「既存 X は2ヶ月遅かった」という**捨てた側の値の記録**なので、
素朴に突き合わせると訂正前の値を現在の主張として読む。年齢語のほうは、
「即位時年齢は数え16歳」を `deathAge` の主張として拾ってしまう（散文は欄を名指ししていない）。

そこで G2 は**宣言の形をとる2つだけ**に絞った——「〜は null とした」（対象を ages 以外の note と
日付フィールドへ拡張・55件中3件が陳腐化）と「欄名 旧→新」の**右辺**（5件・全部一致）。
`hou-han-chongdi`「birthDate は年精度のみとし、月日は null」のような**欄の一部を指す宣言**は除外する。

**G3 も当初案が成立しなかった。** `accessionRoute.note` の続柄語は354件／196人あるが、
無作為20件を見ると**先代を指しているものは2割に満たない**。残りは
「孫権」「公孫帝」「中黄門孫程」のような**人名に含まれる字**、「妻を皇后・母を皇太后に立て」のような
第三者、「文宣帝の実弟」（先代は文宣帝の子なので軸は uncle-younger が正しい）のような別人基準である。
先代の名前でアンカーを取ると59件まで絞れるが、残る不一致8件も
「桓帝は子がなく」「明帝の実子ではなく養子」の**否定**と「李雄の兄李蕩の子」の**連鎖**で、実欠陥は0。

置き換えた G3 は**散文を読まない**。`relationToPredecessor` が名指す続柄を
**血縁エッジの実体**と突き合わせる（「子」なら先代が本人の親エッジに実在するか、
「甥」なら先代が親の兄弟か）。216件を判定して不一致0。#36 A の6件が
「同一レコードの他フィールドが正しい関係を持っていた」型である以上、witness はエッジ側に居る。

**G4** — 世代パリティは**実系を優先**して組む必要がある。養子縁組は世代をまたぐことがあり
（石虎は実系では石勒の従子＝石弘と同世代だが、石勒の父・周曷朱の養子でもあるため養子系では一世代上。
晋書自身が「或称勒弟焉」と両様に記す）、素朴に全親子エッジで組むと**原典どおりの続柄が矛盾に見える**。
実親と子の生年差の下限は **12年**（北魏文成帝440年生と実父・拓跋晃428年生が現存最小・原典どおり）。
養親には年齢差の下限を掛けない（李克用856年生と養子・李嗣源867年生の11差が正当）。

**この節の教訓**: 4-1 の表は「何を突き合わせるか」を書いていたが、
**突き合わせる相手が主張なのか作業ログなのか**を書いていなかった。G2・G3 が転んだのはそこ。
**散文は witness にならない。witness は構造フィールドか別のエッジに置く。**

## 5. 系譜・家系図調査への適用

系譜調査は、**A類型（続柄）が主題そのもの**であり、かつ**冗長性がタダで手に入る**という特殊性がある。

1. **調査単位はエッジではなく人物**。1人1エージェントで父・母・兄弟・子をまとめて取らせると、
   相互チェック（A の父が B ⟺ B の子に A が含まれる）が**副産物として**手に入る。
   エッジ単位で割ると、この冗長性が消える。
2. **出力はグラフパス必須**（P1）。呼称は生成物として扱う。
3. **G4 の内部整合を CI へ**: 往復エッジ・世代パリティ（親子で世代差1・兄弟で同世代）・
   親子の生没年可能性（父の没年 < 子の生年 −1年 などは要確認フラグ）・既存の循環検出。
   これらは**原典を読まずに矛盾を出す**ので、掘り起こし自体を調査コストゼロで進められる。
4. **既投入分（生母ブロック1〜16・唐/五代/十国まで）をどうするか**は判断が要る。
   G3/G4 は既存データにもそのまま掛かるので、**遡及スイープは追加調査コストなしで可能**。
   出た矛盾だけ原典に当てるのが最も安い。
