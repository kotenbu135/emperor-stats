**同じ穴から出てきた走査結果を、新しい Issue にせずここへ足す**ための表です。

2026-08-02〜08-03 に、`data/emperors.json` の1件の訂正から横展開が連鎖して Issue が
28本立ち（#40 起点）、うち6本が「同じ穴が別の場所から顔を出しただけ」でした
（#55・#56・#57・#62 → 親 Issue #68 へ統合）。Issue は**片づけ方が1つに決まる問題**を
持つ器で、「母集団 N のうち M 件が未読」という**量**を持つには向きません。量は本数ではなく
行数で増えるべきなので、この表を置きます。

規則は `docs/process/RULES.yml` の `R-RESIDUAL-TABLE`。`gh issue create` は
`.claude/hooks/guard.py` が一度止めます（理由を書けば通ります）。

## 行を足すとき・立てないとき

**ここへ足す** — 既にある系統の走査結果・横展開で出た同型の疑い・標本監査で測った取りこぼし率。
つまり「**どう直すかは分かっていて、残りが何件あるかの話**」。

**Issue を立てる** — 直し方が決まっていないもの。判断・定義・設計が要るもの。
たとえば #58（唐太宗の在位開始日を動かすか）は原典3箇所を読み終えたうえでの**内容の判断**で、
量ではないので Issue が正しい器です。#66（改元の `date` は詔の日か元号開始日か）も定義の問題です。

**行を消すとき** — 母集団を読み切ったか、検出器が乾いた（K 回続けて新しい該当が出ない）とき。
**「訂正が終わった」ではありません** — 未読が残っているなら行は残します。

## 書き方

- **未読・推定は測った数で書く。** 走査していないなら「未走査」と書く（0件と未走査は違う）
- **absent 側（機械が何も見つけなかった側）は、種つき標本を原典で読んで取りこぼし率を測ってから
  推定に掛ける**（規則 `R-SCREEN-FIRST`）。測っていないなら「未測定」
- **記録の列には `data/screenings.json` のキーか、件数を出すスクリプト名を書く。**
  「どこを見ればこの数字が引き直せるか」が無い行は、次に読む人が数え直せない
