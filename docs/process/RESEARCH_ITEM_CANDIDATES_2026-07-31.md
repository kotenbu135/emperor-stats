# 追加調査項目の検討（2026-07-31）

**これは方針ではなく検討の記録。** 「今後どんな項目を調査すると面白いグラフが作れるか」を、
既存データ・ローカルコーパス（`_corpus_cache/` 365ファイル）の実測に基づいて洗い出した。
着手の判断が出た時点で該当項目を Issue 化し、このファイルは削除する。

図の候補そのもの（既存データで作れるもの）は
[docs/site-design/CHART_CANDIDATES_2026-07-31.md](../site-design/CHART_CANDIDATES_2026-07-31.md)。

## 判定の基準 — 順序が大事

1. **本紀に定型で載るか。** これが最優先。理由は下の失敗例
2. **調査コスト** — 365人の個別調査が要るのか、既に読んだ範囲で済むのか
3. **どんな図が作れるか** — 3番目でよい。1で落ちる項目は図の魅力を検討するだけ無駄になる

### なぜ1が最優先か（`ages.accessionAge` の実例）

`accessionAge` の判明率は **明100%（16/16）・清100%（11/11）・三国100%（11/11）・後漢93%（13/14）に対し、
晋18%・北朝15%（5/34）・南朝8.6%（3/35）・十六国系6.7%（3/45）**。
全体では `accessionAge` 172/365 に対し `deathAge` 269/365 で、**`deathAge` はあるのに `accessionAge` が null の人が108名**いる。

**この状態でヒストグラムを描くと、年齢の分布ではなく「どの人物の年齢が復元できたか」の分布になる。**

ただし**この偏りの原因は当初「史料に書かれていないから」と説明していたが、それは誤り**（2026-07-31 ユーザー検証）。
規約は「**直接記載を最優先、次点で確度の高い逆算値を採用する**」（`data/schema/ADDITIONAL_SCHEMA.md`・
三国ブロックで確立し2026-07-17にスキーマへ正式化）で、逆算は許されている。実際:

- **判明率100%の3ブロックはほぼ全員が逆算値。** 明16名は即位時年齢の直接記載がほぼ無く
  `ming-taizu`「1368-1328+1=41歳と算出」、三国11名は全員が年号年ラベルの差分による逆算、
  清11名も直接記載は `qing-shengzu`（「年八歳」）程度
- 後漢だけが例外的に直接記載主力（幼帝の即位記事に「即皇帝位，年十二」型が並ぶ）

**つまり地域差の主因は史料の記載率ではなく、ブロックごとに逆算を適用したりしなかったりした運用のばらつき。**
明・清・三国は2026-07-18のグループ3合算パスで逆算込みに新規調査され、南朝・北朝は
グループ1〜3の副産物ベースのまま残った。

**教訓は2つに分かれる:**

1. **項目の定型性（本紀に載るか）は着手前に確かめる。** 365人を調べ終えた後に母集団の穴が判明するのが最悪
2. **調査手順そのものもブロック間で揃える。** 規約に逆算が書いてあっても、
   ブロックごとに適用したりしなかったりすれば、結果は「史料の偏り」と見分けがつかない穴になる。
   **これは新項目を足すときにも同じ形で再発する**

## 前提として先に決めることが1つ

`data/emperors.json` の `meta.status.overall` はいま `"completed"`（全12項目・365人）。
**「誤りが見つかったら `in-progress` に戻す」という既存の運用は誤りの話で、項目を増やす話ではない。**
13項目目を足すことをデータセットの仕様変更として扱うのか、`completed` の意味を
「12項目については完了」に読み替えるのかは、着手より前に決める必要がある。

## Tier 0 — 追加調査ゼロ。すでに調べてある情報を構造化するだけ

### 元号名（`eraChangeCount.events[].eraName`）

**いま元号名は note の自由文の中にしか無い。** 改元681件のうち **582件（85%）は正規表現で拾える**:

| パターン | 件数 |
|---|---:|
| 「◯◯元年」 | 524 |
| 「◯◯と改元／建元」 | 211 |
| 「◯◯から△△へ改元」 | 38 |
| **いずれかで拾える** | **582（85%）** |

拾えない99件は「改元爲光熹」のように**原文引用の中にだけ元号名がある**もので、
パターンを足せばほぼ拾えるが、最後は目視が要る。

- **原典調査は不要。** 改元681件はすべて調査済みで出典も付いている。作業は構造化と1件ずつの照合
- ただし**抽出結果は1件ずつ引用元と突き合わせる**必要がある（「スクリプトによるデータの自動生成は禁止」の趣旨に照らして、
  機械抽出したまま確定にしない）。681件の確認作業であって、365人の悉皆調査ではない
- **作れる図**: 元号の寿命の分布（何年で改元されたか）／元号に使われた漢字の頻度（「天」「元」「永」「和」）／
  同じ元号名の再利用／[CHART_CANDIDATES の「8. 一世一元への転換」](../site-design/CHART_CANDIDATES_2026-07-31.md)を
  「回数」ではなく「元号1つあたりの寿命」で描き直す（`eraChangeCount.count` は即位時の建元を
  1回に数える規約なので、「回数」のままでは軸の意味が1つずれる）

**費用対効果はこれが最大。** 他のどの項目より安く、既存の改元データの価値を一段上げる。

### `accessionAge` の取りこぼし37名（新項目ではなくデータ訂正）

上の検証で判明した副産物。**生年が判明しているのに `accessionAge` が null の皇帝が37名**
（うち35名は `deathAge` もある）。規約上は逆算してよいので、これは**規約違反ではなく取りこぼし**。

同じ条件で扱いが割れている:

- 埋めた例: `liang-wudi`「生年464年と即位年502年から逆算（502-464+1=39、原文への直接記載はないが安全な年内計算のため採用）」・`liang-yuandi`
- 空欄の例: `liu-song-wendi`・`chen-wudi`・`qi-gaodi`（いずれも生年・没年齢は直接記載あり）

| 内訳 | 人数 | 作業 |
|---|---:|---|
| `birthDatePrecision` が day / month | 23 | 素直な引き算で埋まる |
| `birthDatePrecision` が year | 14 | **`reigns[].startDateRaw` の年号年を確認してから逆算** |

year 精度の14名を機械的に処理してはいけない。グレゴリオ換算年（`reignSummary.firstStartYear`）を
そのまま引くと**年末年始をまたぐケースで±1年ずれる**（数え年は年号年ラベルの差分で取るのが安全。
メモリ `ages-field-policy` の指摘）。

時代の内訳は南朝9・北朝8・宋遼西夏金8・五代十国5・元4・唐3で、**判明率が低かったブロックに集中している**
＝上で書いた「運用のばらつき」の実体そのもの。

- **これを埋めても図は作れない**（172 → 209名＝57%。南朝は12/35止まり、十六国系はほぼ増えない）。
  残る空白は生年そのものが原典に無い人たちなので、偏りの構造は変わらない
- **それでもデータの一貫性としては直す価値がある。** 37名は「調べれば分かるのに空欄」の状態で、
  「調査済みだが不明」（`note` にその旨を書く規約）とも区別がついていない

### Tier 0 に入らないもの（実測して外した）

既存 note に潜んでいるかを全 note フィールド横断で数えた結果:

| 情報 | 何らかの記述がある皇帝 |
|---|---:|
| 崩御場所（「殿」「宮」を含む） | 170名（47%） |
| 陵墓（「◯陵」を含む） | 36名（10%） |
| 出身地・本貫（「人也」「本貫」） | 4名（1%） |

**陵墓と出身地は既存 note にほぼ入っていない**ので、やるなら新規調査（Tier 2）。

## Tier 1 — 決定済みのバックログ。新たな判断は要らない

### ~~`reigns[].dynastyOrder`（第N代）の悉皆調査~~ — **2026-08-20 に完了（Issue #24）**

## Tier 2 — 新規調査。定型性は高いが被覆を先に確かめる

`_corpus_cache/`（365ファイル・本紀の抜粋）で定型表現の出現ファイル数を数えた。
**キャッシュは本紀の抜粋なので、これは被覆の下限**（志・列伝は含まれない）。

| 定型表現 | 出現ファイル | 割合 | 何が取れるか |
|---|---:|---:|---|
| 崩于／崩於 | 142 | 39% | **崩御場所**（◯◯殿・◯◯宮） |
| 葬于／葬於 | 76 | 21% | **陵墓名** |
| 人也 | 81 | 22% | 出身地・本貫 |
| 謚曰／廟號／上尊號 | 15〜13 | 4% | 諡号・廟号の完全形 |

### 崩御場所（39%）

「◯◯殿に崩ず」は本紀の定型。**どの宮殿で何人が死んだか**という図が作れ、
既存の死因データと組み合わせれば「暗殺は正殿では起きない」といった断面になる。
被覆39%は下限だが、それでも「判明者のみ」の問題は残る。

### 陵墓名（21%）

**地図をやるならこれが起点。** ただし本紀内の被覆が低く、実際には帝紀末尾か礼志にある。
**緯度経度は正史から取れないので外部（Wikidata）に頼ることになり、
一括リクエストのルール（小規模検証 → 想定件数を提示して明示的許可 → 本実行）が掛かる。**

### 諡号・廟号の完全形

前回の検討で見つかった通り、いま `posthumousName` は98名分しかなく「孝明皇帝」のような2〜4文字の短縮形。
**唐以降に諡号が長大化する現象（2文字→10文字超）はこのデータに入っていない。**

- ここは**被覆の低さがそのまま現象**という珍しい項目。前漢〜南北朝の諡号は本当に2文字で、
  長いのは唐以降。**空白の分布そのものに意味がある**ので、Tier 3 の落とし方をしなくてよい
- ただし本紀抜粋内の定型表現は4%しか無く、実際の典拠は帝紀末尾・礼志・冊文になる。**調査コストは高い**

## Tier 2.5 — いちばん面白いが規模が大きい：災異記事

本紀でもっとも定型的なのがこの4つ。`_corpus_cache/` 内の出現数:

| 記事 | 件数 | 出現ファイル | 割合 |
|---|---:|---:|---:|
| 地震 | 619 | 132 | 36% |
| **日有食之（日食）** | **518** | 99 | 27% |
| 蝗（蝗害） | 438 | 88 | 24% |
| 彗星 | 100 | 52 | 14% |
| （参考）大赦天下 | 514 | 135 | 36% |

**狙いは「災異と大赦の時間差」。** 大赦1,338件は日付つきで調査済みなので、
災異に日付を付けて調べれば **「災異の直後に大赦が出る」（天人感応）が図として出せる**。
既存データを土台にできる数少ない新規項目で、しかも中国の政治思想そのものが形になる。

- **規模は被反乱の調査（1,853件）に匹敵する。** 全部やるなら大きな調査ブロックになる
- **日食だけに絞るのが現実的で、しかも別の価値がある。** 「日有食之」は完全な定型表現で、
  かつ**天文学的に外部検証できる**（実際にその日に日食があったか）。
  「正史がどれだけ正確に記録したか」を独立に測れる項目は他に無く、
  「正史原典から調査した」というこのデータセットの主張と正面から噛み合う
- 注意: 記録の有無は時代（どの正史か）に依存するので、**「災異が多かった時代」としては描けない**。
  「記録が細かい時代」としてなら正しい。これは反乱データで既に踏んだ地雷と同じ

## Tier 3 — 定型性で落ちる。図の魅力を検討する前に外す

| 項目 | 落とす理由 |
|---|---|
| **子女数** | 典拠が諸子伝・后妃伝で**本紀の外**。列伝の充実度が王朝で違い、`accessionAge` と同じ失敗になる |
| **人口・戸数** | 地理志・食貨志に断続的にしか無く、王朝ごとに基準年も違う。時系列にならない |
| **科挙の実施回数** | **隋以降にしか存在しない**。母集団が王朝の境界で切れるのは、年齢2タブを落としたのと同じ形 |
| **出身地・本貫** | 本紀は列伝形式でないため「人也」は22%。皇帝は列伝を持たないので典拠が薄い |
| **宰相・重臣の交代** | 本紀に任免記事はあるが件数が膨大で、しかも官制が王朝で違うため横に並べられない |
| **身体的記述（身長など）** | 「長八尺」等はあるが逸話的で、記録される人物が偏る |
| **宦官・外戚の権勢** | 定性判断になり、原典に根拠を置くという原則と相性が悪い |

## まとめ

| 順位 | 項目 | コスト | 作れる図 |
|---|---|---|---|
| **1** | **元号名の構造化**（Tier 0） | **調査ゼロ・681件の照合のみ** | 元号の寿命・使われた漢字・一世一元の描き直し |
| **1'** | **`accessionAge` 取りこぼし37名**（データ訂正） | 小（23名は引き算・14名は年号年の確認） | **図は作れない**。データの一貫性の問題として別枠 |
| **2** | ~~**`dynastyOrder` 53政権**（Tier 1）~~ **2026-08-20 に完了** | 中（決定済み・実行のみ） | 第N代 × 在位長／非業の死率。創業者と末代の違い |
| **3** | **日食記録**（Tier 2.5 の絞り込み） | 中〜大 | 大赦との時間差（天人感応）／**正史の記録精度を外部検証** |
| 4 | 崩御場所 | 中 | どの宮殿で何人が死んだか × 死因 |
| 5 | 諡号・廟号の完全形 | 大 | 諡号が唐以降に長大化する（空白の分布自体が現象） |
| 保留 | 陵墓名＋地図 | 大＋外部API | 陵の地図・時代ごとの重心移動 |

**1と2は性質が違う。** 1は「既にあるものを使える形にする」、2は「決めたのにやっていないものを片づける」。
どちらも新しい判断を必要としないので、13項目目を足すかどうかの議論とは独立に進められる。
