# ローカルコーパス利用メモ

`china-history/`・`daizhigev20/`（[RESEARCH_PROCESS.md](RESEARCH_PROCESS.md)参照）を実際に調査で使う際の実務的な注意点・インデックスをまとめます。Claude の作業メモリにも同内容がありますが、マシン間で共有されないため、他の作業者や別環境で作業を再開する場合に備えてここにも記録します。

## コーパス検索のメモリ事故対策（`.{0,N}KW.{0,N}` 禁止・2026-07-24）

**史書調査中に WSL が落ちる（OOM）事故の主因は、コーパスに対する `grep -oE '.{0,40}(追尊|七廟|…).{0,40}'` 型のコンテキスト抽出パターンである。** 実測（2026-07-24）で確定した事実：

- **研究シェルの素の `grep` は GNU grep ではなく ugrep**（Claude Code が注入するシェル関数が同梱 ugrep を `-G --ignore-files --hidden` で起動するラッパー。`declare -f grep` で確認できる）。`/usr/bin/grep` が GNU grep、`rg` が ripgrep。
- **ugrep はこの `.{0,N}(巨大な漢字選択肢).{0,N}` 形を処理する時だけ爆発する**。再帰の有無は無関係で、**単一10MBファイル（明史.txt）でもピーク 4GB 超で強制終了（約37秒）**。トリガーは有界反復 `.{0,N}` で大きな Unicode 選択肢を挟む正規表現形状（ugrep の自動機構築が肥大）。
- 同じパターン・同じファイルで **`/usr/bin/grep`（GNU）＝3MB、`rg`＝20MB・0.02秒**。ヒット集合は3エンジンともバイト単位で一致（ugrep ≡ GNU grep は diff 0行）＝**品質劣化なし**。

**恒久ルール**（メイン会話・Workflow サブエージェント共通）：

1. **`.{0,N}KW.{0,N}` 形のコンテキスト抽出を素の `grep`／Grep ツールでコーパスに掛けない。** これが唯一の事故トリガー。前後文脈が欲しい時は `-n`（行番号）で位置特定 → `Read` の `offset`/`limit`、または `-C`（前後行）を使う。素のキーワード・選択肢検索（`.{0,N}` なし）は ugrep でも安全に完走する。
2. どうしても `.{0,N}` インライン抽出が必要なら **`/usr/bin/grep`（GNU・フラグ完全互換のドロップイン）か `rg` を明示指定**する。`rg` は最速だがフラグ体系が別（`-E` は「エンコーディング指定」で拡張正規表現ではない・POSIX でなく Rust regex）なので、grep フラグの無変換コピペは不可。
3. **範囲を絞る** — 単一書名ファイルか `_corpus_cache/*.txt`（数KB）を対象にし、コーパスツリーの再帰全走査をしない（本ドキュメントの行番号インデックス・キャッシュ機構がこのためにある）。
4. 重い検索を Bash で回す時は `( ulimit -v 4000000; … )` でハード上限を掛ければ、暴走してもエラー死して WSL 全体を巻き込まない（`ulimit` は Bash 子プロセスのみ有効・内蔵 Grep ツールの ugrep には効かない）。`.wslconfig` の `swap=16GB` は最後の安全網（前回 OOM 時の `swap=0` から改善済み）。

関連: [[wsl-crash-oom-claude-2026-07-23]]（メモリ側の記録）。

## china-history 側のファイル名・ラベルの罠

`china-history/` は正史ごとに本紀・列伝が章単位HTMLに分割されているが、ファイル名の巻数表記やラベルに書ごとの罠がある。新しい書に着手する前に確認する。

### 1. 列伝ディレクトリのファイル名巻数が絶対巻数ではなく相対番号になっている書がある

- **宋史**: 本紀47+志162+表32=241巻を差し引いた相対番号（例: 絶対巻243→列伝ファイル名は2）
- **金史**: 同様に本紀・志・表の巻数を差し引いた相対番号
- **明史**: 本紀24+志75+表13=112巻を差し引いた相対番号（例: 絶対巻122「韓林児伝」→ファイル名10、絶対巻123→ファイル名11）
- **元史**: 本紀ディレクトリは絶対巻数と一致（元史は本紀のみ47巻で完結するため例外）。列伝側は要確認。

対応: 新しい書に着手する際は、着手前に1〜2件を原文の巻数記載（「卷○○」等の見出し文言）と照合し、絶対番号か相対番号かを確定してからWorkflowプロンプトに明記する。

### 2. 「原文」ラベルのファイルが実際には白話訳（現代語訳）になっているデータ不備

実例: `china-history/晋书/帝纪/第十章--原文.html`（東晋・安帝紀＋恭帝紀相当）はラベル「原文」だが中身が白話訳。この巻は`daizhigev20/史藏/正史/晋书.txt`を代わりに使用した。

対応: 新しい巻を原文として引用する前に、文言文（漢文調、断句や虚字の使い方）であることを目視確認する。文体が現代語調（「的」「了」「是」の多用等）なら白話訳の取り違えを疑い、daizhigev20側で裏取りする。

### 2b. 漢書の「傳」ディレクトリ・版系統の罠（2026-07-24・生母調査ブロック1で判明）

- **`china-history/汉书/传/` のファイル番号は篇次と一致しない**（一定オフセットでもない）。実例: 武五子傳＝傳第三十三だがファイルは `第三十四章-武五子传`、外戚傳上＝傳第六十七だがファイルは `第七十二章-外戚传上`。**巻数・篇次から番号を計算せず、`ls` してファイル名の篇名で選ぶこと**。
- **`daizhigev20/史藏/正史/前汉书.txt`（四庫本系統）は「防」が複数の別字のプレースホルダとして現れる破損がある**（例: 典喪→典防・喪主→防主・會昭帝崩→防昭帝崩）。引用は句読点付きの `china-history/汉书/` 側から採る。
- **逆に china-history 側にも脱字・字形破損がある**。実例（外戚傳上）: 「皇孫妻妾無號位皆稱家人子」が「皇孙妻、帝无号位…」と破損／宣帝の外祖父「王廼始」が「王虒始」に破損／「家本涿郡蠡吾平乡」の涿は china-history 側にのみ存在（daizhi 側が脱字）。**漢書の外戚傳・列傳を引用するときは両コーパスを突合してから採用する**。
- 前漢の**生母の裏取り本命は漢書 巻九十七上・下 外戚傳**（`china-history/汉书/传/第七十二章-外戚传上-原文.html`・`第七十三章-外戚传下-原文.html`）。本紀冒頭の「母曰○○皇后」は嫡母・追尊号のことがあるため、必ずこちらで「生」「所生」を確認する。

### 2c. 南史 卷八（daizhigev20）に文字化け区間がある（2026-08-03・Issue #55）

`daizhigev20/史藏/正史/南史.txt` の **1187行目**（梁本紀下・大寶二年八月戊午、簡文帝の廃位記事）に
別エンコーディングの残骸が混ざった区間がある。

- daizhigev20: 「景遣**尬牢厩渑眦痢⑾峁跎笕氲睿系?**晋安王」
- china-history（`南史/原文版南史/卷八-原文.html`）: 「景遣**僞卫尉卿彭隽、厢公王僧贵入殿，废帝爲**晋安王」

同じ行の前後は正常なので、**行単位の検査では気づかない**。南史から引用を採るときは
china-history 側を優先し、daizhigev20 側で採るなら該当断片が文言文として読めるかを目視する
（2b の漢書と同じ型で、書が違えば壊れ方も違うので「片方が正しい」と一般化しない）。

### 3. china-historyに収録がなく daizhigev20 が必須になる書

清史稿・資治通鑑・西夏書事・十国春秋等（china-historyは二十四史＋新旧五代史のみ収録、これらの準正史・編年体史料は非収録）。

対応: 着手前に対象の書が二十四史＋新旧五代史に含まれるか確認し、含まれなければ最初からdaizhigev20（行番号インデックス化が必要な場合は [SOURCE_MAPPING.md](SOURCE_MAPPING.md) 参照）を使う前提で計画する。

## 帝紀に独立記述のない人物は列伝・編年体史料で代替する

在位が極端に短い皇帝・廃位された皇帝・傍系から立てられた皇帝は、**正史が独立した帝紀（本紀）を立てていないことがある**。この場合、本紀を探して見つからないことを「史料に記載がない」と結論せず、列伝・諸子伝・編年体史料へ回る。実例（詳細と巻・行範囲は [SOURCE_MAPPING.md](SOURCE_MAPPING.md)）:

- 前漢・劉賀（在位27日）→ 漢書 武五子傳・霍光傳
- 唐・殤帝（重茂）・徳王裕（李裕）・李承宏・李熅 → 旧唐書／新唐書の列傳（李熅のみ独立伝が見当たらず僖宗紀の当該期間記述で代替）
- 西燕・慕容瑤 → 晋書・十六国春秋とも独立記述なしのため資治通鑑
- 前秦・苻崇 → 晋書に本人の独立記述なし、十六国春秋輯補が唯一の主要出典

対応: 対象人物の本紀が見つからない時点で `_corpus_cache/<id>.txt` が薄い断片になっていないかを確認し（劉賀のキャッシュは180バイトの断片だった）、`scripts/build_corpus_cache.py` のマッピングへ列伝側を追記してから調査に入る。

## 年月日の読み取りで踏んだ罠（2026-08-03・Issue #56 の親征日付）

いずれも「原文はあるのに機械にも人にも見えない／別の日を指す」型で、日付を1〜3ヶ月、ときに1〜3年ずらす。

- **段落見出しの月は、その段落の全記事の月ではない**（telescoping）。魏書 肅宗紀の孝昌元年春正月段は、
  梁書本紀が三月乙丑とする豫章王綜の彭城入りまで含む。段落内の別記事が他書で別月に日付づけされていないか
  1件確認してから月を決める。編年体（資治通鑑）にも同型があり、無日付の連鎖を直前の月見出しへまとめて
  流し込む（後秦の弘始十二年で、後秦録が二月とする記事が三月の後ろに回っていた）。
- **干支の字が壊れていて走査に当たらない。** 晋書は daizhigev20・china-history の**両方**が太寧二年の
  「丁酉」を「丁西」と誤刻している（西は地支ではないので読みは丁酉しかない）。資治通鑑が正しい字を持つ。
  魏書の年号字「神䴥」は PUA、北史は「蒨」で代用。宋史の「鄜」も PUA（U+E24E）で、引用を1断片で作れない。
  **異体字が正規化で同一視されない例もある** — 十六国春秋は「僣」（U+50E3）を使うが引用側は「僭」（U+50ED）で、
  `xia-heliading` の `reigns[0].quote#0` は文面が完全に一致していながら未解決のまま残る（Issue #65 で確認。
  同型が他にあるかは未走査）。**照合が通らないときは、まず底本側の字形を1字ずつ見る。**
- **朔が本文と計算でずれる書がある。** 清史稿 聖祖本紀の康熙二十九年「八月乙未朔」は、同書 福全伝の
  「八月己未朔」および七月庚寅朔＋29日と矛盾する（乙未朔だと同月の乙丑が第31日になって成立しない）。
  **本文に朔の干支があるときは必ず暦ライブラリと突き合わせ、合わなければ同じ書の別の巻で当て直す。**
- **閏月の置き場所が本紀と sxtwl でずれる年がある。** 後漢書 光武帝紀の建武三年「閏月」は正月と二月の間だが
  sxtwl は閏を二月の後に置く。**閏がからむ換算は月番号でなく干支から当てる**（`fromLunar(y,m,d,leap=True)`
  の形で conversion に書くと暦ゲートの再演が別の月に落ちる）。
- **`_corpus_cache/` のスライスが事件の手前で切れていることがある。** `xia-helianchang` は承光三年まで、
  `xia-heliading` は勝光三年までで、いずれも当人の最期（承光四年・勝光四年）を含んでいなかった
  （2026-08-03 に行範囲を1行ずつ広げて解消・Issue #65）。キャッシュだけを読むと「原典に記事が無い」と
  誤読する。**キャッシュの末尾が在位の途中で終わっていたら `build_corpus_cache.py` の行範囲を疑う**。
  疑わしいのは**行番号を直書きしているスライス**（`<書>_lines[a:b]` の形）だけで、`slice_between()` は
  終端マーカーで切るのでこの形では壊れない。直書きは2026-08-03 時点で8箇所あり、この2件以外は
  いずれも巻・紀・伝の境界（賛曰・論曰・次の列伝の見出し）で切れていることを確認済み。直すときは行番号が動いてキャッシュ参照型の引用照合が
  ずれうるので、`verify_quotes.py --backfill && --check` まで含めて1つの作業にする（末尾に足すだけなら
  先行行の行番号は動かない）。

## 皇帝ごとの原文キャッシュ（`_corpus_cache/`）

2026-07-17、トークン効率化のため、同一人物の原文を複数の調査グループ（改元・親征・遷都・年齢等）で何度も読み直す無駄を減らす目的で、`scripts/build_corpus_cache.py`を作成した。china-history（HTML）・daizhigev20（txt）から人物ごとの本紀原文を抽出し、HTMLタグ・ナビゲーション文言を除去した上で`_corpus_cache/<id>.txt`に書き出す。判定・調査を伴わない機械的なテキスト抽出のみで、出典・巻の同定自体は [SOURCE_MAPPING.md](SOURCE_MAPPING.md) のインデックスに基づく。

`_corpus_cache/`は`.gitignore`対象（china-history/daizhigev20と同様、ローカルコーパスから決定論的に再生成可能なため）。再生成する場合は`python3 scripts/build_corpus_cache.py`を実行する。新しいブロックに対応する際は、このスクリプトに書名・巻・行範囲マッピングを追記していく。

**現在対応済み**: 明（16名）・清（11名、宣統帝は清朝期1908-1912のみ）・前漢（14名）・後漢（14名）・五代十国（34名）・宋遼西夏金（52名）・元/北元/元末群雄（18名）・秦/新末群雄/玄漢/西晋/五胡十六国/南北朝（48名、グループ5単独ブロック）・三国/両晋/十六国追加/南朝/北朝/隋/隋末群雄/唐（149名、task.md 3-1 フェーズB B-2、2026-07-21）。364名（`zhonghuadiguo-yuanshikai`＝袁世凱のみ正史範囲外のため対象外）全員分のキャッシュが揃っている。各ブロックの書名・巻・行範囲は [SOURCE_MAPPING.md](SOURCE_MAPPING.md) の対応表に対応する。
## 書名・巻・行番号の対応表は別ファイル

王朝ブロックごとの「どの書のどの巻・どの行範囲を読むか」の対応表は、分量が大きく該当ブロックの作業時にしか使わないため
**[SOURCE_MAPPING.md](SOURCE_MAPPING.md)** に分離した（明・清の行番号インデックス／前漢・後漢／五代十国／宋遼西夏金／
元・北元・元末群雄／明清交替期群雄／グループ5単独ブロック／B-2ブロック）。本ファイルは書物・王朝を問わず効く罠と原則に絞る。

**着手のたびに読むのは本ファイル**で、担当ブロックの表だけ SOURCE_MAPPING.md から引く、という使い分けにする。
