## 1. 「ドキュメントに書いたのに守られなかった」の内訳 — 5類型

すべてこのリポジトリで実際に起きたもので、**型ごとに効く手当てが違う**。

| 型 | 実例 | なぜ守られなかったか |
|---|---|---|
| **1. 読まれない** | CORPUS_NOTES・RESEARCH_PROCESS を読まずに調査エージェントを起動して手戻り（**複数回**。CLAUDE.md 自身がそう記録している） | 「着手前に読む」は行為者の記憶に依存する。読まなかったことを誰も検出しない |
| **2. 適用範囲が書かれていない** | 「判定の根拠は原典に置く」をデータ判定の規則と知らず紹介文にも掛かると解釈し、Web 照合をしないまま76人ぶんを公開（AI_RESEARCH_LESSONS 11-5） | 規則本文に**適用範囲の欄が無い**。広げても狭めても検出できない |
| **3. サブエージェント・Workflow へ届かない** | 引用5項は RESEARCH_PROCESS に「調査エージェント（**Workflow 含む**）のプロンプトにはこの5項の遵守を明記すること」と書いてある — つまり**親が毎回手で写す設計**。写し漏れても誰も気づかない。紹介文の雛形が 2026-08-02 までスクラッチパッドにしか無く、セッションが切れるたび書き直していたのも同型 | 規則の運搬手段が「親の記憶＋コピー」。**運搬経路そのものが無い** |
| **4. 守ったつもりで範囲が狭い** | 「対象 id のフィールドだけ更新」は守ったが、他セッションのブランチにコミットした（2026-08-02）。Issue #34 の「日付フィールドは正しい」が reigns・ages 止まりで events を含んでいなかった | 規則の言葉が指す範囲と、行為者が想定した範囲がずれる |
| **5. そもそも書かれていない結合** | 肖像6件を manifest から外したのに画像ファイルを消さず deploy gate が落ちた／表示名を変えて `kana-readings.ts` の `TABLE_SOURCE` を直さずビルドが落ちた／`timeline-river.ts` の `STREAM_DEFS` 追記漏れ | **規則違反ではない。規則が書かれていなかった。** 「X を触ったら Y も触る」という結合が誰にも登録されていない |

**観察**: 既存のゲートは全部「データの欠陥」を見ていて、**手順が実行されたかどうか**は誰も見ていない。
唯一の例外が引用の手打ち禁止で、引用を変えると照合台帳のハッシュが合わず `--check` が落ちる
＝**規約を迂回したことが機械に分かる**。この形が当たりで、本書は要するにその横展開である。

## 2. 強制力は4層ある — 規則ごとにどの層へ載せるかを決める

| 層 | 手段 | 効く型 | 迂回されるとき |
|---|---|---|---|
| **L0 構造で消す** | 選ぶ工程そのものを無くす（続柄を漢語で書かせずグラフパスで書かせる） | 1・2・4 | ほぼ無い（最強） |
| **L1 その場で止める** | hook（PreToolUse / Stop） | 1・4 | 逃げ道が無いと無効化される |
| **L2 手順に埋め込む** | `.claude/agents/` のエージェント定義・名前つき Workflow・skill | 3・1 | 定義を使わずに素の Agent を立てれば外れる |
| **L3 事後ゲート** | `validate_*.py`・`verify_*.py`（既存） | 1〜5 の結果 | 逃げ道つきなら健全 |

**ドキュメントに書くことの強制力は 0 である。** L0〜L3 のどれにも載っていない規則は
「次に破られる候補」であって、それを可視化するのが最初の一手（3-1）。

## 3. 案

### 3-1. 規則台帳 `docs/process/RULES.yml`（型2・型4に効く・小）

規則1件につき: ID／本文への1行／**適用範囲**／**強制層**／根拠になった失敗／逃げ道。

- **適用範囲の欄を必須にする** — 「判定の根拠は原典」に `scope: data/emperors.json のフィールド判定`
  と書いてあれば 11-5 の事故は起きなかった
- **強制層の欄が空 ＝ 人の記憶頼り** と一目で分かる。台帳の値はここにある
- CONSTRAINTS.md を台帳から**生成しない**。あの文書には「削ってよい指示との区別」という
  人が書いた判断が入っており、10-1 の「入口は軽く」とも噛み合っている。台帳は**機械側の索引**として
  散文へリンクする

### 3-2. 誤りの発生源を消す（型1・2・4／L0）

| # | 案 | 潰す誤り | コスト |
|---|---|---|---|
| **A1** | **claims-first の出力契約をデータ調査へ広げる。** 紹介文（#16）で効いた「原文を読む → 引用台帳 `claims` を作る → note は照合として読む → 台帳の範囲だけで書く」を、データ調査エージェントの**出力スキーマ**にする。`claims: [{quote, book, file, line}]` を必須にし、判定は claims を参照する形しか書けなくする | **C型（出典ラベルの取り違え）は発生時点で消える**。#38 の234件は「引用を先に構造で受け取っていれば台帳が最初から行番号つきで埋まっていた」分 | 小（Workflow の `schema` で機械強制できる） |
| **A2** | 続柄は**グラフパス**で出させ、漢語の呼称は機械生成する（QA プラン P1） | A型（続柄・世代の取り違え。#36 で6件） | 中 |
| **A3** | **史料対立の構造フィールド**を作る（同 P3）。いまは書かなければ「気づかなかった」と「対立が無い」が区別できない | E型（#36 で7件） | 中（スキーマ変更） |
| **A4** | **`note` を「作業ログ」と「主張」に割る** | 下記 | 大 |

**A4 の位置づけ** — G2・G3 が測定で転んだ理由そのものへの手当てである。
`note` は「現行 X → Y に訂正した」という**捨てた側の記録**と、欄の値の**主張**を1つの欄で兼ねている。
だから突合の向きが反転し、散文は witness にならなかった（AI_RESEARCH_LESSONS 8-4）。
主張だけを置く欄を分けると、**否定された G2/G3 がその欄に対しては成立する**。

ただしコストは大きく、v3 の作法（`V3_MIGRATION_PLAN.md`）に従うスキーマ変更で、
#39（note をサイトに出さない）とも干渉する。**新規レコード・新規訂正のみに適用し、既存365人は遡及しない**
のが現実的（遡及すると note の書き直しが365人分になり、それ自体が新しい転記経路になる）。

### 3-3. 規則をサブエージェント・Workflow へ届かせる（型3／L2）

**現状の穴**: `.claude/agents/` も `.claude/workflows/` も**空**（トラッキングされているのは
`settings.json` と `session-start-branch.sh` の2つだけ）。調査エージェントのプロンプトは毎回
親セッションが書き起こしており、規則が届くかどうかが親の記憶に依存している。

| # | 案 | 内容 |
|---|---|---|
| **B1** | **`.claude/agents/` に調査エージェントを定義する** | `corpus-researcher`（原典調査）・`adversarial-verifier`（敵対的検証・報告のみ）・`profile-writer` / `profile-reviser`。引用5項・出力契約・「**食い違い: なし**」を明示させる規則・コーパス grep の禁止形を **system prompt 側**へ移す。Workflow からは `agent(prompt, {agentType: 'corpus-researcher', schema: ...})` で参照できるので、**親は対象と史料マッピングだけ渡せばよくなる**＝写し漏れが構造的に消える |
| **B2** | **`.claude/workflows/` に名前つき Workflow を置く** | 紹介文の4段（執筆→敵対的検証→Web 差分→修正）はすでに手順として確立しているのに、**段構成のスクリプトは毎回書き直している**。雛形をスクラッチ→リポジトリへ移したのと同じ移動を、段構成そのものに対して行う。検証段を省いたら通らない、が構造で保証される |
| **B3** | **着手用の skill（`/research-block`・`/correct-record`）** | 「CORPUS_NOTES を読め」では型1は直らない（読まなかった実績がある）。skill の第1ステップで**その書に固有の罠だけを抽出して出す**（SOURCE_MAPPING・CORPUS_NOTES から該当行を引く小スクリプト）。progressive disclosure の実装であって、念押しの反復ではない |

### 3-4. その場で止める（型1・型4／L1）

**C0（前提の検証・これが先）**: **PreToolUse hook がサブエージェント／Workflow エージェントの
ツール呼び出しでも発火するか、まだ確認していない。** 発火しないなら C1〜C3 の価値はほぼ消え、
荷重は 3-2（A）と 3-3（B）へ全部移る。**未検証の仮説を強制層に固定しない**
（`gates-freeze-unvalidated-assumptions` の教訓を自分の提案へ当てたもの）。
検証は hook 1本とエージェント1体で済む。

worktree 側は**検証済み**: `.claude/settings.json` は git 追跡されていて、この worktree にも
primary と同一のものが入っている（現在 worktree は9本）。

| # | 案 | 判定 |
|---|---|---|
| **C1** | コーパスへの `.{0,N}KW.{0,N}` 型 grep を deny（WSL ごと落ちる） | 静的に判定できる。いま CLAUDE.md にあるがモデルの記憶頼り |
| **C2** | `git add -A`・bare `git stash` / `git stash pop` を deny | 同上。並行セッションを巻き込む事故の直接の原因 |
| **C3** | Stop / SubagentStop: `data/*.json` に差分があるのに該当ゲートが走っていなければ止めて指示を返す | 「コミット前にゲートを通す」の最後の網 |

**逃げ道は1本だけ用意し理由を書かせる**（`EMPSTATS_ALLOW=<rule-id>:<理由>` とログ）。
逃げ道の無いゲートは、正しい操作を落とすか最初にぶつかった人に無効化されるかのどちらかになる（8-3）。

**見送るもの**:

- **`emperors.json` の Read 遮断** — 規則は「**メイン会話で**全体を Read しない」と範囲つきだが、
  hook は主会話とサブエージェントを綺麗に区別できない。**規則より広く当たる**ので入れない
- **`emperors.json` の Write/Edit 遮断** — worktree が9本同時に生きている状態で冷たい deny を
  出すと迂回される。書き込み口を `scripts/patch_emperor.py`（id ＋ フィールドパス指定の
  read-modify-write・`meta` は対象外）へ寄せる案自体は筋がよいが、**opt-in で導入し deny はしない**。
  なおこれは調査済みの値を書き写す**転記ツール**であって、CONSTRAINTS の禁じる
  「スクリプトによるデータの自動生成」ではない（判定はしない）

### 3-5. 結合レジストリ（型5・小・単独で価値がある）

型5は hook でもエージェント定義でも直らない。**「X を触ったら Y も触る＋それを証明する検査」**を
1か所に登録するだけで消える。いま散在している既知の結合:

| 触るもの | 一緒に触るもの | 検査 |
|---|---|---|
| 肖像 `manifest.json` の増減 | 実体ファイル・`focusY`・件数6箇所 | あり（deploy gate で落ちた） |
| `name.commonName` の変更 | `site/src/lib/kana-readings.ts` の `TABLE_SOURCE` | ビルドの assert |
| 皇帝の追加 | `timeline-river.ts` の `STREAM_DEFS`・`kana-readings.ts` | ビルドの assert |
| `dynastyOrder` の調査完了 | `meta.catalogs.regimes[].dynastyOrderSurveyed` | **無い**（#24 に「追加すると再発防止になる」と記載） |
| 引用・日付の変更 | `quote-refs.json`・`verify_calendar.py` | あり |

検査が書けるものは `validate_emperors.py` へ、書けないものは**登録だけでも**「知らなかった」が消える。

### 3-6. 効いているかを測る（分母を持つ）

**hook の発火0は「守られている」と「そもそも掛かっていない」を区別しない。**
「0エラーは綺麗と空回りを区別しない」（G1〜G4 実装時の教訓）を規則にそのまま当てる。

- `.claude/hook-log.jsonl` に発火・deny・逃げ道の使用を残す
- 規則ごとに**分母**（守るべき操作が何回起きたか）を数える。C1 なら「コーパスへの grep 回数」、
  B1 なら「調査エージェントの起動のうち定義経由の割合」
- 定義を使わない素の Agent 起動が増えていたら L2 が外れている合図

## 5. パイロットとロールバック条件

一度に全部入れない。**#37（名前の悉皆補充）を試験対象にする**のが最適 —
量が多く1件あたりのコストが低く、事実は本紀冒頭の1行から取れ、**主たる失敗が転記**だからで、
A1 の効果が最も直接に測れる。#24 は自動採番禁止との兼ね合いがあり、#38 は既存ツールでの修復作業なので
試験には向かない。

導入は、合算パスのときと同じく**明示的なロールバック条件つきの試験導入**にする
（AI_RESEARCH_LESSONS 3節の前例）:

1. 見落としが増えた（悉皆性が落ちた）
2. 検証エラー率が悪化した
3. 削減効果が僅少だった
