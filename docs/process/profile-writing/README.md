# 紹介文（GitHub Issue #16）の執筆手順

皇帝365人の紹介文を書く**4段の手順**と、各段のエージェントに渡すプロンプト雛形を置いています。
紹介文は emperorstats.com に公開され検索結果にも出るので、**誤りを出さないことが分量より優先**です。

雛形は 2026-08-02 までセッションのスクラッチパッドにしか無く、セッションが切れるたびに書き直していました。
**リポジトリに置いてあるこちらが正本**です。

## 4段

| 段 | 雛形 | 入力 | 出力 | 役割 |
|---|---|---|---|---|
| 1. 執筆 | [WRITER.md](WRITER.md) | 原文 → `claims` → 素材（**note 抜き**） | `{{FRAG}}/<id>.json` | 原文から引用台帳を作り、その範囲だけで書く |
| 2. 敵対的検証 | [VERIFIER.md](VERIFIER.md) | 断片＋原文＋素材（**note 込み**） | `{{VERIFY}}/<id>.json` | 事実を1つずつ原文へ突き合わせ直し、note との食い違いも見る。**報告のみ** |
| 3. Web 差分検出 | [WEBDIFF.md](WEBDIFF.md) | 断片＋Web＋原文 | `{{WEBDIFF}}/<id>.json` | 通説との食い違いを見つけ、**原典を読み直す引き金**にする。**報告のみ** |
| 4. 修正 | [REVISER.md](REVISER.md) | 断片＋2・3の出力 | 断片を上書き | 指摘を原文で確かめてから反映する |

**1人につき4人の別エージェント**を立てます。同じエージェントに続けてやらせると、自分の書いたものを
検証することになり通りません。

雛形の `{{WORK}}`（スクラッチパッドのパス）・`{{FRAG}}`・`{{VERIFY}}`・`{{WEBDIFF}}`・`{{ID}}`・
`{{NAME}}`・`{{SECTION}}`・`{{CACHE_SIZE}}` を差し替えて渡します。
ブロックごとにディレクトリを分ける（`frag5`・`verify5`・`webdiff5` …）と、n-gram 照合の範囲が揃います。

## 機械ゲート

```bash
python3 scripts/check_profile_fragment.py <断片.json> --basis-corpus   # 1人ぶん
python3 scripts/check_profile_ngram.py <断片.json> --frag-dir <断片ディレクトリ>
python3 scripts/validate_profiles.py && python3 scripts/validate_readings.py   # 本体投入後
```

`check_profile_fragment.py` の**報告欄はエラーと同じくらい重要**です（引用台帳の裏取り・台帳に無い数値・
前任者との続柄の食い違い）。エラーが 0 でも報告を読まずに通さないこと。

本体への投入は `python3 scripts/add_profile.py <断片.json>`。**親セッションだけが走らせる**（並行編集を避ける）。
`claims` は断片の中だけのフィールドで、`add_profile.py` は転記しません。

## なぜ 1 段目に note を渡さないのか

**素材（`emperors.json` の note）を読むと、note の筋書きに合う原文句を探すことになります。**
実際、2026-08-02 までに見つかった紹介文の誤りは、その多くが note 由来でした
（桓玄「詔を書いたのは臨川王宝」・苻生「皇太子として桓温を迎え撃った」など。いずれも note が誤っていた）。

当初はこれを**順序**で防いでいました（原文 → `claims` → note を照合として読む）。しかし
**順序は守っても、同じ文脈に note が入った時点で筋書きは効きます。** そこで 2026-08-02 から
**誰が見るかで分けています** — 1 段目は原文と構造フィールドだけ、note との突き合わせは
2 段目（検証）の仕事です。

`scripts/extract_profile_material.py` は**既定で note を出しません**（`reigns`・`ages`・
`accessionRoute`・`deathCause`・回数8項目・events・収録メモ・典拠の作業ログのすべて）。
検証段だけが `--notes on` を付けます。付け忘れが安全側に倒れるよう、既定を off にしてあります。
伏せた結果その events が日付だけになる場合は「（内容は note のみ・原文で確かめる）」と出ます
——**「何も無い」と「見せていない」を混同させないため**です（実測で events 全体の 6%、
次に書く後趙・前秦・後燕では 0 件）。

note と原文の食い違いは紹介文を直して終わりにせず、**`emperors.json` 側の疑いとして起票**します
（Issue #32 / #33 は訂正済み、#36 は未訂正）。

## Web の扱い

`docs/process/CONSTRAINTS.md` の「判定の根拠は原典に置く」は**データ判定の規則**です。
紹介文では Web を**差分検出器**として使います（2026-08-02 ユーザー決定）。

- Web の記述を根拠に紹介文の正誤を決めない。決めるのは常に原文
- **Web の文章・言い回しを本文に取り込まない**（CC BY-SA 混入のスクリーニングを過去に実施している）
- 「通説と違うが原典に従った」ケースは `basis` に1句残す。残さないと毎回同じ差分が挙がる
