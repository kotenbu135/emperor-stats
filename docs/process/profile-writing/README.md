手書き5本の最大が1,535だったことと合わせると、**エージェントは上限（2,400）まで書く方へ
寄る**。中身は全文が引用台帳と対応していて水増しではないが、「書くことが尽きたら止める」が
効いているかは本数を重ねて見る必要がある。

## 1. 全員に同じ問いを立てる。同じ字数にはしない

365人を悉皆で収めていることがこのデータセットの価値なので、**有名無名で扱いを変えない。**
ただし揃えるのは字数ではなく**答える問い**で、材料の薄い人物は同じ問いに短く答えることになる。

1. **誰の何にあたる人か** — どの政権の、前任者とどういう関係の人物か
2. **どうやって位に就いたか**
3. **在位のあいだ何が起きたか** — 確かめられる場面を最低1つ
4. **どう終わったか**
5. **記録が伝えないことは何か** — 薄い人物ではこれが本文の主題になる

5 は逃げ口上ではない。「『遼史』がこの皇帝について伝えるのは数行しかない」は**その人物にしか
書けない事実**で、しかも原典を読み通した企画にしか書けない。悉皆調査の価値がいちばん出る場所。

## 2. 長さは材料に従う。水増ししない

ゲートの実値は `lead` 70〜260字・`body` 100〜2400字・`description` 100〜140字。

**`body` の目安は800〜1,500字**（2026-08-05 ユーザー決定）。**上限2,400は据え置き**で、
機械は目安を見ない — 超えてよいが、**超えるなら材料が本当に多いからだと言えること**。
目安を置いた理由は、Workflow の3本が揃って2,000字級に寄り（原文が22倍違う清の咸豊帝と
南漢の劉鋹が3%差）、**上限が長さを決めていた**ため。「材料の量ではなく上限に合わせる」の
一番安い直し方が、目安を書いておくこと。既存8本のうち3本はこの目安を超えているが、
上限内なので書き直さない（**上限まで書くとどうなるかの見本**として残す）。

5本の実測は上の表のとおりで、**原文が300倍違っても本文は7倍しか違わない。**
材料の多寡は「読む量」に効き、「書く量」にはあまり効かない。
**手抜きに見せるのは短さではなく水増し**なので、書くことが尽きたら止める。

## 3. 手順は2段

| 段 | やること |
|---|---|
| 1. 執筆 | 本紀の原文キャッシュ `_corpus_cache/<id>.txt` を**1巡**読んで書く |
| 2. Web差分 | 通説と突き合わせ、**当たった箇所だけ列伝を1箇所読む** |

- **前回の4段（執筆→敵対的検証→Web差分→修正）はやめた。** 同じ原文を4回読み、`basis` に
  1人あたり中央値589字の覚え書きを書いていて、365人に掛けられる形ではなかった
- **Web差分は全員にかける。** 中堅の漢の元帝で4件、原文3行の拓跋余で3件出た。
  「有名人だけ」に絞る案は成り立たない
- **1段目に note を渡さない**（`R-CLAIMS-FIRST`）。`extract_profile_material.py` は既定で
  note を伏せる。`--notes on` を付けない。紹介文の誤りの多くが note 由来だった実績がある

### 列伝を読むのは Web差分が当たったときだけ

本紀は要点しか書かないので、**いちばん面白い場面が列伝にあることが多い**（3本中2本がそうだった）。

- 漢の元帝: 本紀は「封騎都尉甘延壽為列侯」だけ。陳湯伝に「元帝內嘉延壽、湯功，而重違衡、
  顯之議，議久不決」（石顕と匡衡が恩賞に反対し、元帝が決められなかった）がある
- 北魏の拓跋余: 本紀は「余為宗愛所賊」の6字だけ。列伝に東廟での弑逆と隠蔽、劉尼が駆け戻って
  叫ぶ場面がある

**最初から列伝を読みに行かない**（費用が跳ねる）。Web差分が指した1箇所だけ降りる。

**降りる先は書によって違う。** `china-history/` に列伝が無い書がある（**隋書は帝紀と志だけ**）。
その場合は `daizhigev20/史藏/正史/<書名>.txt` に全文がある。

この違いは**道具側で吸収した**（2026-08-05）ので、自分で探さない:

```bash
python3 scripts/find_biography.py <皇帝id> <人名> --dump
```

**`--dump` を付ける。** 窓（前後160字）だけ渡すと、書き手は結局その巻を自分で切り出しに行く
（劉鋹の反映段が `scan.py`・`dump.py` を書いて宋史列伝の章番号を総当たりした）。
降りるのは1箇所と決まっているのだから、その1箇所は最初から丸ごと渡す。

書名はレコードの `source.page` から引き、列伝の節が無ければ daizhigev20 側へ自動で降りる。
窓を出すのも Python なので、**コーパスに素の grep を掛けずに済む**（`R-CORPUS-GREP`）。
0件のときは「**『原文に記事が無い』は証拠にならない**」と出る — 避諱・別称・PUA文字で
当たらないことがあるため。

### 大物は本紀の大半が詔と冊文

原文が大きい人物ほど、本紀は**詔・冊文**が占める割合が高い。**1巡の費用の多くは読み物に
ならない部分に消える**ので、詔と冊文の段落は速く通してよい（そこに事実が無いわけではない。
大赦・改元・遷都は詔の中にある。密度が違うだけ）。

**キャッシュの実体は本紀とは限らない**（2026-08-08）。三国の蜀・呉、晋書の載記、隋末群雄の
ように帝紀が立たない政権では、`_corpus_cache/<id>.txt` は列伝・載記そのものが一次史料になる。
読み地図の見出しは**レコードが先頭で名乗る典拠**から本紀／列伝／載記を出し分け、判定できない
ときは「原文」と中立に出す（実測は 本紀223／列伝68／載記39／原文35人）。主典拠のラベルも
1行出るので、**見出しが違っていれば書き手が現物で気づける。**

どこが詔・冊文かは `extract_profile_material.py` の末尾に**読み地図**として出る
（実装は `scripts/corpus_reading_map.py`）。実測:

| 人物 | 詔・冊文 |
|---|---|
| 隋 文帝 | 23% |
| 南燕 慕容超 | 8% |
| 唐 敬宗・清 咸豊帝・清 乾隆帝 | 0% |

出る割合は**下限**（「詔曰：“…”」と1行に収まる形は叙事として数える）。**読まない理由には
使わない** — 判定を誤ったときに落ちるのは材料そのものなので、迷ったら読む側へ倒す。

## 4. 通説と食い違ったとき

- **数値・年号・序数が割れたらデータ（＝原典）を採る。** Wikipedia にも誤りが多い
- 通説にしかない逸話は、列伝1箇所で裏が取れれば書く。取れなければ書かない
- **割れていることを本文で説明しない**（読み物にならない）。序数のように**書かずに避けられる
  ものは避ける**（拓跋余は通説「第6子」・魏書皇子伝「十一男」で割れたので序数を書かなかった）
- **どう判断したかはコミットメッセージに残す。** 本文には残さない

### 外部レビューを当て直すとき（2026-08-09）

レビューアは原文を持っていないので、**観点3（内心の断定）の指摘はほとんどが空振りする。**
review-08 では10件中9件が載記に心情語をそのまま持っていた（「懼，謀奔和龍」「雄大悦」
「意甚不平」「勢疑當等與廣有謀」「弘大懼」「季龍大驚」…）。**「〜と恐れ」「〜と疑い」を
見つけたら、先に原文の該当語を引く**（引ければ不採用・引けなければ書き手の解釈なので採用）。
採用になった1件は、原文が**逆の側**を書いていた例だった（李班の「李越の不満に気づかない
まま」に対し、載記は「班以未葬，不忍遣，推誠居厚，心無纖芥」と李班の側を書く）。

反対に**観点2（別々の条の融合）は当たる。** 同じ review-08 で、石虎の載記が美女徴発の段に
置いている逯明の切諫を、華林苑の造営の段へ繋いでいた（苑を諫めたのは趙攬たち）。
**融合の疑いが出たら、2つの出来事が同じ条にあるかを必ず原文で見る。** ただし**同じ条だと
原文が言っていることもある** — review-22 で「盧携が毒を飲んだ日と僖宗が金光門から出た日は
別日ではないか」と挙がったが、本紀は「携聞賊至、仰藥而死。**是日**、上與諸王…出幸山南」と
同じ日に置いていた（不採用）。逆に review-22 の白馬駅は、敕が命じたのは**任地での自尽**で、
7人はすでに滑州まで来ていて「並命于白馬驛」となる。**原文に継ぎ目があるなら文を割る。**

**観点9（ルビ）で「一般語なのに振っている」という指摘は、先に
`data/profile-ruby-lexicon.json` を引く。** そこに載る語は「必ず振る語」なので、外すと
ほかの本と割れ、`validate_readings.py` と `reapply_profile_ruby.py` が戻す
（review-21 の「武帝」「始皇帝」3件はこれで不採用）。**足す側は自由・外す側だけ辞書と
突き合わせる。**

**観点4（制度語が地の文で通じない）は、ルビを足して済ませない。** 語の意味を地の文へ開くか、
語ごと日本語へ置き換える（review-21〜22 では 大盈内庫→天子の手もとの金庫／坊市→街区と市場／
方鎮→節度使らの管区／常参官→日ごとの朝の参内に出る官／団練→土地の者を集めた自衛の兵／
行在→皇帝の滞在先）。**読者が読めない語は、読めるようにするのではなく通じるようにする。**

**「肩書きの一語」のような曖昧な指示は原文が具体を持っていることがある** — review-21 の
吐突承璀は、憲宗紀が「詔旨只改處置為宣慰，猶存招討之名」と書いており、どの語をどう替えたかを
本文に書けた。**「どこが」と聞かれたら、まず原文にその答えがあるかを見る。**

| | |

## 6. `basis` はポインタであって覚え書きではない

ファイル名＋行番号＋そこに何があるか。**散文で書かない。**
列伝を読んだときは「Web差分の何に当たって降りたか」を1句だけ添える。

```
_corpus_cache/han-yuandi.txt（漢書 巻九 元帝紀）L1 宣帝との問答・立太子／L16-17 蕭望之と弘恭・石顕／…
china-history/汉书/传/第四十二章-傅常郑甘陈段传-原文.html（漢書 巻七十 陳湯伝）L36-38 論功をめぐる
石顕・匡衡の反対と劉向の上書（Web差分で当たったため1箇所だけ読んだ）。年齢は ages.deathAge。
```

前回は `basis` の総量 49,984字が `body` の総量 46,754字を上回っていた。**成果物より覚え書きが
多い状態を作らない。**

### 引用台帳 `claims` は別物（断片の隣・配布物には入らない）

原文を1巡したことの**唯一の機械的な証拠**が引用台帳。
`{"text": 書く事実, "quote": 根拠の原文句, "src": "ファイル:行"}` を
**断片の隣の `<id>.claims.jsonl` へ1行1件**で書き、**配布物には入らない**
（`add_profile.py` が転記するのは4フィールドだけ）。

**断片の中に持たせない**（2026-08-05）。本文を1文直すたびに台帳40〜53件ごと再送することになり、
実測では執筆エージェントが 6.7KB の `build.py` を書いてゲートで落ちるたび丸ごと書き直していた
（本文2,000字に対して1体3〜6万トークンの出力）。骨格と空の台帳は
`python3 scripts/new_profile_fragment.py <id> --out <workDir>` が作る。
**`Write` は骨格を埋める1回だけで、以降の直しは `Edit`。** 断片の中に `claims` を直接
書いた古い形も `--strict` は受ける（既存8本の断片を落とさないため）。

前回これを潰したのは `basis` の散文の覚え書きであって、台帳ではない。台帳が要るのは、
**原文を開かずに書いた文章が他の検査を全部通ってしまう**から — 字数もルビも12-gram も
`emperors.json` との年の照合も、記憶で書いた文章で満たせる。`--strict` はここを見る。

**`--strict` が見ないもの: 引用より広いことを本文に書く形。** 引用が実在し `src` も
合っていれば、本文がその引用の言っていない所まで踏み越えていても緑で通る。唐の敬宗で
実際に起きた（本紀の「賊は御座に登った」＝主語は無名の賊、五行志の「二人対食于清思殿」の
2条を「張韶と蘇玄明が御座に登って向かい合って食べた」と1文へ融合させかけた。
その像は資治通鑑のもの）。**書いた側が気づいて戻した**もので、機械では出ない。
1つの文が2つの条をまたぐときは、条ごとに主語を分けて書く。

## 7. 文体

- だ・である調。**現代の日本語で書く**（漢文訓読調の「没する」「〜せしむ」を避ける）
- 原文の言い回しを写さず、内容を理解して自分の言葉で書く
- **敬称・賛辞・主観的評価を書かない**（「名君」「暗愚」）。史書の評を引くときは
  「『漢書』は〜と評する」と主語を立てる
- **集計値を書かない**（「改元4回」「大赦10回」）。同じページのすぐ下に回数の表がある。
  **個々の事件は集計値ではないので書く**
- `lead` の第1文は定義文（「〜の皇帝」）。そこから即位・事績・最期までを1段落で見通す。
  **年譜形式にしない**
- **節見出し（`## `）を立てない。** 見出しを立てると本紀の通読要約に引きずられる。
  段落は空行（`\n\n`）で分ける
- 原文（漢文）をそのまま持ち込まない

### 書き出しと結びの型は本ごとに変える（2026-08-09）

外部レビューが**通して読んだときにだけ出る指摘**として、6ファイル60本のうち4ファイルで
同じことを挙げた。1本ずつ書いているかぎり気づけない:

- **書き出し**: 「前漢の皇帝。」で始まる本が6本続く・「後漢の皇帝。〜の子で」が8本続く。
  **定義文（「〜の皇帝」）の規約は保ったまま、先頭へ識別句を置けば型が割れる**
  （「代王から迎えられて位に就いた前漢の皇帝。」「在位27日で退けられた前漢の皇帝。」）
- **結び**: 10本すべてが「本紀は〜を書かない」「末尾の評はこう述べる」で閉じる。
  これは1節の問い5（記録が伝えないことは何か）が出す形なので**内容としては正しい**が、
  並べると使い回しに見える。**同じバッチの中で、後日談・封国の処置・別の巻への送りなど
  別の閉じ方へ寄せる本を混ぜる**
- 太后の臨朝のような**同じ出来事の言い回し**も、5本で「朝廷に出て政務を執った」に揃っていた

**機械では見られない**（12-gram は12字連続でしか当たらず、この型は当たらない）。
バッチを書き終えたら、**そのバッチの lead の第1文と body の最終段落だけを並べて読む。**

**結びの型は60本を並べて測った（2026-08-09）:** 最終段落の第1文が「本紀は〜を書かない」型の
史料観察で始まる本が**60本中およそ45本**あった。問い5が出す形なので**中身は正しく、
一括では直さない** — バッチの中に別の閉じ方（後日談・封国の処置・末尾の評の引用・
最期の場面そのもの）を混ぜる、という運用にする。**落として型を変えない**
（2026-08-09 に武帝と景帝で史料観察の一文を落としたところ、材料そのもの〔五畤の祠祀・
白麟・黄河の氾濫／「可」の一字〕が消え、武帝は「巫蠱の獄でも、」の「も」が宙に浮いた。
同じ日に戻した）。

**2026-08-09、ユーザー指示で観点10（本どうしの型の反復）を外部レビューの依頼文から落とした**
（`scripts/export_profile_review.py` の `CROSS` を空にした）。**外部へ聞くのをやめただけで、
上の「バッチを書き終えたら lead の第1文と最終段落を並べて読む」は書き手側の手順として残る。**
review-19〜22 の依頼文にはもともと観点10の項目が無く、19 と 20 では自分で測って書き出しを
3本ずつ割ったが、**21・22 は観点から落ちたあとに当てたので割っていない**（唐10本の lead は
「唐の皇帝」で始まる型が並んだまま）。

**2026-08-12、外部レビューへ渡す単位を1人1ファイルにした**（`--split`。同じ日に既存の
書き出しを全部消して228人ぶんを取り直した）。10人ずつ束ねていたのは観点10のためで、
その観点が落ちたあとは束ねる理由が無い。1本ずつなら指摘の箇所も「途中で切れていないか」の
確認も1人の中で閉じる。同時に**確定値へ名前系を全部出すようにした**（廟号・諡号・諡号全長・
字・幼名・別称。`regnalTitle` は228人全員が「皇帝」なので出さない）。名前系を出すときは
依頼文に**「本文の呼び方は現代の通用名に揃えてあるので、呼び分けの違いは指摘不要」**の
断りを添える — 断りが無いと「本文は僖宗だが諱は儇」が全ファイルで指摘として返る。


### 訓読しただけの語は機械が落とす（2026-08-05）

「現代の日本語で書く」は 2026-08-04 から規範にあったが、**文言だけでは止まらなかった** —
18本に54箇所残っていた（始皇帝の「六国を併せた」「蒙恬を監させた」、恵帝の
「母を皇太后に尊んだ」をユーザーが読んで見つけた）。語の一覧と言い換えは
`scripts/profile_prose.py` の `ARCHAIC` にあり、`check_profile_fragment.py`（断片）と
`validate_readings.py`（本体・CI）が落とす。

**「没した」は禁じない**（2026-08-05 ユーザー指摘。現代の日本語でも広く通用する）。
規範が 2026-08-04 から「没する」を名指しで禁じていたのは行き過ぎで、同日それに従って
19箇所を「死んだ」へ書き換えたのも**戻した**。判定は「原文の語を訓読でそのまま持ってきたか」で、
**見慣れない語かどうかで決めない。**

| 使わない | 書く |
|---|---|
| 崩じた・薨じた | 死んだ |
| 母を皇太后に尊んだ | 母を皇太后の位に就けた |
| 六国を併せた | 六国を併合した |
| 蒙恬を監させた | 蒙恬の軍を監督させた |
| 誅した／徙した／賜った | 処刑した／移した／与えた |
| 請う／奉じた／可とした | 願い出た／差し出した／認めた |

**カギ括弧の中は対象外。** 『漢書』が「薨」とだけ書く、のように史書の語そのものを
話題にする箇所は落とさない。逆に言えば、原文の語を出したいときはカギ括弧に入れる。

**「即位」「封じる」「詔」は禁じていない**（歴史用語として要る）。増やすときは
既存の紹介文へ当ててから `ARCHAIC` に足す。

### 人物は「現代での通用名」で指す（2026-08-07 ユーザー決定）

> 紹介文の人物名は諱固定ではなく現代での通用名にする。始皇帝なら政ではなく嬴政、劉邦など。
> ただし、耶律阿保機、クビライのように単純に姓諱を繋げればいいというものではない。
> 本人の名前にもルビをふる。

本紀の原文は諱1字で人物を指すので、そのまま持ってくると「垂は兵を返し」「勒が部下を
監督した」になる。日本語では通用しない。**既存148本のうち91本・延べ922箇所**がその形で、
2026-08-07 に `scripts/fix_profile_bare_name.py` でまとめて直した。

**名前は書き手が選ばず `scripts/profile_name.py` から引く**（続柄を `relation_path.py`
から引くのと同じ理由で、選ばせると割れる）。素材コマンドの冒頭に
`本文で使う名前: ｜慕容垂《ぼようすい》` の1行が出るので、それをそのまま使う。
規則は4つで、**既定は姓＋諱**・例外だけが名指し:

| 規則 | 人数 | 例 |
|---|---|---|
| `default` 姓＋諱 | 349 | ｜嬴《えい》｜政《せい》・劉邦・曹丕・石勒・慕容垂・愛新覚羅溥儀 |
| `ethnic` 音写名が通用 | 13 | クビライ・トゴン・テムル（元12人）・ホンタイジ（清太宗） |
| `courtesy` 字で知られる | 2 | 耶律阿保機（諱は億）・完顔阿骨打（諱は旻） |
| `override` 名指しの例外 | 1 | 武則天（姓＋諱は「武曌」） |

**契丹名・女真名は `ethnic` に入れない** — 遼の「耶律堯骨」・金の「合剌」は原音の別名で
あって現代日本の通用名ではなく、通用するのは漢名の「耶律徳光」「完顔亶」のほう。
`aliases` からも機械で拾わない（あの欄には「秦始皇」「海昏侯」「蒼梧王」のような
**号**が混ざる）。

**本人の名前にもルビを振る**（`reapply_profile_ruby.py` が全出現へ写す）。振っていない本が
実際にあった（「劉邦」5箇所・「楊堅」4箇所・「袁術」13箇所）。読みは
`data/name-readings.json` が正本で、365人ぶん揃っている（切り方もあちらに従う —
「｜完顔《ワンヤン》｜阿骨打《アグダ》」のように分ける指定がある）。

**例外は1つだけ: 諱そのものを話題にしている文。**「諱は禅、字は公嗣」「石を姓とし勒を
名として与えた」はそのままでよく、ゲートも数えない（前者へ姓を足すと重複し、後者は
「石勒を名として与えた」になって文が壊れる）。

読みと同じでこれは**原典から得られる調査項目ではない**（日本語の慣用）ので、
`emperors.json` には欄を足していない。例外を足すときは `profile_name.py` の
`OVERRIDES`／`COURTESY_NAMES` に**理由をコメントで添えて**書く。

## 8. ルビ

**総ルビはやめた（2026-08-05 ユーザー決定）。** 難読語と中国史特有の語に振る。
**振るのは固有名詞と中国史の語**（人名・**帝号・廟号**・元号・地名・官職・制度・器物・
故事・干支）で、**一般語には振らない**（「皇太子」「儒学」「政治」）。

> **「元帝には振らない」は 2026-08-05 に撤回した。** ユーザーの指示ではなく、
> 同日に書き手が作って規範へ書き込んでいたもの。**帝号・廟号にも1字の人名断片にも振る。**

- 記法は青空文庫式 `｜親文字《ルビ》`。**`｜` を省略しない**
- 親文字が2字以上で `data/name-readings.json` に載っているものは、**テーブルと同じ切り方・
  同じ読み**にそろえる（「劉奭」は `｜劉《りゅう》｜奭《せき》` と1字ずつ割られているので、
  本文でも割る。読める「劉」を落として `｜奭《せき》` だけにしてもよい）
- **`description` にはルビを振らない**（`<meta>` と JSON-LD にしか出ない）

### 2回目以降の出現にも振る（2026-08-05 ユーザー決定）

初出だけに振って以降を素通りさせない。**同じ本の中で1度でも振った語は、その本の
全出現に振る**（`lead` と `body` はつないで1本として見る）。実測では18本で143語・
延べ305回が初出だけの状態で、「挟書律」は `lead` に振って `body` で素通り、
「邯鄲」は始皇帝の本文に4回出て1回も振られていなかった。

読みを決めるのは書き手（＝担当するエージェント）で、**全出現へ写すのは機械**:

```bash
python3 scripts/reapply_profile_ruby.py <断片.json> --write   # 書き終えてから1回
python3 scripts/reapply_profile_ruby.py --dry-run             # 本体18本ぶん
```

### 振る語の辞書 `data/profile-ruby-lexicon.json`

**本をまたいで必ず振る語**を894語（2026-08-06 時点）持つ。ここに載る語が本文に
ルビ無しで出ていれば、断片のゲートも CI も落とす。載せてあるのは:

- 既に書いた18本で振った語
- **帝号・廟号196語**（`data/name-readings.json` の〜帝／〜宗／〜祖。読みも切り方も
  テーブルのまま。「高宗」は `｜高《こう》｜宗《そう》` と1字ずつ割られている）
- **干支60**（「丙寅」「甲子」。日付に必ず出るのに読みが分からない）
- 官職・制度・器物・地名・故事（「邯鄲」「仲父」「長信侯」「廷尉」「御史大夫」「璽書」）
- 1字の人名断片（「楊広」の「広」・「陳叔宝」の「陳」）

**辞書は書くたびに育てる。** 新しい難読語に振ったら足す。

**読みはユーザーに確認しない（2026-08-06 ユーザー決定）。** 振る語も読みも書き手が
決めて入れる。**辞書に足す語は本をまたぐぶんだけ**にする — 1つ足すごとに残り318人に
対してその読みが固定され、違う読みで書いた正しい断片のほうが落ちる向きにも働くので、
1冊にしか出ない語は辞書へ足さず本文のルビだけで済ませる（同じ本の中の揃いは
ゲートが本文から引く）。**本をまたぐ読みの割れと、辞書と本文の食い違いは
`scripts/validate_readings.py` の検査7・8 が落とす**（2026-08-06 に足した。それまでは
どちらも全ゲートを緑で通っていて、「北匈奴」「北郷侯」が3本ずつに割れていた）。

**1字の語は2方向へこぼれる。** 熟語に食い込む側（「遺詔」「諡法」「璽書」）は
**長い語を辞書へ載せて**防ぐ（長い語から当たるので勝つ）。一般語に当たる側
（「広い」「陳列」）は `scripts/profile_prose.py` の `NOT_TERMS` で伏せる —
**人名として使われているかは機械では決まらない**ので、当たった語を足していく運用。

### ルビで足りない語は地の文で説明する

**読みが分かっても意味が分からない語がある**（「奇貨居くべし」「仲父」）。
ルビは読みの手当てでしかないので、**故事成語・制度語はその場で意味が通るように書く。**
史書の語をそのまま置いて読者に辞書を引かせない。これは機械では見られない。

`scripts/validate_readings.py` の「総ルビ充足」検査は 2026-08-05 に外した。
**どの語が難読かは機械では決まらない**が、**「辞書に載せた語」と「同じ本の中で
振り方が揃っているか」は決まる** — そこだけ機械が見て、残りは人が見る。
実測は1本あたり31.5語（2回目以降と帝号・廟号を振ったあと・その前は10語）。

## 9. ゲート

断片のうちに（本体へ入れる前に）:

```bash
python3 scripts/new_profile_fragment.py   <皇帝id> --out <workDir>   # 骨格と空の台帳
python3 scripts/check_profile_fragment.py <断片.json> --strict
python3 scripts/check_profile_ngram.py    <断片.json>
```

**`check_profile_fragment.py` は落とすときに「直し方」を必ず出す。** エラー文で足りなければ
`--help` に断片の形と字数がある。**ソースを読みに行かない。**

`--strict` が見るのは3つ — **claims が在るか／その `quote` が `src` の指すファイルに実在するか／
`basis` のポインタ（ファイル＋行番号）が実在するか**。**外さない。**

本体へ入れたあと:

```bash
python3 scripts/add_profile.py <断片.json>
python3 scripts/validate_profiles.py    # 文字数・basis の有無・12-gram の重複・年の照合
python3 scripts/validate_readings.py    # ルビの記法・読みテーブルとの整合・本数
cd site && npm run build                # 表示まで通るか
python3 scripts/coverage.py --write     # 本数が増えたら。忘れると CI が落ちる
```

`check_profile_fragment.py`・`check_profile_ngram.py`・`add_profile.py` は 2026-08-05 に
新しい形（ポインタ `basis`・選択的ルビ・`claims`）で通した。**未検証ではない。**

人物の指し方は `check_profile_fragment.py`（断片）と `validate_profiles.py`（本体・CI）の
両方が見る。落ちたら**書き直さずに機械で直せる**:

```bash
python3 scripts/fix_profile_bare_name.py --for <皇帝id> --dry-run
python3 scripts/fix_profile_bare_name.py --expect <件数> --write   # 宣言が合わなければ書かない
python3 scripts/reapply_profile_ruby.py --write                   # 本人の名前にもルビを写す
```

## 11. まとめて進めるとき（Workflow）

段構成は `.claude/workflows/write-profile.js`。**執筆 → Web差分 → 反映**の3段で、
2段目までは規範どおり（3段目は「Web差分が当たったときに列伝を1箇所読む」の実行担当）。

**実行に要る規則はエージェント定義（`.claude/agents/profile-*.md`）が全部持っている。**
そちらはシステムプロンプト側で1回だけキャッシュされるので、**この README を読ませない**
（下の12節）。文言を直すときは定義側も揃える。

```
Workflow({ name: 'write-profile', args: { ids: [...], workDir: '/tmp/write-profile-<日付>' } })
```

- **`data/emperor-profiles.json` を並行して書かせない。** 断片は `workDir` へ1人1ファイル。
  本体への転記はワークフローが戻ってから `add_profile.py` で1本ずつ（`R-RMW`）
- **`isolation: 'worktree'` を付けない。** コーパスの symlink が無い worktree では
  コーパス依存の検査が**黙ってスキップ**される（`R-WORKTREE-SETUP`）
- **Web差分が当たらなければ3段目のエージェントを立てない。** 5本の実測で2本は列伝が要らず、
  空振りに1体ぶんの費用を払う理由が無い
- 断片を本体へ入れてゲートを流すのは**ワークフローが戻ってから**。`data/*.json` に
  未コミット差分があるまま turn を終えると `stop_gate.py` が走る

### 実測（2026-08-05・3人）

- 3人とも Web差分が当たって列伝へ降りた（手書き5本では5本中3本）。**空振り時に3段目を
  立てない仕掛けは、この3人では発火しなかった**
- 唐の敬宗は列伝ではなく**五行志**へ降りた（張韶の乱の手口が本紀に無く志にあった）。
  「列伝を1箇所」は**本紀の外を1箇所**の意味で運用する
- 清の咸豊帝だけ2箇所読んだ（杜受田伝＋後継の穆宗本紀）。上限を超えているので、
  次からは**降り先が本紀の外なら1箇所**と数える

### 12. トークン費用（実測と、そこから道具へ落とした4点）

3人9体の `agent-*.jsonl` を **`usage.iterations` 基準**で集計した結果。
**`message.id` で重複排除しない** — 1回のAPI応答が thinking／tool_use ごとに複数行で書かれる
ので、id で潰すと同一応答の途中経過が1件に畳まれ、**出力が実際の3割に見える**（一度そう誤った）。
`iterations` は `type` を持ち、**`advisor_message` が advisor 自身の消費**。

| 種別 | トークン | 単価重み | 重み付き | 比率 |
|---|---:|---:|---:|---:|
| 出力（本体） | 265,157 | 5.0 | 1,325,785 | 27.4% |
| **advisor（非キャッシュ入力）** | 1,147,322 | 1.0 | 1,147,322 | **23.7%** |
| キャッシュ読み | 9,554,191 | 0.1 | 955,419 | 19.7% |
| キャッシュ書き | 739,820 | 1.25 | 924,775 | 19.1% |
| **advisor（出力）** | 97,855 | 5.0 | 489,275 | **10.1%** |

計 11,804,841トークン／**重み付き入力等価 4,843,072＝1人あたり161万**。残り357人で約5.8億。
キャッシュ書きは全件 `ephemeral_5m` なので重みは 1.25（1時間TTLの 2.0 ではない）。

これを受けて 2026-08-05 に道具側へ落とした（**規範の文言を増やしていない**）:

1. **エージェントに advisor を呼ばせない**（**指示だけでは止まらない。下の検証を見よ**）。
   9体で16回呼ばれ、**その16回だけで重み付き費用の33.8%**（非キャッシュ入力 1,147,322＋
   出力 97,855）。非キャッシュ入力は**この16回が全量**で、他の応答はゼロ。判定者は
   `check_profile_fragment.py --strict` で、助言が判定を変える余地が無い。
   禁止は `.claude/agents/profile-*.md` と段のプロンプトの両方に書いた
2. **引用台帳を `<id>.claims.jsonl` へ分けた**（6節）。本文の直しで台帳が再送されない
3. **ゲートは落とすときに「直し方」を出す。** 落ちたエージェントが
   `check_profile_fragment.py` を全文 Read する・grep + sed で追う・`--help` を叩く、を
   やっていた。1ターン6〜13万トークンの文脈を読み直す地点なので、ターン数がそのまま費用になる
4. **形を探させない。** `extract_profile_material.py` の末尾で**見本1本の全文**・
   `emperor-profiles.json` の構造・ルビの引き方・ゲートの走らせ方を配る。
   `find_biography.py --dump` は当たった巻を丸ごと出す（窓だけ渡すと、書き手は結局
   その巻を自分で切り出しに行く）。**この README と SKILL.md はエージェントに読ませない** —
   9体すべてが計23.5KB を全文 Read して以降20ターンぶん運んでおり、キャッシュ読みの17%だった

### 対策を1体で検証した（2026-08-05・北魏 拓跋余の Web差分）

| 対策 | 結果 |
|---|---|
| README・SKILL.md を読ませない | **効いた**（`ls` 1回だけで、全文 Read はゼロ） |
| **advisor を呼ばせない** | **効かなかった** — 3箇所に書いても1回呼ばれ、**その1回でこの体の費用の24.5%**（非キャッシュ入力 52,999＋出力 7,600）。9体平均の1.78回よりは減っている（n=1） |

**advisor はハーネス側の指示が勝つ。** 文言では止まらないので、**残り約25%は当面の固定費**として
見込む（1人161万のうち約40万）。止める手段が要るなら道具側ではなく設定側の話になる。

### 上の「固定費」は次の10人で消えた（2026-08-05・30体）

|---|---:|---:|
| advisor 呼び出し | 16回 | **0回** |
