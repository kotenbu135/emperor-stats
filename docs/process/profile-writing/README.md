# 紹介文の規範（GitHub Issue #16）

**2026-08-05 に立て直した。** 置き場所はこの1枚だけで、`data/emperor-profiles.json` の
`meta.policy` には戻さない（前回は規範が JSON と `docs/` の2箇所に分かれていた）。

見本は実際に書いた3本 — `han-yuandi`・`beiwei-tuobayu`・`xiliao-renzong`。
原文の量がそれぞれ 14,639B / 686B / 234B で、**材料の厚い側・薄い側・ほとんど無い側**を1本ずつ。

---

## 1. 全員に同じ問いを立てる。同じ字数にはしない

365人を悉皆で収めていることがこのデータセットの価値なので、**有名無名で扱いを変えない。**
ただし揃えるのは字数ではなく**答える問い**で、材料の薄い人物は同じ問いに短く答えることになる。

1. **誰の何にあたる人か** — どの政権の、前任者とどういう関係の人物か
2. **どうやって位に就いたか**
3. **在位のあいだ何が起きたか** — 確かめられる場面を最低1つ
4. **どう終わったか**
5. **記録が伝えないことは何か** — 薄い人物ではこれが本文の主題になる

5 は逃げ口上ではない。「『遼史』がこの皇帝について伝えるのは数行しかない」は**その人物にしか
書けない事実**で、しかも原典を読み通した企画にしか書けない。悉皆調査の価値がいちばん出る場所。

## 2. 長さは材料に従う。水増ししない

| | 実測 |
|---|---|
| `lead` | 70〜260字（ゲートの実値）。3本の実測は 236 / 161 / 131 |
| `body` | 100〜2400字。3本の実測は 635 / 444 / 217 |
| `description` | 100〜140字 |

**原文の量が62倍違っても、本文は3倍しか違わなかった。** 材料の多寡は「読む量」に効き、
「書く量」にはあまり効かない。**手抜きに見せるのは短さではなく水増し**なので、
書くことが尽きたら止める。

## 3. 手順は2段

| 段 | やること |
|---|---|
| 1. 執筆 | 本紀の原文キャッシュ `_corpus_cache/<id>.txt` を**1巡**読んで書く |
| 2. Web差分 | 通説と突き合わせ、**当たった箇所だけ列伝を1箇所読む** |

- **前回の4段（執筆→敵対的検証→Web差分→修正）はやめた。** 同じ原文を4回読み、`basis` に
  1人あたり中央値589字の覚え書きを書いていて、365人に掛けられる形ではなかった
- **Web差分は全員にかける。** 中堅の漢の元帝で4件、原文3行の拓跋余で3件出た。
  「有名人だけ」に絞る案は成り立たない
- **1段目に note を渡さない**（`R-CLAIMS-FIRST`）。`extract_profile_material.py` は既定で
  note を伏せる。`--notes on` を付けない。紹介文の誤りの多くが note 由来だった実績がある

### 列伝を読むのは Web差分が当たったときだけ

本紀は要点しか書かないので、**いちばん面白い場面が列伝にあることが多い**（3本中2本がそうだった）。

- 漢の元帝: 本紀は「封騎都尉甘延壽為列侯」だけ。陳湯伝に「元帝內嘉延壽、湯功，而重違衡、
  顯之議，議久不決」（石顕と匡衡が恩賞に反対し、元帝が決められなかった）がある
- 北魏の拓跋余: 本紀は「余為宗愛所賊」の6字だけ。列伝に東廟での弑逆と隠蔽、劉尼が駆け戻って
  叫ぶ場面がある

**最初から列伝を読みに行かない**（費用が跳ねる）。Web差分が指した1箇所だけ降りる。

## 4. 通説と食い違ったとき

- **数値・年号・序数が割れたらデータ（＝原典）を採る。** Wikipedia にも誤りが多い
- 通説にしかない逸話は、列伝1箇所で裏が取れれば書く。取れなければ書かない
- **割れていることを本文で説明しない**（読み物にならない）。序数のように**書かずに避けられる
  ものは避ける**（拓跋余は通説「第6子」・魏書皇子伝「十一男」で割れたので序数を書かなかった）
- **どう判断したかはコミットメッセージに残す。** 本文には残さない

## 6. `basis` はポインタであって覚え書きではない

ファイル名＋行番号＋そこに何があるか。**散文で書かない。**
列伝を読んだときは「Web差分の何に当たって降りたか」を1句だけ添える。

```
_corpus_cache/han-yuandi.txt（漢書 巻九 元帝紀）L1 宣帝との問答・立太子／L16-17 蕭望之と弘恭・石顕／…
china-history/汉书/传/第四十二章-傅常郑甘陈段传-原文.html（漢書 巻七十 陳湯伝）L36-38 論功をめぐる
石顕・匡衡の反対と劉向の上書（Web差分で当たったため1箇所だけ読んだ）。年齢は ages.deathAge。
```

前回は `basis` の総量 49,984字が `body` の総量 46,754字を上回っていた。**成果物より覚え書きが
多い状態を作らない。**

## 7. 文体

- だ・である調。**現代の日本語で書く**（漢文訓読調の「没する」「諫める」「〜せしむ」を避ける）
- 原文の言い回しを写さず、内容を理解して自分の言葉で書く
- **敬称・賛辞・主観的評価を書かない**（「名君」「暗愚」）。史書の評を引くときは
  「『漢書』は〜と評する」と主語を立てる
- **集計値を書かない**（「改元4回」「大赦10回」）。同じページのすぐ下に回数の表がある。
  **個々の事件は集計値ではないので書く**
- `lead` の第1文は定義文（「〜の皇帝」）。そこから即位・事績・最期までを1段落で見通す。
  **年譜形式にしない**
- **節見出し（`## `）を立てない。** 見出しを立てると本紀の通読要約に引きずられる。
  段落は空行（`\n\n`）で分ける
- 原文（漢文）をそのまま持ち込まない

## 8. ルビ

**総ルビはやめた（2026-08-05 ユーザー決定）。** 難読語と中国史特有の語だけに振り、
**日本人が普通に読める漢字には振らない**（元帝・長安・儒学・皇太子には振らない）。

- 記法は青空文庫式 `｜親文字《ルビ》`。**`｜` を省略しない**
- 親文字が2字以上で `data/name-readings.json` に載っているものは、**テーブルと同じ切り方・
  同じ読み**にそろえる（「劉奭」は `｜劉《りゅう》｜奭《せき》` と1字ずつ割られているので、
  本文でも割る。読める「劉」を落として `｜奭《せき》` だけにしてもよい）
- **`description` にはルビを振らない**（`<meta>` と JSON-LD にしか出ない）
- 実測は1本あたり8〜21語

`scripts/validate_readings.py` の「総ルビ充足」検査は同日に外した。**どの語が難読かは機械では
決まらない**ので、機械が見るのは記法と読みの整合だけになる。ルビの本数は必ず出るので、
0件が「振る語が無かった」のか「振り忘れた」のかは人が見て判断する。

## 9. ゲート

```bash
python3 scripts/validate_profiles.py    # 文字数・basis の有無・12-gram の重複・年の照合
python3 scripts/validate_readings.py    # ルビの記法・読みテーブルとの整合・本数
cd site && npm run build                # 表示まで通るか
```

`scripts/check_profile_fragment.py`・`check_profile_ngram.py`・`add_profile.py` は前回の
4段手順の投入経路で、**新しい `basis` の形（ポインタ）では未検証**。使う前に確かめること。

本数が増えたら `python3 scripts/coverage.py --write`（忘れると CI が落ちる）。
