# Web 差分検出エージェント用プロンプト雛形（{{ID}}）

皇帝紹介文（GitHub Issue #16）の断片1本について、**書いた内容が世間の通説と食い違っていないかを見る**作業です。
作業ディレクトリは `/home/sakis/emperor-stats/.claude/worktrees/profiles`。

## この段の位置づけ（**ここを外さないこと**）

**Web は根拠ではなく、原典を読み直す引き金です。**

- **Web の記述を根拠に「紹介文が誤り」と判定しない**。判定の根拠は常に正史の原文
- **Web の文章を紹介文に取り込まない**（表現も、言い回しも、語順も）。
  このリポジトリは過去に CC BY-SA 混入のスクリーニングを実施しており、Web 由来の文言が本文へ入ると同じ risk が戻る
- あなたは**差分を挙げるだけ**で、断片も `data/` 以下も**書き換えない**

通説の側が誤っていることは実際によくあります（このプロジェクトが見つけた誤りの多くは「Web でよく見る形」でした）。
**食い違い＝紹介文の誤り、ではありません。**

## 対象

- 断片: `{{WORK}}/{{FRAG}}/{{ID}}.json`（`lead`・`body`・`description` と `claims`）
- 原文: `_corpus_cache/{{ID}}.txt`（**簡体字**）
- 出力: `{{WORK}}/{{WEBDIFF}}/{{ID}}.json`

## やること

1. 断片を Read し、**外形的に確かめられる主張**を抜き出す
   （生没年・在位年・前任者との続柄・死に方・廟号/諡号・都・主要な事件の年）
2. WebSearch で通説を引く。**日本語版 Wikipedia・中文 Wikipedia・百度百科**あたりを見る。
   1人あたり **検索3〜5回まで**（それ以上かかるなら「照合できず」と書いて終える）
3. **食い違った項目だけ**を挙げる。一致した項目は書かない
4. 食い違った項目について、**その場で原文に当たり直す**（`/usr/bin/grep -n` → `Read`）。
   - 原文が紹介文どおり → `verdict: "原典どおり"`。**紹介文は直さない**
   - 原文が通説どおりで紹介文が誤り → `verdict: "紹介文の誤り"`。修正案を書く
   - 原文が何も述べていない（紹介文が原文外の事実を書いている）→ `verdict: "原文に根拠なし"`。**これが一番重い**
   - 原文を読んでも決まらない → `verdict: "未決"`

## 出力

```json
{
  "id": "{{ID}}",
  "checked": ["生没年", "前任者との続柄", "死に方", "..."],
  "diffs": [
    {
      "item": "没年",
      "profile": "紹介文の記述",
      "web": "通説（どのサイトか）",
      "corpus": "原文の該当句とその所在（ファイル:行）",
      "verdict": "原典どおり | 紹介文の誤り | 原文に根拠なし | 未決",
      "action": "紹介文の誤りなら修正案。原典どおりなら basis に足す1句"
    }
  ],
  "searches": 4
}
```

## `verdict: "原典どおり"` のときの後始末

`action` に **`basis` へ足す1句**を書いてください（例:
「没年は通説 328 年だが載記の記事順に従い 329 年を採る」）。
これを残さないと、次に誰かが同じ照合をしたときに**同じ項目がまた差分として挙がります**。

## 最終メッセージ

**1行**（例: `{{ID}}: 7項目照合 / 差分2件（紹介文の誤り1・原典どおり1） / 検索4回`）。
本文・検索結果を会話へ貼らないこと。
