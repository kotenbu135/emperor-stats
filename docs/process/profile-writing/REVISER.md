# 修正エージェント用プロンプト雛形（{{ID}}）

皇帝紹介文（GitHub Issue #16）の断片1本を、**敵対的検証の指摘に従って直す**作業です。新規執筆ではありません。
作業ディレクトリは `{{ROOT}}`（**worktree ごとに変わる。ここを取り違えると別セッションの作業ツリーを書き換える**）。

## 対象

- 断片（**ここを上書きする**）: `{{WORK}}/{{FRAG}}/{{ID}}.json`
- 検証結果: `{{WORK}}/{{VERIFY}}/{{ID}}.json`
- Web 差分（あれば）: `{{WORK}}/{{WEBDIFF}}/{{ID}}.json`
- 原文: `_corpus_cache/{{ID}}.txt`（**簡体字**。大きい場合は全文を読まず `/usr/bin/grep -n` → `Read` の offset/limit）

## やること

1. 各ファイルを Read する
2. `findings` を**severity によらず全部**反映する。**`low` も事実に触れるものは直す**（high/medium だけ直して事実に触れる low を残した失敗が過去にある）
   - ただし**指摘が正しいか原文で確かめてから直す**。検証側が誤っていることもある。直さないと判断した場合は理由を最終メッセージに1行で書く
   - **本文が検証時から更新されている場合がある**。指摘の `quote` が本文に見つからなければ反映済みとみなしてよいが、**同趣旨の誤りが別の表現で残っていないか**は確かめる
   - **優先順位は「`findings` の反映」が先、「3節の素材の採用」（下の4）が後**。上限に当たったら落とすのは素材の側で、落としたものは最終メッセージに名前と理由を書く。**`findings` を黙って落とさない**
3. `dataDoubts`（`emperors.json` 側の疑い）は**紹介文の修正対象ではない**。本文がその疑わしい note に引きずられていないかだけ確認する。**`data/emperors.json` は絶対に触らない**
4. Web 差分 `diffs` を扱う。**読むのは `verdict` ではなく `action` の本文**で、両者が食い違うときは `action` が勝つ（`verdict` は4語しかないので、`action` が「本紀の範囲外なだけで事実ではある」「本文に1文足す案」まで書いていても `verdict` には出ない）
   - `紹介文の誤り` → 直す（ただし**原文で確かめてから**。Web の記述を根拠にしない）
   - `原文に根拠なし` → 既定は**その記述を本文から落とす**（Web と原文の両方に無い事実が残っている状態が一番まずい）。ただし `action` が別の書に典拠があると書いている場合は、**落とすのではなく本紀の書き方へ直す**
   - `原典どおり` → **本文は直さない**が、ここが3節の素材の主な供給源。`action` が「本文に1文足す案」と書いているものは**採用を検討する**（読者が最もよく知っている通説と史書がずれている型ほど採る価値がある）。採らなかったもの・採れなかったものは `action` の1句を `basis` に足して、次回同じ差分が挙がらないようにする
   - `未決` → 直さず、最終メッセージに1行で残す
   - **Web の文章・言い回しを本文に取り込まない**（CC BY-SA 混入の risk）。素材として本文に足すときも、**ずれの内容だけを自分の言葉で1文にする**
5. `basis`・`claims` を直した箇所に合わせて更新する。**本文に足した事実は必ず `claims` にも足す**
   - **`claims` が空の断片は、この段で台帳を起こす**。`「」` で括った箇所は STYLE 5節により `claims` の裏づけが要る（台帳が無いために「原文は地の文なのに直接話法として括った」誤りが実際に残った）
   - **要素の形は `{"text": …, "quote": …, "src": "<ファイル:行番号>"}`**（キー名は `line` ではなく `src`。`check_profile_fragment.py` が見るのはこの名前）
   - **`text` が `quote` の射程を超えないこと。** 超えるなら claim を2つに割って、それぞれに対応する原文句を当てる
   - 最終メッセージに **`「」` の総数・`claims` で裏づけの取れた数・取れなかった数**を書く。取れなかった数は 0 でなければならない
   - **数えるときは「引用型」（発言・書物の記述）と「語の言及」（「皇帝」「阿房宮」のように語そのものを指す括弧）を分けて、合計を出す。** 語の言及も裏づけは要る — 「『史記』に「坑儒」の語は無い」のように**語の不在を主張する括弧**は、不在を示す条（460人を阬にした記事）の claim が担保になる

## 規約（変えてはいけない前提）

- 字数（**ルビを剥がした長さ**。`scripts/validate_profiles.py` の LIMITS が正で、ここを信じて削らない — **必ず `check_profile_fragment.py` の出す実測に従う**）: `lead` 70〜260字・`body` 100〜2400字・`description` 100〜140字（先頭70字に名前・政権・在位年）
- **`body` は `## 見出し` で5〜6節に分ける**（新文体）。節を丸ごと足したり潰したりしない
- **総ルビ**（`lead`・`body` は漢字すべてに `｜親文字《ルビ》`。`description` は平文・ルビ禁止）
- **かなの前に裸の `｜` を書かない**
- **固有名詞は `data/name-readings.json` の切り方に合わせる**（`python3 -c "import json;print(json.load(open('data/name-readings.json'))['names'].get('<語>'))"`）
- **`「」` に入れてよいのは [STYLE.md](STYLE.md) 5節の2つだけ**（史料が直接話法「〜曰」で載せる発言／書物の記述を『史記』は「〜」と記す の形で引くとき）。どちらも `claims` に対応する原文句が無ければ書けない。**地の文の言い換えを括弧に入れない**（2026-08-01 の「和訳を括って引かない」は 2026-08-04 に改訂され、担保が `claims` へ移った）
- 敬称・賛辞・主観評価を書かない。回数の集計値は書かない
- **`body` は上限に張り付いている**。字を足したら同じ段落から削る。削る先は固有名詞の列挙・本筋に効かない年月日
- **`data/emperor-profiles.json` は絶対に触らない**（本体への投入は親セッションがやる）

## 完了条件

断片を上書き Write したうえで、次の2本がどちらも通ること:

```bash
python3 scripts/check_profile_fragment.py <断片> --basis-corpus
python3 scripts/check_profile_ngram.py <断片> --frag-dir {{WORK}}/{{FRAG}}
```

最終メッセージは**1〜3行**（反映した件数・直さなかった指摘があればその理由・字数）。本文は会話へ貼らないこと。
