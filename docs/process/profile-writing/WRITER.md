# 執筆エージェント用プロンプト雛形（{{ID}} / {{NAME}} / {{SECTION}}）

中国皇帝統計プロジェクト（作業ディレクトリ: `/home/sakis/emperor-stats/.claude/worktrees/profiles`）で、
皇帝1人ぶんの紹介文（GitHub Issue #16）を執筆してください。**担当は `{{ID}}`（{{NAME}}・{{SECTION}}）1人だけ**です。

この紹介文は emperorstats.com に公開され、検索結果にも出ます。**誤りを出さないことが字数を埋めることより優先**です。

## 成果物

`{{WORK}}/{{FRAG}}/{{ID}}.json` に次の形で Write する。**`data/emperor-profiles.json` は絶対に触らない**（本体への投入は親セッションがやる）。

```json
{"{{ID}}": {"lead": "...", "body": "...", "description": "...", "basis": "...",
  "claims": [{"text": "本文で書いた事実", "quote": "根拠の原文句", "src": "_corpus_cache/{{ID}}.txt:123"}]}}
```

| フィールド | 用途 | 字数（**ルビ記法を剥がした長さ**） |
|---|---|---|
| `lead` | ヒーロー内に出る**概要**。人物の一生を1段落で見通す | **150〜250字**・総ルビ |
| `body` | 「人物紹介」節。**節見出し `## ` つきの時系列**。段落区切りは空行 `\n\n` | **100〜2200字**・総ルビ・史料が乏しければ省略可 |
| `description` | `<meta>`・JSON-LD | **100〜140字**・**平文（ルビ禁止）**・先頭70字に名前・政権・在位年 |
| `basis` | サイトに出さない。何を読んで書いたか | 原文の該当句を10〜20字ずつ列挙。**採らなかった表記・本紀の外から採った事実もここ** |
| `claims` | サイトに出さない（断片の中だけ） | **本文の事実1つ = 1項目**の引用台帳。下の手順2で作る |

**文体と構成の正は [STYLE.md](STYLE.md) です。書き始める前に読んでください。**
この雛形には手順しか書いてありません。

## 手順（**この順で。逆にしない**）

### 1. 原文を先に読む

`_corpus_cache/{{ID}}.txt`（**{{CACHE_SIZE}}**）を読む。**素材（note）はまだ開かない。**

- 大きいときは全文を読まず `/usr/bin/grep -n` で行番号を出し `Read` の offset/limit で読む
- **キャッシュは簡体字**。grep は簡体字で打つ（「劉」→「刘」・「漢」→「汉」）。変換は `python3 scripts/hanzi_norm.py`
- **`.{0,N}KW.{0,N}` 型のコンテキスト抽出 grep を掛けない**（素の `grep` は ugrep でメモリが暴走し WSL ごと落ちる）
- 本紀・載記に無い事実（列伝・裴注・資治通鑑・華陽国志）を使うなら `china-history/`・`daizhigev20/` に当たり、**出所を `src` に書く**
- **キャッシュが 2KB 未満の人物は、載記が父や兄の巻に同居している**。その場合キャッシュは冒頭の数百字しか無く、
  `--basis-corpus` の照合はほとんど効かない（正しく引いた句も「未検出」に並ぶ）。
  **`daizhigev20/`・`china-history/` の該当巻を直接読み、`src` に書名・巻を書く**

### 2. 書く前に `claims` を作る

読んだ原文から、**本文に書くつもりの事実を1つずつ**列挙する。`quote` は**原文からのコピー**で、
手打ち・要約・語順変更をしない。この段階で原文に無い事実は**書かない**と決める。

台帳に載らない事実は本文に書けません。**本文を先に書いて後から根拠を集めない**（順序が逆になると、
書きたい筋書きに合う句を探すことになり、主語や世代の取り違えが通ります）。

### 3. 素材の構造フィールドを照合として読む

`python3 scripts/extract_profile_material.py {{ID}}` を走らせ、**1 で読んだ原文と突き合わせる**。

**この出力に既存 note は入りません**（`--notes off` が既定）。あなたに渡らないのは意図的です
——note の筋書きに合う原文句を探してしまい、note の誤りがそのまま本文へ流れるからです。
note との突き合わせは検証段の仕事です。**`--notes on` を自分で付けないでください。**

- 見るのは在位年・年齢・即位経路の軸・死因・回数8項目の**値**と、events の**日付と構造キー**
- 値が原文と食い違ったら**原文が正**。食い違いは最終メッセージに列挙する（下記）
- events が「（内容は note のみ・原文で確かめる）」になっている行は、**そこに何かがあった**という
  意味です。書きたければ 1 に戻って原文で確かめ、`claims` に足す
- **数値の理由を推測で埋めない**（「0回なのは在位が短いため」など）。原文に無ければ書かない

`emperors.json` を直接 Read しない（素材はこのスクリプトから出す）。

### 4. 執筆する

`claims` に載せた事実だけで書く。**台帳の全部を使い切る必要はありません。**

## 執筆規約

**全文は [STYLE.md](STYLE.md)。** ここには、そちらを読んだうえで**手を動かすときに毎回外す点**だけ置きます。

- **人物の内心を書いていないか。**「〜と考えた」「〜を望んだ」「〜を恐れた」を全部検索して、
  史料の発言・詔・行動へ置き換える。**史料自身が心情を書いている範囲だけ書ける**
- **通説とのずれを本文に1文入れたか。** 原典に当てて「世間で言われている形と違う」と気づいた点が
  あれば、黙って正しく書くのではなく**ずれを示す**（「後世〜と呼ぶが、『史記』に〜の語はない」）
- **時制は過去形にそろえたか。** 歴史的現在（「継ぐ」「定める」「上奏する」）を混ぜない
- **節や段落の頭で主語を落としていないか**
- **節見出しは内容を指す名詞句か**（口語的な比喩は差し戻しになる）
- **発言の「」には対応する原文句が `claims` にあるか。** 地の文の言い換えは括弧に入れない
- **`諱は◯` に姓を入れない**（「諱は劉盈」ではなく「諱は盈」）。素材の「諱」の側をそのまま使う。
  姓を抜いて字数が足りなくなったら**別の事実で埋める**（字数合わせに姓を戻さない）
- **回数8項目の集計値は書かない**（「改元3回」「反乱8件」）。個々の事件名は書く。在位年・年齢は書く
- **有名な逸話でも原文で裏が取れないものは書かない**（記憶のまま書かない）
- **confidence が high でなくても言い切る。** 史料同士が直接矛盾する場合だけ1句触れる
- **史書の「評曰」「論曰」「太史公曰」は日付付きの記事ではない。** 地の文に混ぜず
  「史書の評は〜と書く」と主語を立てる
- **字数を埋めない。** `body` の上限は2200字ですが**下限は100字**です。確かなことが少ない人物は短く終える

## 書く前に見る「毎回出る誤りの型」

検証段で繰り返し出ているのは次の6つです。**書き終えたら自分で1つずつ当たってください。**

1. **世代が1つずれる** — 族子・兄の子・弟・従子を取り違える。**原文が続柄を直接述べていない関係は書かない**
   （「Ａの子のＢ」と書くなら、その続柄を述べた句が `claims` にあること）
2. **別々の月の出来事を1つに混ぜる** — 原文の月見出しをまたいだ2件を1文にしない
3. **干支2つを同じ日として書く** — 別の日です
4. **詔・上奏の起草者と受け手を入れ替える** — 「誰が誰に書かせたか」を原文の主語で確かめる
5. **「評曰」を地の文にする** — 史官の評価を事実として書かない
6. **背景説明を直列化して因果を作る** — 原文が並べているだけの2件を「〜のため」でつながない

## ルビ（総ルビ）

- 記法は `｜親文字《ルビ》`。**`lead`・`body` は漢字すべてに振る**（`description` は平文）
- **かなの前に裸の `｜` を書かない**（「｜のちに」は画面にそのまま `｜` が出る。毎回起きる事故）
- **読みテーブル `data/name-readings.json` は一体形と分割形が混在する**。固有名詞を書く前に必ず引く
  （`劉邦`＝`｜劉邦《りゅうほう》` だが `劉盈`＝`｜劉《りゅう》｜盈《えい》`）。テーブルと違う切り方はゲートが落とす
  - 引き方: `python3 -c "import json;d=json.load(open('data/name-readings.json'));print(d.get('<語>'))"` か `/usr/bin/grep -n '<語>' data/name-readings.json`

## 自己チェック（Write したあと必ず走らせる）

```bash
python3 scripts/check_profile_fragment.py <断片.json> --basis-corpus
```

エラーは直して再実行する。**報告欄も読むこと**:

- `claims` の引用がキャッシュ外 → 出所を `src` に書くか、書いた事実そのものを疑う
- 「台帳に無い数値」 → その年・人数・年齢の出所を `claims` に足すか、本文から落とす
- 「データの前任者続柄 = X ／ 本文の続柄語 = Y」の食い違い → **原文で確かめる**。
  前任者以外との続柄を書いているだけなら無視してよい

`body` は放っておくと上限に張り付きます。**先に節4〜6本の骨子（見出しの言葉）を決めてから書き出す**。

## 最終メッセージ

**2行**にしてください。本文は断片ファイルに書くので、会話へは貼らないこと。

```
{{ID}}: lead 184字 / body 2050字 / description 116字 — ゲート OK
note と原文の食い違い: なし（または「deathCause.note の『従兄弟』は原文『伯父』」のように列挙）
```

**2行目は必ず書く**（食い違いが無ければ「なし」と書く）。無言は「照合していない」と見なします。
