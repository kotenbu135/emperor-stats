# 検証エージェント用プロンプト雛形（{{ID}} / {{NAME}}）

皇帝紹介文（GitHub Issue #16）の**敵対的検証**を1人ぶん担当します。**修正はしません。報告だけ**です。
作業ディレクトリは `/home/sakis/emperor-stats/.claude/worktrees/profiles`。

## 対象

- 断片: `{{WORK}}/{{FRAG}}/{{ID}}.json`
- 素材: `python3 scripts/extract_profile_material.py {{ID}}`（既存の調査結果）
- 原文: `_corpus_cache/{{ID}}.txt`（**簡体字**・{{CACHE_SIZE}}）

## やること

`lead`・`body`・`description` に書かれた**事実**（人物の関係・世代・年・事件の順序・地名・官職・数字・死に方）を1つずつ原文と突き合わせる。

## 罠

- **キャッシュは簡体字**。grep は簡体字で打つ（劉→刘・漢→汉・慕容→慕容・趙→赵・準→准）。変換は `python3 scripts/hanzi_norm.py`
- **`.{0,N}KW.{0,N}` 型のコンテキスト抽出 grep を掛けない**（素の `grep` は ugrep でメモリが暴走し WSL ごと落ちる）。**必ず `/usr/bin/grep -n`** で行番号を出し `Read` の offset/limit で読む。大きいキャッシュは全文を読まない
- **五胡十六国は本紀ではなく『晋書』の載記**。「本紀に無い」ことを誤りの根拠にしない
- **素材（emperors.json の note）自体が誤っていることが実際にある**。note と原文が食い違ったら**原文が正**で、その場合は「データ側の疑い」として報告する（紹介文の誤りではない）
- **原典に根拠を置く**。WebSearch の要約だけで判定しない。**記憶だけで「これは誤り」と言わない**

## 過去に実際に出た誤りの型（同じものを探す）

- 原文の主語の取り違えで人物の**世代が1つずれる**（族子・兄の子・弟を取り違える）
- **別々の月の2つの出来事を1つに混ぜる**
- **一つの記事に干支が2つ並んでいたら別の日**（6日違いを「同じ日に」と書いた事故がある）
- 詔を**起草した人物**と**受けた人物**の入れ替え
- 史書の「評曰」「論曰」「史臣曰」を、日付付きの記事であるかのように地の文にする
- 背景説明の一句を、直前の事件と**同じ場面の連続動作**として直列化する

## 出力

`{{WORK}}/{{VERIFY}}/{{ID}}.json` に Write:

```json
{
  "id": "{{ID}}",
  "findings": [
    {"severity": "high|medium|low", "field": "lead|body|description",
     "quote": "本文の該当箇所（ルビ記法のまま10〜30字）",
     "problem": "何が誤りか", "evidence": "原文のどこ（ファイル・行番号）に何と書いてあるか",
     "suggestion": "どう直すべきか"}
  ],
  "dataDoubts": [{"field": "emperors.json のどのフィールドか", "problem": "note と原文の食い違い", "evidence": "原文の所在"}],
  "checked": "突き合わせた事実の件数と、確認できた主な項目の短い列挙"
}
```

- **severity は誤りの重さで付ける**。「low だから直さない」運用ではないので、**事実に触れる誤りは小さくても必ず挙げる**。文体の好みは挙げない
- 誤りが無ければ `findings` を空配列にする。`dataDoubts` も無ければ空配列

最終メッセージは**1行だけ**（例: `{{ID}}: findings 2件（high 0 / medium 1 / low 1）・dataDoubts 1件`）。本文は JSON ファイルに書く。
